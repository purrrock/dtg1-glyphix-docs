# Спецификация бинарного формата `TEMP.bin`
**Платформа:** Actions Semiconductor ATS3085S  
**Программная платформа:** Glyphix OS / Zephyr RTOS  
**Целевое устройство:** Смарт-часы DT NO.1 G1 и совместимые  
**Версия спецификации:** 1.6 (Финальная верифицированная)

---

## 1. Общая архитектура контейнера

Бинарный файл `TEMP.bin` представляет собой проприетарный загрузочный контейнер второй ступени (Stage-2 Bootable Image Container). Файл предназначен для исполнения первичным загрузчиком чипа Actions ATS3085S, инициализации аппаратной периферии/контроллера памяти и последующей декомпрессии системных разделов прошивки в RAM.

Контейнер состоит из пяти ключевых логических зон:
1. **Actions Boot Header (`ACTHHTCA`)** — 40 байт (`0x00000000`–`0x00000027`).
2. **Alignment Padding** — 472 байта нулей (`0x00000028`–`0x000001FF`), выравнивание IVT на границу 512 байт.
3. **Interrupt Vector Table (IVT)** — 320 байт (`0x00000200`–`0x0000033F`), аппаратная таблица векторов прерываний ARM Cortex-M.
4. **Boot Stub Code & Padding Gap** — исполняемый Thumb-2 код первичной инициализации железа и выравнивающий зазор до первого сжатого блока.
5. **Compressed Payload Chunks** — последовательность сжатых XZ-потоков, представляющих собой нарезанный на порции по **2 MiB (`0x200000`)** монолитный образ внутреннего контейнера `inner_aota_container.bin`.

## 2. Глобальная карта памяти файла (Memory Map)

| Смещение (Hex) | Конец блока | Размер (Байт) | Описание / Содержимое |
| :--- | :--- | :--- | :--- |
| `0x00000000` | `0x00000027` | 40 | **Главный загрузочный заголовок** (`ACTHHTCA`) |
| `0x00000028` | `0x000001FF` | 472 | **Заполнитель выравнивания** (байты `0x00`) |
| `0x00000200` | `0x0000033F` | 320 | **Таблица векторов прерываний (IVT)** ARM Cortex-M |
| `0x00000340` | `entry_point - 1` | Переменный | **Boot Stub Engine**: машинный код Thumb-2 инициализации железа |
| `entry_point` | `first_lzma - 1` | Переменный | **Padding Gap**: технический выравнивающий зазор до секции LZMA |
| `first_lzma` | `chunk2_start - 1` | Переменный | **Чанк #1**: Заголовок `LZMA` (16б) + XZ-поток (Блок #1 монолита, 2 MiB / `0x200000`) |
| `chunk2_start` | `EOF` | Переменный | **Чанк #2**: Заголовок `LZMA` (16б) + XZ-поток (Блок #2 монолита, остаток байт) |

## 3. C-Структуры заголовков (Little-Endian)

### 3.1. Главный заголовок Actions Boot Header (40 байт / 0x28)
Начинается с нулевого смещения файла (`0x00000000`).

```c
struct actions_boot_header_t {
    char     magic[8];       // "ACTHHTCA" (0x41 0x43 0x54 0x48 0x48 0x54 0x43 0x41)
    uint32_t load_addr;      // Адрес загрузки Reset Vector в XIP Flash (например, 0x1000246D или 0x100024B1)
    uint32_t block_size;     // 0x00000062 (Размер служебного блока заголовка, 98 байт)
    uint32_t padding;        // 0x00000000 (Нулевой заполнитель)
    uint32_t exec_addr;      // Точка входа исполнения в памяти (совпадает с load_addr)
    uint32_t entry_point;    // Абсолютное смещение границы исполняемого кода Boot Stub (например, 0x00011028)
    uint32_t header_sig;     // Заводская статическая подпись заголовка (например, 0xCA99494D)
    uint32_t payload_sig;    // Заводская статическая подпись полезной нагрузки (например, 0x8BCDC3C5)
    uint32_t ivt_offset;     // 0x00000200 (Смещение начала векторной таблицы IVT = 512 байт)
};
```

#### Назначение ключевых полей:
* **`load_addr` / `exec_addr` (`0x0008`, `0x0014`):** Задают физический адрес старта процессора ARM Cortex-M в режиме Thumb (младший бит равен `1`). Адрес уникален для каждой сборки прошивки.
* **`entry_point` (`0x0018`):** Отмечает конец исполняемой секции Boot Stub. Между `entry_point` и первым сжатым чанком `LZMA` располагается заполнитель (Padding Gap).
* **`header_sig` / `payload_sig` (`0x001C`, `0x0020`):** Заводские статические сигнатуры текущей сборки. Не подлежат динамическому пересчету через zlib/SUM32, сохраняются в неизменном виде при репакинге.

### 3.2. Заголовок сжатого чанка Actions LZMA Header (16 байт / 0x10)
Указывается перед каждым сжатым блоком.

```c
struct actions_lzma_header_t {
    char     magic[4];       // Магические байты "LZMA" (0x4C 0x5A 0x4D 0x41)
    uint32_t header_size;    // Фиксированный размер заголовка: 0x00000010 (16 байт)
    uint32_t comp_size;      // Физический размер упакованного XZ-потока в байтах
    uint32_t uncomp_size;    // Заявленный размер после разжатия блока в RAM (лимит 0x200000)
};
```

## 4. Аппаратная векторная таблица (IVT)

Таблица векторов располагается строго по смещению **`0x00000200`** (`ivt_offset = 0x200`):

* **`0x00000200` (Initial MSP):** Указатель стека в области внутренней SRAM ATS3085S.
* **`0x00000204` (Reset Vector):** Вектор сброса (указывает на `load_addr`).
* **`0x00000208`–`0x0000023F`:** Системные обработчики прерываний ARM Cortex-M (NMI, HardFault, SVC, SysTick).
* **`0x00000240`–`0x0000033F`:** Дефолтные обработчики периферийных прерываний чипа.

## 5. Механика фрагментации полезной нагрузки (2 MiB Chunking)

Контейнер `TEMP.bin` хранит **один непрерывный бинарный образ (`inner_aota_container.bin`)**, который при сборке нарезается на порции размером не более **2 MiB (`0x200000` байт / 2 097 152 байт)**.

### Доказательство межблочного разреза:
* **Монолитный образ:** Содержит внутренний AOTA-контейнер с файлами `ota.xml`, `app.bin` (размером >3 МБ) и `sdfs.bin`.
* **Chunk #1:** Сжимает первые `0x200000` байт монолита. Из-за этого тело `app.bin` оказывается разрезано: первые `0x001FF800` байт ядра попадают в Чанк #1.
* **Chunk #2:** Сжимает оставшуюся часть монолита (`0xFD600` байт), содержащую хвост `app.bin` и `sdfs.bin`.

## 6. Регламент работы утилит (Protocol Standard)

1. **Распаковка (`unpack_temp.py` v1.3):**
   - Читает 40-байтный `actions_boot_header.bin`.
   - Извлекает `boot_stub.bin` (от `0x28` до первого строгого маркера `LZMA\x10\x00\x00\x00`).
   - Разворачивает все XZ-потоки в памяти (In-Memory) и склеивает их в единый монолит `inner_aota_container.bin`.
   - Промежуточные чанки `chunk_*.*` сохраняются на диск только при передаче опционального флага `-s` (`--save-chunks`).

2. **Сборка (`compress_and_pack_temp.py` v1.6):**
   - Использует оригинальный 40-байтный `actions_boot_header.bin`, сохраняя заводские адреса и подписи.
   - Записывает `boot_stub.bin`.
   - Нарезает модифицированный `inner_aota_container.bin` на куски по `0x200000` байт, сжимает каждый в XZ и оборачивает заголовком `actions_lzma_header_t`.
   - Формирует итоговый `TEMP_new.bin`.
