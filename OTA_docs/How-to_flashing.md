### Шаг 0.

Как скачать заводкую ОТА прошивку для своих часов.
Есть ссылка: https://dt1pro.wanruxia.com/xky-api/firmware/checkUpdate?devicePlan=10&number=88265
Вместо номера в конце 88265 нужно подставить нужный вам. Его можно увидеть на часах в меню 'Настройка - О часах'.
Там будет строка вида Version1.73.21-88265R, вот последние цифры нам и нужны.
Подставляете в ссылку свой номер и видите JSON. Там в поле "file": ссылка на вашу ОТА-прошивку:

### Шаг 4. Установка прошивки на часы

Вы можете установить полученный файл `ota_patched_custom.bin` одним из двух способов.

---

#### Способ A. Прошивка напрямую через ПК (`dt_ota_flasher.py`) (ПОКА НЕ РАБОТАЕТ!)

Данный способ не требует наличия смартфона, приложения WearPro или подмены ответов серверов.

1. Зарядите часы минимум до 50%.
2. Отключите часы от приложения WearPro на смартфоне (и выключите Bluetooth на смартфоне, чтобы освободить GATT-сервер часов).
3.  Узнайте MAC-адрес часов:
   * **На часах:** В меню настроек - 'О часах'
   * **Windows / Linux:** MAC-адрес вида `AA:BB:CC:DD:EE:FF` (можно посмотреть в свойствах устройства или через утилиту сканирования BLE, например `nRF Connect`).
4. Запустите консольный флешер:

```bash
python dt_ota_flasher.py AA:BB:CC:DD:EE:FF ota_patched_custom.bin
```

Пример успешного процесса передачи:

```text
[*] Подготовка данных: 4274688 байт...
[*] Файл разбит на 18586 BLE-пакетов.
[*] Подключение к часам (MAC: AA:BB:CC:DD:EE:FF)...
[+] Подключено. Инициализация AOTA сессии...
[*] Текущий размер MTU соединения: 247 байт
[+] Инициализация успешна. Начинаем заливку прошивки...
    Прогресс: 1000/18586 пакетов (5.4%)
    ...
    Прогресс: 18586/18586 пакетов (100.0%)
[+] Передача завершена. Отправка команды Reboot...
[*] Успешно! Часы уходят в перезагрузку.
```

#### Способ B. Прошивка через приложение WearPro (HTTP Mocking)

Если вы хотите использовать штатное мобильное приложение WearPro, отправку прошивки можно форсировать путем перехвата HTTP-запроса проверки обновлений.

**Инструмент перехвата:** [HTTP Toolkit](https://httptoolkit.com/) (с включенным ADB-перехватом на Android-смартфоне с Root или через эмулятор).

##### 1. Настройка Mock-ответа для сервера обновлений

В HTTP Toolkit создайте правило (**Mock Rule**) для перехвата запроса проверки версий:
* **Match Request:** `URL` -> `Contains` -> `/xky-api/firmware/checkUpdate`
* **Action:** `Provide response`
* **Status:** `200`
* **Headers:** `Content-Type: application/json`
* **Body (JSON):**
  ```json
    {
    "code": 200,
    "message": "Request successful",
    "success": true,
    "data": {
      "id": 1182,
      "createTime": "2026-03-02 16:12:11",
      "updateTime": "2026-03-04 10:35:00",
      "name": "C175GA3",
      "adapterId": 1203,
      "limitationId": null,
      "version": "V1.73.23",
      "versionNum": 830023,
      "file": "https://ota.local/firmware.bin",
      "fileSize": 6438400,
      "originFileName": "ota_A5S10GLY_C175G_A3-2026-02-28-17-03_V1_73_23.bin",
      "forceUpdate": true,
      "description": "null",
      "prodType": true
    },
    "fail": false
  }
  
  ```
  *(Значение `fileSize` должно строго совпадать с байтовым размером вашего `ota_patched_custom.bin`)*.

##### 2. Настройка правила отдачи бинарного файла
Добавьте второе правило в HTTP Toolkit для перехвата скачивания прошивки:
* **Match Request:** `URL` -> `Equals` -> `https://ota.local/firmware.bin`
* **Action:** `Provide response`
* **Status:** `200`
* **Headers:** `Content-Type: application/octet-stream`
* **Body:** Выберите `From File` и укажите путь к `ota_patched_custom.bin` на вашем ПК.

##### 3. Запуск обновления
1. Принудительно завершите приложение WearPro на смартфоне для сброса кэша.
2. Откройте WearPro -> раздел **Устройство** -> **Обновление прошивки**.
3. Приложение обнаружит "версию V1.73.23", скачает сгенерированный файл с `ota.local` и зальет его в часы по Bluetooth.

## 🔧 Диагностика и устранение ошибок

1. **Приложение WearPro останавливается на "Подготовка прошивки 0%":**
   * **Причина:** Несовпадение байтового размера файла `TEMP.bin` или `app.bin` с данными, записанными в тегах `<file_size>` файлов `ota.xml`.
   * **Решение:** Убедитесь, что вы использовали актуальный скрипт упаковки прошивки, который автоматически обновляет метаданные XML.

2. **Скрипт `dt_ota_flasher.py` выдает `BleakError` или обрывает связь на 1-2%:**
   * **Причина:** Bluetooth-адаптер ПК не поддерживает расширение длины кадра DLE или сбрасывает большие MTU буферы.
   * **Решение:** Добавьте небольшую задержку между отправкой кадров в скрипте (увеличьте значение `asyncio.sleep` до `0.01` сек) или используйте внешний USB Bluetooth 5.0+ адаптер.
