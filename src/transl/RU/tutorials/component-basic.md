# Основы компонентов

В предыдущем документе «[Быстрый старт](getting-started)» было кратко представлено понятие компонентов. Данное руководство познакомит вас с компонентами более подробно. Прежде чем приступить к чтению этого документа, вам необходимо знать, как создавать и собирать проекты, а также как редактировать исходные файлы. Если вы этого не знаете, пожалуйста, прочитайте руководство «[Быстрый старт](getting-started)».

## Введение

В разработке приложений Glyphix все интерфейсы представляют собой компоненты — от маленьких кнопок до целых страниц. Компонентный подход позволяет разрабатывать интерфейсы с использованием простого языка шаблонов:
``` html
<!-- main/index.ux -->
<template>
  <p>{{text}}</p>
</template>

<style>
  * {
    text-align: center;
  }
</style>

<script>
  export default {
    data: {
      text: "Hello, World!"
    }
  }
</script>
```
По сути, это файл `main/index.ux` из шаблона проекта по умолчанию. Вы можете посмотреть результат отображения, выполнив команду `gx emu`. Содержимое тега `<template>` является шаблоном компонента, который описывает его внешний вид. В данном случае узел `<p>` будет отображать свойство `text` объекта модели компонента. Обратите внимание, что внутренний фреймворк компонентов связывает содержимое узла `<p>` со свойством `text` модели компонента: как только значение свойства `text` изменяется, интерфейс синхронно обновляется.

Мы можем протестировать это с помощью таймера:
``` js
export default {
  data: { text: "begin!" },
  onInit() {
    let count = 0
    setInterval(() => this.text = "timeout: " + count++, 1000)
  }
}
```
Теперь вы увидите, что отображаемое значение счетчика увеличивается на 1 каждую секунду.

## Программная модель компонентов

 Одной из важных функций GUI-программ является изменение своего внешнего вида на основе данных и пользовательского ввода для реализации интерактивности. В традиционном программировании GUI и нативном HTML разработчикам необходимо найти целевой элемент узла в дереве интерфейса, а затем вызвать API для его обновления. Как показывает практика, разработка интерфейсов таким способом очень сложна, поэтому появились шаблоны проектирования, подходящие для GUI, такие как MVC, MVP, MVVM, а в сфере веб-разработки появились новые фреймворки. Все эти технологии значительно снизили сложность разработки интерфейсов.

Программная модель компонентов Glyphix очень похожа на фронтенд-фреймворки вроде Vue. Основная идея этих фреймворков заключается в вычислении нового интерфейса на основе состояния модели интерфейса, а не в принудительном обновлении элементов интерфейса при изменении состояния. По сравнению с традиционными технологиями, часть представления интерфейса в таком решении не имеет собственного состояния (stateless), что делает его гораздо проще. Давайте продолжим использовать предыдущий пример для иллюстрации:
``` html
<template>
  <p>{{ text }}</p>
</template>
```
Как мы уже знаем, интерфейс автоматически обновляется при изменении свойства `text` модели компонента. Однако в традиционных GUI-фреймворках часто требуется вручную обновлять узел `<p>` после обновления свойства `text` в модели (что обычно происходит из-за ввода данных или изменения внутренних данных). Такие фреймворки, как MVC, могут упростить эти операции, но не делают их предельно простыми.

Теперь рассмотрим очень простой подход: мы пишем функцию `render()`, которая генерирует дерево интерфейса на основе текущего состояния модели. Если бы мы заменяли исходное дерево интерфейса результатом функции `render()` на каждом кадре, то любые изменения модели отражались бы в интерфейсе. Это решение очень простое, но вы бы отвергли его из-за низкой эффективности. На самом деле традиционная модель программирования GUI зародилась именно для решения проблемы эффективности этого подхода: изменять только те элементы в интерфейсе, которые действительно изменились. Однако это привносит состояние на уровень представления, что также влечет за собой немалую сложность.

Фреймворк компонентов Glyphix основан на этой простой идее: содержимое внутри тега `<template>` выполняет роль функции `render()`, в то время как JS-код сосредоточен на поддержке модели, а изменения данных модели автоматически отражаются в связанном интерфейсе. Вы можете считать, что фреймворк компонентов Glyphix всегда вычисляет новый интерфейс на основе состояния модели, поэтому нам не нужно вручную обновлять элементы интерфейса.

::: tip
Под капотом Glyphix нет дерева DOM, и, соответственно, нет API для манипуляции элементами DOM. Фактически, именно фреймворк компонентов и является нативным JavaScript API для Glyphix.
:::

## Реакция на ввод

Некоторые компоненты могут реагировать на события ввода пользователя. В этом случае вы можете использовать директиву `on` для указания обработчика событий. Например, прослушивание события клика по текстовому компоненту:
``` html
<template>
  <p on:click="text += ' click'">{{text}}</p>
</template>

<style>
  * {
    text-align: center;
  }
</style>

<script>
  export default {
    data: {
      text: "Text "
    }
  }
</script>
```
Клик по тексту автоматически обновит отображаемое содержимое. Значение атрибута `on:click` — `text += ' click'` — является JavaScript-выражением, и Glyphix автоматически свяжет `this` переменных в выражении с объектом компонента.

## Условный рендеринг

Директива `if` используется для условного рендеринга содержимого компонента. Область содержимого, управляемая этой директивой, будет отображаться только тогда, когда значение выражения в директиве `if` истинно (true).
``` html
<p if="display">Hello World</p>
```

Следующий пример реализует эффект взаимоисключающего переключателя: при последовательных кликах интерфейс будет попеременно отображать текст "Component A" или "Component B".
``` html
<template>
  <p if="display" on:click="display = false">Component A</p>
  <p if="!display" on:click="display = true">Component B</p>
</template>

<style>
  * {
    font-size: 48;
    text-align: center;
  }
</style>

<script>
  export default {
    data: {
      display: true
    }
  }
</script>
```

## Рендеринг списков

Используйте директиву `for` для многократного рендеринга компонента с целью создания списка. Базовое использование директивы `for`:
``` html
<p for="(index, value) in list">{{index}}: {{value}}</p>
```
Здесь `list` — это свойство-список в модели компонента (обязательно должно быть типа `Array`), `index` и `value` — две переменные итерации, где `index` — это индекс текущего элемента, а `value` — значение текущего элемента.

Директива `for` может быть записана в нескольких сокращенных формах:
``` html
<p for="list">{{$idx}}: {{$item}}</p>
<p for="value in list">{{$idx}}: {{value}}</p>
<p for="index, value in list">{{$idx}}: {{value}}</p>
```
Первый сокращенный вариант заключается в указании только выражения для итерации, при этом в качестве имен переменных итерации по умолчанию используются `$idx` и `$item`. Второй вариант явно определяет переменную итерации для значения, в то время как имя переменной индекса использует значение по умолчанию `$idx`. Третий вариант — это стандартная запись с опущенными круглыми скобками.

::: tip
Из-за особенностей области видимости (scope), переменные, используемые для итерации при написании директивы `for`, будут работать только при использовании после директивы `for`.
:::

``` html
<!-- correct -->
<button for="list" text="{{$item}}"/>
<!-- error -->
<button text="{{$item}}" for="list"/>
```

### Одновременное использование директив `if` и `for`

Вы можете одновременно использовать директивы `if` и `for` на одном и том же элементе, причем директива `if` имеет более высокий приоритет. В этом примере, когда свойство `display` ложно, весь список компонентов `button` не будет отрендерен:
```html
<button for="value in items" if="display">Hello {{value}}</button>
<p if="!display">Paragraph 1</p>
```

Если же ваша цель — условно отрендерить только некоторые узлы в списке, созданном директивой `for`, вам нужно поместить директиву `if` на внутренний элемент по отношению к директиве `for`.
```html
<button for="value in items">
  <p if="display">item: {{value}}</p>
</button>
```

::: tip
Не рекомендуется использовать директивы `if` и `for` на одном и том же элементе, так как это снижает читаемость кода.
:::

## Слоты

Подобно распространению контента в других фреймворках, в Glyphix также реализован API распространения контента. Мы можем использовать компонент `slot` в качестве точки выхода для распределяемого контента.

В дочернем компоненте используйте компонент `slot` для размещения контента, определенного в родительском компоненте. При рендеринге компонент `slot` заменяется элементами, переданными из родительского компонента.

```html
<div>
  <slot/>
</div>
```

## Комбинирование компонентов

Комбинирование нескольких компонентов в более крупные интерфейсы — это способ построения интерфейсов в фреймворке компонентов Glyphix. Если у вас есть компонент с именем `Menu`, вы можете импортировать его, используя тег `<import>` в корневом узле UX-файла, где он требуется:
``` html
<import src="path/to/Menu" name="Menu"/>
```
Атрибут `src` — это путь к компоненту, пожалуйста, не добавляйте суффикс `.ux`. Атрибут `name` является необязательным именем компонента; если этот атрибут не заполнен, в качестве имени компонента будет использоваться имя файла компонента.

Используйте тег `<import>` несколько раз для импорта всех зависимых компонентов:
``` html
<import src="path/to/ComA"/>
<import src="path/to/ComB"/>
<import src="path/to/ComC"/>
```

Вы можете использовать кастомные компоненты так же, как и нативные:
``` html
<div>
  <menu for="menus" on:click="clickMenu($idx, $item)">
    <p>Menu {{$item}}</p>
  </menu>
</div>
```

``` css
div {
  display: flex;
  flex-direction: column;
}

text {
  text-align: center;
}
```

``` js
export default {
  data: {
    menus: ["Dog", "Cat", "Pig", "Fish"],
  },
  clickMenu(id, name) {
    console.log(`clicked id: ${id}, name: ${name}.`)
  }
}
```

Это интерфейс меню, и мы хотим, чтобы при клике пользователя по меню выводилась информация о текущем элементе меню с помощью метода `clickMenu`. Поэтому компонент `Menu` должен уметь отображать содержимое меню и передавать свое событие клика через слушатель `on:click`.

Вот содержимое файла `Menu.ux`:
``` html
<template>
  <div on:click="$emit('click')"> <slot /> </div>
</template>

<style>
  div { display: flex; }
</style>

<script>
  export default {}
</script>
```
Мы просто используем нативный компонент `div`, чтобы реагировать на клики пользователя и передавать событие наверх. Внутри компонента `div` также будет отображаться дочерний компонент, переданный ранее, что в итоге позволит отобразить список меню.
