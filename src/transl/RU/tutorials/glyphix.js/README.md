# Утилита сборки Glyphix.js

glyphix.js — это утилита сборки для приложений Glyphix. Она включает в себя инструмент командной строки под названием `gx`, который используется для создания, сборки и запуска приложений Glyphix. Утилита также содержит графический симулятор для имитации работы приложений Glyphix на компьютере.

В этой документации приведены инструкции по установке и использованию glyphix.js. Руководство [Быстрый старт](/tutorials/getting-started.md) представляет собой более простое введение. Ознакомьтесь также с разделом [Сборка и запуск](#сборка-и-запуск), чтобы узнать, как разрабатывать, собирать и публиковать приложение Glyphix.

## Установка

В этом разделе описывается процесс установки утилиты сборки glyphix.js. Для обычного использования достаточно ознакомиться с методом [Установка через npm](#установка-через-npm). Метод [Ручная установка](#ручная-установка) предназначен для особых сценариев, таких как среды с ограниченным доступом к сети или CI-сборки.

### Установка через npm

Для установки утилиты сборки glyphix.js вы можете использовать менеджер пакетов [npm](https://nodejs.org). Рекомендуется использовать опцию `-g` для глобальной установки:
::: code-tabs
@tab npm
```bash
npm install -g glyphix-cli
```

@tab pnpm
```bash
pnpm install -g glyphix-cli
```

@tab yarn
```bash
yarn global add glyphix-cli
```
:::

::: tip
Перед глобальной установкой с помощью pnpm может потребоваться выполнить команду `pnpm setup` для настройки переменных окружения. Команда `pnpm install -g` подскажет, как это сделать.
:::

После завершения установки вы можете проверить успешность установки, выполнив в терминале команду `gx --version`. Например:
```bash
$ npm install -g glyphix-cli
$ gx --version
gx v0.10.1 - The Glyphix applet development toolchain
commit a9337cf1 - Tue Sep 23 10:03:48 2025 +0800
```

Кроме того, для сборки ресурсов приложений под определенные устройства необходимо установить [pngquant](#pngquant).

### Ручная установка

Вы также можете установить glyphix.js вручную из архива: добавьте каталог `bin` из распакованной директории в переменную окружения `PATH`. Ниже описан процесс установки для основных операционных систем.

::: tip
Утилита glyphix.js — это не просто один исполняемый файл. Не забудьте сохранить остальные файлы ресурсов (включая все файлы в каталогах `bin` и `share`).
:::

#### macOS / Linux

Для macOS или Linux для установки утилиты glyphix.js можно использовать команду `tar`. Перед этим необходимо установить такие инструменты, как `xz`:

::: code-tabs
@tab macOS
```bash
brew install xz
```

@tab Ubuntu / Debian
```bash
sudo apt update
sudo apt install xz-utils
```

@tab Arch Linux
```bash
sudo pacman -S xz
```
:::

После скачивания архива glyphix.js используйте следующие команды для его распаковки и установки:
::: code-tabs
@tab macOS
```bash
tar -xvJf glyphix-v0.7.2-darwin-arm64.tar.xz -C ~/.local
```

@tab Linux
```bash
tar -xvJf glyphix-v0.7.2-linux-x86_64.tar.xz -C ~/.local
```
:::
Не забудьте заменить имя файла `.tar.xz` на актуальное скачанное имя файла, соответствующее вашей операционной системе и архитектуре процессора. После распаковки такие команды, как `gx`, будут находиться в директории `~/.local/bin`. Добавьте эту директорию в переменную окружения `PATH`, обновив, например, файл `.bashrc` следующим образом:
```bash
# Если ~/.local/bin нет в PATH, добавляем его
echo "$PATH" | grep -q "$HOME/.local/bin" || echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc # Перезагружаем конфигурацию bash
```

::: tip
При использовании `Zsh` файл конфигурации `.zshrc` может импортировать `.bashrc`, поэтому достаточно обновить только `.bashrc`. В противном случае обновите `.zshrc` описанным выше способом.

Рекомендуется устанавливать утилиту сборки glyphix.js в пользовательскую директорию `~/.local`, чтобы избежать использования прав root.
:::

#### Windows

Чтобы установить glyphix.js в Windows, скачайте архив соответствующей версии для Windows, а затем распакуйте его с помощью программы, поддерживающей формат `7z` (например, [7-Zip](https://www.7-zip.org/)), в какую-либо директорию, например `C:\glyphix`. Затем добавьте `C:\glyphix\bin` в [переменную окружения `PATH`](https://learn.microsoft.com/zh-cn/previous-versions/office/developer/sharepoint-2010/ee537574(v=office.14)) системы.

Вы также можете использовать инструмент командной строки `7z` для распаковки, например:
```shell
7z x -y glyphix-v0.7.2-windows-x64.7z -oC:/glyphix
```
Это аналогично процессу установки в macOS и других системах.

### Установка системных зависимостей

#### pngquant

Пользователям Linux и macOS необходимо дополнительно установить `pngquant`. Вы можете установить его с помощью `npm`:
```bash
npm install -g pngquant-bin # pngquant-bin поддерживает установку только через npm
```
Пакет `glyphix-cli` для Windows уже включает в себя `pngquant.exe`, поэтому дополнительная установка не требуется.

::: tip
Вы также можете скачать предварительно скомпилированные бинарные файлы с сайта [pngquant.org](https://pngquant.org/) или установить их через пакетный менеджер вашей системы.
:::

#### Системные зависимости Linux

Установочный пакет glyphix.js для Linux не зависит от конкретного дистрибутива, на данный момент доступны сборки только для архитектуры `linux-x86_64`. Мы протестировали его работу на Ubuntu 20.04 (или новее) и Arch Linux.

Если вы используете команду `gx` исключительно для сборки (что часто применяется в CI), дистрибутивы Linux без графического окружения должны работать «из коробки». Запуск графического симулятора зависит от оконной системы X11, поэтому может потребоваться установка пакетов, связанных с xorg. В частности, в окружении Wayland вам также потребуется установить пакет `xwayland` (симулятор пока не поддерживает нативный Wayland).

### Удаление

Для удаления glyphix.js, установленного глобально через менеджер пакетов вроде npm, используйте соответствующую команду удаления:
::: code-tabs
@tab npm
```bash
npm uninstall -g glyphix-cli
```

@tab pnpm
```bash
pnpm uninstall -g glyphix-cli
```

@tab yarn
```bash
yarn global remove glyphix-cli
```
:::

::: tip
При локальной (не глобальной) установке через менеджер пакетов достаточно удалить зависимость `glyphix-cli` из файла `package.json` и выполнить `npm install` (или `pnpm install`, `yarn install`) для обновления папки `node_modules`.
:::

При ручной установке просто удалите файлы из установочного архива. Например, для файлов установки `.tar.xz` на macOS и Linux:
```bash
tar -tf glyphix-v0.7.2-darwin-arm64.tar.xz > filelist.txt
cat filelist.txt # Проверьте список файлов для удаления
xargs -I {} rm -f "~/.local/{}" < filelist.txt # Выполните удаление после проверки
```
Команда `tar -tf` выведет список файлов в архиве; замените `glyphix-xxx.tar.xz` на ваше фактическое имя установочного файла. Ручное удаление в Windows выполняется аналогичным образом.

## Сборка и запуск

После установки glyphix.js перейдите в корневой каталог исходного кода приложения и используйте команду [`gx build`](#gx-build) для сборки пакета приложения или команду [`gx emu`](#gx-emu) для запуска симулятора.

После сборки приложения обратитесь к разделу [Отправка пакета приложения](#отправка-пакета-приложения), чтобы узнать, как установить приложение на устройство или отправить его на платформу публикации приложений.

## Параметры командной строки

### Общие опции

#### `gx --help`

Просмотр справки. Справку также можно использовать для конкретных подкоманд, например, `gx build --help` выведет справку исключительно для подкоманды `build`.

#### `gx --version`

Опция `-V --version` используется для просмотра версии команды `gx`.

#### `gx --verbose`

Опция `-v --verbose` включает вывод подробных логов, что обычно не требуется разработчикам приложений.

#### `gx --numeric-version`

Выводит чистый номер версии команды `gx`, например `0.10.1`.

#### `gx --quiet`

Опция `-q --quiet` включающие тихий режим, подавляющий большинство не предупреждающих и не ошибочных логов. Сюда входят логи прогресса сборки при использовании `gx build`. Этот режим обычно используется в CI-средах, где требуется собирать большое количество пакетов приложений.

Просмотр номера версии.

### `gx new`

Создание нового проекта, например `gx new myapp` создаст новый проект с именем `myapp`.

### `gx build`

Сборка проекта (действие по умолчанию). С помощью опции `--device` или `-d` можно указать целевое устройство, например:
``` bash
gx build -d default # Сборка для устройства default
```
Опция `--dump` позволяет вывести подробную информацию о компиляции файлов UX.

Glyphix.js поддерживает инкрементальную сборку: при изменении исходного кода пересобирается только измененная часть.

Параметр `-r --image-rules` позволяет указать файл правил упаковки изображений (по умолчанию `config/image-rules.json`). Значение этого параметра кэшируется, и последующие вызовы `gx build` или `gx emu` будут выполняться в соответствии с предыдущей конфигурацией.

#### Опции команды

- `-d --device=NAME`: указывает имя целевого устройства, которое должно совпадать с именем установленной конфигурации устройства. Список установленных устройств можно посмотреть с помощью команды `gx list device`. Если эта опция не указана, по умолчанию используется устройство `default`.
- `-f --full`: принудительная полная пересборка проекта вместо инкрементальной.
- `-e --emulator`: сборка проекта для симулятора, а не для реального устройства. Эта опция автоматически применяется при выполнении команды `gx emu`.
- `-r --image-rules=PATH`: указывает файл правил упаковки изображений по умолчанию (`config/image-rules.json`).

#### Отправка пакета приложения

После сборки с помощью `gx build` в каталоге проекта будет создана директория `.glyphix-work/dist/<device-name>/<package-name>`, содержащая собранные файлы пакета приложения (файлы `.pkg`). Полученный файл можно установить на устройство через приложение отладки на телефоне или отправить на платформу публикации приложений.

Рекомендуется использовать опцию `-d` для сборки пакетов приложений под все поддерживаемые устройства. Пример структуры каталогов:
```bash
.glyphix-work/dist
├─ generic-watch-368x448
│  └─ com.example.app
│     ├─ bundle.pkg
│     ├─ icon.png
│     └─ manifest.json
└─ generic-watch-466x466
   └─ com.example.app
      ├─ bundle.pkg
      ├─ icon.png
      └─ manifest.json
```
При отправке пакета приложения упакуйте и загрузите **всю** директорию `.glyphix-work/dist`, а не только файл `.pkg` или какую-либо отдельную поддиректорию. Платформа распознает приложение по информации из файла `manifest.json`, а файл `icon.png` может потребоваться в качестве иконки предпросмотра.

::: tip
Пользователи Linux или macOS могут использовать следующую команду для сборки приложений под определенный класс устройств:
```bash
gx list device | grep "^generic-" | xargs -n 1 gx build -d
```
Это соберет пакеты приложений для всех устройств, чьи имена начинаются с `generic-`.

В Windows для пакетной сборки можно использовать аналогичную команду PowerShell:
```shell
gx list device | ? { $_ -match "^generic-" } | % { gx build -d $_ }
```
:::

### `gx emu`

См. документацию [Симулятор и отладка](/tutorials/glyphix.js/emulator.md).

### `gx clean`

Очистка результатов сборки. Эта команда удаляет каталог `.glyphix-work` в папке проекта.

### `gx config`

Эта команда запускает веб-интерфейс для редактирования файла правил упаковки изображений. Следуя подсказкам в командной строке, вы можете открыть страницу в браузере для выполнения операций. Команда имеет два варианта использования:
``` bash
gx config # Находясь в проекте Glyphix, указывать исходную директорию не нужно (в настоящее время может использоваться только в корне проекта)
gx config path/to/dir # Настройка для указанной директории, может применяться для настройки не-проектных ресурсов изображений
```

Параметр `-r --image-rules` задает файл правил упаковки изображений (по умолчанию `config/image-rules.json`).

### `gx image-forge`

Преобразование отдельных файлов изображений. Команда позволяет указать произвольный исходный путь и путь вывода, ее не обязательно выполнять внутри проекта Glyphix:
``` bash
gx image-forge src -o dist
```

Описание опций:
- `src` — исходный путь для конвертации. Команда `image-forge` рекурсивно преобразует все изображения и сохраняет их в целевой каталог, указанный в параметре `-o, --output` (по умолчанию `dist`), сохраняя относительную структуру директорий.
- `-r --image-rules` задает файл правил упаковки изображений (по умолчанию `config/image-rules.json`).
- `-d --device` указывает целевое устройство для конвертации изображений.

### `gx list`

Вывод определенной информации. В настоящее время поддерживается три операции:
``` bash
gx list device # Вывести список всех установленных конфигураций устройств
gx list template # Вывести список всех установленных шаблонов проектов
gx list image # Вывести относительные пути ко всем ресурсам изображений в текущей директории (аналогично команде find)
```

Для некоторых видов информации можно использовать флаг `-d, --detailed` для вывода подробного описания:
```
$ gx list device -d
The following devices have been found:
  default
    Default virtual device, for debugging purposes only.

  rtt-watch
    A smartwatch from RT-Thread. With a 1.43 inch screen
    and 4 GB of storage.
```

### `gx completion`

Эта команда используется для генерации скрипта автодополнения командной строки для `gx`. В настоящее время поддерживаются [Zsh](https://www.zsh.org/) и [PowerShell 7+](https://github.com/PowerShell/PowerShell). Вызов `gx completion [SHELL]` выведет скрипт автодополнения для указанного shell (если параметр `SHELL` не указан, текущий Shell определяется автоматически). Для установки скрипта автодополнения используйте:
```bash
gx completion --install
```
После успешной установки появится подсказка с путем установки скрипта автодополнения. Перезапустите сеанс Shell, чтобы автодополнение заработало, либо примените изменения немедленно с помощью следующих команд:
::: code-tabs
@tab Oh My Zsh
```bash
omz reload
```

@tab PowerShell
```shell
Import-Module glyphix -Force
```
:::

При использовании скрипта автодополнения вы можете выбирать устройства для `gx emu`, опции командной строки и т. д. прямо в терминале без необходимости вводить их вручную.

По умолчанию в PowerShell используется циклическое дополнение, рекомендуется изменить его на выпадающее меню:
```shell
Set-PSReadLineKeyHandler -Key Tab -Function MenuComplete
```
Добавьте эту команду в файл конфигурации [`$PROFILE`](https://learn.microsoft.com/en-us/powershell/scripting/learn/shell/creating-profiles#adding-customizations-to-your-profile), чтобы настройки действовали постоянно.

::: note
Если опция `--install` не может выполнить установку автоматически, вы можете установить скрипт автодополнения вручную с помощью команды `gx completion`, например:
```shell
gx completion zsh > ~/.zsh/completion/_gx.zsh
```
:::

## Пути конфигурации по умолчанию

Конфигурации, шаблоны проектов, информация об устройствах и другие данные в утилите glyphix.js могут храниться по следующим путям:
- Системная конфигурация: директория `share/glyphix`, расположенная на уровень выше исполняемого файла `gx`/`gx.exe`. Например, если исполняемый файл `gx` находится по пути `/usr/local/glyphix`, то путем к системным ресурсам конфигурации будет `/usr/local/share/glyphix`.
- Пользовательская конфигурация: `~/.local/share/glyphix` в Unix-подобных системах и `%APPDATA%\AppData\Roaming\glyphix` в Windows.

Вы можете разместить файлы конфигурации в любом из этих путей, причем пользовательская конфигурация имеет более высокий приоритет. Пакет `gx.js` поставляется с файлами конфигурации по умолчанию.

## Шаблоны проектов

Шаблоны проектов хранятся в директории `templates` папки конфигурации. В настоящее время поддерживается только шаблон `simple`, кастомизация не поддерживается.

## Файлы конфигурации устройств

Конфигурационные файлы устройств хранятся в директории `devices` папки конфигурации. Каждый устройство имеет файл конфигурации в формате YAML с именем `<device-name>.yml`. Ниже приведено описание формата файла конфигурации:

``` yaml
# file: default.yml
description:
  Описание устройства для разработчиков.

screen: # Поля, описывающие конфигурацию экрана устройства. Все они являются обязательными (влияют на UI-верстку и масштабирование ресурсов).
  width: 454 # Количество пикселей по горизонтали
  height: 454 # Количество пикселей по вертикали
  dpi: 326 # Плотность пикселей экрана в пикселях на дюйм

ui: # Глобальная конфигурация интерфейса, все поля необязательны
  font-family: sans-serif # Имя семейства системных шрифтов по умолчанию (по умолчанию serif)
  font-size: 3.5 # Размер шрифта системы по умолчанию в пунктах (pt). Обратите внимание — не в пикселях!
  font-map: true # Использовать ли глобальный файл сопоставления конфигурации шрифтов. Если true, в системных ресурсах обязательно должен присутствовать файл
                 # font-faces.css

# Необязательный путь к пакету глобальных системных ресурсов. Конфигурация ниже означает, что
# глобальный пакет ресурсов хранится в папке default-global рядом с default.yml.
# Глобальный пакет ресурсов содержит предустановленные в системе шрифты и файлы сопоставления шрифтов.
global-assets: default-global

# Необязательный скрипт конвертации изображений. Путь к скрипту задается относительно файла
```
