# Соглашения об именовании компонентов

В этом документе описаны обязательные соглашения об именовании компонентов фреймворка, а также рекомендуемые стили именования. Обязательные соглашения являются строгими требованиями, несоблюдение которых может привести к некорректной работе. Использование рекомендуемых соглашений обеспечивает максимальную совместимость.

## Соглашения об именовании в шаблонах

Имена тегов в шаблонах должны быть записаны в стиле kebab-case или PascalCase:
``` html
<Button></Button>
<button></button>
<scroll-area></scroll-area>
<ScrollArea></ScrollArea>
```

Имена атрибутов должны быть записаны в стиле kebab-case или camelCase:
``` html
<component prop-name="expr"></component>
<component propName="expr"></component>
```

Рекомендуется единообразно использовать стиль kebab-case, соответствующий веб-стандартам.

## Соглашения об именовании в JavaScript-коде

Имена компонентов в JavaScript-коде должны быть записаны в стиле PascalCase, а в шаблоне используется соответствующее имя в стиле kebab-case.

Имена свойств компонентов в JavaScript-коде должны быть записаны в стиле camelCase:
``` js
export default {
  data: {
    propName: 0 // В шаблоне имя атрибута будет prop-name
  }
}
```
Эти имена свойств в коде шаблона автоматически преобразуются в соответствующий стиль kebab-case.

## Соглашения об именовании файлов

Файлы UX должны иметь то же имя, что и компонент, то есть быть записаны в стиле PascalCase. В теге `<import>` атрибут `src` должен содержать URL файла с учетом регистра, а атрибут `name` — использовать стиль PascalCase или kebab-case:
``` html
<import src="path/to/UxFile" name="UxFile"/>
<import src="path/to/UxFile" name="ux-file"/>
```
Фактически требования к именованию атрибута `name` совпадают с требованиями к именам тегов в шаблонах.
