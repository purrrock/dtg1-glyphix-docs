# Спецификация именования компонентов

В этом документе описаны обязательные правила именования и рекомендуемые стили для структуры компонентов. Обязательные правила являются строгими требованиями; их несоблюдение может привести к неожиданным результатам. Соблюдение рекомендуемых правил гарантирует максимальную совместимость.

## Правила именования шаблонов

Имена тегов в шаблонах должны быть в стиле kebab-case (через дефис) или PascalCase (паскальский регистр):
``` html
<Button></Button>
<button></button>
<scroll-area></scroll-area>
<ScrollArea></ScrollArea>
```

Имена свойств должны быть в стиле kebab-case или camelCase (верблюжий регистр):
``` html
<component prop-name="expr"></component>
<component propName="expr"></component>
```

Рекомендуется повсеместно использовать стиль kebab-case, соответствующий спецификации Web.

## Правила именования в коде JavaScript


Имена компонентов в коде JavaScript должны быть в стиле PascalCase, в то время как в шаблоне используется соответствующий им стиль kebab-case.

Имена свойств компонентов в коде JavaScript должны быть в стиле camelCase:
``` js
export default {
  data: {
    propName: 0 // Имя свойства в шаблоне будет prop-name
  }
}
```
Эти имена свойств автоматически преобразуются в соответствующие имена kebab-case при использовании в коде шаблона.

## Правила именования файлов

Файлы UX должны иметь то же имя, что и компонент, то есть в стиле PascalCase. В теге `<import>` атрибут `src` должен быть чувствительным к регистру URL-адресом файла, а для атрибута `name` следует использовать стиль PascalCase или kebab-case:
``` html
<import src="path/to/UxFile" name="UxFile"/>
<import src="path/to/UxFile" name="ux-file"/>
```
Фактически требования к именованию атрибута `name` совпадают с требованиями к именам тегов в шаблонах.
