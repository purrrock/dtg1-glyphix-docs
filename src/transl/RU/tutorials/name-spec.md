# Спецификация именования компонентов

В этом документе описываются обязательные правила именования и рекомендуемые стили для структуры компонентов. Обязательные правила должны строго соблюдаться, так как их нарушение может привести к непредвиденному поведению. Использование рекомендуемых правил именования обеспечивает максимальную совместимость.

## Правила именования шаблонов

Имена тегов в шаблонах должны быть записаны в стиле kebab-case (через дефис) или PascalCase (пар-камерный регистр):
``` html
<Button></Button>
<button></button>
<scroll-area></scroll-area>
<ScrollArea></ScrollArea>
```

Имена атрибутов должны быть в стиле kebab-case или camelCase (верблюжий регистр):
``` html
<component prop-name="expr"></component>
<component propName="expr"></component>
```

Рекомендуется повсеместно использовать стиль kebab-case, соответствующий стандартам Web.

## Правила именования в коде JavaScript


Имена компонентов в коде JavaScript должны быть в стиле PascalCase, а в шаблонах для них используется соответствующий стиль kebab-case.

Имена свойств компонентов в коде JavaScript должны быть в стиле camelCase:
``` js
export default {
  data: {
    propName: 0 // В шаблоне имя свойства будет prop-name
  }
}
```
Эти имена свойств автоматически преобразуются в соответствующие имена kebab-case при использовании в коде шаблона.

## Правила именования файлов

UX-файлы должны называться так же, как и сам компонент, то есть в стиле PascalCase. В теге `<import>` атрибут `src` должен быть чувствительным к регистру URL-адресом файла, а для атрибута `name` следует использовать стиль PascalCase или kebab-case:
``` html
<import src="path/to/UxFile" name="UxFile"/>
<import src="path/to/UxFile" name="ux-file"/>
```
Фактически, требования к именованию атрибута `name` совпадают с требованиями к именам тегов в шаблонах.
