# Быстрый старт

В этой главе мы расскажем, как использовать Glyphix.js для создания простого приложения. Мы начнем с установки инструментов сборки, затем создадим проект и запустим симулятор, чтобы посмотреть результат. В завершение мы кратко рассмотрим структуру проекта и основные файлы. В данном руководстве не рассматривается запуск и публикация приложения на реальном устройстве.

## Подготовка к работе

Прежде чем начать, обратитесь к [этой документации](/tutorials/glyphix.js/README.md#npm-安装) для установки инструмента сборки Glyphix. Если говорить кратко, вы можете использовать [npm](https://nodejs.org) для установки пакета `glyphix-cli`:
```bash
npm install -g glyphix-cli
```

Поскольку инструменты разработки Glyphix преимущественно работают через командную строку, рекомендуется установить современную оболочку, такую как Zsh или PowerShell 7+, а также полезные плагины для повышения эффективности работы.

### Инструменты терминала

Пользователям Linux или macOS рекомендуется установить [Oh My Zsh](https://ohmyz.sh/). Пользователям Windows рекомендуется установить [Windows Terminal](https://aka.ms/terminal) и использовать [Oh My Posh](https://ohmyposh.dev/). Также обратитесь к документации [`gx completion`](/tutorials/glyphix.js/README.md#gx-completion) для установки скрипта автодополнения команды `gx`.

Для разработки приложений на Glyphix вы можете использовать любой редактор, например [VS Code](https://code.visualstudio.com/) или [IDE быстрых приложений (QuickApp IDE)](https://www.quickapp.cn/devtool).

::: tip
В IDE быстрых приложений не встроен инструмент сборки glyphix.js, поэтому вам все равно потребуется установить `glyphix-cli` и использовать команду `gx` в терминале для сборки и запуска проекта. При использовании таких редакторов, как VS Code, рекомендуется связать файлы с расширением `*.ux` с форматом `html`, чтобы получить базовую подсветку синтаксиса.
:::

### Использование Node.js

Если вы решили использовать npm-пакеты в своем проекте или любые ресурсы веб-экосистемы разработки, обратитесь к документации по настройке [Node.js](/tutorials/nodejs.md). Использование Node.js не является обязательным, но оно обеспечивает поддержку современных инструментов разработки, таких как TypeScript.

### Использование инструментов сборки

Когда все будет готово, введите в терминале команду `gx list device`. Если вы получите вывод, похожий на следующий, это означает, что установка прошла успешно:
``` bash
$ gx list device
  default
  ...
```

Затем создайте проект приложения и запустите его в симуляторе! Просто используйте следующие команды:
``` bash
gx new myapp # Создает проект с именем myapp, при этом будет создана директория с именем myapp
cd myapp     # Переходит в директорию myapp
gx emu       # Запускает симулятор
```
Если все прошло успешно, вы увидите окно с надписью «Hello World!». В последующих руководствах будет более подробно рассказано об использовании команд инструмента glyphix.js.

::: tip
Обратитесь к документации [`gx build`](/tutorials/glyphix.js/README.md#gx-build) и [`gx emu`](glyphix.js/emulator.html) для получения дополнительной информации о сборке и запуске симулятора.
:::

## Структура проекта

Вы можете использовать файловый менеджер для просмотра структуры директории `myapp`. В текущей версии она выглядит следующим образом:
``` bash
<app-name>
├─ README.md         # Файл с описанием проекта (README)
└─ src               # Директория с исходным кодом проекта
    ├─ app.js        # Корневой скрипт приложения
    ├─ manifest.json # Конфигурация базовой информации о приложении
    ├─ assets        # Хранилище общих ресурсов (шрифты, изображения и т.д.)
    │  ├─ fonts      # Хранилище шрифтов
    │  └─ images     # Хранилище изображений
    └─ main          # Директория главной страницы
        └─ index.ux  # Файл описания интерфейса главной страницы
```

В шаблоне проекта по умолчанию исходный код находится в директории `<app-name>/src`. Документация и другие ресурсы проекта, не требующие упаковки, могут размещаться в других директориях.

Мы рекомендуем выделять отдельную директорию для каждой страницы (использовать имя страницы в качестве названия директории) и размещать ее в корне директории исходного кода. Исходные файлы компонентов, используемых только на определенной странице (файлы `*.ux`), должны находиться в директории этой страницы, в то время как общие файлы могут размещаться по следующим правилам:
- Общие UX-файлы и скрипты могут размещаться в директории `common`.
- Файлы скриптов, ссылающиеся только на конкретную страницу, хранятся непосредственно в директории этой страницы.
- Файлы шрифтов хранятся в директории `assets/fonts`.
- Файлы изображений хранятся в директории `assets/images`.
- Другие ресурсы могут размещаться в соответствующих поддиректориях директории `assets`.

### Файлы проекта

Теперь вы видите, что в `myapp` есть несколько файлов. Обратите внимание на файлы с расширением `*.ux` и файл `manifest.json` — это файлы, с которыми чаще всего приходится работать во время разработки. В следующем руководстве приводится их краткий обзор.

## Файл `manifest.json`

Файл `manifest.json` является конфигурационным файлом приложения и используется при его сборке. Он содержит основную информацию о приложении, такую как название и версия, а также описание всех страниц приложения и информацию о маршрутизации (роутинге). Иными словами, чтобы добавить описание страницы в коде, его необходимо предварительно прописать в `manifest.json`, иначе переход на эту страницу будет невозможен.

Вот содержимое файла `manifest.json` для шаблонного приложения, сгенерированного командой `gx`:
``` json
{
  "package": "com.example.app",
  "name": "Example App",
  "versionName": "1.0.0",
  "versionCode": 1,
  "features": [],
  "router": { // Информация о маршрутизации страниц
    "entry": "main", // Начальная страница приложения
    "pages": { // Описание страниц
      "main": {
        "component": "index"
      }
    }
  }
}
```

::: warning
В учебных целях в данном фрагменте кода `manifest.json` присутствуют комментарии, однако формат JSON не поддерживает комментарии. Пожалуйста, не добавляйте комментарии в файл `manifest.json` вашего проекта.
:::

### Заполнение информации о приложении

Вы можете указать информацию о своем приложении в файле `manifest.json`.

### Добавление описания страниц

В корневых полях файла `manifest.json` поля `router` и `pages` связаны с описанием страниц. Поле `router` представляет собой таблицу маршрутизации страниц приложения и должно содержать как минимум поле `entry`, определяющее начальную страницу приложения (обычно в качестве начальной используется страница `main`).

Если вы хотите добавить новую страницу, вам нужно внести изменения в поле `pages`. Например, если мы хотим создать новую страницу с именем `NewPage`, а ее корневым компонентом является `NewPage/index.ux`, то поле `pages` будет выглядеть следующим образом:
``` json
"pages": {
  "main": {
    "component": "index"
  },
  "NewPage": { // Это новодобавленная страница
    "component": "index"
  }
}
```
Поле `pages` представляет собой объект JSON, где каждый ключ является именем страницы (по умолчанию оно также совпадает с путем к директории страницы). Значением ключа также является объект, содержащий поле `component` — имя корневого компонента страницы, который должен находиться в директории данной страницы. Поле `component` задает имя файла корневого компонента страницы (без расширения). Все имена чувствительны к регистру.

При добавлении или удалении страниц не забывайте обновлять соответствующие поля в файле `manifest.json`.

Подробное описание структуры файла `manifest.json` см. в соответствующей документации.

## Знакомство с UX-файлами

UX (UI XML) — это файл описания интерфейса в Glyphix. На примере исходного шаблонного проекта содержимое файла `main/index.ux` выглядит следующим образом:
``` html
<template>
  <p>{{text}}</p>
</template>

<style>
  * {
    text-align: center;
  }
</style>

<script>
  export default {
    data: {
      text: "Hello, World!"
    }
  }
</script>
```

UX-файл по сути является XML-файлом и содержит три корневых узла: `<template>`, `<style>` и `<script>`. Узел `<template>` описывает структуру интерфейса, в узле `<style>` определены таблицы стилей, а узел `<script>` содержит JavaScript-скрипты, реализующие логику взаимодействия компонента.

::: tip
VS Code не подсвечивает синтаксис UX-файлов по умолчанию. Вы можете переключить язык в правом нижнем углу на «HTML», чтобы получить хорошую подсветку.
:::

### Введение в компоненты

Объект, соответствующий UX-файлу во время выполнения, называется **компонентом**. Компоненты являются важнейшей концепцией в фреймворке приложений Glyphix JavaScript. Каждый компонент представляет собой элемент интерфейса и обладает следующими характеристиками:
- Компонент имеет собственное визуальное представление.
- Некоторые компоненты могут реагировать на ввод пользователя.
- Некоторые компоненты могут отображать результаты в зависимости от данных и состояния.
- Компоненты могут встраиваться в другие компоненты.

Распространенные элементы интерфейса в фреймворке Glyphix JavaScript являются компонентами, например:
- Текст: используется для отображения текстовой информации.
- Кнопка: кнопка также может отображать текст, но самое главное — она может реагировать на события нажатия (и, конечно же, визуально отображать момент нажатия).
- Список: список вмещает в себя другие компоненты и располагает их вертикально; кроме того, элементы списка можно перемещать с помощью жестов прокрутки.

Компоненты, способные содержать в себе другие компоненты (как, например, списки), также называются **компонентами-контейнерами**.

Как нетрудно догадаться, компонент состоит из двух основных элементов: внешнего вида и логики поведения. Тег `<template>` в UX-файле определяет внешний вид компонента. На примере `main/index.ux`:
``` html
<template>
  <p>{{text}}</p>
</template>
```
Компонент `main/index.ux` отображает контент с помощью компонента `<p>`, который используется для вывода текста. Значение выражения `{{text}}` определяет текст, который будет выведен на экран.

JavaScript-скрипт внутри тега `<script>` реализует логику поведения компонента. Этот тег всегда экспортирует **объект компонента** с помощью ключевых слов `export default`. В первую очередь следует обратить внимание на свойство `data` объекта компонента, которое обычно представляет собой объект:
``` js
export default {
  data: {
    text: 'Hello, World!'
  }
}
```
Здесь у объекта `data` есть свойство `text`, значение которого будет использоваться в качестве отображаемого содержимого упомянутого выше компонента `<text>` (в оригинале `<p>`).

### Модель компонентов и обновление состояния

Допустим, нам нужно спроектировать следующий компонент: при нажатии на компонент он должен менять отображаемый текст. В этом случае нам нужно прослушивать событие ввода на компоненте и обновлять отображаемый контент. Следующий код прослушивает событие нажатия на компоненте `<p>`:
``` html
<template>
  <p on:click="text += '!'">{{text}}</p>
</template>
```
Выражение в атрибуте `on:click` выполняется при нажатии на текст. В результате при каждом нажатии к тексту `text`, отображаемому в компоненте `<p>`, будет добавляться символ `'!'`:

``` html
<p on:click="text += '!'">{{text}}</p>
```

export default {
