# Быстрый старт

В этой главе мы расскажем, как использовать Glyphix.js для создания простого приложения. Мы начнем с установки инструментов сборки, затем создадим проект и запустим симулятор, чтобы посмотреть результат. В конце мы кратко рассмотрим структуру проекта и основные файлы. В данном руководстве не рассматривается запуск и публикация приложения на реальном устройстве.

## Подготовка к работе

Прежде чем начать, обратитесь к [этому документу](/tutorials/glyphix.js/README.md#npm-安装), чтобы установить инструмент сборки Glyphix. Если кратко, вы можете использовать [npm](https://nodejs.org) для установки пакета `glyphix-cli`:
```bash
npm install -g glyphix-cli
```

Поскольку инструменты разработки Glyphix ориентированы на командную строку, рекомендуется установить современную оболочку, такую как Zsh или PowerShell 7+, а также полезные плагины для повышения эффективности работы.

### Инструменты терминала

Пользователям Linux или macOS рекомендуется установить [Oh My Zsh](https://ohmyz.sh/). Пользователям Windows рекомендуется установить [Windows Terminal](https://aka.ms/terminal) и использовать [Oh My Posh](https://ohmyposh.dev/). Также обратитесь к документации [`gx completion`](/tutorials/glyphix.js/README.md#gx-completion) для установки скрипта автодополнения для команды `gx`.

Для разработки приложений Glyphix вы можете использовать любой редактор, например [VS Code](https://code.visualstudio.com/) или [IDE швидких додатків (QuickApp IDE)](https://www.quickapp.cn/devtool).

::: tip
В IDE быстрых приложений не встроен инструмент сборки glyphix.js, поэтому вам все равно потребуется установить `glyphix-cli` и использовать команду `gx` в терминале для сборки и запуска проекта. При использовании редакторов вроде VS Code рекомендуется сопоставить файлы с расширением `*.ux` с форматом `html`, чтобы получить базовую подсветку синтаксиса.
:::

### Использование Node.js

Если вы решили использовать пакеты npm или любые другие ресурсы веб-экосистемы разработки в своем проекте, обратитесь к документации по настройке [Node.js](/tutorials/nodejs.md). Использование Node.js не является обязательным, но оно обеспечивает поддержку современных инструментов разработки, таких как TypeScript.

### Использование инструментов сборки

Когда все будет готово, введите в терминале команду `gx list device`. Если вы получите вывод, похожий на приведенный ниже, это означает, что установка прошла успешно:
``` bash
$ gx list device
  default
  ...
```

Затем создайте проект приложения и запустите его в симуляторе! Просто используйте следующие команды:
``` bash
gx new myapp # Создает проект с именем myapp и директорию с тем же именем
cd myapp     # Переходит в директорию myapp
gx emu       # Запускает симулятор
```
Если все прошло успешно, вы увидите окно с надписью «Hello World!». В последующих руководствах будет более подробно рассказано об использовании команд инструментария glyphix.js.

::: tip
Обратитесь к документации [`gx build`](/tutorials/glyphix.js/README.md#gx-build) и [`gx emu`](glyphix.js/emulator.html) для получения дополнительной информации о сборке и запуске симулятора.
:::

## Структура проекта

Вы можете использовать файловый менеджер для просмотра структуры директории `myapp`. В текущей версии она выглядит следующим образом:
``` bash
<app-name>
├─ README.md         # Файл с описанием проекта (README)
└─ src               # Директория с исходным кодом проекта
    ├─ app.js        # Корневой скрипт приложения
    ├─ manifest.json # Конфигурация основных сведений о приложении
    ├─ assets        # Хранилище общих ресурсов (шрифты, изображения и т.д.)
    │  ├─ fonts      # Шрифты
    │  └─ images     # Изображения
    └─ main          # Директория главной страницы
        └─ index.ux  # Файл описания интерфейса главной страницы
```

В шаблоне проекта по умолчанию исходный код находится в директории `<app-name>/src`. Документация и другие ресурсы проекта, не требующие упаковки, могут размещаться в других директориях.

Мы рекомендуем выделять отдельную директорию для каждой страницы (используя имя страницы в качестве имени директории) и размещать ее в корне директории исходного кода. Исходные файлы компонентов, используемых только на определенной странице (файлы `*.ux`), должны находиться в директории этой страницы, в то время как общие файлы могут размещаться по следующим правилам:
- Общие UX-файлы и скрипты могут размещаться в директории `common`.
- Файлы скриптов, используемые исключительно на странице, хранятся непосредственно в директории страницы.
- Файлы шрифтов хранятся в директории `assets/fonts`.
- Файлы изображений хранятся в директории `assets/images`.
- Остальные ресурсы могут быть размещены в подходящих местах внутри директории `assets`.

### Файлы проекта

Теперь вы видите, что внутри `myapp` есть несколько файлов. Обратите внимание на файлы с расширением `*.ux` и файл `manifest.json` — это файлы, с которыми чаще всего приходится сталкиваться при разработке. В следующем руководстве будет приведено краткое описание каждого из них.

## Файл `manifest.json`

Файл `manifest.json` является конфигурационным файлом приложения и используется при его сборке. Он содержит основные сведения о приложении, такие как имя и версия, а также описание всех страниц и информацию о маршрутизации. Другими словами, описание страницы нужно добавить в `manifest.json`, прежде чем переходить к ней в коде.

Вот содержимое файла `manifest.json` для шаблона приложения, сгенерированного командой `gx`:
``` json
{
  "package": "com.example.app",
  "name": "Example App",
  "versionName": "1.0.0",
  "versionCode": 1,
  "features": [],
  "router": { // Информация о маршрутизации страниц
    "entry": "main", // Начальная страница приложения
    "pages": { // Описание страниц
      "main": {
        "component": "index"
      }
    }
  }
}
```

::: warning
В учебных целях данный фрагмент кода `manifest.json` содержит комментарии, однако формат JSON не поддерживает комментарии. Пожалуйста, не добавляйте комментарии в файл `manifest.json` вашего проекта.
:::

### Заполнение информации о приложении

Вы можете указать информацию о своем приложении в файле `manifest.json`.

### Добавление описания страниц

В корневых полях файла `manifest.json` поля `router` и `pages` связаны с описанием страниц. Поле `router` представляет собой таблицу маршрутизации страниц приложения и должно содержать как минимум поле `entry`, определяющее начальную страницу приложения. Обычно в качестве начальной страницы используется `main`.

Если вам нужно добавить новую страницу, вам потребуется внести изменения в поле `pages`. Например, если мы хотим создать новую страницу с именем `NewPage`, а ее корневым компонентом является `NewPage/index.ux`, то поле `pages` будет выглядеть следующим образом:
``` json
"pages": {
  "main": {
    "component": "index"
  },
  "NewPage": { // Это новодобавленная страница
    "component": "index"
  }
}
```
Поле `pages` представляет собой объект JSON, где каждый ключ является именем страницы, которое по умолчанию также совпадает с путем к директории страницы. Значением для имени страницы является объект, у которого поле `component` указывает на имя корневого компонента страницы. Этот компонент должен находиться внутри директории страницы. Поле `component` содержит имя файла корневого компонента страницы (без расширения). Все имена чувствительны к регистру.

При добавлении или удалении страниц не забывайте обновлять соответствующие поля в файле `manifest.json`.

Подробное описание структуры файла `manifest.json` смотрите в соответствующей документации.

## Знакомство с UX-файлами

UX (UI XML) — это файл описания интерфейса в Glyphix. На примере исходного шаблона проекта, файл `main/index.ux` имеет следующее содержимое:
``` html
<template>
  <p>{{text}}</p>
</template>

<style>
  * {
    text-align: center;
  }
</style>

<script>
  export default {
    data: {
      text: "Hello, World!"
    }
  }
</script>
```

UX-файл фактически представляет собой XML-файл с тремя корневыми узлами: `<template>`, `<style>` и `<script>`. Содержимое узла `<template>` описывает структуру интерфейса, в узле `<style>` определены таблицы стилей, а содержимое узла `<script>` представляет собой JavaScript-скрипт, реализующий логику взаимодействия компонента.

::: tip
VS Code не подсвечивает синтаксис UX-файлов автоматически. Вы можете переключить язык в правом нижнем углу на «HTML», чтобы включить удобную подсветку.
:::

### Введение в компоненты

Объект, соответствующий UX-файлу во время выполнения, называется **компонентом**. Компоненты являются важнейшей концепцией в структуре JavaScript-приложений Glyphix. Каждый компонент представляет собой элемент интерфейса со следующими характеристиками:
- Компонент имеет собственное визуальное представление.
- Некоторые компоненты могут реагировать на ввод пользователя.
- Некоторые компоненты могут отображать результаты в зависимости от данных и состояния.
- Компоненты могут быть встроены в другие компоненты.

Распространенные элементы интерфейса в фреймворке JavaScript-приложений Glyphix являются компонентами, например:
- Текст: используется для отображения текстовой информации.
- Кнопка: кнопка также может отображать текст, но самое главное — она может реагировать на события нажатия (и, конечно же, визуально отображать момент нажатия).
- Список: список вмещает другие компоненты и располагает их вертикально. Кроме того, с помощью жестов прокрутки можно перемещать дочерние элементы списка.

Компоненты, способные вмещать другие компоненты, такие как списки, также называются **компонентами-контейнерами**.

Как можно догадаться, компонент состоит из двух основных элементов: внешнего вида и логики поведения. Тег `<template>` в UX-файле определяет внешний вид компонента. На примере `main/index.ux`:
``` html
<template>
  <p>{{text}}</p>
</template>
```
Компонент `main/index.ux` отображает содержимое с помощью компонента `<p>`, который предназначен для показа текста. Значение выражения `{{text}}` определяет отображаемый текст.

JavaScript-скрипт внутри тега `<script>` реализует логику поведения компонента. Этот тег всегда использует `export default` для экспорта **объекта компонента**. В первую очередь стоит обратить внимание на свойство `data` объекта компонента, которое обычно представляет собой объект:
``` js
export default {
  data: {
    text: 'Hello, World!'
  }
}
```
Здесь у объекта `data` есть свойство `text`, значение которого будет использоваться в качестве отображаемого содержимого упомянутого ранее компонента `<text>` (прим. переводчика: в оригинале упоминается `<p>`).

### Модель компонентов и обновление состояния

Предположим, нам нужно разработать компонент, который меняет отображаемый текст при нажатии. В таком случае нам потребуется отслеживать событие ввода на компоненте и обновлять отображаемое содержимое. Следующий код отслеживает событие нажатия на компоненте `<p>`:
``` html
<template>
  <p on:click="text += '!'">{{text}}</p>
</template>
```
Выражение в атрибуте `on:click` будет выполняться при нажатии на текст. В результате при клике в конце текста `text`, отображаемого в компоненте `<p>`, будет добавляться символ `'!'`:

<glyphix id="getting-started-click-p" height="120" width="360" title="Событие клика">

``` html
<p on:click="text += '!'">{{text}}</p>
```

``` js
export default {
  data: {
    text: "Hello, World!"
  }
}
```

``` css
p {
  font-size: 32px;
  text-align: center;
}
```
