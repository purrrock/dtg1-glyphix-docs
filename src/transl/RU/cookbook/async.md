# Асинхронные операции

Введение асинхронных операций в сценарии JavaScript преследует главную цель — перенести ресурсоемкие задачи в фоновый режим, чтобы избежать блокировки потока JavaScript. В фоновом режиме в основном выполняются задачи, связанные с интенсивным вводом-выводом (IO-bound). Glyphix предоставляет разработчикам базовый асинхронный фреймворк для JavaScript, который реализует только необходимую абстракцию для асинхронных рабочих процессов, не создавая при этом дополнительных накладных расходов.

## Области применения

Модель асинхронного рабочего процесса применима в следующих сценариях:

- Запрос инициируется кодом JavaScript, обрабатывается нативным потоком асинхронной обработки, после чего возвращается результат;
- Запрос инициируется кодом JavaScript, нативный поток асинхронной обработки выполняет обработку и периодически отправляет отчеты о сообщениях;
  - Код JavaScript может主动 (активно) запросить отмену или аннулирование запроса.

## Режим запроса данных

В режиме запроса данных код JavaScript вызывает C++ API для создания запроса, выполняет операцию в асинхронном потоке и возвращает результат коду JavaScript. В этом процессе данные передаются через асинхронную очередь. Шаблонный класс `async::ResultSession` предоставляет общий операционный фреймворк для этого режима.

### Описание сценариев

Следующие сценарии являются типичными примерами режима запроса данных:

- **Чтение и запись файлов**: при вызове из JavaScript необходимо указать путь к файлу, смещение для чтения и записи, длину данных или записываемые данные; когда запрос отправляется в асинхронный поток для выполнения, происходят реальные операции с файлом, и по их завершении результат возвращается в код JavaScript или отправляется уведомление.
- **Сетевые запросы**: аналогично чтению и записи файлов, при вызове из JavaScript необходимо указать параметры запроса, которые затем обрабатываются в фоновом потоке с возвратом результата.

Сценарии режима запроса данных имеют следующие особенности:
- Результат запроса возвращается однократно, поэтому этот режим не подходит для датчиков или таймеров, которые могут срабатывать многократно;
- Запрос всегда имеет результат: в случае успеха возвращается результат, в противном случае — сообщение об ошибке. Возврат результата также происходит асинхронно;
- Запрос невозможно отменить после его инициации.

### Пример: Получение уровня заряда батареи

#### JavaScript API

Предположим, требуется реализовать асинхронную функцию JavaScript для получения уровня заряда батареи:
``` ts
getLevel(): Promise<number> // API в стиле Promise
getLevel(options: { // API в стиле callback
    success: (level: number) => void,
    fail: (code: number, msg: string) => void // Чтение уровня заряда батареи фактически не вызывает fail
}): void
```
Функция `getLevel()` используется для асинхронного получения уровня заряда батареи и поддерживает два стиля API: в стиле `Promise` и в стиле callback. Код для обоих стилей выглядит следующим образом:
``` js
async function printBatteryLevel() {
    const level = await getLevel() // Асинхронное получение уровня заряда
    console.log(`battery level: ${level}%`)
}
printBatteryLevel() // Печать уровня заряда, пример вывода в консоль:
// battery level: 59%

// Ниже приведен код в стиле callback, его использование не рекомендуется:
getLevel({
    success(level) { console.log(`battery level: ${level}%`) }
})
```

#### Экспорт нативных интерфейсов C++

Функция `getLevel()` в JavaScript фактически реализуется на C++. Когда код JavaScript вызывает эту функцию, он инициирует асинхронный запрос на получение уровня заряда батареи и после получения результата возвращает его в JavaScript через функцию обратного вызова или `Promise`. Функция C++, реализующая `getLevel()`, выглядит следующим образом:
``` cpp
static JsValue getLevel(const JsCallContext &ctx) {
    typedef async::ResultSession<BatteryGetLevel> Session;
    Session *session = new Session; // Создание объекта Session
    session->request(ctx.argc() ? ctx.arg(0) : JsValue());
    return session->promise();
}
```

Шаблонный класс `async::ResultSession` (далее пространство имен `async` опускается) реализует фреймворк, необходимый для асинхронных запросов данных. Каждый асинхронный запрос данных состоит из следующих шагов:
1. Создание объекта `ResultSession`.
2. Вызов метода `ResultSession::request()` для отправки запроса.
3. Использование `ResultSession::promise()` для возврата объекта `Promise` в JavaScript.

Эта строка кода:
``` cpp
session->request(ctx.argc() ? ctx.arg(0) : JsValue());
```
помимо отправки запроса, также передает методу `ResultSession::request()` аргумент под индексом $0$, переданный вызывающим кодом JavaScript. `ResultSession` автоматически определяет стиль (Promise или callback) в зависимости от наличия в этом аргументе функций обратного вызова `success` / `fail` и т. д. Если используется стиль `Promise`, то:
``` cpp
return session->promise();
```
возвращает объект `Promise` для получения результата асинхронного запроса; в противном случае возвращается `undefined`, а результат обрабатывается функцией обратного вызова.

#### Шаблонный класс `ResultSession`

Объявление шаблонного класса `ResultSession` выглядит следующим образом:
``` cpp
template<class T, class H = ResultHandler> class ResultSession;
```
Шаблонный параметр `T` представляет собой класс, реализующий конкретную асинхронную операцию. В данном примере реализуется класс `BatteryGetLevel` для асинхронного получения уровня заряда батареи. Шаблонный параметр `H` определяет способ обработки результата асинхронного запроса; стандартный `ResultHandler` автоматически выбирает стиль callback или Promise, и разработчикам обычно не требуется его изменять.

#### Класс `BatteryGetLevel`

Определение класса `BatteryGetLevel`:
``` cpp
struct BatteryGetLevel {
    async::Result<int> resolve() const {
        return battery_read_level(); // Получение уровня заряда батареи
    }
    // errorMessage() используется для перевода кода ошибки в текст. Чтение заряда не вызывает ошибок, реализация может быть произвольной.
    static const char *errorMessage(Status) {
        return "get battery level failed";
    }
};
```
Как видно, у `BatteryGetLevel` есть две функции-члена. Функция `resolve()` используется для выполнения конкретной операции в асинхронном потоке. Возвращаемое значение функции `resolve()` должно иметь тип `async::Result<T>`, в данном случае — `async::Result<int>`.

Тип шаблонного параметра `T` возвращаемого значения функции `resolve()` (`async::Result<T>`) совпадает с типом данных параметра callback-функции JavaScript API или данных `Promise`. Например, в данном случае `int` соответствует следующему JavaScript API:
``` ts
// Тип возвращаемого значения функции C++ BatteryGetLevel::resolve()
// async::Result<int> соответствует Promise<number> в JavaScript
getLevel(): Promise<number>
```

Иными словами, если `resolve()` возвращает значение `async::Result<String>`, то в JavaScript будет возвращен `Promise<string>`, а для функции обратного вызова — `{ success(value: string): void }`. Подробную информацию о преобразовании типов данных между C++ и JavaScript см. в разделе [Преобразование типов данных](#преобразование-типов-данных).

### Пример: Чтение файлов

#### JavaScript API

Предположим, требуется реализовать асинхронную функцию JavaScript для чтения файлов:
``` ts
readfile(url:string): Promise<string> // API в стиле Promise
readFile(option: {   // API в стиле callback
  uri: string,
  success?: (data: string) => void,
  fail?: (code: number, msg: string) => void,
}): void
```
Эта функция асинхронно читает содержимое файла и возвращает его через объект `Promise`, возвращаемым значением является содержимое файла. Фактический код JavaScript выглядит следующим образом:
``` js
async function printReadFile() {
    const data = await readFile("file.txt") // Асинхронное получение содержимого файла
    console.log('文件读取成功：', data)
}

printReadFile() // Печать содержимого файла в виде строки, пример вывода в консоль:
// 文件读取成功：hello

// Ниже приведен код в стиле callback
readFile({
    url: "file.txt", 
    success: (data: string) => {  
        console.log('文件读取成功：', data);  
    }
})
```

#### Экспорт нативных интерфейсов C++

Функция `readFile()` в JavaScript фактически реализуется на C++. Когда код JavaScript вызывает эту функцию, он инициирует асинхронный запрос на чтение файла и после получения результата возвращает его в JavaScript через функцию обратного вызова или `Promise`. Функция C++, реализующая `readFile()`, выглядит следующим образом:
``` cpp
JsValue readFile(const JsCallContext &ctx) {
    typedef async::ResultSession<ReadFileRequest> Session;
    if (ctx.argc() > 0 && ctx.arg(0).isObject()) { 
        Session *session = new Session;
        // Преобразование поля url аргумента функции JavaScript в String C++ 
        session->client().url = ctx.arg(0)["url"].toString(); 
        session->request(ctx.argc() ? ctx.arg(0) : JsValue());
        return JsValue();
    }
}
```
Описание используемого шаблонного класса см. в разделе [Шаблонный класс resultsession](#шаблонный-класс-resultsession), а пояснение к коду — в разделе [Экспорт нативных интерфейсов C++](#экспорт-нативных-интерфейсов-c) для получения уровня заряда батареи.

#### Класс `readFile`

Определение класса `ReadFileRequest`:
``` cpp
struct ReadFileRequest {
    String url; // URL читаемого файла.
    Result<String> resolve() {
        ByteArray array = File::read(url); // Чтение содержимого файла по URL
        return String(array.charData(), array.size());
    }
    // errorMessage() используется для перевода кода ошибки в текст
    const char *errorMessage(Status) { return "read file error"; }
};
```
Как видно, у `ReadFileRequest` есть две функции-члена. Функция `resolve()` используется для выполнения конкретной операции в асинхронном потоке. Возвращаемое значение функции `resolve()` должно иметь тип `async::Result<T>`, в данном случае — `async::Result<String>`. Стоит отметить, что в функции `resolve()` нельзя обрабатывать типы данных JavaScript: `url` преобразуется в тип `String` C++ внутри функции `readFile()` перед инициацией асинхронного запроса, и подобные преобразования данных нельзя выполнять внутри `resolve()`.

## Режим прослушивания (Listener Mode)

В режиме прослушивания код JavaScript вызывает C++ API для создания запроса на мониторинг многократных асинхронных событий, таких как получение данных с датчиков. При изменении данных выполняется асинхронное событие, которое возвращает результат в JavaScript. Шаблонные классы `async::ListenSession` и `async::Signal` предоставляют общий операционный фреймворк для этого режима.

### Описание сценариев

Следующие сценарии являются типичными примерами режима прослушивания:

- **Мониторинг различных датчиков**: инициируется из JavaScript путем вызова C++ API для мониторинга соответствующего датчика с указанием функции обратного вызова. Когда данные датчика изменяются, новые данные возвращаются в код JavaScript через асинхронный поток в качестве параметра функции обратного вызова.
- **Периодические задачи по таймеру**: при вызове из JavaScript необходимо задать время таймера, функцию обратного вызова по истечении времени, а также признак периодичности. После отправки запроса по истечении каждого интервала таймера асинхронный поток возвращает результат в JavaScript, запуская установленную callback-функцию.

Сценарии режима прослушивания имеют следующие особенности:
- После запуска мониторинга поддерживаются множественные асинхронные запросы, поэтому этот режим может не подходить для однократных асинхронных событий, таких как чтение/запись файлов или сетевые запросы;
- После запуска мониторинга его необходимо обязательно отменить, когда он больше не нужен, иначе возникнет утечка памяти.

### Пример: Мониторинг уровня заряда батареи

#### JavaScript API

Предположим, требуется реализовать асинхронную функцию JavaScript для мониторинга уровня заряда батареи:
``` ts
subscribe(callback: (Level: number) => void): number // Мониторинг уровня заряда батареи
unsubscribe(subscribeID: number): void // Отмена мониторинга
```

Функция `subscribe()` используется для асинхронного мониторинга уровня заряда батареи, а `unsubscribe()` — для отмены мониторинга. Пример использования:
``` js
// Запуск мониторинга, возвращается ID для отмены подписки
let id = subscribe(level => {
  // При изменении уровня заряда батареи вызывается callback-функция мониторинга, пример вывода в консоль:
  // now battery level: 59
  console.log(`now battery level: ${level}%`)
})

unsubscribe(id); // Отмена мониторинга
``` 

#### Экспорт интерфейса прослушивания C++

Функция `subscribe()` в JavaScript фактически реализуется на C++. Когда код JavaScript вызывает эту функцию, запускается мониторинг уровня заряда батареи. При каждом изменении уровня заряда инициируется асинхронный запрос, и результат возвращается в код JavaScript через функцию обратного вызова. Функция C++, реализующая `subscribe()`, выглядит следующим образом:
``` cpp
async::Signal<int> Level; // Создание глобального объекта Level

level(45); // Значение Level изменилось, отправлен асинхронный запрос

static JsValue subscribe(const JsCallContext &ctx) {
    Applet *applet = Applet::current(&ctx.vm());
    if (applet && ctx.argc())  // Проверка передачи параметров
        return applet->bindObject(Level.connect(ctx.arg(0)));
    return JsValue();
}
```
Обязательно требуется создать глобальный объект `Level`. Используемый шаблонный класс `async::Signal` (далее пространство имен `async` опускается) реализует фреймворк запроса мониторинга. Запрос мониторинга включает следующие шаги:
1. Перед началом мониторинга необходимо создать объект глобального класса `Signal`;
2. Использовать метод `Signal::connect()` для связывания первого аргумента, переданного из JavaScript, с объектом `Level`;
3. Вызвать `Applet::bindObject` для привязки объекта `Level`; при изменении состояния `Level` вызывается функция обратного вызова, возвращающая результат в код JavaScript.

Эта строка кода:
```cpp
level(45);
```
изменяет значение `Level` на $45$, запуская механизм мониторинга, который инициирует асинхронный запрос. Измененное значение передается в качестве параметра функции обратного вызова, и в конечном итоге результат возвращается в код JavaScript.

#### Экспорт интерфейса отмены прослушивания C++

Функция `unsubscribe()` в JavaScript также реализуется на C++. Код JavaScript вызывает эту функцию для отмены мониторинга во избежание утечек памяти, когда мониторинг больше не используется. Функция C++, реализующая `unsubscribe()`, выглядит следующим образом:
``` cpp
static JsValue unsubscribe(const JsCallContext &ctx) {
    Applet *applet = Applet::current(&ctx.vm());
    if (applet && ctx.argc() >= 1 && ctx.arg(0).isNumber()) // Проверка правильности переданных параметров
        delete applet->unbindObject<async::Slot>(ctx.arg(0).toInt());   
    return JsValue();
}
```
Для отмены запроса мониторинга необходимо вызвать `Applet::unbindObject` для снятия привязки. Для определения отвязываемого объекта требуется передать ID, возвращенный функцией `subscribe()`.

#### Шаблонный класс `Signal`

``` cpp
template<class T, class H = ListenHandler> class Signal;
```
Шаблонный параметр `T` представляет собой класс, реализующий конкретную асинхронную операцию. В данном примере демонстрируется использование типа `int` для реализации мониторинга заряда батареи. Шаблонный параметр `H` определяет способ обработки результата асинхронного запроса; стандартный `ResultHandler` автоматически выбирает стиль callback или Promise, и разработчикам обычно не требуется его изменять.

## Преобразование типов данных

В `ResultSession` или `ListenSession` данные асинхронных операций должны быть преобразованы в объект `JsValue`, чтобы их можно было использовать в коде JavaScript. Например, в [Классе BatteryGetLevel](#класс-batterygetlevel) определена функция:
``` cpp
async::Result<int> BatteryGetLevel::resolve() const;
```
Это объявление функции означает, что типом возвращаемых данных запроса заряда батареи является `int`. Этот тип данных может быть преобразуем в `JsValue`. На самом деле следующие типы могут быть преобразованы в `JsValue`:
- `bool`: преобразуется в тип `boolean`;
- `int`: преобразуется в тип `number`;
- `float`, `double`: преобразуются в тип `number`;
- `String`: преобразуется в тип `string`.

::: warning
Строки в стиле C не поддерживаются. Они будут преобразованы в тип `boolean`.
:::

Преобразование происходит автоматически, вмешательство разработчика не требуется.
