# Рекомендации по изучению C++

Этот документ не является учебником по C++, а представляет собой руководство по быстрому освоению предварительных знаний для разработчиков, которые собираются читать документацию из этого каталога.

В нем предполагается, что вы уже долгое время пишете на C и знакомы с микроконтроллерами (MCU), операционными системами реального времени (RTOS), драйверами, LVGL или аналогичными встроенными фреймворками. У вас должен быть богатый опыт программирования, но вы можете быть не знакомы с той частью C++, которая требуется для работы с Glyphix.

::: tip
Если ваша цель — разработка Native-модулей, асинхронного функционала или Native-виджетов, пожалуйста, сначала прочитайте этот документ, а затем переходите к [Системе объектов](./object-system.md) и другим разделам. Это поможет избежать множества проблем из серии «код понятен, а написать самому не получается».
:::

## Подмножество возможностей C++

В проекте Glyphix отключен ряд возможностей C++, и разработчикам вовсе не обязательно их изучать:

- Отключен **RTTI**: нельзя использовать `dynamic_cast`, `typeid` и прочие механизмы идентификации типов во время выполнения. Если вам нужно безопасное приведение типов вниз по иерархии (downcasting), используйте [`dyn_cast`](object-system.md#动态类型转换).
- Отключены **исключения**: нет необходимости изучать `try` / `catch` / `throw` в качестве основного пути. Для обработки ошибок в первую очередь используются возвращаемые значения, коды состояния, состояние объектов и явные проверки. Это похоже на привычки обработки ошибок в языке C.


Кроме того, среда выполнения Glyphix имеет ряд специфических ограничений, вызванных главным образом фрагментацией и ограничениями совместимости систем на базе MCU:
1. Инструменты параллелизма из стандартной библиотеки C++, такие как `std::thread` и `std::mutex`, на MCU недоступны.
2. Библиотеки работы со временем вроде `std::chrono` на MCU также недоступны.
3. Не используйте статические локальные переменные (function-local static): гарантированная с C++11 атомарная инициализация на MCU **с высокой долей вероятности ненадежна**.
4. Не используйте глобальные переменные (объекты) с динамическим выделением памяти в куче, так как фаза глобальной инициализации на MCU может быть неконтролируемой, а память в куче может быть недоступна.

Пункты 3 и 4 встречаются очень часто, к ним нужно относиться с особым вниманием.

## Знания C++, которые необходимо освоить

Следующего материала будет достаточно для понимания большей части документов в этом каталоге.

### Классы и объектно-ориентированное программирование

Вы должны быть способны как минимум читать и писать код следующего вида:

```cpp
class MyWidget : public Widget {
public:
    explicit MyWidget(Widget *parent = nullptr)
        : Widget(parent) {}

    void setValue(int value);
    int value() const;
};
```

Вы должны понимать:

- Разницу между классами и структурами (она невелика, в основном касается прав доступа по умолчанию).
- Смысл публичного наследования (обычно используется только оно).
- Конструкторы и списки инициализации.
- Инициализацию членов класса и **`const`-члены функций**.
- В каких случаях происходит переопределение (override) интерфейса базового класса, а в каких — просто объявление обычной функции-члена.

Эти знания напрямую понадобятся в [Системе объектов](./object-system.md), [Руководстве по разработке виджетов](./widget.md) и [Регистрации и экспорте виджетов](./widget-export.md).

### Указатели, ссылки и `const`

Если вы знакомы с C, этот раздел кажется самым простым для самопроверки, но правила использования в C++ гораздо строже, чем в C.

Что нужно усвоить на практике:

- Разницу между `T *` и `T &`.
- Когда передавать указатель, а когда — ссылку.
- Значение **`const T *`**, `T *const` и **`const T &`**.
- Почему `const`-функции членов класса встречаются так часто.
- Почему объекты не следует обрабатывать произвольно побайтово, как это принято в C.

В Glyphix эти знания напрямую связаны с проектированием интерфейсов и безопасностью жизненного цикла объектов.

### Жизненный цикл и управление ресурсами

Это самый важный раздел при переходе с C на C++.

У вас должна сформироваться привычка:

- Объекты автоматически уничтожаются (вызывается деструктор) при выходе из области видимости.
- Конструктор отвечает за создание валидного состояния.
- Деструктор отвечает засвободу ресурсов.
- Не нужно вручную «зачищать ресурсы» в самом конце функции.
- Нельзя обращаться со сложными объектами как с обычными блоками памяти через `memset` / `memcpy`.


Множество средств и возможностей Glyphix построены на модели жизненного цикла объектов C++, включая такие темы, как RAII.

### Базовое использование шаблонов

Глубокого понимания здесь не требуется, но вы должны уметь читать такие конструкции:

- `Signal<int>`
- `Pointer<Label>`
- `SharedRef<MyData>`
- `async::ResultSession<Client>`
- `std::vector<T>`

И понимать, что «шаблоны — это механизм генерации кода с параметрами типов», а не какой-то продвинутый трюк, доступный только авторам библиотек.

В документации Glyphix шаблоны встречаются в основном в двух формах:

- **Обобщенные контейнеры / вспомогательные типы**, например `Signal<T>`, `Pointer<T>`.
- **Точки специализации**, например, добавление `js_cast<T>` для пользовательских типов.

Разработчик должен как минимум понимать базовые термины, такие как «параметры шаблона», «инстациация» и «специализация», а также уметь читать объявления и использования шаблонных типов. Однако от вас не требуется умение создавать собственные шаблонные классы или функции.

### Лямбда-выражения

В современном C++ лямбда — это очень практичный способ написания одноразовых функций. Вы должны как минимум понимать такой код:

```cpp
mod["double"] = [](JsCtx ctx) -> JsValue {
    return ctx.arg(0).asInt(0) * 2;
};
```

А также:

```cpp
int factor = readScaleFactorFromConfig();
mod["scale"] = [factor](JsCtx ctx) -> JsValue {
    return ctx.arg(0).asInt(0) * factor;
};
```

Сначала следует ознакомиться с базовым синтаксисом лямбд и механизмами захвата (capture), а также уяснить следующее:

- Лямбда — это объект анонимной функции.
- Лямбда без захвата часто может использоваться как обычный указатель на функцию.
- Лямбда с захватом хранит состояние.
- Как только лямбда начинает удерживаться асинхронно, жизненный цикл захваченных объектов становится критически важным.

Это напрямую влияет на безопасность кода при [разработке Native-модулей](./native-module.md) и в [примерах асинхронной разработки](./async-examples.md).

::: tip Лямбды встречаются повсеместно
Лямбды фактически полностью заняли нишу функций обратного вызова (callbacks), а это значит, что они повсюду. В некотором смысле лямбды — это, пожалуй, самый важный синтаксический элемент C++.

Лямбда-выражения **без захвата** практически эквивалентны указателям на функции в C, за исключением иного синтаксиса, и избавляют от проблемы «придумывания имен».
:::

### Минимально необходимый набор стандартной библиотеки

Не нужно системно изучать весь STL, но рекомендуется ознакомиться с его наиболее распространенными частями:

- `std::vector`
- `std::array`
- `std::move`
- Базовые алгоритмы из `<algorithm>`, итераторы и цикл `for` с диапазоном (range-based for).

::: tip Ассоциативные контейнеры
Glyphix реализует собственные `HashMap` и `HashSet`, которые очень похожи на `std::unordered_map`. Однако использовать ассоциативные контейнеры вроде `std::map` и `std::unordered_map` не рекомендуется, так как у них низкая производительность, а `std::map` также приводит к значительному раздуванию кода (code bloat).
:::

### Взаимодействие C и C++ (Interop)

Если вам предстоит интеграция с низкоуровневым SDK, эта часть практически неизбежна.

Вы должны уметь:

- Понимать назначение `extern "C"`.
- Работать с указателями на функции обратного вызова в стиле C.
- Работать с контекстными параметрами `void *` и ограничениями неявного приведения `void *` в C++ (в C++ требуется явное приведение).
- Разделять обязанности между структурами C и обертками (wrapper layers) на C++.

В [примерах асинхронной разработки](./async-examples.md) вы увидите типичный паттерн: C API отвечает за реальное выполнение асинхронных операций, а слой C++ занимается только упаковкой параметров, управлением жизненным циклом и возвратом результатов.

::: tip Ожидания по сложности
Эта часть не сложна, но в ней легко допустить ошибки компоновки (link errors). Вам может потребоваться научиться решать различные проблемы, вызванные смешиванием заголовочных файлов C и C++, такие как отсутствие `extern "C"`.
:::

## Рекомендуемый порядок изучения

Рекомендуется восполнять пробелы в следующем порядке, а не читать увесистый учебник с первой страницы.

### 1. Сначала сформируйте «взгляд на миграцию с C на C++»

[ISO C++ FAQ](https://isocpp.org/faq)
- В первую очередь изучите разделы «Learning C++ if you already know C» и «How to mix C and C++».
- Этот материал отлично подходит для опытных разработчиков на C, так как он подразумевает, что вы уже понимаете концепции памяти, интерфейсов, сборки и аппаратных ограничений.

### 2. Быстро составьте впечатление о современном C++

[A Tour of C++](https://www.stroustrup.com/Tour.html)
- Если вы готовы прочитать небольшую книгу, это лучший выбор для вложений времени.
- Это не «обучение программированию с нуля», а обзор современного C++ для опытных разработчиков.
- Цель состоит не в том, чтобы запомнить всё, а в том, чтобы узнать, какие основные компоненты есть в C++ и какие задачи они решают.

### 3. Справочник по синтаксису и стандартной библиотеке

[cppreference](https://en.cppreference.com/w/cpp)
- Подходит для поиска информации в процессе работы, а не для последовательного чтения от корки до корки.
- Когда при чтении документации Glyphix вы сталкиваетесь с синтаксисом или именами библиотек вроде `override`, лямбд, списков инициализации, специализации шаблонов, `std::vector`, вы можете искать их здесь.
- Если вам нужно освежить в памяти какие-то детали языка C, их тоже можно найти здесь.

### 4. Переключите свои привычки кодирования на современный C++

[C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)
- Это не учебник, а руководство по инженерной практике (доступна и печатная версия).
- Не рекомендуется читать целиком подряд; в первую очередь изучите следующие разделы:
  - `P`: Общие принципы (Philosophy)
  - `I`: Проектирование интерфейсов (Interfaces)
  - `F`: Функции (Functions)
  - `C`: Классы и объекты (Classes and class hierarchies)
  - `R`: Управление ресурсами (Resource management)
  - `ES`: Выражения и инструкции (Expressions and statements)
  - `CPL`: Взаимодействие с C (C-style programming)
  - `SF`: Организация исходных файлов (Source files)
  - `SL`: Использование стандартной библиотеки (Standard Library)
  - `CP`: Параллелизм (Concurrency) — читать по необходимости.

[Статьи Embedded Artistry по C++](https://embeddedartistry.com/blog/tag/cpp/)
- Больше подходят для тематического чтения, чем для системного курса.
- Наиболее интересные темы включают: как использовать C++ без кучи, инкапсуляция регистров с сильной типизацией, что происходит с программой до вызова `main()`.

## Как эффективнее использовать эти ресурсы

Наиболее эффективный подход заключается не в том, чтобы «сначала поучить C++ какое-то время, а потом начать смотреть Glyphix», а в их совмещении (параллельном процессе):

1. Прочитайте этот документ целиком, чтобы понять, какие знания требуют восполнения.
2. Прочитайте [A Tour of C++](https://www.stroustrup.com/Tour.html) или разделы FAQ, посвященные миграции с C.
3. Приступайте к чтению [Системы объектов](./object-system.md) и [Разработки Native-модулей](./native-module.md).
4. Когда встретите непонятный синтаксис, используйте [cppreference](https://en.cppreference.com/w/cpp) для точечного поиска.
5. Если возникает вопрос вроде «почему в современном C++ принято писать именно так?», обратитесь к соответствующим разделам [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines).

Такой темп обучения ближе к реальной работе и лучше подходит разработчикам, уже имеющим опыт в области встраиваемых систем.
