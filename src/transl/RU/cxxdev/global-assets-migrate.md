# Руководство по миграции глобальных ресурсов

Это руководство предназначено для проектов, интегрирующих Glyphix, и поможет вам обновить способ загрузки глобальных ресурсов в старых проектах до актуального решения. Это обеспечит простую в управлении и редактировании структуру глобальных ресурсов и избавит от необходимости зависеть от инструментов упаковки или конвертации от производителя.

На ранних этапах Glyphix использовала бинарные архивные пакеты `global.pkg` для управления глобальными ресурсами (файлами шрифтов, таблицами сопоставления шрифтов и т.д.). Позже система постепенно перешла на прямое использование распакованных файлов ресурсов, и в конечном итоге формат файлов сопоставления шрифтов также был переведен из бинарного в стандартный JSON <version-badge since="0.9" />. Если код вашей точки входа все еще использует старый подход, вы можете обновить его, следуя данному руководству.

::: tip
Использование старого режима неудобно в обслуживании, затрудняет управление и редактирование глобальных ресурсов, поэтому рекомендуется выполнить обновление незамедлительно.
:::

## Удаление `global.pkg`

### Хазнаки старого кода

Если в коде вашей точки входа присутствует любой из следующих шаблонов, это означает, что вы используете `global.pkg`:

```cpp
EnvPath::setEntry(EnvPath::GlobalPackage, "/global.pkg");
static String globalUri(const String &path) { return "pkg:///" + path; }
```

Эффект этих двух строк заключается в следующем: все запросы ресурсов с протоколом `pkg:///` перенаправляются на файлы внутри бинарного архивного пакета `/global.pkg`.

Зачем нужно удаление:
- При каждой замене шрифтов или других ресурсов необходимо заново запускать инструмент упаковки для генерации файла `.pkg`.
- При отладке нельзя напрямую просмотреть или заменить отдельные файлы внутри `.pkg`, а также сложно проверить их содержимое.
- Процесс сборки зависит от специализированных инструментов, что увеличивает затраты на коммуникацию и поддержку.

### Процесс миграции

**Шаг 1: Извлечение ресурсов из `global.pkg`.**

Если у вас не осталось исходных файлов `.pkg`, вы можете извлечь содержимое из `global.pkg` (используя инструмент командной строки Glyphix или запросив исходные файлы ресурсов). Обычно требуется извлечь следующее:

```
fonts/
    NotoSans-Regular.ttf
    NotoSansSC-Regular.ttf
    ...
    font-faces          ← Файл сопоставления шрифтов (впоследствии будет обновлен до JSON)
```

Поместите извлеченный каталог в каталог ресурсов вашего проекта, например, в `/fonts/`.

**Шаг 2: Удаление кода, связанного с `global.pkg`.**

1. Удалите всю строку `EnvPath::setEntry(EnvPath::GlobalPackage, "/global.pkg")`.
2. Удалите вспомогательные функции вроде `globalUri()`.
3. Замените все ссылки на ресурсы `pkg:///xxx` на прямые пути к файлам, то есть `/xxx`.

**Шаг 3: Изменение кода загрузки шрифтов.**

Предположим, что ваш код инициализации изначально выглядел примерно так:

```cpp
static String globalUri(const String &path) { return "pkg:///" + path; }

static void setupFont(const String &fontMap) {
    String uri = globalUri(fontMap);
    FontFaceMap &map = App()->fontManager()->faces();
    if (!map.readFile(uri))
        LogError() << "Failed to load font face map: " << fontMap;
}

int main() {
    Application app;
    EnvPath::setEntry(EnvPath::GlobalPackage, "/global.pkg");
    setupFont("font-faces");
    // ...
}
```

Замените его на прямое использование путей к файлам (без функции `globalUri()` и регистрации `GlobalPackage`):

```cpp
static void setupFont(const String &fontMap) {
    auto &map = App()->fontManager()->faces();
    if (!map.readFile(fontMap))
        LogError() << "Failed to load font face map: " << fontMap;
}

int main() {
    Application app;
    setupFont("/fonts/font-faces");
    // ...
}
```

Теперь структура ресурсов выглядит следующим образом:

```
/fonts/
    font-faces          ← Бинарный формат
    NotoSans-Regular.ttf
    ...
```

На этом этапе вы все еще используете бинарный файл `font-faces`. В следующем разделе он будет обновлен до JSON.

## Переход на JSON-файлы сопоставления шрифтов

### Признаки старого кода

```cpp
FontFaceMap &map = App()->fontManager()->faces();
map.readFile("/fonts/font-faces");
```

`readFile` считывает пользовательский бинарный файл. Этот бинарный файл невозможно отредактировать вручную — его необходимо конвертировать и генерировать из CSS-файла с помощью инструмента упаковки.

### Описание формата JSON

Теперь мы используем JSON-файлы для прямого описания отношений сопоставления шрифтов. Вам нужно лишь создать файл `font-faces.json` со следующим форматом:

```json
{
  "font-faces": [
    {
      "family": "sans-serif",
      "weight": 400,
      "style": "normal",
      "urls": [
        "NotoSans-Regular.ttf",
        "NotoSansSC-Regular.ttf",
        "NotoSansJP-Regular.ttf"
      ]
    },
    {
      "family": "sans-serif",
      "weight": 700,
      "style": "normal",
      "urls": [
        "NotoSans-Bold.ttf"
      ]
    },
    {
      "family": "serif",
      "weight": 400,
      "style": "normal",
      "urls": [
        "NotoSerif-Regular.ttf"
      ]
    }
  ]
}
```

Описание полей:

| Поле | Тип | Обязательное | Значение по умолчанию | Описание |
|------|------|------|--------|------|
| `family` | Строка | Да | - | Имя семейства шрифтов, например `sans-serif`, `serif` |
| `weight` | Целое число | Нет | 400 | Значение толщины шрифта CSS (100–900): 400 — обычный, 700 — жирный |
| `style` | Строка | Нет | normal | Стиль шрифта, возможные значения `italic` или `oblique` |
| `urls` | Массив строк | Да | - | Пути к файлам шрифтов относительно каталога, в котором находится JSON-файл |

Ниже приводится дополнительное описание ключевых полей.

**Поле weight**

В поле weight просто указывается числовое значение толщины CSS, которое округляется до ближайшего стандартного значения:

- `100` Thin (Тонкий)
- `400` Regular (Обычный — значение по умолчанию, можно не указывать)
- `700` Bold (Жирный)
- `900` Black (Черный)

**Разрешение путей urls**

Пути в массиве `urls` разрешаются относительно каталога, в котором находится JSON-файл. Например, если JSON-файл расположен по адресу `/fonts/font-faces.json`, то указание в `urls` значения `"fonts/NotoSans-Regular.ttf"` в итоге разрешится в `/fonts/fonts/NotoSans-Regular.ttf`.

Поэтому рекомендуется размещать JSON-файл непосредственно в том же каталоге, что и файлы шрифтов, чтобы в URL можно было указывать просто имя файла. Например, структура каталогов:

```
/fonts/
    font-faces.json
    NotoSans-Regular.ttf
    NotoSansSC-Regular.ttf
    NotoSans-Bold.ttf
```

В этом случае содержимое JSON выглядит так, как показано в примере выше.

### Изменение кода

Замените `readFile` в коде инициализации на `readJSON`:

```cpp
#include "gx_fontmanager.h"

static void setupFont() {
    auto &map = App()->fontManager()->faces();
    if (!map.readJSON("/fonts/font-faces.json"))
        LogError() << "Failed to load font-faces.json";
    App()->setFont(Font("sans-serif", 24));
}

int main() {
    Application app;
    setupFont();
    // ...
}
```

Это единственное изменение вызова API, остальной код менять не требуется. После этого вы сможете напрямую редактировать `font-faces.json` для добавления/удаления шрифтов или настройки сопоставлений, не нуждаясь в каких-либо инструментах конвертации.

## Часто задаваемые вопросы (FAQ)

**Как поступить, если у одного семейства есть несколько вариантов: Regular, Bold, Italic и т.д.?**

Добавьте отдельную запись для каждого варианта в массив `font-faces`, различая их по полям `weight` и `style`:

```json
{
  "font-faces": [
    {
      "family": "sans-serif",
      "weight": 400,
      "style": "normal",
      "urls": ["NotoSans-Regular.ttf"]
    },
    {
      "family": "sans-serif",
      "weight": 700,
      "style": "normal",
      "urls": ["NotoSans-Bold.ttf"]
    },
    {
      "family": "sans-serif",
      "weight": 400,
      "style": "italic",
      "urls": ["NotoSans-Italic.ttf"]
    }
  ]
}
```

Проекты для микроконтроллеров (MCU) обычно используют только шрифты `sans-serif` с обычной толщиной `normal` (`Regular`), система выполнит резервное переключение автоматически.

**Можно ли указать несколько файлов в массиве `urls`? Когда это нужно?**

Да, можно. Когда одному семейству шрифтов требуется поддержка нескольких языковых символов, поместите несколько файлов шрифтов в один массив `urls`. Например, если для `sans-serif` необходимо одновременно поддерживать латиницу, китайские/японские/корейские иероглифы и арабский язык:

```json
{
  "family": "sans-serif",
  "weight": 400,
  "style": "normal",
  "urls": [
    "NotoSans-Regular.ttf",
    "NotoSansSC-Regular.ttf",
    "NotoSansJP-Regular.ttf",
    "NotoSansArabic.ttf"
  ]
}
```

При отрисовке текста движок будет последовательно искать глифы символов в этих файлах, и будет использован первый найденный глиф.

**Обязательно ли файлы шрифтов должны находиться в том же каталоге, что и JSON?**

Нет. Пути в `urls` разрешаются относительно каталога JSON-файла, поэтому вы можете использовать относительные пути, чтобы поместить шрифты в подкаталог. Также можно использовать абсолютные пути, и в этом случае они не будут зависеть от расположения JSON.

**Можно ли передать JSON-строку прямо в коде?**

Да. Используйте версию с двумя параметрами:

```cpp
map.readJSON("/fonts/", R"({
  "font-faces": [
    {"family": "sans-serif", "urls": ["NotoSans-Regular.ttf"]}
  ]
})");
```

Первый параметр — это baseUri, используемый для разрешения относительных путей в `urls`.
