# Таймеры

Этот модуль предоставляет функции таймера для отложенного или периодического выполнения кода. API таймеров можно использовать напрямую без необходимости импорта.

## Определение интерфейсов

### `setTimeout` <decl type="(callback: () => void, duration: number): number" />

Устанавливает таймер, который выполняет функцию обратного вызова (callback) по истечении указанной задержки. Описание параметров:
- `callback`: функция обратного вызова, которая будет выполнена по истечении времени задержки;
- `duration`: время задержки в миллисекундах.

Возвращает идентификатор таймера (ID), который можно использовать для его отмены с помощью метода [`clearTimeout()`](#cleartimeout).

Пример:
``` js
// Выполнить callback через 1 секунду
const timerId = setTimeout(() => {
  console.log('Прошла 1 секунда')
}, 1000)
```

### `setInterval` <decl type="(callback: () => void, duration: number): number" />

Устанавливает таймер, который повторяет выполнение функции обратного вызова с заданным интервалом. Описание параметров:
- `callback`: функция обратного вызова, выполняемая при каждом срабатывании таймера;
- `duration`: интервал выполнения в миллисекундах.

Возвращает идентификатор таймера (ID), который можно использовать для его отмены с помощью метода [`clearInterval()`](#clearinterval).

Пример:
``` js
// Выполнять callback каждые 500 миллисекунд
const timerId = setInterval(() => {
  console.log('Прошло еще 500 миллисекунд')
}, 500)
```

### `clearTimeout` <decl type="(timerId: number): void" />

Отменяет таймер, установленный методом [`setTimeout()`](#settimeout). Параметр `timerId` — это идентификатор отменяемого таймера.

::: warning
В отличие от веб-окружения, пул идентификаторов таймеров в данной реализации **может переиспользоваться**. Поэтому **не вызывайте** `clearTimeout()` повторно для одного и того же действующего ID таймера, так как это может случайно остановить другой работающий таймер.

Рекомендуется устанавливать ID таймера в значение `null` после его очистки во избежание повторного удаления. `clearTimeout()` безопасно принимает недействительные ID, такие как `null` или `0`, и эти вызовы не вызывают побочных эффектов.
:::

Пример:
``` js
const timerId = setTimeout(() => {
  console.log('Это сообщение не будет выведено')
}, 1000)

// Отменяем таймер до того, как он сработает
clearTimeout(timerId)
```

Рекомендуемый подход заключается в том, чтобы обнулять ID таймера после очистки во избежание повторного удаления действующего ID:
``` js
export default {
  onInit() {
    this.timerId = setTimeout(() => {
      console.log('Таймер сработал')
      this.timerId = null // Очищаем ID после выполнения
    }, 1000)
  },
  onDestroy() {
    // Безопасная очистка, даже если timerId равен null
    clearTimeout(this.timerId)
  },
  someMethod() {
    // Очищаем таймер и обнуляем ID
    clearTimeout(this.timerId)
    this.timerId = null
  },
}
```

### `clearInterval` <decl type="(timerId: number): void" />

Отменяет таймер, установленный методом [`setInterval()`](#setinterval). Параметр `timerId` — это идентификатор отменяемого таймера.

::: warning
В отличие от веб-окружения, пул идентификаторов таймеров в данной реализации **может переиспользоваться**. Поэтому **не вызывайте** `clearInterval()` повторно для одного и того же действующего ID таймера, так как это может случайно остановить другой работающий таймер.

Рекомендуется устанавливать ID таймера в значение `null` после его очистки во избежание повторного удаления. `clearInterval()` безопасно принимает недействительные ID, такие как `null` или `0`, и эти вызовы не вызывают побочных эффектов.
:::

Пример:
``` js
let count = 0
const timerId = setInterval(() => {
  count++
  console.log(`Количество выполнений: ${count}`)
  if (count >= 5)
    clearInterval(timerId) // Остановить после 5 выполнений
}, 500)
```

::: tip
`clearInterval` и `clearTimeout` фактически являются двумя псевдонимами одной и той же функции, однако для поддержания чистоты кода рекомендуется использовать соответствующие методы.
:::

## Заметки по разработке

### Переиспользование идентификаторов (ID) таймеров

Существует важное отличие данной реализации от стандартного веб-окружения: **идентификаторы таймеров могут переиспользоваться**.

В веб-браузерах и Node.js каждый вызов `setTimeout()` или `setInterval()` возвращает уникальный, монотонно возрастающий ID, который не используется повторно. Поэтому в веб-окружении вызов `clearTimeout()` или `clearInterval()` для уже очищенного или недействительного ID таймера является безопасным и не имеет побочных эффектов.

Однако в текущей реализации ID таймеров берутся из ограниченного пула. Когда таймер очищается или завершает работу, его ID может быть переиспользован новым созданным таймером. Это означает, что если вы попытаетесь повторно очистить один и тот же ID (число, возвращенное `setTimeout()` или `setInterval()`), вы можете случайно остановить другой работающий таймер.

`clearTimeout()` и `clearInterval()` могут безопасно принимать такие значения, как `null`, `0`, `undefined` и другие значения, не являющиеся ID таймеров (эти вызовы не имеют побочных эффектов).

Поэтому **обязательно соблюдайте следующие лучшие практики**:
1. Очищайте каждый ID таймера только один раз;
2. После очистки устанавливайте ID таймера в значение `null`, `0` или `undefined`, чтобы избежать случайной повторной очистки.

Поскольку `clearTimeout()` и `clearInterval()` безопасно принимают `null`, `0` и другие недействительные ID, проверять их на валидность перед вызовом не требуется.

В примерах из документации API выше показан рекомендуемый подход.

Исключением является возможность очистить собственный ID таймера прямо внутри callback-функции `setTimeout`:
``` js
let timer = setTimeout(() => {
  clearTimeout(timer) // Это не повлияет на другие таймеры и не вызовет предупреждений в логах
}, 1000)
```

### Проблемы с точностью таймеров

API таймеров **не гарантирует точных интервалов времени**, и фактическое время выполнения может отличаться. Это связано со следующим:
- Системное планирование (scheduling) и ограничения производительности могут приводить к неточному срабатыванию таймеров;
- Минимальный интервал таймера ограничен системой и может в любой момент зависеть от стратегий энергосбережения.

Поэтому **не используйте** API таймеров для точного измерения времени. Если вам нужно измерить интервалы времени или реализовать секундомер, используйте объект `Date` для получения актуальной метки времени (timestamp).

#### Неправильный пример: использование счетчика таймера для отсчета времени

Следующий код пытается вычислить прошедшее время путем суммирования количества срабатываний таймера, что является неверным подходом:
``` js
export default {
  data: {
    elapsedTime: 0, // Вычисление прошедшего времени путем накопления
  },
  onInit() {
    // Ошибка: предполагается, что таймер срабатывает ровно каждую секунду
    this.timerId = setInterval(() => {
      this.elapsedTime += 1000
    }, 1000)
  },
  onDestroy() {
    clearInterval(this.timerId)
  },
}
```

Проблема этого метода заключается в том, что даже при заданном интервале в $1000\rm ms$, фактический интервал срабатывания может составлять $1010\rm ms$ или даже больше. Накопленная погрешность со временем сделает отсчет все менее точным. После перехода устройства в режим энергосбережения таймеры могут работать с точностью до секунд или быть вовсе приостановлены.

#### Правильный пример: использование объекта Date для отсчета времени

Правильный подход заключается в фиксации начальной метки времени и вычислении разницы с текущим моментом при каждом обновлении:
``` js
export default {
  data: {
    elapsedTime: 0, // Прошедшее время (в миллисекундах)
  },
  onInit() {
    // Записываем начальную метку времени
    this.startTime = Date.now()
    // Используем таймер для периодического обновления отображения
    this.timerId = setInterval(() => {
      // Вычисляем реально прошедшее время через разницу меток времени
      this.elapsedTime = Date.now() - this.startTime
    }, 100) // Можно установить меньший интервал для более плавной анимации отображения
  },
  onDestroy() {
    clearInterval(this.timerId)
  },
}
```

### Полный пример секундомера

Ниже приведен полный пример компонента секундомера, демонстрирующий правильную реализацию функций запуска, паузы и сброса:

<glyphix id="api-timer-stopwatch" height="200" width="410">

``` html
<div class="container">
  <text class="timer">{{ formatTime(elapsedTime) }}</text>
  <div class="buttons">
    <text class="button" on:click="start">Start</text>
    <text class="button" on:click="pause">Pause</text>
    <text class="button" on:click="reset">Reset</text>
  </div>
</div>
```

``` js
export default {
  data: {
    elapsedTime: 0,     // Прошедшее время (в миллисекундах)
    isRunning: false,   // Запущен ли секундомер
  },
  onInit() {
    this.startTime = 0       // Метка времени текущего запуска
    this.accumulatedTime = 0 // Накопленное время (для возобновления после паузы)
    this.timerId = null
  },
  onDestroy() {
    // Очищаем таймер
    clearInterval(this.timerId)
  },
  start() {
    if (this.isRunning)
      return // Уже запущен, избегаем повторного старта

    this.isRunning = true
    // Записываем метку времени текущего запуска
    this.startTime = Date.now()

    // Периодически обновляем отображение
    this.timerId = setInterval(() => {
      // Накопленное время + (текущее время - время старта)
      this.elapsedTime = this.accumulatedTime + (Date.now() - this.startTime)
    }, 20)
  },
  pause() {
    if (!this.isRunning)
      return // Уже на паузе, делать ничего не нужно

    this.isRunning = false
    // Останавливаем таймер
    clearInterval(this.timerId)
    this.timerId = null // Обнуляем ID после очистки

    // Сохраняем накопленное время для продолжения в будущем
    this.accumulatedTime = this.elapsedTime
  },
  reset() {
    // Останавливаем таймер
    this.isRunning = false
    clearInterval(this.timerId)
    this.timerId = null // Обнуляем ID после очистки

    // Сбрасываем все состояния
    this.elapsedTime = 0
    this.accumulatedTime = 0
    this.startTime = 0
  },
  formatTime(ms) {
    // Конвертируем миллисекунды в формат "минуты:секунды.миллисекунды"
    const totalSeconds = Math.floor(ms / 1000)
    const minutes = Math.floor(totalSeconds / 60)
    const seconds = totalSeconds % 60
    const milliseconds = Math.floor((ms % 1000) / 10)

    return `${String(minutes).padStart(2, '0')}:${String(seconds).padStart(2, '0')}.${String(milliseconds).padStart(2, '0')}`
  },
}
```

- Очистку ресурсов таймера при уничтожении компонента.

### Предотвращение утечек памяти

При использовании таймеров обязательно вовремя очищайте их, иначе это может привести к утечкам памяти или попыткам обращения к уже уничтоженным компонентам. Очищайте все таймеры в функции жизненного цикла компонента [`onDestroy()`](/framework/component/life-cycle.md):
``` js
export default {
  onInit() {
    this.timerId = setTimeout(() => {
      // Выполнение определенных действий
      this.timerId = null // Обнуляем ID после выполнения
    }, 5000)
  },
  onDestroy() {
    // Очищаем таймер во избежание утечек памяти
    clearTimeout(this.timerId)
  },
}
```

Это особенно важно для периодических таймеров, созданных с помощью `setInterval()`, так как они будут работать непрерывно, пока не будут явно отменены.
