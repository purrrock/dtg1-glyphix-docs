# image

Компонент изображения используется для отображения элементов изображений, по умолчанию выравнивается по центру. Компонент `image` по умолчанию является строчным элементом.

## Свойства

### `src` <decl type="string" get set />

Устанавливает [URI](/framework/application/resource.md) изображения. Для локальных ресурсов изображения внутри пакета приложения поддерживаются как относительные, так и абсолютные пути. Компонент `image` поддерживает распространенные форматы изображений PNG и JPEG.

::: tip
Компонент `image` поддерживает только локальные ресурсы изображений, в отличие от элемента `img` в Web, который может напрямую отображать сетевые ресурсы изображений. Подробнее см. в разделе [Отображение сетевых изображений](#显示网络图片) в Glyphix.
:::

### `noCache` <decl type="boolean" get set />

Определяет, нужно ли кэшировать изображение. По умолчанию кэширование используется для оптимизации скорости загрузки. При включении свойства `noCache` компонент `image` не будет использовать кэш, и в этом случае при изменении свойства [`src`](#src) изображение всегда будет перезагружаться из файла.

Кэширование изображений — это технология, позволяющая оптимизировать скорость загрузки и уменьшить потребление памяти. Когда в системе уже загружено изображение с тем же URI, компонент `image` с включенным кэшем будет использовать этот ресурс напрямую. Однако файлы изображений с фиксированным именем, загружаемые из сети, содержимое которых может меняться (например, аватар пользователя `internal://cache/avatar.png`), обычно требуют включения свойства `noCache` для обеспечения корректного поведения.

Даже при включенном свойстве `noCache` компонент `image` по-прежнему не отслеживает обновление содержимого файла изображения, поэтому в таких случаях необходимо вручную изменить свойство [`src`](#src). Учитывая, что реактивный фреймворк фильтрует одинаковые операции присваивания, вы должны использовать следующий прием:
``` html
<!-- Предположим, это изображение, отображение которого нужно обновить; свойство no-cache является обязательным. -->
<image :src="avatarImage" no-cache />
```

``` js
const avatarImage = 'internal://cache/avatar.png' // Предположим, это изображение, загруженное из сети

export default {
  data: {
    avatarImage: avatarImage
  },
  // Вызовите этот метод после завершения загрузки аватара для обновления интерфейса
  onAvatarDownloaded() {
    this.avatarImage = null // Сначала необходимо присвоить новое значение
    this.avatarImage = avatarImage // Повторно присвоить правильный URI
  }
}
```
В приведенном выше примере реактивное свойство `this.avatarImage` сначала изменяется на `null`, а затем переназначается. Таким образом, значение меняется, что позволяет обойти механизм оптимизации реактивного фреймворка и выполнить обновление изображения.

::: warning
Вы должны использовать этот прием для обновления ресурсов с фиксированным URI, иначе отображаемое содержимое может не измениться. Для перестраховки, если путь к ресурсу, полученному из сети, может повторяться, вам также следует использовать этот прием для обеспечения обновления интерфейса.

Кроме того, необходимо дождаться завершения загрузки изображения или записи файла перед обновлением свойства `src` компонента `image`, иначе интерфейс также не сможет обновиться должным образом.
:::

### `async` <decl type="boolean" get set />

Использует асинхронный способ загрузки ресурсов изображений. Этот режим гарантирует, что загрузка изображения не будет блокировать UI-поток, повышая плавность интерфейса. Однако по сравнению с режимом синхронной загрузки по умолчанию, изображения при асинхронной загрузке не отображают фактическое содержимое, поэтому этот режим подходит не для всех интерфейсов.

Режим асинхронной загрузки подходит для изображений, загружаемых из сети. В отличие от ресурсов изображений, которые автоматически оптимизируются при сборке приложения, сетевые изображения обычно представляют собой универсальные форматы с медленным декодированием, такие как PNG или JPEG. Синхронное декодирование сетевых изображений может сильно тормозить работу, кроме того, в подобных сценариях обычно не требуется немедленное отображение картинки.

Свойство `async` может использоваться вместе со свойством [`noCache`](#nocache), так как последнее также в основном применяется для сетевых изображений:
``` html
<image :src="avatarImage" no-cache async />
```

## Наследуемые свойства

Эти свойства наследуются от [общих свойств](/framework/generic/properties.md) базовых компонентов, однако компонент `image` обрабатывает их особым образом.

### `opacity` <decl type="number" set />

Устанавливает прозрачность изображения. Диапазон значений составляет $[0, 1]$, где $0$ означает полную прозрачность, а $1$ — полную непрозрачность. Значение по умолчанию — $1$.

### `transform` <decl type="string" set />

Устанавливает эффект трансформации изображения, что эквивалентно свойству [`transform`](/framework/generic/styles.md#transform) в CSS.

## Описание CSS

### Неподдерживаемые общие свойства

По сравнению с другими базовыми компонентами, `image` является особенным: он не поддерживает такие общие свойства, как `background-color`, `border` и т. д. Это сильно отличается от стандартов Web. В частности, не поддерживаются следующие CSS-свойства:

- [`background-color`](/framework/generic/styles.md#background-color), [`background-image`](/framework/generic/styles.md#background-image)
- [`border`](/framework/generic/styles.md#border), [`border-top`](/framework/generic/styles.md#border-top), [`border-right`](/framework/generic/styles.md#border-right), [`border-bottom`](/framework/generic/styles.md#border-bottom), [`border-left`](/framework/generic/styles.md#border-left)

Это означает, что вы не можете добавить цвет фона или изображение к компоненту `image`, установив CSS-свойства, а также не можете задать для него стиль границы. Тем не менее, компонент `image` поддерживает свойство [`border-radius`](/framework/generic/styles.md#border-radius).

### Специальные свойства

Компонент `image` поддерживает другие CSS-свойства, применимые к неконтейнерным компонентам, но несколько свойств используются для достижения специальных эффектов.

#### `transform`

Устанавливает трансформацию изображения. Когда это CSS-свойство применяется к `image`, оно работает аналогично [`transform`](/framework/generic/styles.md#transform) для других элементов, но для корректного отображения не требуется устанавливать свойство [`transparent`](/framework/generic/styles.md#transparent).

#### `opacity`

Устанавливает прозрачность изображения, эффект аналогичен свойству [`opacity`](#opacity).

#### `border-radius`

Устанавливает радиус скругления углов изображения. Вы можете использовать это свойство для добавления скругленных углов к изображению, способ использования совпадает с общим [`border-radius`](/framework/generic/styles.md#border-radius). Компонент `image` всегда применяет скругление к четырем углам изображения независимо от того, совпадают ли соотношение сторон изображения и соотношение сторон самого компонента `image`.

#### `object-fit`

Значение свойства `object-fit` для компонента `image` по умолчанию равно `none`, что отличается от стандартов Web (где по умолчанию используется `fill`). По умолчанию изображения не масштабируются автоматически, а отображаются по центру в своем исходном размере; если размер превышает контейнер, они обрезаются. Такой дизайн обусловлен особенностями устройств на базе MCU:
- **Производительность превыше всего**: масштабирование изображений обычно требует дополнительных вычислений, а на некоторых устройствах интерполяционное масштабирование и вовсе реализуется программным путем, что существенно снижает частоту кадров.
- **Однородность качества изображения**: на некоторых устройствах даже пропорциональное уменьшение может привести к заметному размытию или зубчатым краям. Отказ от масштабирования по умолчанию гарантирует, что попиксельный рендеринг останется без искажений.
- **Ограниченная память**: масштабирование по умолчанию может замаскировать проблемы с использованием ресурсов, приведя к непреднамеренной загрузке слишком больших изображений и, как следствие, к пустой трате драгоценного места на хранилище и в оперативной памяти.

Рекомендуется на этапе проектирования предоставлять ресурсы изображений, соответствующие области отображения, и по возможности позволять изображению правильно отображаться в состоянии по умолчанию; настраивать отображение с помощью явного задания `object-fit` (например, `contain`) следует только тогда, когда это действительно необходимо.

## Советы по использованию

### Отображение сетевых изображений

#### Сценарии с аватарами

В этом разделе демонстрируется метод загрузки изображений из сети, который в основном используется в таких случаях, как аватары пользователей, когда у изображения есть фиксированное место хранения локально, но его содержимое может изменяться. Из-за стратегии кэширования среды выполнения Glyphix вам потребуется использовать прием из этого примера, чтобы обеспечить обновление отображаемого содержимого.

``` html
<template>
  <image :src="avatar" no-cache />
</template>
```

``` js
import request from '@system.request'

export default {
  data: {
    avatar: null
  },
  onInit() {
    this.downloadAvatar()
  },
  async downloadAvatar() {
    const saveFile = 'internal://files/avatar.png'
    await request.download({
      url: 'https://example.com/url/to/avatar.png',
      filename: saveFile,
    }).complete
    // Подробнее об этом приеме см. в описании свойства noCache
    this.avatar = null
    this.avatar = saveFile
  }
}
```
