# span

`span` 也是一种文本组件。和 [`p` 组件](p)不同，`span` 组件默认是行内元素并且可以跨行，[`label`](label) 组件和 [`a`](a) 组件也有类似的效果。文本跨行是指元素可以跨越多行进行布局，而不是占据一整个“盒子”。

`span` 组件可以用于实现[富文本排版](/framework/render/rich-text.md#富文本显示)。

<glyphix id="span" :height="36">

``` html
<div>
  Hello Glyphix, this is <span style="color: #f0f">span</span> label!
</div>
```

</glyphix>

# marquee

Компонент `marquee` используется для отображения бегущей строки с текстом и поддерживает вывод только в одну строку. Компонент `marquee` не поддерживает никакие дочерние компоненты, включая `span`.

`marquee` поддерживает общие CSS-свойства, однако по техническим причинам в настоящее время свойство `text-align` может не поддерживаться. Поскольку `marquee` отображает только одну строку текста и прокручивает её при превышении доступной ширины, такие свойства, как `max-lines`, также не работают.

## Свойства

### `text` <decl type="string" get set/>

Устанавливает текстовое содержимое. Используется аналогично свойству [`text`](p.md#text) компонента `p`. Когда длина текста превышает ширину `marquee`, текст начинает автоматически прокручиваться.

# scroll-bar

Компонент полосы прокрутки. Этот компонент отображает полосу прокрутки, когда контента для прокрутки слишком много, позволяя пользователю управлять прокруткой содержимого.

## Свойства

### `value` <decl type="number" set get listen />

Текущее значение полосы прокрутки. Это значение находится в диапазоне между `min` и `max`, значение по умолчанию — $0$.

### `min` <decl type="number" set />

Минимальное значение полосы прокрутки, которое должно быть меньше или равно `max`. Значение по умолчанию — $0$.

### `max` <decl type="number" set />

Максимальное значение полосы прокрутки, которое должно быть больше или равно `min`. Значение по умолчанию — $100$.

### `pagestep` <decl type="number" set />

Шаг прокрутки полосы прокрутки, то есть расстояние прокрутки за один раз. Значение по умолчанию — $10$.

# p

Текстовый компонент. По умолчанию `p` является блочным элементом. В отличие от [`span`](span), компонент `p` не поддерживает перенос текста на другую строку даже при установке в качестве строчного элемента. Если требуется верстка богатого текста (rich text), следует использовать такие компоненты, как `span`.

## Свойства

### `text` <decl type="string" get set/>

Устанавливает текстовое содержимое. Поддерживаются следующие два варианта написания:

``` html
<p text="Hello Glyphix"></p>
<p>Hello Glyphix</p>
```

<glyphix id="p" :height="70" inline>

``` html
<div>
  <p text="Hello Glyphix"></p>
  <p>Hello Glyphix</p>
</div>
```

</glyphix>

### `color` <decl type="string" get set/>

Устанавливает цвет текста. Поддерживаются только шестнадцатеричные коды цветов, такие как `#f00`, `#e8bb80ff` и т. д. Это свойство является быстрым способом изменения встроенного CSS-свойства [`color`](/framework/generic/styles.md#color).

### `lines` <decl type="number" get set/>

Устанавливает максимальное количество строк текста. Текст, превышающий это количество строк, будет обрезаться или заменяться многоточием. Это свойство является быстрым способом изменения встроенного CSS-свойства [`max-lines`](/framework/generic/styles.md#max-lines).

### `text-align` <decl type="string" set/>

Устанавливает выравнивание текста. Поддерживаются такие значения, как `left`, `center`, `right` и т. д. Это свойство является быстрым способом изменения встроенного CSS-свойства [`text-align`](/framework/generic/styles.md#text-align).

### `font-size` <decl type="string" set/>

Устанавливает размер шрифта текста. Поддерживаются значения размера шрифта CSS, такие как `12px`, `1.5em` и т. д. Это свойство является быстрым способом изменения встроенного CSS-свойства [`font-size`](/framework/generic/styles.md#font-size).

### `font-weight` <decl type="number" set/>

Устанавливает толщину (начертание) шрифта текста. В настоящее время поддерживаются только целочисленные значения, такие как `400`, `600` и т. д. Это свойство является быстрым способом изменения встроенного CSS-свойства [`font-weight`](/framework/generic/styles.md#font-weight).

## Советы по использованию

### Управление размерами

Как правило, не следует вручную устанавливать высоту компонента `p`, например:
``` css
p.my-paragraph {
  height: 48px;
  font-size: 32px;
}
```
На первый взгляд это задает для компонента `p` высоту, превышающую размер шрифта, но на практике:
- Для однострочного текста фактическая высота некоторых шрифтов может превышать размер шрифта, и даже при высоте `48px` может происходить вертикальная обрезка.
- Для многострочного текста установка фиксированной высоты приведет к тому, что текст будет обрезан и не сможет отобразиться полностью.

Если вы хотите управлять количеством отображаемых строк текста, следует использовать [`max-lines`](/framework/generic/styles.md#max-lines) и [`text-overflow`](/framework/generic/styles.md#text-overflow) для обрезки и сокращения текста, вместо установки фиксированной высоты.

### Анимация обрезки текста <version-badge since="0.9"/>

Вы можете использовать свойство [`width`](/framework/generic/styles.md#width) в сочетании с модификатором [`transition`](/framework/component/prop-modifier.md#transition-модификатор) для реализации анимации обрезки текста. Например:

``` html
<p :width="state ? 240 : 0"
   width.transition="{duration: 2.0}">
  Hello Glyphix!
</p>
```

В сочетании со стилем `max-lines: 1` это позволяет реализовать анимацию обрезки текста слева направо. Однако у этой анимации есть проблема: когда ширины недостаточно, последний символ будет напрямую отброшен, а не обрезан. Текущий обходной путь заключается в том, чтобы поместить текстовое содержимое в дочерний компонент и применить анимацию ширины к родительскому компоненту:

``` html
<div :width="state ? 240 : 1"
     width.transition="{duration: 2.0}">
  <p style="max-lines: 1">Hello Glyphix!</p>
</div>
```

<glyphix id="p-width-transition" title="Анимация обрезки текста" height="120">

``` html
<div class="container">
  <p class="animated-text"
     :width="state ? 240 : 0"
     width.transition="{duration: 2.0}">
    Hello Glyphix!
  </p>
  <div class="animated-text"
       :width="state ? 240 : 1"
       width.transition="{duration: 2.0}">
    <p>Hello Glyphix!</p>
  </div>
</div>
```

``` js
export default {
  data: {
    state: false
  },
  onReady() {
    setInterval(() => this.state = !this.state, 2500)
  }
}
```

```css
.container {
  display: flex;
  flex-direction: column;
  align-items: center;
  justify-content: center;
  font-size: 1.25rem;
}

.animated-text {
  margin: 4px;
  border: 1px solid #f00;
}

p {
  max-lines: 1;
  text-overflow: clip;
}
````

</glyphix>

Однако при использовании элемента `div` в качестве родительского компонента у анимации возникает проблема: когда ширина равна `0`, размеры макета вычисляются как `(width: 0, height: 0)`, что приводит к тому, что элемент не занимает вертикального пространства и в начале анимации происходит вертикальный скачок. Решением является установка ширины в очень маляемую величину (например, `1px`) вместо `0`, чтобы элемент мог занимать вертикальное пространство, тем самым избегая проблемы со скачками.

# div

`div` 是最基本的容器组件。`div` 支持子组件及布局，但是不支持滚动（内容超出边界会直接裁剪）。如果想要内容滚动，请使用 [scroll](scroll) 组件。

## 注意事项

### 文本显示

`div` 组件不能直接用于显示文本，而是要使用 `p` 等文本组件来显示文本，例如：

```html
<!-- 错误的写法，不会显示文本 -->
<div>text content.</div>
<!-- 正确的写法 -->
<p>text content.</p>
```

不过如果 `div` 内有多个子元素，那么可以将文本作为它的子元素：

```html
<div>
  first element,
  <span style="color: #f0f">second element.</span>
</div>
```

# image-animator

Компонент `image-animator` используется для воспроизведения анимации из набора кадров последовательности изображений. По умолчанию компонент является строчным элементом (inline).

<glyphix id="image-animator-1" height="190" width="360" >

```html
<div class="flex-column">
  <div class="frame-box">
    <image-animator :images="frames" :play="play" :duration="100" />
  </div>
  <div>
    <button on:click="play = 'start'">start</button>
    <button on:click="play = 'pause'">pause</button>
    <button on:click="play = 'stop'">stop</button>
  </div>
</div>
```

```js
export default {
  data: {
    play: "stop",
  },
  frames: Array.from({ length: 60 }, (_, i) => `/assets/planet-${i}.png`),
};
```

```css
.flex-column {
  display: flex;
  flex-direction: column;
  justify-content: space-between;
  align-items: center;
}

.frame-box {
  border: 2px solid lightgray;
  border-radius: 8px;
  padding: 8px;
}

button {
  border-radius: 8px;
  background-color: #dee2e6;
  margin: 8px;
  padding: auto 12px;
}

button:active {
  opacity: 0.5;
}
```

</glyphix>

## Свойства

### `images` <decl type="string[]" set />

Задает набор кадров изображений. Каждый элемент `images` представляет собой путь или URI изображения для данного кадра. Как правило, размеры всех кадров одинаковы.

Поддерживаются изображения в формате PNG или JPEG.

Если последовательность кадров не меняется, рекомендуется объявить ее как нереактивное свойство для экономии памяти:

```js
export default {
  // frames — это нереактивное свойство компонента
  frames: [
    "/assets/sprite-1.png",
    "/assets/sprite-2.png",
    "/assets/sprite-3.png",
  ],
};
```

Преимущество такого подхода заключается в том, что несколько экземпляров компонентов будут использовать один и тот же массив `frames` (реактивные свойства копируются в каждый экземпляр компонента). Добавлять `frames` в объект `data` стоит только в том случае, если последовательность кадров действительно должна быть реактивной.

Если кадры пронумерованы по порядку, вы можете использовать следующий трюк для упрощения создания массива кадров:

```js
export default {
  // 4 кадра, пронумерованных начиная с 0
  frames: Array.from({ length: 4 }, (_, i) => `/assets/sprite-${i}.png`),
  // Или 4 кадра, пронумерованных начиная с 1
  frames: Array.from({ length: 4 }, (_, i) => `/assets/sprite-${i + 1}.png`),
};
```

Передайте массив `frames` в свойство `images` в шаблоне компонента, чтобы указать последовательность кадров и запустить анимацию:

```html
<image-animator :images="frames" play :duration="100" />
```

::: note
Свойство `images` пока не поддерживает структуру `ImageFrame` из QuickApp, поэтому вы не можете использовать определения набора кадров в виде `[{ src: '...' }, ...]`.
:::

### `duration` <decl type="number" get set />

Задает продолжительность воспроизведения каждого кадра в миллисекундах.

### `play` <decl type="'start' | 'pause' | 'stop'" get set listen />

Задает состояние воспроизведения: поддерживает старт, паузу и остановку. Изначально `image-animator` находится в состоянии `stop`, поэтому он автоматически остановится на первом кадре из [`images`](#images).

| Значение  | Описание                                      |
| :-------: | --------------------------------------------- |
| `'start'` | Начать воспроизведение с текущего кадра.      |
| `'pause'` | Поставить воспроизведение на паузу и показать текущий кадр. |
| `'stop'`  | Остановить воспроизведение и показать первый кадр. |

Как показано выше, `play` поддерживает только три значения перечисления: `'start'`, `'pause'` или `'stop'`. Тем не менее, следующий прием можно использовать для автоматического запуска анимации:

```html
<image-animator :images="frames" play :duration="100" />
```

То есть, простое написание свойства `play` без значения эквивалентно синтаксису `:play="true"` ([неявное значение свойства](/framework/component/template.md#неявные-значения-свойств)). Булево значение `true` всегда преобразуется в значение перечисления по умолчанию `'start'`. Этот подход отлично подходит для сценариев, где требуется автоматическое воспроизведение анимации последовательности кадров.

### `iteration` <decl type="number" set />

Задает количество повторов воспроизведения всех кадров в `images`. При достижении лимита повторов компонент автоматически переключится в режим `'pause'`. Значение `0` означает бесконечное воспроизведение.

## Наследуемые свойства

`image-animator` поддерживает такое же поведение [наследуемых свойств](/components/image.md#наследуемые-свойства), как и компонент `image`.

## Описание CSS

`image-animator` имеет такое же [поведение CSS](/components/image.md#описание-css), как и компонент `image`.

# picker

Компонент текстового селектора. Этот компонент отображает набор текста: нажатие на текстовый элемент посередине инициирует событие выбора, а прокрутка позволяет просматривать все текстовые элементы.

::: warning
Функциональность компонента `picker` не проверена и он не поддерживается.
:::

## Свойства

### `range` <decl type="string[]" set />

Все строки из значения свойства `range` будут отображаться в компоненте `picker`. Пользователь может взаимодействовать с компонентом `picker`, прокручивая или выбирая эти строки.

Способ индексации строк в значении свойства `range` см. в описании [свойства `index`](#index).

### `loop` <decl type="boolean" set />

Настраивает, будет ли компонент `picker` отображаться в цикле (то есть бесконечно). Когда это свойство имеет значение `true`, цикличное отображение включено; по умолчанию установлено значение `false`.

### `value` <decl type="string" listen />

Отслеживает текст текущего выбранного элемента. Это прослушивание срабатывает при изменении выбранного элемента в результате прокрутки. Функциональность этого свойства также может быть реализована с помощью метода `on:index="handle(rangeData[$event])"`.

### `index` <decl type="Integer" get set listen />

Индекс выбранного элемента компонента `picker`. Правило индексации следующее: индекс первой строковой позиции в массиве значения [свойства `range`](#range) равен $0$, а индексы остальных строк увеличиваются на единицу по порядку. Установка свойства `index` позволяет задать выбранный элемент компонента `picker`, а также прослушивать изменения этого свойства для отслеживания изменений выбранного элемента, вызванных прокруткой.

### `scroll` <decl type="{ x: number y: number }" get set listen />

С помощью свойства `scroll` можно отслеживать операции прокрутки, а также программно управлять отображением эффекта прокрутки в компоненте `picker`. Подобно компонентам выровненных списков, операция `scroll` для `picker` также выравнивается по ближайшему элементу.

Поскольку компонент `picker` поддерживает только вертикальный режим, поле `x` значения свойства `scroll` всегда равно `0`.

### `scrolled` <decl type="boolean" read listen />

С помощью свойства `scrolled` можно отслеживать, находится ли `picker` в состоянии прокрутки. Значение свойства, вызывающее событие, равное `true`, означает, что `picker` прокручивается в данный момент, в противном случае `picker` прекратил прокрутку.

Событие `scrolled` вызывается как операциями прокрутки, инициированными пользователем (касанием), так и программной прокруткой через свойство `scroll`. Когда `picker` останавливается после прокрутки, значение параметра события `scrolled` становится `false`.

### `damping` <decl type="number" set />

Устанавливает коэффициент затухания для анимации прокрутки `picker`. Допустимый диапазон значений составляет $[0.1, 50]$ (неподдерживаемые значения будут автоматически скорректированы до нижней или верхней границы), значение по умолчанию — $1.5$. Больший коэффициент затухания заставляет анимацию останавливаться быстрее, а значение по умолчанию создает эффект инерции на более длинные дистанции и с большей продолжительностью.

Коэффициент затухания должен быть задан как константа, его не следует изменять динамически; изменение коэффициента затухания не влияет на анимацию при возврате в исходное положение (отскоке).

# drawer

Компонент выдвижной панели (drawer), скрытый по умолчанию, содержимое которого можно отобразить с помощью свайпа.
drawer — это базовый компонент выдвижной панели. drawer поддерживает дочерние компоненты и верстку, внутри drawer можно настроить 4 компонента `drawer-navigation` для отображения панелей с четырех сторон: сверху, снизу, слева и справа.

Скорость прокрутки компонента [`drawer`](drawer) зависит от скорости движения жеста: чем быстрее движение жеста, тем выше скорость прокрутки компонента.

### Пример

В следующем примере продемонстрирована работа компонента drawer.

<glyphix id="components-drawer" height="360" width="360" >

``` html
 <drawer class="drop-down">
      <drawer-navigation direction="down" class="drop-down1">
        <p>dawn panel</p>
      </drawer-navigation>
      <drawer-navigation direction="up" class="drop-down1">
        <p>up panel</p>
      </drawer-navigation>
       <drawer-navigation direction="left" class="drop-down1">
        <p>left panel</p>
      </drawer-navigation>
       <drawer-navigation direction="right" class="drop-down1">
        <p>right panel</p>
      </drawer-navigation>
</drawer>
```
``` css
.drop-down {
    background-color: pink;
  }
.drop-down1 {
    background-color: blue;
  }
p {
  background-color: lightgreen;
  text-align: center;
  margin: 10px;
}
```
</glyphix>

# switch

Компонент переключателя, по умолчанию является строчным элементом (inline). Используется для отображения двух состояний: включено/выключено, и позволяет пользователю переключаться между ними. Функционал `switch` аналогичен `checkbox`, однако имеет другое взаимодействие и назначение, выражая соответственно переключение и выбор (флажок).

<glyphix id="components-switch" height="30">

``` html
<div>
  <switch ::value="enabled" />
  <span>switch state: {{ enabled ? 'on' : 'off' }}</span>
</div>
```

``` js
export default {
  data: {
    enabled: false
  }
}
```
</glyphix>

::: note
Внешний вид компонента `switch` обычно соответствует показанному в примере, но может отличаться в зависимости от устройства. Стоит особенно отметить, что ширина `switch` на разных устройствах может варьироваться, поэтому разработчикам следует предусматривать подходящие отступы в макете.
:::

## Свойства (Attributes)

### `value` <decl type="boolean" set get listen/>

Представляет состояние `switch`. Если значение равно `true`, компонент `switch` находится в активном (включенном) состоянии, в противном случае — в выключенном. Если свойство `value` не задано, по умолчанию компонент `switch` находится в выключенном состоянии.

### `checked` <decl type="boolean" set get/>

Это совместимое свойство Quick App, однако настоятельно рекомендуется использовать [`value`](#value).

### `change` <decl type="{ checked: boolean }" get listen/>

Это совместимое свойство Quick App, однако настоятельно рекомендуется использовать [`value`](#value).

## Поведение CSS

Общий стиль компонента `switch` определяется системой и не контролируется разработчиком, подобно различиям в стилях между [Fluent 2](https://fluent2.microsoft.design/components/web/react/switch/usage) и [Material 3](https://m3.material.io/components/switch/overview). Glyphix позволяет настраивать цвет `switch` с помощью CSS, а также изменять его размер.

### CSS Свойства

#### `color`

Задает цвет ползунка компонента `switch`. В отличие от обычного CSS [`color`](/framework/generic/styles.md#color), свойство `color` для `switch` не наследуется, поэтому вы должны определять его непосредственно для текущего компонента `switch`.

<glyphix id="components-switch-color" height="36" title="siwtch 滑块颜色">

``` html
<div>
  red color: <switch class="red"/>,
  not inherited: <switch/>
</div>
```

``` css
div {
  color: red; /* Обратите внимание, что switch не наследует свойство color */
}

.red {
  color: red; /* Цвет color должен быть задан в стилях компонента switch */
}
```
</glyphix>

#### `background-color`

Управляет цветом фона компонента `switch`. Подробнее см. в документации по псевдоклассу [`active`](#active). 

#### `font-size`

Размер `switch` можно регулировать с помощью CSS-свойства [`font-size`](/framework/generic/styles.md#font-size), чтобы он гармонично сочетался с размером строчного (inline) текста. В следующем примере показана зависимость между `font-size` и размером `switch`:

<glyphix id="components-switch-size" height="100" title="font-size 与 siwtch 大小">

``` html
<div>
  <p class="title">
    title text: <switch/> (1.25rem)
  </p>
  <p>
    content text: <switch/> (1rem)
  </p>
</div>
```

``` css
div {
  line-height: 1.8rem;
}

.title {
  color: #415a77; /* Обратите внимание, что switch не наследует свойство color */
  font-size: 1.25rem;
}
```
</glyphix>

::: warning
Отображаемый размер `switch` не контролируется такими свойствами, как `width` и `height`, а всегда определяется свойством `font-size`. Поэтому не задавайте свойства размеров, такие как `width`, вручную, чтобы избежать некорректного отображения.
:::

### Псевдоклассы CSS

#### `active`

Псевдокласс `active` используется для определения стиля `switch` в активном (включенном) состоянии. Как показано в примере ниже, он обычно настраивается вместе с правилами обычного стиля:

<glyphix id="components-switch-colors" height="36" title="siwtch 滑块颜色设置">

``` html
<div>
  color switch: <switch/>
</div>
```

``` css
/* Стиль switch в выключенном состоянии */
switch {
  color: #415a77;
  background-color: #bde0fe;
}

/* Стиль switch в во включенном состоянии */
switch:active {
  color: #fefae0;
  background-color: #ffafcc;
}
```
</glyphix>

В этом примере цвета при переключении `switch` управляются с помощью CSS-свойств `color` и `background-color`. Компонент `switch` реагирует только на настройки этих двух CSS-свойств даже в состоянии активации псевдокласса `active`.

::: tip
Пожалуйста, определяйте свойства `color` и `background-color` как для обычного состояния, так и для состояния `active`, иначе при переключении `switch` не будет плавной смены цветов.
:::

# image

Компонент изображения используется для отображения элементов изображений, по умолчанию выравнивается по центру. Компонент `image` по умолчанию является строчным элементом.

## Свойства

### `src` <decl type="string" get set />

Задает [URI](/framework/application/resource.md) изображения. Для ресурсов изображений внутри пакета приложения поддерживаются как относительные, так и абсолютные пути. Компонент `image` поддерживает универсальные форматы изображений PNG и JPEG.

::: tip
Компонент `image` поддерживает только локальные ресурсы изображений, в отличие от элемента `img` в Web, который может напрямую отображать сетевые изображения. Подробнее см. в разделе [Как отображать сетевые изображения в Glyphix](#显示网络图片).
:::

### `noCache` <decl type="boolean" get set />

Определяет, нужно ли кэшировать изображение. По умолчанию кэширование используется для оптимизации скорости загрузки. При включении свойства `noCache` компонент `image` не использует кэш, и в этом случае при изменении свойства [`src`](#src) изображение всегда будет перезагружаться из файла.

Кэширование изображений — это технология, оптимизирующая скорость загрузки и снижающая потребление памяти. Если в системе уже загружено изображение с тем же URI, компонент `image` с включенным кэшем использует этот ресурс напрямую. Однако файлы изображений, загружаемые из сети с фиксированными именами и потенциально изменяющимся содержимым (например, аватар пользователя `internal://cache/avatar.png`), обычно требуют включения свойства `noCache` для корректной работы. 

Даже при включенном свойстве `noCache` компонент `image` по-прежнему не отслеживает изменения содержимого файла изображения, поэтому в таких случаях необходимо вручную изменять свойство [`src`](#src). Учитывая, что реактивный фреймворк фильтрует одинаковые операции присваивания, вы должны использовать следующий прием:
``` html
<!-- Предполагается, что это изображение требует обновления отображения, свойство no-cache является обязательным. -->
<image :src="avatarImage" no-cache />
```

``` js
const avatarImage = 'internal://cache/avatar.png' // Предполагается, что это изображение загружено из интернета

export default {
  data: {
    avatarImage: avatarImage
  },
  // Вызывайте этот метод после завершения загрузки аватара для обновления интерфейса
  onAvatarDownloaded() {
    this.avatarImage = null // Сначала необходимо присвоить новое значение
    this.avatarImage = avatarImage // Повторно присвоить правильный URI
  }
}
```
В приведенном выше примере реактивное свойство `this.avatarImage` сначала изменяется на `null`, а затем переназначается. Таким образом, значение изменяется, что позволяет обойти механизм оптимизации реактивного фреймворка и обновить изображение.


::: warning
Этот прием обязателен для обновления ресурсов с фиксированным URI, в противном случае отображаемое содержимое может не измениться. Во избежание проблем, если путь к ресурсу, полученному из сети, может повторяться, этот прием также необходимо использовать для обеспечения обновления интерфейса.

Кроме того, необходимо дождаться завершения загрузки изображения или записи файла перед обновлением свойства `src` компонента `image`, иначе интерфейс также не сможет обновиться должным образом.
:::

### `async` <decl type="boolean" get set />

Загрузка ресурсов изображений асинхронным способом. Такой режим гарантирует, что загрузка изображений не блокирует UI-поток, повышая плавность интерфейса. Однако по сравнению с режимом синхронной загрузки по умолчанию, изображения при асинхронной загрузке не отображают фактическое содержимое сразу, поэтому подход применим не для всех интерфейсов.

Режим асинхронной загрузки подходит для изображений, загружаемых из сети. В отличие от ресурсов изображений, которые автоматически оптимизируются при сборке приложения, сетевые изображения обычно имеют формат с медленным декодированием, такой как PNG или JPEG. Синхронное декодирование сетевых изображений может вызывать сильные задержки (фризы), к тому же в таких сценариях обычно не требуется немедленное отображение картинки.

Атрибут `async` может использоваться совместно со свойством [`noCache`](#nocache), так как последнее также в основном применяется для сетевых изображений:
``` html
<image :src="avatarImage" no-cache async />
```

## Наследуемые свойства

Эти свойства наследуются от [общих свойств](/framework/generic/properties.md) базовых компонентов, однако компонент `image` обрабатывает их особым образом.

### `opacity` <decl type="number" set />

Задает прозрачность изображения. Диапазон значений: $[0, 1]$, где $0$ означает полную прозрачность, а $1$ — полную непрозрачность. Значение по умолчанию: $1$.

### `transform` <decl type="string" set />

Задает эффект трансформации изображения, эквивалентно свойству [`transform`](/framework/generic/styles.md#transform) в CSS.

## Описание CSS

### Неподдерживаемые общие свойства

По сравнению с другими базовыми компонентами, `image` является особым: он не поддерживает такие общие свойства, как `background-color`, `border` и т.д. Это сильно отличается от веб-стандартов. В частности, следующие CSS-свойства не поддерживаются:

- [`background-color`](/framework/generic/styles.md#background-color), [`background-image`](/framework/generic/styles.md#background-image)
- [`border`](/framework/generic/styles.md#border), [`border-top`](/framework/generic/styles.md#border-top), [`border-right`](/framework/generic/styles.md#border-right), [`border-bottom`](/framework/generic/styles.md#border-bottom), [`border-left`](/framework/generic/styles.md#border-left)

Это означает, что вы не можете добавить цвет фона или изображение к компоненту `image` с помощью CSS-свойств, а также установить для него стиль рамки. Тем не менее, компонент `image` поддерживает свойство [`border-radius`](/framework/generic/styles.md#border-radius).

### Специальные свойства

Компонент `image` поддерживает другие CSS-свойства, применимые к неконтейнерным компонентам, но несколько свойств используются для достижения особых эффектов.

#### `transform`

Задает трансформацию изображения. При применении этого CSS-свойства к `image` оно работает аналогично [`transform`](/framework/generic/styles.md#transform) для других элементов, но для корректного отображения не требуется устанавливать свойство [`transparent`](/framework/generic/styles.md#transparent).

#### `opacity`

Задает прозрачность изображения, эффект аналогичен свойству [`opacity`](#opacity).

#### `border-radius`

Задает радиус скругления углов изображения. Это свойство можно использовать для скругления углов изображения, способ применения совпадает с общим [`border-radius`](/framework/generic/styles.md#border-radius). Компонент `image` всегда применяет скругление к четырем углам изображения, независимо от того, совпадают ли пропорции изображения с пропорциями самого компонента `image`.

#### `object-fit`

Значение свойства `object-fit` для компонента `image` по умолчанию равно `none`, что отличается от веб-стандартов (где по умолчанию используется `fill`). По умолчанию изображение не масштабируется автоматически, а отображается по центру в исходном размере. Если размер превышает контейнер, оно обрезается. Такой дизайн обусловлен особенностями устройств с микроконтроллерами (MCU):
- **Приоритет производительности**: масштабирование изображений обычно требует дополнительных вычислений, а на некоторых устройствах интерполяционное масштабирование реализуется даже программным способом, что существенно снижает частоту кадров (FPS).
- **Консистентность качества изображения**: на некоторых устройствах даже пропорциональное уменьшение может приводить к заметному размытию или зубчатым краям. Отказ от масштабирования по умолчанию гарантирует пиксель-перфектное отображение без искажений.
- **Ограничения памяти**: масштабирование по умолчанию может скрывать проблемы с использованием ресурсов, приводя к непреднамеренной загрузке слишком больших изображений и, как следствие, к расточительному расходованию драгоценного места в хранилище и оперативной памяти.

Рекомендуется на этапе проектирования предоставлять ресурсы изображений, соответствующие области отображения, и по возможности делать так, чтобы изображение корректно отображалось в состоянии по умолчанию. Настраивать визуальное оформление с помощью явного задания `object-fit` (например, `contain`) следует только при реальной необходимости.

## Советы по использованию

### Отображение сетевых изображений

#### Сценарии с аватарами

В этом разделе описывается метод загрузки изображений из сети, который в основном используется в таких сценариях, как аватары пользователей: когда изображение имеет фиксированное место хранения локально, но его содержимое может изменяться. Из-за стратегии кэширования среды выполнения Glyphix вам потребуется использовать прием из данного примера для обеспечения обновления отображаемого контента.

``` html
<template>
  <image :src="avatar" no-cache />
</template>
```

``` js
import request from '@system.request'

export default {
  data: {
    avatar: null
  },
  onInit() {
    this.downloadAvatar()
  },
  async downloadAvatar() {
    const saveFile = 'internal://files/avatar.png'
    await request.download({
      url: 'https://example.com/url/to/avatar.png',
      filename: saveFile,
    }).complete
    // Подробнее об этом приеме см. в описании свойства noCache
    this.avatar = null
    this.avatar = saveFile
  }
}
```

# barcode

组件 `barcode` 用于显示 [Code 128](https://en.wikipedia.org/wiki/Code_128) 条形码。`barcode` 组件可以显示任意 ASCII 字符串，适合用于显示商品条形码、支付码等信息。

在流式布局中，`barcode` 组件默认为块级元素（`block`），会单独占据一行显示。

## 属性

### `value` <decl type="string" get set />

设置条形码要显示的内容。支持任意 ASCII 字符串。

## CSS 说明

要想让条形码容易被扫描，应正确设置 `barcode` 组件的 CSS 属性，这包括：
- `color`：条形码线条的颜色，一般设置为黑色（`black` 或者 `#000`）；
- `background-color`：条形码的背景色，通常应为白色（`white` 或者 `#fff`）；
- `padding` / `margin`：充足的内外边距可以避免条形码与其他元素混淆，提高扫描识别率；
- `width` / `height`：条形码的尺寸必须足够大，以便于拍摄。

默认情况下，条形码组件的每个条码宽度为 $2\rm px$，高度为 $32\rm px$，这在手表等小屏幕设备上可能过小，建议开发者根据需要手动设置条形码组件的 `width` / `height` 属性，并在实际设备上进行测试。

以下示例展示了条形码组件的使用方法。请注意，CSS 中为 `barcode` 组件设置了各种边距，这是为了确保条形码与其他界面元素之间有足够的间距，以免干扰扫描。

<glyphix id="barcode-1" :height="150" :width="350">

``` html
<div>
  <barcode :value="text"/>
  <p>{{ text }}</p>
</div>
```

``` js
export default {
  data: {
    text: '9787111407010'
  }
}
```

``` css
div {
  background-color: black;
  padding: 8px;
}

barcode {
  margin: 8px;
  padding: 8px;
  color: black; /* 将条形码前景色设置为黑色 */
  background-color: white; /* 将条形码背景色设置为白色 */
  border-radius: 16px;
  height: 80px;
}

p {
  color: white;
  font-size: 0.75rem;
  text-align: center;
}
```

</glyphix>

::: tip
应始终显式设置**高对比度**的条形码组件码点颜色（`color`）和背景（`background-color`）样式，以避免因设备默认样式主题和继承的样式属性偏差而导致识别率下降。

同时，请设置足够大的内边距（`padding`），以确保易于扫描识别。
:::

# slider

Ползунок (slider), по умолчанию является блочным элементом.

## Свойства

### `value` <decl type="number" get set listen />

Текущее значение, значение по умолчанию: $10$.

При установке свойства `value` изменяется текущее значение компонента. Вы можете отслеживать изменения текущего значения с помощью директивы `on`, которая срабатывает при каждом изменении значения.

### `min` <decl type="number" set />

Минимальное значение, значение по умолчанию: $0$.

### `max` <decl type="number" set />

Максимальное значение, значение по умолчанию: $100$.

### `vertical` <decl type="boolean" set />

Если значение свойства `vertical` равно `true`, компонент `slider` отображается вертикально, в противном случае — горизонтально. Значение по умолчанию: `false`.

## Спецификация CSS

Разработчики могут настраивать внешний вид компонента `slider` с помощью CSS.

### Расчет размеров

Ширина и высота `slider` по умолчанию равны размеру шрифта элемента, который задается свойством [`font-size`](/framework/generic/styles.md#font-size) (или может наследоваться). Вы можете задать размеры `progress` самостоятельно с помощью свойств [`width`](/framework/generic/styles.md#width) и [`height`](/framework/generic/styles.md#height).

### CSS-свойства

Следующие CSS-свойства могут быть особенно полезны:
- [`background-color`](/framework/generic/styles.md#background-color) управляет цветом фона `slider`;
- [`color`](/framework/generic/styles.md#color) управляет цветом индикатора выполнения (прогресс-бара) `slider`;
- [`border-radius`](/framework/generic/styles.md#border-radius) позволяет сделать углы `slider` скругленными, например, значение `50%` создаст полукруглые края.

Другие CSS-свойства также могут быть полезны, например, для задания стиля рамки можно использовать свойство [`border`](/framework/generic/styles.md#border).

### Псевдоэлементы CSS

#### `value`

Этот псевдоэлемент позволяет отдельно задавать стили для полосы прогресса `slider`, исключая фоновую часть. Например, можно задать разные радиусы скругления для фона полосы прокрутки и для части индикатора выполнения, чтобы получить эффект, при котором внешняя рамка имеет скругленные концы, а полоса прогресса — прямые.

``` css
slider {
  border-radius: 50%; /* Скругление фона полосы прокрутки */
}

slider::value {
  border-radius: 0; /* Индикатор прогресса без скругления */
}
```

#### `thumb` <experimental/>

Псевдоэлемент `thumb` используется для задания стилей ползунка (бегунка) `slider`. По умолчанию `slider` не содержит бегунка; чтобы он отображался, необходимо явно указать ширину и высоту элемента `thumb`:
``` css
slider::thumb {
  width: 150%;
  height: 150%;
  border-radius: 50%;
}
```
Значения `width` и `height` в процентах рассчитываются относительно размеров самого элемента. Ширина и высота бегунка для горизонтального `slider` рассчитываются в процентах от CSS-свойства `height` элемента, а для вертикального `slider` — в процентах от CSS-свойства `width`. Например, если CSS элемента выглядит так:
``` css
slider {
  width: 200px;
  height: 24px;
}
```
То в этом случае ширина и высота бегунка для `slider::thumb` составят $24\rm{px} \times 150\% = 36\rm{px}$. Процентный радиус скругления бегунка рассчитывается на основе его собственных размеров. В данном примере расчетное значение радиуса скругления псевдоэлемента `thumb` со значением `50%` составит $36\rm{px} \times 50\% = 18\rm{px}$.

Псевдоэлемент `thumb` поддерживает CSS-свойство `border`, однако граница не будет выходить за пределы размеров самого псевдоэлемента `thumb`.

# textarea

`textarea` <experimental/><version-badge since="0.9" /> — это многострочный компонент ввода текста, который по умолчанию отображается как блочный элемент. В отличие от аналогичных GUI-элементов на телефонах или ПК, `textarea` в настоящее время не реагирует на устройства ввода, такие как клавиатура, и не вызывает интерфейс метода ввода (системную клавиатуру), поэтому вам необходимо редактировать его содержимое вручную. `textarea` поддерживает управление курсором с помощью сенсорных жестов (например, нажатие и прокрутка) и предоставляет методы для перемещения курсора вверх, вниз, влево и вправо.

`textarea` подходит в качестве базового компонента для ввода многострочного текста, при этом мягкую клавиатуру и управление курсором нужно реализовать самостоятельно в соответствии с вашими требованиями. Подробности см. в [примере](#基本示例).

::: important Совместимость
`textarea` является экспериментальным расширенным компонентом, который в настоящее время доступен только в Glyphix версии 0.9 и выше, и поддерживается только на некоторых устройствах.
:::

## Свойства

### `text` <decl type="string" get set listen />

Свойство `text` представляет собой строку, которая является текущим редактируемым текстом в `textarea`. Чтение или прослушивание этого значения позволяет получить введенный текст, также это свойство можно устанавливать.

Обычно `text` двунаправленно связывается с определенным реактивным свойством, либо текст можно задать через внутреннее содержимое элемента, например:

```html
<textarea ::text="inputText" />
```

или

```html
<textarea @text="onTextChanged">{{ inputText }}</textarea>
```

:::tip
Свойство `text` компонента `textarea` аналогично по функционалу свойству [`value`](text-field.md#value) компонента [`text-field`](text-field.md).
:::

### `placeholder` <decl type="string" set get />

Когда содержимое `textarea` пусто, вы можете использовать `placeholder`, чтобы предоставить пользователю короткую подсказку, например, фразу вроде «Введите текст».

`placeholder` автоматически отображается, когда вводимый текст пуст, поэтому обычно требуется только фиксированное содержимое, например:

```html
<textarea ::text="inputText" placeholder="type here" />
```

### `insert` <decl type="(text: string): void" method />

Вставляет фрагмент текста с содержимым `text` в позицию курсора, после чего курсор автоматически смещается за вставленный текст. Вызов этой функции инициирует событие прослушивания `text`.

### `backspace` <decl type="(): void" method />

Удаляет символ в позиции курсора, при этом курсор автоматически смещается вперед. Вызов этой функции инициирует событие прослушивания `text`.

### `moveCaret` <decl type="(direction: 'up' | 'down' | 'left' | 'right'): void" method />

Перемещает курсор на одну позицию в указанном направлении. Параметр `direction` может принимать значения `'up'`, `'down'`, `'left'`, `'right'`, которые соответствуют четырем направлениям: вверх, вниз, влево и вправо.

# button

Компонент кнопки, по умолчанию является строчным элементом. При касании компонента генерируются соответствующие события.

## Свойства

### `checkable`  <decl type="boolean" set />

Если установлено значение `true`, это означает, что одно касание вызывает изменение состояния только один раз, а именно: переход из состояния нажатия в отпущенное состояние или из отпущенного в нажатое. При этом значение прослушивателя состояния `press` равно `true` для нажатия и `false` для отпускания.

### `toggleable` <decl type="boolean" set />

Если установлено значение `true`, это означает, что значение прослушивателя `press` может изменяться: при нажатии оно равно `true`, а при отпускании — `false`.

### `press` <decl type="boolean" get set listen />

Установка свойства `press` позволяет изменять состояние компонента. Также можно прослушивать состояние компонента с помощью директивы `on`. По умолчанию после завершения одного касания параметр обратного вызова равен `true`. Вы можете использовать свойства `checkable` и `toggleable` для получения различных значений и состояний прослушивания.

## Ограничения функциональности

### Сбой события `click`

Когда компонент `button` не используется, для прослушивания событий нажатия любых нативных компонентов обычно применяется свойство [`click`](/framework/generic/properties.md#click). Однако этот подход обычно не применим к `button`. Например, следующий код:
```html
<button on:click="onOuterClick">
  <p on:click="onInnerClick">inner</p>
  outer button
</button>
```

```js
export default {
  onOuterClick() {
    console.log('outer click');
  },
  onInnerClick(event) {
    // Останавливаем всплытие события, чтобы внешняя кнопка не реагировала на клик
    event.stopPropagation();
    console.log('inner click');
  }
}
```

Вы можете ожидать, что при нажатии на текст `"inner"` сработает метод `onInnerClick` и предотвратится вызов `onOuterClick`. Но вы обнаружите, что это не так (лучше открыть консоль браузера для просмотра логов): метод `onInnerClick` не сработает вообще, и на клик отреагирует только внешний компонент `button`, а именно:
- При клике на текст `inner` лог `inner click` не появится, будет только лог `outer click`;
- Сработает интерактив нажатия `button` (уменьшится прозрачность).

Это работает так же, как клик по внешнему тексту `outer text`. Причина этого заключается в том, что компонент `button` имеет приоритет при обработке всего жизненного цикла жеста нажатия (от нажатия до отпускания), в то время как событие `click` срабатывает в момент отпускания. Это означает, что независимо от того, останавливает ли обработчик события `click` внутреннего элемента всплытие, такое поведение изменить нельзя.

#### Решение

Чтобы решить эту проблему, следует прослушивать событие `press` внешней кнопки `button` и событие `touchstart` внутреннего элемента:

```html
<button on:press="onOuterClick">
  <p on:touchstart="onInnerClick">inner</p>
  outer button
</button>
```

```js
export default {
```

#### Другие моменты срабатывания

Ограничение этого метода заключается в том, что событие `touchstart` внутреннего элемента срабатывает в момент нажатия. Вместо него вы также можете использовать событие `touchend` для срабатывания, но при этом необходимо сохранить функцию остановки всплытия в событии `touchstart`. Это гарантирует, что событие `press` внешней кнопки не сработает в момент нажатия.

```html
<button on:press="onOuterClick">
  <p on:touchstart="$event.stopPropagation()" on:touchend="onInnerClick">inner</p>
  outer button
</button>
```

```js
export default {

    console.log('outer click');
  },
  onInnerClick(event) {
    // Здесь не нужно останавливать всплытие, так как оно уже остановлено в touchstart
    console.log('inner click');
  }
}
```

# progress-arc

Компонент `progress-arc` используется для отображения кругового индикатора выполнения (прогресс-бара) и по умолчанию является блочным элементом.

## Свойства

### `max` <decl type="number" set />

Максимальное значение прогресса. Значение [`value`](#value) не может быть больше него.

### `min` <decl type="number" get setet />

Минимальное значение прогресса. Значение [`value`](#value) не может быть меньше него.

### `value` <decl type="number" get set listen />

Установка значения прогресса. Отображаемая доля прогресса зависит от соотношения значения свойства `value` в диапазоне от `min` до `max`, при этом коэффициент отображения ограничивается в пределах от $0\% \text{ до } 100\%$. Значение `value` является целым числом; если задано число с плавающей точкой, будет взята только его целая часть.

### `busy` <decl type="boolean" get set />

Устанавливает, находится ли компонент `progress-arc` в состоянии занятости (загрузки). В этом состоянии отображается анимация загрузки вместо значения свойства `value`. В следующем примере показано, как использовать круговой индикатор выполнения для симуляции анимации загрузки:

<glyphix id="components-progress-arc-busy" height="100" width="300" title="Симуляция анимации загрузки">

``` html
<progress-arc busy :startAngle="0" :stopAngle="360" />
```

</glyphix>

В этом примере начальный и конечный углы индикатора выполнения отличаются на $360^\circ$. В таком случае свойство `busy` позволяет отобразить типичный эффект анимации загрузки.

::: tip
Если индикатор выполнения имеет форму кольца, всегда будет отображаться фиксированный эффект анимации загрузки, при этом начальный и конечный углы не имеют значения.
:::

### `startAngle` <decl type="number" get set />

Начальный угол дугового индикатора выполнения, значение по умолчанию — $135$. Более подробную информацию см. в разделе [Настройка углов](#настройка-углов).

### `stopAngle` <decl type="number" get set />

Конечный угол дугового индикатора выполнения, значение по умолчанию — $405$. Более подробную информацию см. в разделе [Настройка углов](#настройка-углов).

## Инструкции по использованию

### Настройка углов

В отличие от линейного компонента [`progress`](progress.md), для корректного отображения дугового или кругового индикатора выполнения необходимо правильно настроить свойства `startAngle` и `stopAngle`. Оба эти свойства используют градусы в качестве единицы измерения. В системе координат экрана $0^\circ$ указывает в горизонтальном направлении вправо (т.е. на позицию «3 часа» на циферблате часов) и увеличивается по часовой стрелке, уменьшаясь против часовой стрелки.

Отображение `progress-arc` выполняет линейную интерполяцию диапазона углов на основе пропорции `value` в диапазоне $[\texttt{min}, \texttt{max}]$. В частности, пользователь увидит, что подсветка прогресса начинается с `startAngle` и заканчивается на `valueAngle`:

$$
\begin{aligned}
  k &= \frac{\texttt{value} - \texttt{min}}{\texttt{max}-\texttt{min}}\\
  \texttt{valueAngle} &= (1-k)\texttt{startAngle} + k\cdot\texttt{stopAngle}
\end{aligned}
$$

Поэтому для отображения полного кольцевого индикатора выполнения необходимо, чтобы начальный и конечный углы отличались на $360^\circ$, даже если визуально эти углы совпадают. Кроме того, начальный угол может быть больше конечного, что инвертирует направление прогресса.

В следующем примере показаны реальные эффекты различных конфигураций углов. Обратите внимание, что второй пример демонстрирует прием обратного отображения прогресса.

## Спецификация CSS

### Расчет размеров

Отображаемый размер `progress-arc` определяется его свойствами `width` и `height`. Компонент `progress-arc` заполняет более короткую ось, а центром дугового индикатора выполнения является центр элемента. По умолчанию размер `progress-arc` может быть близок к размеру одного символа, что может привести к очень странному отображению. Поэтому обычно требуется явно указывать ширину и высоту в CSS или использовать другие разумные стратегии компоновки.

::: tip
Лучше всего задать разумную ширину и высоту для компонента `progress-arc`, иначе он может оказаться неразличимым. Как минимум, следует установить CSS-свойство `width`, и стратегия компоновки компонента автоматически применит соотношение сторон $1:1$.
:::

### Свойства CSS

Внешний вид компонента `progress-arc` можно настроить с помощью CSS.

#### `stroke-width`

Это свойство определяет ширину контура дуги компонента `progress-arc`. Тип значения — [длина](/framework/render/style-and-layout.md#长度), единицы в процентах не поддерживаются.

::: tip
Если вы хотите, чтобы толщина линии рисования компонента `progress-arc` была пропорциональна размеру шрифта, рекомендуется использовать единицы длины [`rem`](/framework/application/font-config.md#rem-字号单位), например `0.15rem`.
:::

#### `color`

Устанавливает цвет выделенной полосы прогресса `progress-arc`. По умолчанию используется цвет системной темы.

#### `background-color`

Устанавливает цвет фоновой полосы прогресса `progress-arc`. По умолчанию цвет настраивается в соответствии с системной темой.

# checkbox

Элемент `checkbox` (флажок) в активированном состоянии отображает квадрат с галочкой, что означает выбор пункта.

``` html
<div>

```

``` js
export default {
  data: {
    checked: true
  }

```
</glyphix>

::: note
Обычно `checkbox` представляет собой квадрат, в котором можно поставить галочку, однако точный внешний вид зависит от устройства. На данный момент разработчики не могут изменять цвет и другие стили `checkbox` с помощью CSS.
:::

## Свойства

### `checked` <decl type="boolean" get set listen />

Это свойство указывает, выбран ли данный флажок. Установка свойства `checked` позволяет переключать состояние выбора флажка: когда значение равно `true`, он отображается как выбранный. Также можно управлять отдельным флажком с помощью двустороннего связывания:
``` html
<checkbox model:checked="yes" />
```

В предыдущем примере из этой статьи показано использование такого связывания. Обратите внимание, что следует привязываться не к свойству [`value`](#value), а к `checked`.

Событие срабатывает только тогда, когда пользователь нажимает на флажок, что приводит к изменению свойства `checked`.

::: warning
Не устанавливайте свойство `checked` в [группе флажков](#group), чтобы избежать путаницы.
:::

### `value` <decl type="any" get set />

Значение JavaScript, идентифицирующее флажок, обычно строка или число. Это значение не отображается визуально, но может использоваться в [групповых операциях](#group).

### `group` <decl type="any[]" get set listen />

Если у вас есть несколько связанных компонентов `checkbox`, вы можете объединить свойства `group` и `value`; флажки внутри одной группы образуют массив выбранных значений. Пожалуйста, обратите внимание на следующий пример:

<glyphix id="checkbox-group" :height="65" title="复选框组" >

``` html
<div>
  <p>selected colors: {{selected.join(', ')}}</p>
  <div>
    <checkbox id="red" value="red" model:group="selected" />
    <label target="red">red</label>
    <checkbox id="blue" value="blue" model:group="selected" />
    <label target="blue">blue</label>
    <checkbox id="yellow" value="yellow" model:group="selected" />
    <label target="yellow">yellow</label>
  </div>
</div>
```

``` js
export default {
  data: {
    selected: ['yellow']
  }
}
```

``` css
label {
  margin-right: 0.5rem;
}
```

</glyphix>

Используя `model:group` или `::group` для двустороннего связывания свойства `group` с реактивным массивом (`selected` в примере), можно добиться следующего:
- После того как пользователь взаимодействует с каким-либо флажком в группе, значение реактивного массива обновляется;
- Изменения элементов реактивного массива отражаются на внешнем виде `checkbox`.

Как показано в примере выше: в начальном состоянии выбор флажков в группе определяется значением свойства `group`. В частности, для такого флажка:
``` html
<checkbox value="red" model:group="selected" />
```
Поскольку свойство `value` задает значение `"red"`, когда значение реактивного свойства `selected` содержит `"red"` (например, `["red"]`), этот флажок будет выбран. Повторный клик пользователя по этому флажку переведет его в невыбранное состояние, а из массива `selected` будет удален элемент `"red"`.

::: tip
Если вы не хотите группировать флажки, вы можете использовать свойство [`checked`](#checked) для управления каждым по отдельности. Но не используйте `checked` и `group` одновременно, Glyphix не рассчитан на такой сценарий.
:::

### `indeterminate` <decl type="boolean" get set />

Свойство `indeterminate` указывает, что флажок находится в **неопределенном** состоянии. Когда это свойство имеет значение `true`, посередине флажка отображается горизонтальная линия, похожая на знак минус, обозначающая неопределенность его состояния.

Неопределенное состояние может использоваться, когда у элемента есть несколько дочерних элементов: если выбраны все дочерние элементы, родительский элемент также выбирается; если не выбран ни один, родительский элемент также не выбирается. Если выбрана лишь часть дочерних элементов, родительский элемент переходит в неопределенное состояние.

В следующем примере демонстрируется такое использование. Здесь показан список для создания стола зачарования (Enchantment table): когда вы выбираете часть рецепта, флажок «Enchantment table» переходит в частично выбранное состояние. Как вы можете видеть, этот пример позволяет использовать родительский флажок для выбора или отмены выбора всех дочерних элементов.

<glyphix id="checkbox-indeterminate" :height="140" title="三态复选框" >

``` html
<div>
  <div>
    <!--
      当 selected.length == 3 时，entirety 就会选中，否则：
      - 如果 selected.length == 0，那么未选中；
      - 其他情况意味着选择了部分配方，因此处于 indeterminate 状态。 
      -->
    <checkbox id="entirety"
              :indeterminate="selected.length && selected.length < 3"
              :checked="selected.length == 3"
              on:checked="selectEntirety" />
    <label target="entirety">
      &nbsp;Enchantment table:
    </label>
  </div>
  <div class="group">
    <div for="x in parts">
      •
      <checkbox :id="x" :value="x" model:group="selected" />
      <label :target="x">&nbsp;{{x}}</label>
    </div>
  </div>
</div>
```

``` js

  data: {
    selected: ['Diamonds'],
  },
  parts: ['Book', 'Diamonds', 'Obsidian'],
  // 点击 entirety 复选框时调用此函数设置所有配方的选中状态
  selectEntirety(status) {
    // 要使用 [...this.parts] 拷贝列表，以免原地修改
    this.selected = status ? [...this.parts] : []
  },
}
```

``` css

  margin-left: 0.4rem;
}
```

</glyphix>

При установке свойства `checked` (обратите внимание, не при очистке) свойство `indeterminate` автоматически сбрасывается. Даже если у флажка одновременно заданы оба эти свойства, он будет отображаться как выбранный, а не в неопределенном состоянии.
:::

# qrcode

Компонент `qrcode` используется для отображения [QR-кода](https://en.wikipedia.org/wiki/QR_code). Этот компонент может отображать любые текстовые данные и подходит для показа URL-адресов, платежных кодов, ссылок для входа через сканирование и другой информации.

В потоковой компоновке (flow layout) компонент `qrcode` по умолчанию является блочным элементом (`block`) и занимает отдельную строку.

## Свойства

### `value` <decl type="string" get set />

Задает текстовые данные, которые необходимо отобразить в виде QR-кода. Компонент `qrcode` автоматически выбирает подходящую версию в зависимости от объема данных. В настоящее время поддерживаются версии до $12$ включительно.

## Описание CSS

Чтобы QR-код легко сканировался, следует правильно настроить CSS-свойства компонента `qrcode`, к которым относятся:
- `color`: цвет элементов (модулей) QR-кода, обычно устанавливается черным (`black` или `#000`);
- `background-color`: цвет фона QR-кода, обычно должен быть белым (`white` или `#fff`);
- `padding` / `margin`: достаточные внутренние и внешние отступы позволяют избежать слияния QR-кода с другими элементами и повышают процент успешного сканирования и распознавания;
- `width` / `height``: размеры QR-кода должны быть достаточно большими для удобства съемки камерой.

По умолчанию каждый модуль компонента QR-кода занимает область $4\rm{px}\times 4\rm{px}$, что на часах может оказаться лишь минимально распознаваемым размером. Однако такие стратегии компоновки, как flex, могут уменьшить размер QR-кода, поэтому разработчикам рекомендуется вручную задавать свойства `width` / `height` компонента QR-кода в соответствии с потребностями и проводить тестирование на устройстве.

# mapview

Картографический компонент, используемый для загрузки и отображения карт на основе тайлов (Tile). Компонент `mapview` поддерживает панорамирование жестами, переключение уровней масштабирования, отображение текущего местоположения и прорисовку маршрутов навигации. Это ключевой компонент для создания картографических приложений.

По умолчанию `mapview` является блочным элементом.

::: tip
`mapview` — это компонент расширения среды выполнения (runtime). Перед использованием убедитесь, что целевая платформа интегрировала модуль `mapview`.
:::

## Свойства

### `baseUri` <decl type="string" get set />

URI **базового пути** к ресурсам тайловой карты. Файлы тайлов будут храниться в этом каталоге в соответствии с фиксированной иерархической структурой. `mapview` автоматически вычисляет путь к требуемому файлу тайла на основе текущего уровня масштабирования и координат в следующем формате:

```
{baseUri}/{zoomLevel}/{tileX}/{tileY}/normal.png     (стандартная карта)
{baseUri}/{zoomLevel}/{tileX}/{tileY}/satellite.png  (спутниковая карта)
```

Типичным вариантом использования является кэширование тайлов карты в локальное хранилище устройства с последующим указанием `baseUri` на соответствующий каталог:

```html
<mapview baseUri="internal://files/tiles/map_provider" />
```

### `tileType` <decl type="number" get set />

Тип слоя тайловой карты. Возможные значения:

| Значение | Описание |
| :-: | :-- |
| `0` | Стандартная карта (значение по умолчанию), загружает файлы тайлов `normal.png` |
| `1` | Спутниковая карта, загружает файлы тайлов `satellite.png` |

### `loadPlace` <decl type="string" get set />

URI **изображения-заполнителя** (плейсхолдера), отображаемого во время загрузки тайла. Если соответствующий файл тайла еще не кэширован локально, `mapview` отобразит это изображение в позиции данного тайла до тех пор, пока тайл не будет загружен, после чего вызывается метод [`reload()`](#reload) для обновления.

```html
<mapview loadPlace="/assets/imgs/loading.png" />
```

### `zoomLevel` <decl type="number" get set />

Уровень масштабирования карты, диапазон значений составляет $[3, 23]$, значение по умолчанию — $17$. Чем выше уровень, тем подробнее карта; чем ниже уровень, тем больше видимая область.

::: info
Это свойство соответствует стандарту уровня масштабирования (Zoom Level) в картографических тайлах и совпадает с определениями уровней в таких популярных картографических сервисах, как Bing Maps и Google Maps.
:::

### `arrowIcon` <decl type="string" get set />

URI изображения иконки текущего местоположения. Эта иконка будет отрисована на экране в позициях широты и долготы, заданных свойством [`navCoordinate`](#navcoordinate) или методом [`setLocation()`](#setlocation), с выравниванием иконки по ее центральной точке.

```html
<mapview arrowIcon="/assets/imgs/location.png" />
```

### `navCoordinate` <decl type="{ x: number, y: number }" get set />

Координаты широты и долготы текущего местоположения в формате `{ x: latitude, y: longitude }`, где `x` — широта, а `y` — долгота. Установка этого свойства обновляет только положение иконки и не приводит к автоматическому смещению центра карты в эту точку. Если вам нужно одновременно центрировать карту на текущем месте, используйте метод [`setLocation()`](#setlocation) с параметром `force: true`.

::: tip
Для сценариев, требующих отслеживания местоположения в реальном времени, рекомендуется использовать метод [`setLocation()`](#setlocation) вместо прямого присваивания значений этому свойству, чтобы управлять автоматическим возвратом в центр с помощью параметра `force`.
:::

### `arrowLineWidth` <decl type="number" get set />

Ширина линии навигационного маршрута в пикселях, значение по умолчанию — `12`.

### `arrowLineBackgroundColor` <decl type="color" get set />

**Цвет фона** навигационного маршрута (цвет пройденного участка). Принимает значения цветов CSS, значение по умолчанию — `#898b90`.

### `arrowLineForgeColor` <decl type="color" get set />

**Цвет переднего плана** навигационного маршрута (цвет оставшейся части маршрута). Принимает значения цветов CSS, значение по умолчанию — `#4b73ec`.

### `smallMem` <decl type="boolean" get set />

Включать ли режим работы на устройствах с малым объемом памяти, значение по умолчанию — `false`.

Если этот режим включен, `mapview` объединяет и масштабирует четыре тайла размером 256×256 в одно изображение размером 512×512 для отрисовки, что снижает количество одновременно кэшируемых в памяти тайлов и оптимизирует работу на устройствах с ограниченной памятью.

::: warning
Режим пониженного потребления памяти ухудшает детализацию карты и должен включаться только в условиях явной нехватки памяти на устройстве.
:::

### `missTiles` <decl type="Array<{ z: number, x: number, y: number }>" get listen />

Только для чтения. Срабатывает, когда карта обнаруживает отсутствие локальных файлов тайлов. Параметр обратного вызова представляет собой массив, каждый элемент которого описывает отсутствующий тайл:

| Поле | Тип | Описание |
| :-- | :-- | :-- |
| `z` | `number` | Уровень масштабирования (Zoom Level) |
| `x` | `number` | X-координата тайла (номер столбца) |
| `y` | `number` | Y-координата тайла (номер строки) |

После получения этого события приложение обычно должно скачать соответствующие файлы тайлов с сервера и после завершения загрузки вызвать метод [`reload()`](#reload) для обновления карты:

```js
export default {
  missTileHandler(tiles) {
    // tiles: [{ z: 17, x: 105234, y: 49832 }, ...]
    downloadTiles(tiles).then(() => {
      this.$element('mapview').reload()
    })
  }
}
```

```html
<mapview id="mapview" on:missTiles="missTileHandler" />
```

### `directionInfo` <decl type="{ event: string, stepIndex?: number, distance?: number }" get listen />

Свойство событий карты (только для чтения), которое активирует прослушивание при выполнении следующих действий на карте:

| Значение `event` | Момент срабатывания | Дополнительные поля |
| :-- | :-- | :-- |
| `"move"` | Срабатывает при панорамировании карты пользователем с помощью жестов | Нет |
| `"calc"` | Срабатывает при пересчете местоположения и отклонения от маршрута во время навигации | `stepIndex` (индекс текущего сегмента маршрута), `distance` (расстояние отклонения текущего положения от маршрута в метрах) |

```js
export default {
  onDirectionInfo(info) {
    if (info.event === 'move') {
      // Пользователь вручную перетащил карту, можно приостановить автовозврат в центр
    } else if (info.event === 'calc') {
      console.log(`Текущий шаг: ${info.stepIndex}, расстояние отклонения: ${info.distance} м`)
    }
  }
}
```

## Методы

### `reload()`

Перезагружает все тайлы. Этот метод необходимо вызывать для обновления отображения карты после записи новых файлов тайлов в локальное хранилище.

```js
this.$element('mapview').reload()
```

### `locate()`

Перемещает центр карты в текущее местоположение (координаты, заданные свойством [`navCoordinate`](#navcoordinate)). Используется для функции «вернуться к текущему местоположению».

```js
this.$element('mapview').locate()
```

### `setLocation(location)`

Устанавливает координаты текущего местоположения и опционально перемещает в эту точку центр карты.

| Поле параметра | Тип | Описание |
| :-- | :-- | :-- |
| `latitude` | `number` | Широта |
| `longitude` | `number` | Долгота |
| `force` | `boolean` | Если `true`, немедленно центрирует карту на этих координатах (эквивалентно вызову [`locate()`](#locate)); если `false`, обновляет только положение иконки |

```js
// Обновляет только положение иконки, не смещая карту
this.$element('mapview').setLocation({
  latitude: 39.9042,
  longitude: 116.4074,
  force: false,
})

// Обновляет положение иконки и центрирует карту на этих координатах
this.$element('mapview').setLocation({
  latitude: 39.9042,
  longitude: 116.4074,
  force: true,
})
```

### `startNav(linePoints)`

Задает навигационный маршрут и запускает навигацию. После вызова карта автоматически позиционируется на начале маршрута и прорисовывает его целиком.

Параметр `linePoints` представляет собой массив точек маршрута, где каждый элемент является двумерным массивом формата `[долгота, широта]`:

```js
const route = [
  [116.397428, 39.909736],  // [долгота, широта]
  [116.404730, 39.913370],
  [116.410072, 39.918933],
]
this.$element('mapview').startNav(route)
```

::: warning
Обратите внимание на порядок параметров: первое значение в каждой координатной точке — это **долгота** (longitude), а второе — **широта** (latitude), что противоположно общепринятому соглашению «широта на первом месте».
:::

### `insetNavPoint(linePoints)`

Добавляет точки маршрута к существующему навигационному маршруту. Формат аналогичен [`startNav()`](#startnav). Применяется для сценариев поэтапного получения данных маршрута. После добавления необходимо вызвать [`reload()`](#reload) для обновления отображения.

```js
this.$element('mapview').insetNavPoint(newPoints)
this.$element('mapview').reload()
```

# collapsible-header

Компонент `collapsible-header` используется для добавления сворачиваемой панели заголовка в прокручиваемый список. Такой эффект применяется на устройствах типа «умные часы» для экономии экранного пространства и улучшения пользовательского опыта.

::: warning
<experimental /> Это экспериментальный компонент. Не используйте его методами, не описанными в данной документации.
:::

## Свойства

Данный компонент поддерживает [общие свойства](/framework/generic/properties.md) и не имеет собственных специализированных свойств.

## Использование

Компонент `collapsible-header` должен содержать ровно два дочерних компонента, в противном случае возможно возникновение непредвиденных эффектов. Конкретный пример использования:

```html
<collapsible-header>
  <p>Это сворачиваемый заголовок</p>
  <scroll> ... </scroll>
</collapsible-header>
```

Здесь первый дочерний элемент является сворачиваемым заголовком, а второй элемент обязательно должен быть прокручиваемым контейнером, таким как [`scroll`](/components/scroll.md). Ниже приведен конкретный пример:

<glyphix id="components-collapsible-header-1" height="360" width="360" title="Сворачиваемая панель заголовка">

```html
<collapsible-header>
  <p class="title-bar" on:click="clickTitle">TITLE BAR</p>
  <scroll scroll-snap="center" deformation="fisheye">
    <p for="x in 20" class="item">item {{ x + 1 }}</p>
  </scroll>
</collapsible-header>
```

```js
import prompt from "@system.prompt";

export default {
  clickTitle() {
    prompt.showToast({ message: "title clicked" });
  }
}
```

```css
.title-bar {
  margin: 56px auto auto;
  transparent: true;
  font-size: 1.5rem;
}

.item {
  height: 33.3%;
  background-color: #ddd;
  border-radius: 20%;
  margin: 8px;
  transparent: true;
  padding: 12px;
  text-align: center;
}
```

</glyphix>

### Описание принципа работы

`collapsible-header` принимает два дочерних компонента: первый представляет собой сворачиваемую панель заголовка, а второй обязательно должен быть прокручиваемым компонентом, похожим на `scroll`. `collapsible-header` объединяет эти два компонента и управляет эффектом отображения панели заголовка при прокрутке списка.

Для управления положением панели заголовка можно использовать методы, подобные потоковой компоновке (flow layout), например:

```css
/* Верхний отступ элемента 48px, центрирование по горизонтали, подходит для круглых экранов. */
margin: 48px auto auto;
/* Отступы слева и сверху 12px, подходит для квадратных экранов. */
margin: 12px auto auto 12px;
```

Установив указанные выше стили для элемента заголовка в соответствии с вашими реальными потребностями, вы можете добиться определенного эффекта выравнивания. В качестве заголовка также можно использовать сложный компонент, содержащий дочерние элементы (например, компонент, включающий кнопку «Назад» и текст заголовка страницы). Однако обратите внимание, что при клике на панель заголовка событие клика может одновременно отправляться и в прокручиваемый список, и в панель заголовка. Если возникает конфликт, его можно решить путем предотвращения всплытия событий (stopPropagation).

### Меры предосторожности

Необходимо предоставить для `collapsible-header` ровно два дочерних компонента в соответствии с требованиями, описанными выше, и не перепутать их порядок. Кроме того, поскольку сворачиваемая панель заголовка и лежащий в основе прокручиваемый список отображаются с наложением друг на друга, это может привести к тому, что первый элемент списка будет перекрываться с заголовком. При необходимости разработчикам следует предусмотреть какой-либо способ заполнителя (placeholder), чтобы избежать наложения. Кроме того, центрированный [режим привязки](/components/scroll.md#scrollsnap) (`scroll-snap="center"`) компонента `scroll` также помогает избежать наложения.

# label

Компонент `label` используется для отображения текста или информации о метке и по умолчанию является строчным элементом. `label` может использоваться совместно со следующими компонентами форм для отображения меток:
- [input](input)
- [radio](radio)
- [switch](switch)
- [checkbox](checkbox)

Когда `label` связан с поддерживаемым компонентом формы, нажатие на компонент `label` также инициирует обновление значения компонента формы.

## Свойства

### `text` <decl type="string" set get />

Текстовое содержимое метки, поддерживает синтаксис атрибутов или синтаксис текстовых дочерних элементов:
``` html

<label>label text</label>
```

### `target` <decl type="string" set get />

Идентификатор (ID) целевого компонента. Например:
```html
<radio id="red" /><label target="red">red</label>
```
Нажатие на компонент `label` в примере также инициирует обновление компонента `radio` с ID `red`, однако нажатие на компонент `label` не вызывает события касания целевого компонента, такие как `click`.

Из соображений производительности поддерживаются только целевые компоненты, находящиеся на том же уровне, что и компонент `label` (то есть имеющие общего родительского компонента).

::: warning
В настоящее время изменение целевого компонента не поддерживается.
:::

## Поведение компоновки

Компонент `stack` имеет фиксированную стратегию компоновки стека. Его размеры определяются двумя типами ограничений:
1. Размеры `stack` сначала задаются с помощью таких CSS-свойств размеров, как [`width`](../framework/generic/styles.md#width) или [`height`](../framework/generic/styles.md#width);
2. Компоновка родительского элемента может напрямую определять компоновку `stack`, например, такие свойства flex-компоновки, как `align-items: stretch`, `flex: 1` и т. д.;
3. В противном случае размеры компонента `stack` определяются максимальной шириной и максимальной высотой его дочерних элементов.

Как только размеры `stack` определены, все его дочерние элементы будут иметь одинаковые внешние размеры рамки (то есть размер дочернего элемента с учетом `border` и `margin`). Иногда это может вызывать неудобства: например, если использовать `stack` для установки изображения в качестве фона, а расположенный поверх него элемент окажется слишком большим, это может привести к тому, что фоновое изображение не заполнит всю область.

# scroll

Контейнер списка с возможностью прокрутки, поддерживающий любые дочерние компоненты. Направление прокрутки списка определяется конкретным способом компоновки: при использовании потоковой компоновки (flow layout) или flex-компоновки в направлении `column` элементы располагаются по вертикали, и список может прокручиваться по вертикали; при использовании flex-компоновки в направлении `row` элементы располагаются по горизонтали, и список может прокручиваться по горизонтали. Компонент `scroll` не поддерживает двунаправленную прокрутку (т.е. одновременную прокрутку по горизонтали и вертикали).

По умолчанию компонент `scroll` является блочным элементом, использующим потоковую компоновку.

Прокрутку в компоненте `scroll` можно осуществлять с помощью жестов, а вертикальный компонент `scroll` также поддерживает прокрутку с помощью энкодера (вращающегося безеля умных часов, либо колесика мыши в симуляторе).

::: tip
Некоторые интерактивные примеры в этой документации поддерживают управление с помощью колесика мыши (в правой части заголовка имеется значок мыши): вы можете навести указатель мыши внутрь примера и прокручивать список с помощью колесика мыши.
:::

## Свойства

### `scroll` <decl type="{ scrollX: number, scrollY: number, scrollState: number }" get listen />

Значение свойства `scroll` представляет собой объект, содержащий следующие поля: `scrollX`, `scrollY` и `scrollState`. Свойства `scrollX` и `scrollY` обозначают позиции прокрутки по горизонтали и вертикали соответственно, в пикселях; свойство `scrollState` обозначает состояние прокрутки и может принимать значения $0$, $1$ или $2$, значение которых описано в таблице ниже. С помощью директивы `on` можно прослушивать изменения свойства `scroll`. Любое изменение позиции контента, вызванное действиями пользователя или операциями API, вызывает срабатывание прослушивателя.

| Значение `scrollState` | Описание эффекта                                                                                    |
| :--------------------: | --------------------------------------------------------------------------------------------------- |
|          $0$           | Прокрутка остановлена                                                                               |
|          $1$           | Выполняется прокрутка жестом пользователя                                                           |
|          $2$           | Пользователь отпустил руку; прокрутка вызвана методами вроде [`scrollTo`](#scrollto) либо инерцией    |

::: info
Область, в которой находятся дочерние элементы `scroll`, называется «областью контента» (content), а фактически отображаемая часть компонента списка называется «областью просмотра» (view). Элементы располагаются в области контента, их размеры могут превышать размеры области просмотра, а с помощью прокрутки можно изменять отображаемую позицию контента.
:::

Диапазон позиций прокрутки обычно находится в пределах области контента, то есть `scrollX` для горизонтального списка находится в диапазоне $[0, \texttt{contentWidth}]$, а `scrollY` для вертикального списка — в диапазоне $[0, \texttt{contentHeight}]$. Однако, когда список прокручен выше начала контента, `scrollX` или `scrollY` станут меньше $0$; аналогично, при прокрутке ниже конца контента значения `scrollX` или `scrollY` будут больше `contentWidth` или `contentHeight`.

::: warning
Событие `scroll` срабатывает на каждом кадре во время прокрутки. Прослушивание этого события в коде JavaScript может привести к заметному падению частоты кадров (потере кадров), поэтому по возможности следует избегать его использования.
:::

### `scrollTop` <decl type="number" set get listen />

Позиция прокрутки по вертикали, то есть расстояние от верхней границы контента компонента `scroll` до верхней границы видимой области (вьюпорта), в пикселях. С помощью этого свойства можно устанавливать позицию прокрутки, а также отслеживать изменения позиции прокрутки.

В отличие от свойства [`scroll`](#scroll), прослушивание самого свойства `scrollTop` не позволяет различить, была ли прокрутка вызвана жестом пользователя, вызовом API или инерцией.

### `scrollLeft` <decl type="number" set get listen />

Позиция прокрутки по горизонтали, то есть расстояние от левой границы контента компонента `scroll` до левой границы видимой области, в пикселях. С помощью этого свойства можно устанавливать позицию прокрутки, а также отслеживать изменения позиции прокрутки.

В отличие от свойства [`scroll`](#scroll), прослушивание самого свойства `scrollLeft` не позволяет различить, была ли прокрутка вызвана жестом пользователя, вызовом API или инерцией.

### `scrollWidth` <decl type="number" get listen />

Ширина области контента компонента `scroll`. Ширина вертикального `scroll` равна ширине области просмотра, а ширина горизонтального `scroll` равна сумме ширин всех элементов. С помощью этого свойства можно отслеживать изменения ширины контента.

### `scrollHeight` <decl type="number" get listen />

Высота области контента компонента `scroll`. Высота вертикального `scroll` равна высоте области просмотра, а высота горизонтального `scroll` равна сумме высот всех элементов. С помощью этого свойства можно отслеживать изменения высоты контента.

### `damping` <decl type="number" set />

Устанавливает коэффициент затухания (демпфирования) для анимации прокрутки списка. Допустимый диапазон значений составляет $[0.1, 50]$ (неподдерживаемые значения автоматически ограничиваются верхним или нижним пределом), значение по умолчанию — $1.5$. Больший коэффициент затухания приводит к более быстрой остановке анимации; значение по умолчанию обеспечивает инерционный эффект на относительно большие расстояния и с большой длительностью.

### `snapshot` <decl type="boolean" get set />

При включении свойства `snapshot` дочерние компоненты в списке переходят в режим снимков (snapshot mode). С примером можно ознакомиться в описании свойства [`quiescent`](/framework/generic/properties.md#quiescent) для нативных компонентов.

Включение снимков может повысить частоту кадров (FPS) в сложных интерфейсах. Например, если элементы списка содержат много текста и непрозрачный фон, режим снимков позволяет кэшировать множество операций отрисовки и объединять их в небольшое количество снимков. Фреймворк Glyphix кэширует такие снимки при повторяющейся отрисовке для дальнейшего повышения производительности.

Тем не менее, свойство `snapshot` не гарантирует использование снимков дочерними компонентами; эта настройка может быть проигнорирована при нехватке системной памяти или если использование снимков не требуется.

### `deformation` <decl type="string | function" set />

Задает эффект деформации списка, с помощью которого можно реализовать такие внешние виды, как «рыбий глаз» (fisheye). Встроенный эффект деформации можно указать по имени (строке), либо определить его с помощью функции JavaScript.

|   Значение   |           Описание эффекта            |
| :----------: | :-----------------------------------: |
|   `'none'`   | Без эффекта деформации (значение по умолчанию) |
| `'fisheye'`  | Встроенный эффект «рыбий глаз»        |
|   function   | Задание эффекта деформации через JS-функцию |

Эффект деформации должен быть константой и не должен изменяться.

При настройке списка с эффектом деформации «рыбий глаз» рекомендуется установить свойство [`scrollSnap`](#scrollsnap) в значение `'center'` для достижения наилучшего результата.

:::

### `scrollSnap` <decl type="'none' | 'start' | 'center' | 'edge'" get set />

Задает способ выравнивания и привязки (snapping) элементов списка. Например, позволяет выравнивать элементы по центру или привязывать их к границам.

| Значение  | Описание                                                                                                                                              |
| :-------: | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `'none'`  | Элементы не выравниваются и не привязываются, то есть дочерние элементы могут останавливаться в любой позиции в соответствии с инерцией прокрутки.   |
| `'start'` | При остановке прокрутки начальная позиция элемента выравнивается по начальной позиции области просмотра. Данный режим в настоящее время не поддерживается. |
| `'center'`| При остановке прокрутки центральная позиция элемента выравнивается по центру области просмотра.                                                       |
|  `'edge'` | При остановке прокрутки начальная или конечная позиция элемента ближайшим образом выравнивается по начальной или конечной границе области просмотра. Однако, если прокрутка не пересекает границу элемента, привязка не происходит. |

Свойство `scrollSnap` не изменяет размеры элементов, однако механизмы компоновки позволяют использовать его для списков с элементами одинакового размера.

::: warning
Это свойство следует задавать при инициализации компонента, его нельзя изменять в процессе работы, иначе могут возникнуть ошибки взаимодействия.
:::

### `index` <decl type="number" get set listen />

Индекс текущего отображаемого дочернего компонента. При установке свойства `index` компонент с помощью анимации прокручивается к указанному дочернему компоненту. Изменение позиции можно отслеживать с помощью директивы `on`, а при изменении индекса дочернего компонента об этом можно узнать через свойство `index`.

Значение `index` автоматически ограничивается для гарантии указания на существующий элемент. При использовании `index` необходимо гарантировать, что все элементы компонента `scroll` являются статическими (т.е. CSS-свойство [`position`](/framework/generic/styles.md#position) имеет значение по умолчанию `static`), в противном случае возникнут ошибки.

### `finalChanged` <decl type="bool" get set />

Устанавливает, должно ли событие изменения свойства [`index`](#index) срабатывать только после полной остановки прокрутки. По умолчанию (когда `finalChanged` равен `false`), событие прослушивания срабатывает всякий раз, когда жест прокрутки или другая причина приводит к изменению свойства `index` компонента `scroll`. Однако это может легко привести к пропуску кадров анимации или слишком частым, избыточным срабатываниям событий. Если установлено свойство `finalChanged`, событие изменения `index` будет срабатывать только тогда, когда прокрутка полностью остановилась.

::: tip
При реализации таких эффектов, как индикаторы точек (пагинация) путем прослушивания свойства `index`, рекомендуется устанавливать `finalChanged` в значение `true`, так как это позволяет избежать потери кадров из-за обновлений рендеринга, вызванных срабатыванием событий во время процесса прокрутки.
:::

В следующем примере продемонстрирован эффект от использования `finalChanged`. Вы можете попробовать переключить флажок «final-changed», а затем прокрутить список, наблюдая за частотой и моментом изменения `index`.

``` html
  </p>

    <p for="x in 50">
      Item {{ x + 1 }}
    </p>
  </scroll>

```

### `bounces` <decl type="'none' | 'start' | 'end' | 'edge'" get set />

Задает, будет ли срабатывать отскок (пружинный возврат) при перетаскивании `scroll` за границы с помощью жеста. Начальное значение этого свойства — `edge`, что означает разрешение отскока как для начальной, так и для конечной позиции.

| Значение  | Описание                                                      |
| :-------: | ------------------------------------------------------------- |
| `'none'`  | Отключить отскок на всех границах.                            |
| `'start'` | Разрешить отскок только при перетаскивании за начало контента.|
|  `'end'`  | Разрешить отскок только при перетаскивании за конец контента. |
| `'edge'`  | Разрешить отскок при перетаскивании за начало или конец контента. |

В примере ниже показано действие различных значений `bounces`. Вы можете попробовать сдвинуть каждый элемент влево или вправо за пределы границ и понаблюдать за соответствующим поведением.

<glyphix id="components-scroll-bounces" height="360" width="400" title="Анимация отскока при перетаскивании">

``` html
<scroll class="column-box">
  <scroll for="item in items" class="row-box"
          :bounces="item" scroll-snap="edge">
    <p class="item-body">bounces: {{item}}</p>
    <p class="slide-button">×</p>
  </scroll>
</scroll>
```

```js
export default {
  data: {
    items: ['none', 'start', 'end', 'edge']
  }
}
```

```css
.column-box {
  display: flex;
  flex-direction: column;
}

.row-box {
  display: flex;
  flex-direction: row;
}

.row-box > p {
  border-radius: 12px;
  text-align: center;
  margin: 8px;
  padding: 16px;
}

.item-body {
  background-color: #f0f0f0;
  width: 100%;
}

.slide-button {
  width: 30%;
  color: #ffffff;
  background-color: #f04040;
}
```

</glyphix>


::: note
В настоящее время свойство `bounces` влияет только на отскок при жестовых операциях, но не затрагивает быстрый инерционный отскок. В приведенном выше примере используется прием для предотвращения непредвиденного поведения:
- `.row-box` использует стратегию привязки к краям (`scroll-snap="edge"`), чтобы избежать жестовой анимации с отскоком.
- Каждый элемент `.row-box` имеет ширину не более `100%`, что гарантирует отсутствие внутренних граничных отскоков при стратегии привязки к краям.

Этот прием можно использовать для таких интерфейсов, как меню удаления смахиванием в сторону.
:::

Свойство `bounces` также выполняет функцию, аналогичную [`weakGesture`](#weakgesture). В частности, при пересечении границы, где отскок запрещен, автоматически разрешается всплытие (bubble) событий жестов прокрутки. Таким образом, нет необходимости одновременно задавать свойства `bounces` и `weakGesture`.

::: tip
Поведение всплытия жестов прокрутки для `bounces` и `weakGesture` является «противоположным». Например, стратегия отскока в режиме `end` позволяет пользователю прокручивать контент с отскоком за пределы конца списка, и эта же стратегия разрешает всплытие жестов прокрутки в начале списка. Это соответствует эффекту свойства `weakGesture` со значением `'start'`.
:::

### `weakGesture` <decl type="'none' | 'start' | 'end' | 'edge'" get set />

Задает, в каких ситуациях компонент `scroll` должен передавать жесты прокрутки дальше по цепочке всплытия (будет ли происходить всплытие событий жестов). По умолчанию `scroll` перехватывает и предотвращает всплытие обрабатываемых им жестов, поэтому его родительские элементы не могут получить жесты, вызывающие прокрутку `scroll`. `weakGesture` позволяет включить всплытие событий жестов при перетаскивании к границам контента, благодаря чему родительские элементы получают возможность принимать эти жесты.

| Значение  | Описание                                                                        |
| :-------: | ------------------------------------------------------------------------------- |
| `'none'`  | Не передавать события обрабатываемых жестов через всплытие.                     |
| `'start'` | Передавать события жестов через всплытие после перетаскивания к началу контента.|
|  `'end'`  | Передавать события жестов через всплытие после перетаскивания к концу контента.   |
| `'edge'`  | Передавать события жестов через всплытие после перетаскивания к началу или концу контента. |

Если базовый элемент страницы представляет собой горизонтальный компонент `scroll`, но вы хотите, чтобы жест смахивания вправо возвращал страницу назад, можно настроить его следующим образом:
``` html
<scroll weak-gesture="start"> ... </scroll>
```
Когда пользователь прокрутит содержимое до начала `scroll` и продолжит смахивание вправо, страница закроется.

::: warning
Это свойство следует задавать при инициализации компонента, его нельзя изменять в процессе работы, иначе могут возникнуть ошибки взаимодействия.
:::

### `scrollbar` <decl type="boolean" get set />

Определяет, должен ли компонент `scroll` отображать полосу прокрутки (по умолчанию не отображается). Поддерживается только для вертикальных компонентов `scroll`. Свойство `scrollbar` должно быть константой и не может изменяться с помощью реактивных свойств, например:
``` html
<scroll scrollbar>
  ...
</scroll>
```
Это создаст компонент `scroll` с полосой прокрутки. Внешний вид полосы прокрутки можно посмотреть в примере для метода [`setIndex`](#setindex).

Стиль полосы прокрутки определяется системой (например, на круглом экране она может отображаться в виде дуги, а на прямоугольном — в виде прямой линии).

### `scrolled` <decl type="boolean" listen />

С помощью свойства `scrolled` можно отслеживать, находится ли список в состоянии прокрутки. Значение свойства, передаваемое в событие, равно `true`, если список прокручивается, в противном случае оно означает, что список остановился.

Событие `scrolled` вызывается как операциями прокрутки, вызванными касанием пользователя, так и прокруткой через свойство `scroll`. Когда список останавливается после состояния прокрутки, параметр события `scrolled` принимает значение `false`.

### `setIndex`
<decl method><pre>

  index: number,
  behavior?: 'instant' | 'smooth'
}): void
</pre></decl>

Перемещает область просмотра к дочернему компоненту, указанному по индексу. Если это перемещение выходит за границы области просмотра, позиция области просмотра остановится на первом или последнем компоненте. Описание свойств параметра `options`:
- `index`: индекс целевого дочернего компонента, к которому нужно выполнить переход; $0$ обозначает первый дочерний компонент.
- `behavior`: при значении `'smooth'` используется плавный переход (анимация), при значении `'instant'` (по умолчанию) происходит мгновенное перемещение к позиции указанного дочернего компонента.

### `scrollTo`
<decl method><pre>
(options: {
  left?: number,
  top?: number,
  behavior?: 'instant' | 'smooth'
}): void
</pre></decl>

Прокручивает контент в указанную позицию. Описание свойств параметра `options`:
- `left`: задает позицию прокрутки контента по оси y. Если параметр `left` пропущен или компонент scroll имеет вертикальную компоновку, прокрутка по оси y производиться не будет.
- `top`: задает позицию прокрутки контента по оси x. Если параметр `top` пропущен или компонент scroll имеет горизонтальную компоновку, прокрутка по оси x производиться не будет.
- `behavior`: задает эффект перехода при прокрутке: `'instant'` (по умолчанию) означает мгновенный переход к целевой позиции без эффекта перехода, а `'smooth'` выполняет плавную прокрутку с переходом.

Метод `scrollTo` игнорирует эффект привязки (snap) элементов.

### `scrollBy`
<decl method><pre>
(options: {
  left?: number,
  top?: number,
  behavior?: 'instant' | 'smooth'
}): void
</pre></decl>

Прокручивает контент на определенное расстояние. В отличие от [`scrollTo()`](#scrollto), метод `scrollBy()` выполняет прокрутку относительно текущей позиции контента. Описание свойств параметра `options`:
- `left`: задает расстояние прокрутки контента по оси y. Если параметр `left` пропущен или компонент scroll имеет вертикальную компоновку, прокрутка по оси y производиться не будет.
- `top`: задает расстояние прокрутки контента по оси x. Если параметр `top` пропущен или компонент scroll имеет горизонтальную компоновку, прокрутка по оси x производиться не будет.
- `behavior`: задает эффект перехода при прокрутке: `'instant'` (по умолчанию) означает мгновенный переход к целевой позиции без эффекта перехода, а `'smooth'` выполняет плавную прокрутку с переходом.

Метод `scrollBy` игнорирует эффект привязки (snap) элементов.

### `padding` и `overflow` <version-badge since="0.9" />

По умолчанию (`overflow: clip`) внутренние отступы (padding) компонента `scroll` напрямую обрезают видимую область. После того как содержимое прокручено, область отступов всегда остается невидимой. Установка `overflow: visible` позволяет сохранять видимость области отступов даже во время прокрутки содержимого.

<glyphix id="components-scroll-padding-overflow-visible" height="360" width="740" title="Внутренние отступы при overflow: visible">

``` html
<div>
  <scroll :index="2">
    <p for="20">overflow: clip</p>
  </scroll>
  <!-- Используется для элемента-заполнителя, так как flex-компоновка пока не поддерживает gap -->
  <div style="width: 20px"></div>
  <scroll style="overflow: visible;" :index="2">
    <p for="20">overflow: visible</p>
  </scroll>
</div>
```

``` css
div {
  display: flex;
}

scroll {
  padding: 20px;
  background-color: #f0f0f0;
  flex: 1;
}

p {
  background-color: #bdbdbd;
  text-align: center;
  padding: 20px;
  margin: 4px;
  border-radius: 16px;
}
```

</glyphix>

Даже при установке `overflow: visible`, `scroll` обрезает содержимое по границе `padding-box`, не позволяя ему выходить за этот диапазон, в отличие от обычных элементов вроде `div`. Это обусловлено тем, что поведение прокрутки и механизм компоновки `scroll` требуют, чтобы содержимое прокручивалось в строго определенной области, а не расширялось во внешнее пространство без ограничений.

В аналогичных условиях с `overflow: visible` обычные контейнеры, такие как `div`, могут выходить за пределы всего `div` (например, за красную рамку `border`):

<glyphix id="components-scroll-overflow-div" height="360" width="360" title="overflow: visible для div">

``` html
<div style="overflow: visible;">
  <p for="20">div {overflow: visible}</p>
</div>
```

``` css
div {
  display: flex;
  flex-direction: column;
  padding: 20px;
  margin-bottom: 100px;
  border: 2px solid red;
  background-color: #f0f0f0;
}

p {
  background-color: #bdbdbd;
  text-align: center;
  padding: 8px;
  margin: 4px;
  border-radius: 16px;
  flex-shrink: 0;
}
```

</glyphix>

#### Рекомендуемые настройки для сценариев i18n

В сценариях интернационализации (i18n) текст внутри `scroll` может потребовать выхода за границы (overflow), чтобы избежать возможного усечения. Для таких случаев рекомендуется использовать настройку `overflow: visible`, которая позволяет[ переполняющему тексту](/framework/application/i18n.md#文本溢出) выходить за границы контента `scroll` во время прокрутки, максимально задействуя пространство для отображения текста.

#### Связь со спецификацией HTML/CSS

Поведение `scroll` при установке `overflow: visible` аналогично поведению `div { overflow-y: scroll; }` в спецификации HTML/CSS. В этом случае отступы (padding) сохраняют содержимое видимым во время прокрутки, например при таком CSS:

```css
div {
  padding: 20px;
  overflow-y: scroll;
}
```

Это дает следующий эффект: при прокрутке область `padding` не обрезает контент:

<div style="padding: 20px; background-color: var(--vp-c-grey-bg); overflow-y: scroll; height: 100px; width: 200px; border: 2px dotted red; font-family: sans-serif;">
  Michaelmas term lately over, and the Lord Chancellor sitting in Lincoln's Inn Hall.
  Implacable November weather. As much mud in the streets as if the waters had but
  newly retired from the face of the earth.
</div>

Элемент `div` в HTML не имеет прямого аналога поведения `scroll` в режиме `overflow: clip`.

# text-field

Компонент для ввода однострочного текста, по умолчанию является строчным элементом (inline). В отличие от аналогичных GUI-элементов на телефонах или ПК, `text-field` в настоящее время не реагирует на устройства ввода, такие как клавиатура, и не вызывает интерфейс метода ввода (клавиатуру), поэтому вы должны редактировать его содержимое вручную. `text-field` поддерживает управление курсором с помощью сенсорных жестов (например, нажатие и прокрутка).

`text-field` подходит в качестве базового компонента для ввода однострочного текста, позволяя реализовать мягкую клавиатуру (soft keyboard) в соответствии с вашими требованиями (например, цифровую клавиатуру для ввода пароля или даже голосовой ввод). Подробности см. в [примере](#基本示例).

## Свойства

### `value` <decl type="string" set get listen />

Свойство `value` представляет собой строку, которая является текущим редактируемым содержимым `text-field`. Чтение или прослушивание (listen) этого значения позволяет получить введенный текст, а также установить это свойство.

Обычно `value` двунаправленно связывается с определенным реактивным свойством, например:

```html
<text-field ::value="inputText" />
```

### `placeholder` <decl type="string" set get />

Когда содержимое `text-field` пусто, вы можете предоставить пользователю краткую подсказку с помощью `placeholder`, такую как «Пожалуйста, введите текст» и т.п.

`placeholder` автоматически отображается, когда вводимый текст пуст, поэтому обычно требуется только фиксированное содержимое, например:

```html
<text-field ::value="inputText" placeholder="type here" />
```

### `password` <decl type="boolean" set get />

Когда это свойство установлено, `text-area` переходит в «режим пароля», то есть каждый символ заменяется на «•» ([Bullet, U+2022](http://www.fileformat.info/info/unicode/char/2022/index.htm)). Вы можете в любой момент включить или выключить свойство `password`, чтобы реализовать переключение между состоянием отображения и скрытия пароля.

В новых версиях <version-badge since="0.9" /> в режиме пароля введённые символы скрываются с задержкой: пользователь может видеть только что введенный символ короткое время, после чего он заменяется на «•». В старых версиях символы скрывались немедленно.

### `insert` <decl type="(text: string): void" method />

Вставляет текст с содержимым `text` в позицию курсора, при этом курсор автоматически смещается за вставленный текст. Вызов этой функции инициирует событие прослушивания `value`.

### `backspace` <decl type="(): void" method />

Удаляет символ в позиции курсора, и курсор автоматически смещается вперед. Вызов этой функции инициирует событие прослушивания `value`.

## Инструкция по использованию

### Базовый пример

В следующем примере показано базовое использование `text-field`. Вы можете нажимать кнопки клавиатуры для ввода цифр. Нажатие кнопки «×» удаляет содержимое в позиции курсора, а нажатие «A/*» переключает между режимом пароля и режимом ввода обычного текста. В режиме пароля вводимое содержимое скрывается с помощью `•`.

<glyphix id="components-text-field-1" width="410" height="160">

```html
<div class="flex-column">
  <div class="flex-row align-baseline">
    <text-field id="text-field"
                ::value="inputText"
                :password="password"
                placeholder="type here" />
    <button checkable ::press="password">A/*</button>
    <button on:click="textField.backspace()">×</button>
  </div>
  <!-- Простая матричная цифровая клавиатура -->
  <div class="flex-row" for="rows in keyboard">
    <button class="flex-1" for="key in rows"
            on:click="textField.insert(key)">
      {{key}}
    </button>
  </div>
</div>
```

```js
export default {
  data: {
    inputText: "",
    password: false,
  },
  keyboard: [
    ['1', '2', '3', '4', '5'],
    ['6', '7', '8', '9', '0'],
  ],
  textField: null,
  onReady() {
    // Получаем объект компонента TextField для удобного вызова методов insert() и backspace().
    this.textField = this.$element("text-field")
  },
}
```

```css
.flex-column {
  display: flex;
  flex-direction: column;
}

.flex-row {
  display: flex;
}

.align-baseline {
  align-items: baseline;
}

text-field {
  flex: 1;
  text-align: center;
  border-bottom: 2px solid #666;
}

button {
  border-radius: 8px;
  background-color: #dee2e6;
  margin: 8px;
  padding: auto 12px;
}

button:active {
  opacity: 0.5;
}

.flex-1 {
  flex: 1;
}
```
</glyphix>

В этом примере текст в `text-field` отображается по центру, что достигается с помощью `text-align`:
```css
text-field {
  text-align: center;
}
```

Сначала мы получаем объект компонента `text-field` с помощью метода `$element` в функции жизненного цикла `onReady()`, так как в дальнейшем потребуется редактировать содержимое через методы [`insert()`](#insert) и [`backspace`](#backspace).

На этой основе мы можем напрямую вызывать методы `text-field` в прослушивателе события `click` компонента `button`, например:
```html
<button on:click="textField.backspace()">×</button>
```

Из-за отсутствия физической клавиатуры разработчикам обычно требуется предоставлять собственную реализацию клавиатуры. В учебных целях в данном примере реализована лишь цифровая клавиатура из 2 строк и 5 столбцов. Значение каждой клавиши вставляется в `text-field` внутри функции-слушателя события `click` для каждой кнопки:
```html
<div class="flex-row" for="rows in keyboard">
  <button class="flex-1" for="key in rows"
          on:click="textField.insert(key)">
    {{key}}
  </button>
</div>
```

В этом примере также продемонстрирован стандартный способ переключения режима пароля.

### Валидация и форматирование содержимого

Вы можете реализовать валидацию и форматирование вводимого содержимого путем двунаправленного связывания свойства [`value`](#value) компонента `text-field` с вычисляемым свойством (computed property). В следующем примере показан этот метод: он позволяет вводить не более 9 цифр (буквы и т.д. вводить нельзя) и автоматически добавляет разделитель «`,`» каждые три цифры.

<glyphix id="components-text-field-validator" title="Валидатор содержимого" width="410" height="200">

```html
<div class="flex-column">
  <div class="flex-row align-baseline">
    <text-field id="text-field"
                ::value="inputText"
                :password="password"
                placeholder="type here" />
    <button checkable ::press="password">A/*</button>
    <button on:click="textField.backspace()">×</button>
  </div>
  <div class="flex-row" for="rows in keyboard">
    <button class="flex-1" for="key in rows"
            on:click="textField.insert(key)">
      {{key}}
    </button>
  </div>
</div>
```

```js
export default {
  data: {
    password: false,
    rawText: "",
  },
  computed: {
    inputText: {
      get() { return this.rawText },
      set(text) {
        if (text.length < 12 && /^[\d,]*$/.test(text)) {
          this.rawText = text.replace(/[^\d]/g, '')
                             .replace(/\B(?=(\d{3})+(?!\d))/g, ",")
        }
      },
    },
  },
  keyboard: [
    ["1", "2", "3", "4", "5"],
    ["6", "7", "8", "9", "0"],
    ["A", "B", "C", "D", "E"],
  ],
  textField: null,
  onReady() {
    this.textField = this.$element("text-field")
  },
}
```

```css
.flex-column {
  display: flex;
  flex-direction: column;
}

.flex-row {
  display: flex;
}

.align-baseline {
  align-items: baseline;
}

text-field {
  flex: 1;
  border-bottom: 2px solid #666;
}

button {
  border-radius: 8px;
  background-color: #dee2e6;
  margin: 8px;
  padding: auto 12px;
}

button:active {
  opacity: 0.5;
}

.flex-1 {
  flex: 1;
}
```
</glyphix>

Валидация и форматирование содержимого реализованы с помощью двунаправленного связывания и вычисляемых свойств. Для узла компонента `text-field`:
```html
<text-field id="text-field"
            ::value="inputText"
            :password="password"
            placeholder="type here" />
```
свойство `value` двунаправленно связано с `inputText`, которое по сути является вычисляемым свойством. Его метод `set()` проверяет, соответствует ли вводимое содержимое стандартам (не более 11 символов, разрешены только цифры и запятые), затем с помощью регулярного выражения отфильтровывает цифры и форматирует их, добавляя запятую каждые три цифры:
```js
function set(text) {
  if (text.length < 12 && /^[\d,]*$/.test(text)) {
    this.rawText = text.replace(/[^\d]/g, '')
                       .replace(/\B(?=(\d{3})+(?!\d))/g, ",")
  }
}
```
Если вводимое содержимое не соответствует требованиям, метод `set()` игнорирует введенное значение, а механизм двунаправленного связывания поддерживает согласованность содержимого `text-field` и значения свойства `inputText` (получаемого через метод `get()`). В результате вы увидите, что ввод буквенных клавиш невозможен.

# progress

Компонент `progress` используется для отображения полосы прогресса и по умолчанию является блочным элементом.

## Свойства

### `max` <decl type="number" set />

Максимальное значение прогресса, свойство [`value`](#value) не может быть больше него.

### `min` <decl type="number" set />

Минимальное значение прогресса, свойство [`value`](#value) не может быть меньше него.

### `value` <decl type="number" set get listen />

Установка значения прогресса. Отображаемое соотношение прогресса зависит от доли свойства `value` в диапазоне от `min` до `max`, при этом соотношение отображения ограничивается в пределах от $0\% \text{ до } 100\%$ . Значение `value` является целым числом; если задано число с плавающей точкой, будет взята только его целая часть.

### `vertical` <decl type="boolean" set />

Если значение свойства `vertical` равно `true`, компонент `progress` будет отображаться вертикально, в противном случае — горизонтально. Значение по умолчанию — `false`. 

## Спецификация CSS

Разработчики могут настраивать внешний вид компонента `progress` с помощью CSS.

### Расчет размеров

Ширина и высота `progress` по умолчанию равны размеру шрифта элемента, который задается свойством [`font-size`](/framework/generic/styles.md#font-size) (или может наследоваться). Размеры `progress` можно настроить с помощью свойств [`width`](/framework/generic/styles.md#width) и [`height`](/framework/generic/styles.md#height).

### CSS-свойства

Следующие CSS-свойства могут быть весьма полезны:
- [`background-color`](/framework/generic/styles.md#background-color) управляет цветом фона `progress`;
- [`color`](/framework/generic/styles.md#color) управляет цветом полосы прогресса `progress`;
- [`border-radius`](/framework/generic/styles.md#border-radius) позволяет сделать границы `progress` скругленными, например, значение `50%` создаст полукруглые края;

Другие CSS-свойства также могут быть полезны, например, для настройки стилей рамок можно использовать свойство [`border`](/framework/generic/styles.md#border).

### Псевдоэлементы CSS

#### `value`

Этот псевдоэлемент позволяет отдельно задавать стили для самой полосы прогресса `progress`, исключая фоновую часть. Например, можно раздельно настроить радиус скругления углов для фона шкалы и для самой полосы прогресса, чтобы получить эффект, при котором внешний контур имеет закругленные концы, а полоса прогресса — прямые.

``` css
progress {
  border-radius: 50%; /* Скругление углов фона шкалы */
}

progress::value {
  border-radius: 0; /* Без скругления углов у полосы прогресса */
}
```

### Пример CSS

В следующем примере показаны некоторые способы настройки внешнего вида полосы прогресса с помощью CSS.

<glyphix id="components-progress-styles" height="140" width="480" title="Стили полосы прогресса">

``` html
<div>
  <!-- Стиль по умолчанию -->
  <progress :value="40" />
  <!-- Стиль полосы прогресса с прямыми краями -->
  <progress class="flat" :value="50" />
  <progress class="more-style" :value="60" />
</div>
```

``` css
div > * {
  margin: 8px;
}

.flat::value {
  /* Установка радиуса скругления псевдоэлемента value в 0 создает эффект прямых краев прогресса */
  border-radius: 0;
}

.more-style {
  /* Пользовательский радиус скругления */
  border-radius: 30%;
  /* Цвет фона полосы прогресса */
  background-color: #b3c5d7;
  /* Цвет переднего плана полосы прогресса */
  color: #b5179e;
  /* Свойство padding позволяет настраивать отступы переднего плана прогресса */
  padding: 6px;
  height: 1.25rem;
}
```

</glyphix>

# a

Компонент якоря, по умолчанию является строчным элементом, используется для перехода на указанную страницу.

## Свойства

### `href` <decl type="string" get set />

Указывает [название страницы](/framework/application/manifest.md#pages) или строку URI, на которую необходимо выполнить переход.

``` html
<a href="page1">Перейти на страницу page1</a>
``` 

В отличие от тега `<a>` в веб-разработке, компонент `a` поддерживает только переходы между страницами и не поддерживает гиперссылки.

Свойство `href` также поддерживает строки [URI](/framework/application/resource.md#uri) вида `PageName?key=value`, то есть URI, состоящий из названия страницы (в качестве поля path) и поля query. Поле query этого URI будет преобразовано в параметры перехода на страницу. Например, при нажатии на этот элемент `<a>`:

``` html
<a href="page1?text=test-text&message=hello">Перейти на страницу page1</a>
```

Это эквивалентно вызову следующего метода [`router.push()`](/api/system-router.md#push):

``` js
router.push({
  uri: 'page1',
  params: {text: 'test-text', message: 'hello'}
})
```

::: tip
Обратите внимание, что значение поля query в URI всегда преобразуется в тип string. Таким образом, значение `100` в `page1?size=100` будет интерпретировано как строка `'100'`, а не как число `100`. Если вам нужно передать параметры определенного типа, используйте API [`router`](/api/system-router.md).
:::

# swiper

Контейнер представлений карточек (карусель/свайпер), поддерживающий любые дочерние компоненты. Направление прокрутки представления карточек определяется конкретным способом компоновки: список с компоновкой `flex-column` является вертикальным, а список с компоновкой `flex-row` — горизонтальным.

## Свойства

### `scroll` <decl type="{ scrollX: number, scrollY: number, scrollState: number }" get listen />

Значение свойства `scroll` представляет собой объект, содержащий следующие поля: `scrollX`, `scrollY` и `scrollState`. Свойства `scrollX` и `scrollY` обозначают положение прокрутки по горизонтали и вертикали соответственно, в пикселях; свойство `scrollState` обозначает состояние прокрутки и может принимать значение $0$, $1$ или $2$, значения которых приведены в таблице ниже. С помощью директивы `on` можно прослушивать изменения свойства `scroll`. Любое изменение позиции контента, вызванное действиями пользователя или API, запускает прослушивание.

| Значение `scrollState` | Описание эффекта                                                                                    |
| :--------------------: | --------------------------------------------------------------------------------------------------- |
|          $0$           | Прокрутка остановлена                                                                               |
|          $1$           | Выполняется прокрутка жестом пользователя                                                           |
|          $2$           | Пользователь отпустил палец, прокрутка вызвана методами вроде [`scrollTo`](#scrollto) или инерцией    |

### `scrollTop` <decl type="number" get listen />

Положение прокрутки по вертикали, то есть расстояние от верхней границы контента компонента `swiper` до верхней границы области просмотра, в пикселях. С помощью этого свойства можно отслеживать изменения положения прокрутки. В отличие от свойства [`scroll`](#scroll), прослушивание самого свойства `scrollTop` не позволяет определить, была ли прокрутка вызвана жестом пользователя, вызовом API или инерцией.

### `scrollLeft` <decl type="number" get listen />

Положение прокрутки по горизонтали, то есть расстояние от левой границы контента компонента `swiper` до левой границы области просмотра, в пикселях. С помощью этого свойства можно отслеживать изменения положения прокрутки. В отличие от свойства [`scroll`](#scroll), прослушивание самого свойства `scrollLeft` не позволяет определить, была ли прокрутка вызвана жестом пользователя, вызовом API или инерцией.

### `scrollWidth` <decl type="number" get listen />

Ширина области контента компонента `swiper`. Ширина `swiper` при вертикальной компоновке равна ширине области просмотра, а при горизонтальной компоновке равна сумме ширин всех элементов. С его помощью можно отслеживать изменения ширины контента.

### `scrollHeight` <decl type="number" get listen />

Высота области контента компонента `swiper`. Высота `swiper` при вертикальной компоновке равна высоте области просмотра, а при горизонтальной компоновке равна сумме высот всех элементов. С его помощью можно отслеживать изменения высоты контента.

### `snapshot` <decl type="boolean" get set />

Когда свойство `snapshot` включено, дочерние компоненты `swiper` переходят в режим снимка (snapshot). Пожалуйста, обратитесь к свойству [`snapshot`](scroll.md#snapshot) компонента `scroll`.

### `deformation` <decl type="string" set />

Задает эффект деформации дочерних элементов, с помощью которого можно реализовать такие внешние виды, как "рыбий глаз" (fisheye). Вы можете указать встроенный эффект деформации по имени (строке) либо определить его с помощью функции JavaScript.

| Значение | Описание эффекта |
| :---: | :--- |
| `'none'` | Без эффекта деформации (значение по умолчанию). |
| `'fade'` | Эффект затухания и масштабирования при переключении. Этот эффект подчеркивает «фокус» на элементах внутри текущей области просмотра и делает элементы за ее пределами менее заметными. Подробности см. в примере в этом разделе. |
| `'fisheye'` | Встроенный эффект «рыбий глаз». Этот компонент свойств используется для компонента [`scroll`](scroll.md), а не `swiper`. |
| function | Определение эффекта деформации с помощью функции JavaScript. |

Эффект деформации должен быть константным и не должен изменяться.

Если содержимое дочерних элементов `swiper` часто меняется, при использовании эффекта деформации рекомендуется добавить к элементам свойство [`quiescent`](/framework/generic/properties.md#quiescent), чтобы избежать обновления при переключении и повысить производительность. Вы можете обратиться к следующему примеру:

<glyphix id="components-swiper-deformation" height="360" width="360" title="Эффект деформации элементов">

```html
<swiper deformation="fade" indicator>
  <div for="x in 5" :quiescent="x != 0">
    <progress-arc busy :start-angle="0" :stop-angle="360" />
    <p>pane {{ x + 1 }}</p>
  </div>
</swiper>
```

``` css
div {
  background-color: #eee;
  text-align: center;
  margin: 10px;
  border-radius: 24px;
  display: flex;
  flex-direction: column;
  justify-content: center;
}

progress-arc {
  width: 30%;
  height: 30%;
  margin-bottom: 5%;
}
```

</glyphix>

Первый дочерний элемент в примере не имеет включенного свойства `quiescent`, поэтому он будет непрерывно обновляться в процессе переключения, в то время как остальные элементы прекратят обновление.

Следующий пример демонстрирует интерактивный эффект `swiper` при вертикальной компоновке (обратите внимание, что прокрутка должна быть вертикальной, горизонтальные свайпы не вызывают реакции).

``` html
  <p for="x in 5">
    pane {{ x + 1 }}
    {{ x == 0 ? '(swipe up)' : x == 4 ? '(swipe down)' : '' }}
```

``` css
  text-align: center;
```

### `indicator` <decl type="boolean" get set />

Определяет, отображать ли точечный индикатор (индикатор страниц) у компонента `swiper`. Позиция отображения точечного индикатора определяется свойством `vertical`: при вертикальной компоновке точечный индикатор отображается по центру справа, а при горизонтальной — по центру внизу. Подробный эффект см. в примерах свойств [`deformation`](#deformation) и [`vertical`](#vertical).

Обратитесь к разделу [CSS-свойства точечного индикатора](#css-свойства-точечного-индикатора), чтобы узнать, как настроить стиль отображения точечного индикатора.

### `pageLength`  <decl type="number" set />

Задает размер или долю дочерней страницы. Если указано в процентах, задает размер дочернего компонента в направлении прокрутки (относительно самого компонента); если указано другое число, задает размер дочернего компонента в направлении прокрутки в пикселях.

### `index`  <decl type="number" get set listen />

Индекс текущего отображаемого дочернего компонента. При установке свойства `index` компонент с помощью анимации прокрутится к указанному дочернему компоненту. Вы можете прослушивать изменения положения с помощью директивы `on`, а при изменении индекса дочернего компонента его можно отследить через свойство `index`.

### `finalChanged` <decl type="bool" get set />

Задает, следует ли вызывать событие изменения [`index`](#index) только после остановки прокрутки. По умолчанию (то есть когда `finalChanged` имеет значение `false`), событие прослушивания срабатывает всякий раз, когда жест прокрутки или другая причина изменяет свойство `index` компонента `swiper`. Однако это может легко привести к пропуску кадров анимации или слишком частым, ненужным вызовам событий. Если установлено свойство `finalChanged`, событие изменения `index` будет срабатывать только тогда, когда прокрутка полностью остановится.

::: tip
При реализации эффектов вроде точечных индикаторов путем прослушивания свойства `index` рекомендуется устанавливать `finalChanged` в значение `true`, так как это позволяет избежать пропуска кадров, вызванного обновлениями рендеринга из-за срабатывания событий в процессе свайпа.
:::

### `weakGesture` <decl type="'none' | 'start' | 'end' | 'edge'" get set />

Задает ситуации, в которых компонент `swiper` будет распространять (всплытие) жесты прокрутки. По умолчанию `swiper` предотвращает всплытие обрабатываемых им жестов, поэтому его родительский элемент не может получить жест, заставляющий `swiper` прокручиваться. `weakGesture` позволяет включить всплытие событий жестов при перетаскивании до границ содержимого, позволяя родительскому элементу принимать эти жесты.

| Значение  | Описание                                                                        |
| :-------: | ------------------------------------------------------------------------------- |
| `'none'`  | Не передавать (не всплывать) события жестов.                                    |
| `'start'` | Передавать события жестов после перетаскивания к начальной позиции контента.    |
|  `'end'`  | Передавать события жестов после перетаскивания к конечной позиции контента.     |
| `'edge'`  | Передавать события жестов после перетаскивания к начальной или конечной позиции контента. |

Если базовый элемент страницы представляет собой горизонтальный компонент `swiper`, но вы хотите, чтобы жест свайпа вправо возвращал назад (на предыдущую страницу), вы можете настроить его следующим образом:
``` html
<swiper weak-gesture="start"> ... </swiper>
```
Когда пользователь прокрутит до начала компонента `swiper` и продолжит свайп вправо, он сможет выйти со страницы.

### `bounces` <decl type="'none' | 'start' | 'end' | 'edge'" get set />

Задает, следует ли запускать отскок (bounce) после прокрутки `swiper` к границе с помощью жеста. Начальное значение этого свойства — `edge`, что означает разрешение отскока как в начальной, так и в конечной точках. Свойство `bounces` компонента `swiper` похоже на свойство [`bounces`](scroll.md#bounces) компонента [`scroll`](scroll.md), подробнее см. в соответствующей документации.

### `scrolled` <decl type="boolean" listen />

С помощью свойства `scrolled` можно отслеживать, находится ли компонент `swiper` в состоянии прокрутки. Значение свойства `true` указывает на то, что выполняется прокрутка, в противном случае это означает, что прокрутка остановлена.

Как операции прокрутки, вызванные касанием пользователя, так и программная прокрутка через свойство `scroll` вызывают событие `scrolled`. При выходе из состояния прокрутки значение параметра события `scrolled` равно `false`.

### `setIndex`
<decl method><pre>
(options: {
  index: number,
  behavior?: 'instant' | 'smooth'
}): void
</pre></decl>

Перемещает область просмотра к дочернему компоненту, указанному по индексу. Если это перемещение выходит за пределы границ области просмотра, положение области просмотра остановится на первом или последнем компоненте. Назначение свойств объекта `options`:
- `index`: индекс целевого дочернего компонента для перемещения, $0$ обозначает первый дочерний компонент.
- `behavior`: если указано `'smooth'`, используется плавный переход с анимацией; если `'instant'` (значение по умолчанию), происходит мгновенное перемещение в позицию указанного дочернего компонента.

### `scrollTo` <decl type="(position: number): void" method />

Прокручивает содержимое в указанную позицию, направление прокрутки совпадает с направлением компоновки компонента scroll.

Метод `scrollTo` игнорирует эффект привязки (snap) элементов.

# pullable

Компонент `pullable` используется для добавления функции инкрементальной загрузки или взаимодействия с обновлением, которые срабатывают при потягивании вниз в верхней части или потягивании вверх в нижней части прокручиваемого списка. Компонент `pullable` по умолчанию является блочным элементом.

::: warning
<experimental /> Это экспериментальный компонент. Функционал `pullable` нестабилен, а анимация может выглядеть недостаточно естественно.
:::

`pullable` должен быть первым или последним дочерним компонентом [`scroll`](scroll.md). Когда он является первым дочерним элементом, дальнейшее потягивание вниз в начале содержимого `scroll` вызывает событие `pulling`; наоборот, когда `pullable` является последним дочерним элементом `scroll`, потягивание вверх внизу вызывает событие `pulling`.

Компонент `pullable` по умолчанию скрыт и отображается только при потягивании вверх/вниз. В следующем примере продемонстрировано использование компонента `pullable`.

<glyphix id="components-pullable-1" height="360" width="360" title="Потяните вниз/вверх для загрузки большего количества">

```html
<scroll scrollbar>
  <pullable :hold="pulldown" on:pulling="onPulldown">
    <progress-arc busy start-angle="0" stop-angle="360" />
    <p>{{pulldown || 'keep pull down...'}}</p>
  </pullable>
  <p for="item in items">item ({{item}})</p>
  <pullable :hold="pullup" on:pulling="onPullup">
    <progress-arc busy start-angle="0" stop-angle="360" />
    <p>{{pullup || 'keep pull up...'}}</p>
  </pullable>
</scroll>
```

```js
export default {
  data: {
    pulldown: null,
    pullup: null,
    items: []
  },
  first: 0,
  last: 0,
  onInit() {
    this.update(0, 10)
  },
  update(first, last) {
    for (let i = this.first; i > first; --i)
      this.items.unshift(i)
    for (let i = this.last; i < last; ++i)
      this.items.push(i)
    this.first = first
    this.last = last
  },
  onPulldown(event) {
    this.pulldown = event ? 'please release' : 'updating...'
    if (!event) {
      setTimeout(() => {
        this.update(this.first - 5, this.last)
        this.pulldown = null
      }, 1000)
    }
  },
  onPullup(event) {
    this.pullup = event ? 'please release' : 'updating...'
    if (!event) {
      setTimeout(() => {
        this.update(this.first, this.last + 5)
        this.pullup = null
      }, 1000)
    }
  }
}
```

## Свойства

### `hold` <decl type="bool" get set />

По умолчанию `pullable` виден только при потягивании вниз вверху или вверх внизу, но когда свойство `hold` имеет значение `true`, компонент `pullable` остается видимым. Это свойство обычно устанавливается, когда событие [`pulling`](#pulling) приводит к обновлению содержимого, и сбрасывается после завершения обновления.

### `pulling` <decl type="bool" get listen />

Событие `pulling` срабатывает, когда `pullable` вытянут полностью. Значение этого события означает следующее:
- `true`: событие срабатывает при потягивании вниз/вверх до расстояния срабатывания полного вытягивания `pullable`;
- `false`: событие срабатывает, когда пользователь отпускает палец после достижения вышеуказанного условия полного вытягивания.

В следующем примере показан момент срабатывания значений события `pulling`. Вы можете попытаться медленно потянуть вниз с верхней части списка и обратить внимание на всплывающее сообщение toast при срабатывании события `pulling`.

<glyphix id="components-pullable-pulling" height="360" width="360" title="Событие pulling">

```html
<scroll scrollbar>
  <pullable :hold="refresh" on:pulling="onPulling">
    <p>pulling...</p>
  </pullable>
  <p for="item in 10">item {{item}}</p>
</scroll>
```

```js
import prompt from '@system.prompt'

export default {
  data: {
    refresh: false
  },
  onPulling(event) {
    prompt.showToast({
      message: `pulling: ${event ? 'trigged' : 'release'}`
    })
    if (!event) {
      this.refresh = true
      setTimeout(() => this.refresh = false, 1000)
    }
  }
}
```

## Инструкции по использованию

### Расположение компонента

Компонент `pullable` должен быть первым или последним дочерним элементом вертикального `scroll`. Он автоматически определяет режим работы в зависимости от своего положения: если он является первым дочерним элементом, он определяет операцию потягивания пользователем вниз от верхней части списка, и наоборот.

Для списка, которому требуется только обновление потягиванием вниз, достаточно следующего использования:
```html
<scroll>
  <pullable :hold="refresh" on:pulling="onPulling">
    <p>pulling...</p>
  </pullable>
  <div for="item in items">
    ...
  </div>
</scroll>
```

В коде JavaScript вы можете прослушивать событие `pulling` и управлять свойством `refresh`:
``` js
export default {
  data: {
    refresh: false
  },
  onPulling(hold) {
    if (!hold) { // hold равен false, когда пользователь отпускает палец
      this.refresh = true // Означает, что идет обновление
      // В этом примере таймер используется для имитации операции загрузки и остановки загрузки через 1 секунду
      setTimeout(() => this.refresh = false, 1000)
    }
  }
}
```

Конкретный эффект см. в примере в документации по событию [`pulling`](#pulling).

### Управление подсказками

Внутри компонента `pullable` можно размещать различные компоненты для отображения подсказок. Как показано в предыдущем примере в этой статье, вы можете объединить анимацию загрузки и текст подсказки. Кроме того, значение события `pulling` можно использовать для управления содержимым подсказки. Обычно рекомендуется использовать следующий подход к обработке состояний:
1. Установите реактивное свойство (например, `refresh`) для каждого компонента `pullable` со значением по умолчанию `null`. Свойство `refresh` также используется для управления свойством [`hold`](#hold) компонента `pullable`.
2. В исходном состоянии (т. е. когда `refresh` имеет ложное значение) подсказка `pullable` должна напоминать пользователю: «Продолжайте тянуть для обновления».
3. Когда пользователь тянет вниз, срабатывает событие `pulling`. В зависимости от его значения выполните шаг 4 или 5.
4. Когда `pulling` равен `true`, пользователю должна быть выдана подсказка: «Отпустите, чтобы начать обновление».
5. Когда `pulling` равен `false`, это означает, что пользователь отпустил палец. В этот момент `refresh` следует установить в `true` и начать обновление содержимого. Также пользователю должно быть выведено сообщение: «Идет обновление».
6. После завершения обновления содержимого снова установите `refresh` в `false`, чтобы вернуться в исходное состояние.

Вы также можете обратиться к первому примеру в этом документе, который реализует непрерывную загрузку как при потягивании вниз в начале списка, так и при потягивании вверх в конце. В этом примере используется прием управления всеми состояниями `pullable` с помощью всего одного реактивного свойства.

Этот прием устанавливает начальное значение реактивного свойства `refresh` в `null` (аналогично `false`) и использует следующий шаблон кода:
``` html
<pullable :hold="refresh" on:pulling="onPulling">
  <p>{{refresh || 'Продолжайте тянуть вниз'}}</p>
</pullable>
```
Когда `refresh` не задан, как только `pullable` вытягивается, отображается подсказка по умолчанию «Продолжайте тянуть вниз». Затем функция обратного вызова события `onPulling` должна быть написана следующим образом:
``` js
export default {
  async onPulling(event) {
    this.refresh = event ? 'Пожалуйста, отпустите' : 'Обновление'
    if (!event) { // Запуск обновления при отпускании
        await runRefreshJobs()
        this.refresh = null // Сброс состояния после завершения обновления
    }
  }
}
```

### Ограничения

В настоящее время компонент `pullable` имеет некоторые ограничения. Помимо обязательного использования внутри вертикального компонента `scroll`, вам также необходимо убедиться, что количество элементов списка превышает размеры видимой области `scroll`, иначе могут возникнуть проблемы. Кроме того, интерактивный эффект `pullable` может быть относительно жестким.
