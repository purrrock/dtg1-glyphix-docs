# span

`span` 也是一种文本组件。和 [`p` 组件](p)不同，`span` 组件默认是行内元素并且可以跨行，[`label` ](label) 组件和 [`a`](a) 组件也有类似的效果。文本跨行是指元素可以跨越多行进行布局，而不是占据一整个“盒子”。

`span` 组件可以用于实现[富文本排版](/framework/render/rich-text.md#富文本显示)。

<glyphix id="span" :height="36">

``` html
<div>
  Hello Glyphix, this is <span style="color: #f0f">span</span> label!
</div>
```

</glyphix>

# marquee

Компонент `marquee` используется для отображения бегущего текста и поддерживает только одну строку. Компонент `marquee` не поддерживает никакие дочерние компоненты, включая `span`.

`marquee` поддерживает общие CSS-свойства, однако по техническим причинам в настоящее время свойство `text-align` может не поддерживаться. Поскольку `marquee` отображает только одну строку текста и прокручивает её при превышении допустимой длины, такие свойства, как `max-lines`, также не работают.

## Свойства

### `text` <decl type="string" get set/>

Устанавливает текстовое содержимое. Использование аналогично свойству [`text`](p.md#text) компонента `p`. Когда длина текста превышает ширину `marquee`, текст начинает автоматически прокручиваться.

# scroll-bar

Компонент полосы прокрутки. Этот компонент отображает полосу прокрутки при наличии большого объема прокручиваемого контента, позволяя пользователю управлять прокруткой с ее помощью.

## Свойства

### `value` <decl type="number" set get listen />

Текущее значение полосы прокрутки. Это значение находится в диапазоне между `min` и `max`, значение по умолчанию — $0$.

### `min` <decl type="number" set />

Минимальное значение полосы прокрутки. Это значение не должно превышать `max`. Значение по умолчанию — $0$.

### `max` <decl type="number" set />

Максимальное значение полосы прокрутки. Это значение должно быть не меньше `min`. Значение по умолчанию — $100$.

### `pagestep` <decl type="number" set />

Шаг прокрутки полосы прокрутки, то есть расстояние прокрутки за один раз. Значение по умолчанию — $10$.

# p

Текстовый компонент. По умолчанию `p` является блочным элементом. В отличие от [`span`](span), компонент `p` не поддерживает перенос текста на другую строку даже при установке в качестве строчного элемента. Если требуется верстка богатого текста (rich text), следует рассмотреть использование таких компонентов, как `span`.

## Свойства

### `text` <decl type="string" get set/>

Установка текстового содержимого. Поддерживает два следующих варианта написания:

``` html
<p text="Hello Glyphix"></p>
<p>Hello Glyphix</p>
```

<glyphix id="p" :height="70" inline>

``` html
<div>
  <p text="Hello Glyphix"></p>
  <p>Hello Glyphix</p>
</div>
```

</glyphix>

### `color` <decl type="string" get set/>

Установка цвета текста. Поддерживаются только шестнадцатеричные коды цветов, такие как `#f00`, `#e8bb80ff` и т. д. Это свойство является быстрым способом изменения встроенного CSS-свойства [`color`](/framework/generic/styles.md#color).

### `lines` <decl type="number" get set/>

Установка максимального количества строк текста. Текст, превышающий это число строк, будет обрезаться или сокращаться. Это свойство является быстрым способом изменения встроенного CSS-свойства [`max-lines`](/framework/generic/styles.md#max-lines).

### `text-align` <decl type="string" set/>

Установка выравнивания текста. Поддерживает такие значения, как `left`, `center`, `right` и др. Это свойство является быстрым способом изменения встроенного CSS-свойства [`text-align`](/framework/generic/styles.md#text-align).

### `font-size` <decl type="string" set/>

Установка размера шрифта текста. Поддерживает значения размеров шрифта CSS, такие как `12px`, `1.5em` и т. д. Это свойство является быстрым способом изменения встроенного CSS-свойства [`font-size`](/framework/generic/styles.md#font-size).

### `font-weight` <decl type="number" set/>

Установка жирности шрифта текста. В настоящее время поддерживаются только целочисленные значения, такие как `400`, `600` и т. д. Это свойство является быстрым способом изменения встроенного CSS-свойства [`font-weight`](/framework/generic/styles.md#font-weight).

## Советы по использованию

### Управление размером

Как правило, не следует вручную устанавливать высоту компонента `p`, например:
``` css
p.my-paragraph {
  height: 48px;
  font-size: 32px;
}
```
На первый взгляд это задает для компонента `p` высоту, превышающую размер шрифта, но на практике:
- Для однострочного текста фактическая высота некоторых шрифтов может превышать размер шрифта, и даже при высоте в `48px` может происходить вертикальная обрезка.
- Для многострочного текста установка фиксированной высоты приведет к тому, что текст будет обрезан и не отобразится полностью.

Если вы хотите контролировать количество отображаемых строк текста, вам следует использовать [`max-lines`](/framework/generic/styles.md#max-lines) и [`text-overflow`](/framework/generic/styles.md#text-overflow) для обрезки и сокращения текста, вместо установки фиксированной высоты.

### Анимация обрезки текста <version-badge since="0.9"/>

Вы можете использовать свойство [`width`](/framework/generic/styles.md#width) в сочетании с модификатором [`transition`](/framework/component/prop-modifier.md#transition-修饰符) для реализации анимации обрезки текста. Например:

``` html
<p :width="state ? 240 : 0"
   width.transition="{duration: 2.0}">
  Hello Glyphix!
</p>
```

В сочетании со стилем `max-lines: 1` это позволяет реализовать анимацию обрезки текста слева направо. Однако у этой анимации есть проблема: когда ширины недостаточно, последний символ отбрасывается напрямую, а не обрезается. Текущий обходной путь заключается в том, чтобы поместить текстовое содержимое в дочерний компонент и настроить анимацию ширины для родительского компонента:

``` html
<div :width="state ? 240 : 1"
     width.transition="{duration: 2.0}">
  <p style="max-lines: 1">Hello Glyphix!</p>
</div>
```

<glyphix id="p-width-transition" title="文字裁剪动画" height="120">

``` html
<div class="container">
  <p class="animated-text"
     :width="state ? 240 : 0"
     width.transition="{duration: 2.0}">
    Hello Glyphix!
  </p>
  <div class="animated-text"
       :width="state ? 240 : 1"
       width.transition="{duration: 2.0}">
    <p>Hello Glyphix!</p>
  </div>
</div>
```

``` js
export default {
  data: {
    state: false
  },
  onReady() {
    setInterval(() => this.state = !this.state, 2500)
  }
}
```

```css
.container {
  display: flex;
  flex-direction: column;
  align-items: center;
  justify-content: center;
  font-size: 1.25rem;
}

.animated-text {
  margin: 4px;
  border: 1px solid #f00;
}

p {
  max-lines: 1;
  text-overflow: clip;
}
````

</glyphix>

Однако при использовании элемента `div` в качестве родительского компонента у анимации возникает проблема: когда ширина равна `0`, размеры макета вычисляются как `(width: 0, height: 0)`, из-за чего элемент не может занимать вертикальное пространство, и в начале анимации происходит вертикальный скачок. Решение состоит в том, чтобы установить ширину в очень маленькое значение (например, `1px`) вместо `0`, чтобы элемент мог занимать вертикальное пространство, тем самым избегая проблемы со скачками.

# div

`div` 是最基本的容器组件。`div` 支持子组件及布局，但是不支持滚动（内容超出边界会直接裁剪）。如果想要内容滚动，请使用 [scroll](scroll) 组件。

## 注意事项

### 文本显示

`div` 组件不能直接用于显示文本，而是要使用 `p` 等文本组件来显示文本，例如：

```html
<!-- 错误的写法，不会显示文本 -->
<div>text content.</div>
<!-- 正确的写法 -->
<p>text content.</p>
```

不过如果 `div` 内有多个子元素，那么可以将文本作为它的子元素：

```html
<div>
  first element,
  <span style="color: #f0f">second element.</span>
</div>
```

# image-animator

Компонент `image-animator` используется для воспроизведения анимации из набора кадров последовательности изображений. По умолчанию компонент является строчным элементом (inline).

<glyphix id="image-animator-1" height="190" width="360" >

```html
<div class="flex-column">
  <div class="frame-box">
    <image-animator :images="frames" :play="play" :duration="100" />
  </div>
  <div>
    <button on:click="play = 'start'">start</button>
    <button on:click="play = 'pause'">pause</button>
    <button on:click="play = 'stop'">stop</button>
  </div>
</div>
```

```js
export default {
  data: {
    play: "stop",
  },
  frames: Array.from({ length: 60 }, (_, i) => `/assets/planet-${i}.png`),
};
```

```css
.flex-column {
  display: flex;
  flex-direction: column;
  justify-content: space-between;
  align-items: center;
}

.frame-box {
  border: 2px solid lightgray;
  border-radius: 8px;
  padding: 8px;
}

button {
  border-radius: 8px;
  background-color: #dee2e6;
  margin: 8px;
  padding: auto 12px;
}

button:active {
  opacity: 0.5;
}
```

</glyphix>

## Свойства

### `images` <decl type="string[]" set />

Задает набор кадров изображений. Каждый элемент `images` представляет собой путь или URI изображения для соответствующего кадра. Как правило, все кадры имеют одинаковый размер.

Поддерживаются изображения в формате PNG или JPEG.

Если последовательность кадров не меняется, рекомендуется объявить ее как нереактивное свойство для экономии памяти:

```js
export default {
  // frames — это нереактивное свойство компонента
  frames: [
    "/assets/sprite-1.png",
    "/assets/sprite-2.png",
    "/assets/sprite-3.png",
  ],
};
```

Преимущество такого подхода заключается в том, что несколько экземпляров компонентов будут использовать один и тот же массив `frames` (реактивные свойства копируются в каждый экземпляр компонента). Определять кадры в объекте `data` стоит только в том случае, если им действительно требуется реактивность.

Если кадры пронумерованы по порядку, вы можете использовать следующий прием для упрощения создания массива кадров:

```js
export default {
  // 4 кадра, пронумерованных с 0
  frames: Array.from({ length: 4 }, (_, i) => `/assets/sprite-${i}.png`),
  // Или 4 кадра, пронумерованных с 1
  frames: Array.from({ length: 4 }, (_, i) => `/assets/sprite-${i + 1}.png`),
};
```

Передайте массив `frames` в свойство `images` в шаблоне компонента, чтобы указать кадры и запустить анимацию:

```html
<image-animator :images="frames" play :duration="100" />
```

::: note
В настоящее время свойство `images` не поддерживает структуру `ImageFrame` из QuickApp, поэтому вы не можете использовать определения набора кадров вроде `[{ src: '...' }, ...]`.
:::

### `duration` <decl type="number" get set />

Задает продолжительность воспроизведения каждого кадра в миллисекундах.

### `play` <decl type="'start' | 'pause' | 'stop'" get set listen />

Задает состояние воспроизведения, поддерживаются состояния старта, паузы и остановки. Изначально `image-animator` находится в состоянии `stop`, поэтому он автоматически останавливается на первом кадре из [`images`](#images).

| Значение  | Описание                              |
| :-------: | ------------------------------------- |
| `'start'` | Начать воспроизведение с текущего кадра. |
| `'pause'` | Приостановить воспроизведение и отобразить текущий кадр. |
| `'stop'`  | Остановить воспроизведение и отобразить первый кадр. |

Как показано выше, `play` поддерживает только три значения перечисления: `'start'`, `'pause'` или `'stop'`. Тем не менее, следующий прием можно использовать для автоматического запуска анимации:

```html
<image-animator :images="frames" play :duration="100" />
```

То есть, можно просто указать атрибут `play` без значения. Это эквивалентно синтаксису [неявного значения свойства](/framework/component/template.md#неявные-значения-свойств) `:play="true"`. Булево значение `true` всегда преобразуется в значение перечисления по умолчанию `'start'`. Этот подход отлично подходит для сценариев, требующих автоматического воспроизведения анимации из кадров.

### `iteration` <decl type="number" set />

Задает количество повторов воспроизведения для всех кадров в `images`. При достижении лимита компонент автоматически переключится в режим `'pause'`. Значение `0` означает бесконечное воспроизведение.

`image-animator` имеет такое же поведение [наследуемых свойств](/components/image.md#наследуемые-свойства), как и компонент `image`.

## Стили CSS

`image-animator` имеет такое же [поведение CSS](/components/image.md#стили-css), как и компонент `image`.

# picker

Компонент текстового селектора. Этот компонент отображает набор текста: нажатие на текстовый элемент посередине инициирует событие выбора, а прокрутка позволяет просматривать все текстовые элементы.

::: warning
Функциональность компонента `picker` не проверена и он не поддерживается.
:::

## Свойства

### `range` <decl type="string[]" set />

Все строки из значения свойства `range` будут отображаться в компоненте `picker`. Пользователь может взаимодействовать с компонентом `picker`, прокручивая или выбирая эти строки.

Способ индексации строк в значении свойства `range` см. в описании [свойства `index`](#index).

### `loop` <decl type="boolean" set />

Настраивает, должен ли компонент `picker` отображаться в цикле (то есть быть бесконечным). Если это свойство установлено в значение `true`, циклическое отображение включено. По умолчанию используется значение `false`.

### `value` <decl type="string" listen />

Слушает текст текущего выбранного элемента. Это прослушивание срабатывает при изменении выбранного элемента в результате прокрутки. Функциональность этого свойства также может быть реализована с помощью метода `on:index="handle(rangeData[$event])"`.

### `index` <decl type="Integer" get set listen />

Индекс выбранного элемента компонента `picker`. Правило индексации следующее: индекс первого строкового элемента в массиве значения [свойства `range`](#range) равен $0$, а индексы остальных строк увеличиваются на единицу по порядку. Установка свойства `index` позволяет задать выбранный элемент компонента `picker`, а также прослушивать изменения этого свойства для отслеживания изменений выбранного элемента, вызванных прокруткой.

### `scroll` <decl type="{ x: number y: number }" get set listen />

С помощью свойства `scroll` можно прослушивать операцию прокрутки, а также программно управлять отображением эффекта прокрутки в компоненте `picker`. Подобно компонентам выровненного списка, операция `scroll` для `picker` также выполняет выравнивание по ближайшему элементу.

Поскольку компонент `picker` поддерживает только вертикальный режим, поле `x` значения свойства `scroll` всегда равно `0`.

### `scrolled` <decl type="boolean" read listen />

Используйте свойство `scrolled`, чтобы отслеживать, находится ли `picker` в состоянии прокрутки. Значение свойства, при котором срабатывает событие, равное `true`, означает, что `picker` прокручивается в данный момент; в противном случае `picker` прекратил прокрутку.

Событие `scrolled` вызывается как операциями прокрутки, вызванными прикосновениями пользователя, так и программной прокруткой через свойство `scroll`. Когда `picker` останавливается после прокрутки, значение параметра события `scrolled` равно `false`.

### `damping` <decl type="number" set />

Задает коэффициент затухания для анимации прокрутки `picker`. Допустимый диапазон значений составляет $[0.1, 50]$ (неподдерживаемые значения будут автоматически скорректированы до верхней или нижней границы), значение по умолчанию — $1.5$. Больший коэффициент затухания заставляет анимацию останавливаться быстрее, в то время как значение по умолчанию создает эффект инерции на более длинные дистанции и с большей продолжительностью.

Коэффициент затухания должен быть задан как константа, его не следует изменять динамически. Изменение коэффициента затухания не влияет на анимацию при отскоке.

# drawer

Компонент выдвижной панели (drawer), скрытый по умолчанию, содержимое которого можно отобразить с помощью смахивания.
`drawer` — это базовый компонент выдвижной панели. Он поддерживает дочерние компоненты и верстку. Внутри `drawer` можно разместить до 4 компонентов `drawer-navigation` для отображения панелей с четырех сторон: сверху, снизу, слева и справа.

Скорость прокрутки компонента [`drawer`](drawer) зависит от скорости жеста: чем быстрее движение пальца, тем быстрее перемещается компонент.

### Пример

В следующем примере продемонстрирована работа компонента `drawer`.

<glyphix id="components-drawer" height="360" width="360" >

``` html
 <drawer class="drop-down">
      <drawer-navigation direction="down" class="drop-down1">
        <p>dawn panel</p>
      </drawer-navigation>
      <drawer-navigation direction="up" class="drop-down1">
        <p>up panel</p>
      </drawer-navigation>
       <drawer-navigation direction="left" class="drop-down1">
        <p>left panel</p>
      </drawer-navigation>
       <drawer-navigation direction="right" class="drop-down1">
        <p>right panel</p>
      </drawer-navigation>
</drawer>
```
``` css
.drop-down {
    background-color: pink;
  }
.drop-down1 {
    background-color: blue;
  }
p {
  background-color: lightgreen;
  text-align: center;
  margin: 10px;
}
```
</glyphix>

# switch

Компонент переключателя, по умолчанию является строчным элементом (inline). Используется для отображения двух состояний — включено/выключено, и позволяет пользователю переключаться между ними. Функционал `switch` аналогичен `checkbox`, но имеет другие принципы взаимодействия и назначение, выражая соответственно переключение и выбор нескольких опций.

<glyphix id="components-switch" height="30">

``` html
<div>
  <switch ::value="enabled" />
  <span>switch state: {{ enabled ? 'on' : 'off' }}</span>
</div>
```

``` js
export default {
  data: {
    enabled: false
  }
}
```
</glyphix>

::: note
Стили компонента `switch` обычно выглядят так, как показано в примере, но могут отличаться в зависимости от устройства. Стоит особенно отметить, что ширина `switch` на разных устройствах может варьироваться, поэтому разработчикам следует закладывать подходящие отступы в макете.
:::

## Свойства (Attributes)

### `value` <decl type="boolean" set get listen/>

Определяет состояние `switch`. Когда значение равно `true`, `switch` находится во включенном состоянии, в противном случае — в выключенном. Если свойство `value` не задано, компонент `switch` по умолчанию выключен.

### `checked` <decl type="boolean" set get/>

Это совместимое свойство платформы Quick App, рекомендуется использовать [`value`](#value).

### `change` <decl type="{ checked: boolean }" get listen/>

Это совместимое свойство платформы Quick App, рекомендуется использовать [`value`](#value).

## CSS-поведение

Общий стиль компонента `switch` определяется системой и не контролируется разработчиком, подобно различиям в стилях между [Fluent 2](https://fluent2.microsoftdesign/components/web/react/switch/usage) и [Material 3](https://m3.material.io/components/switch/overview). Glyphix позволяет настраивать цвет `switch` с помощью CSS, а также изменять его размер.

### CSS-свойства

#### `color`

Устанавливает цвет ползунка компонента `switch`. В отличие от обычного CSS-свойства [`color`](/framework/generic/styles.md#color), свойство `color` для `switch` не наследуется, поэтому вы должны определять его непосредственно для текущего компонента `switch`.

<glyphix id="components-switch-color" height="36" title="siwtch 滑块颜色">

``` html
<div>
  red color: <switch class="red"/>,
  not inherited: <switch/>
</div>
```

``` css
div {
  color: red; /* Обратите внимание: switch не наследует свойство color */
}

.red {
  color: red; /* color должен быть определен в стилях компонента switch */
}
```
</glyphix>

#### `background-color`

Управляет фоновым цветом компонента `switch`. Подробнее см. в документации по псевдоклассу [`active`](#active). 

#### `font-size`

Вы можете использовать CSS-свойство [`font-size`](/framework/generic/styles.md#font-size) для настройки размера `switch`, чтобы согласовать его с размером окружающего строчного (inline) текста. В следующем примере показана зависимость между `font-size` и размером `switch`:

<glyphix id="components-switch-size" height="100" title="font-size 与 siwtch 大小">

``` html
<div>
  <p class="title">
    title text: <switch/> (1.25rem)
  </p>
  <p>
    content text: <switch/> (1rem)
  </p>
</div>
```

``` css
div {
  line-height: 1.8rem;
}

.title {
  color: #415a77; /* Обратите внимание: switch не наследует свойство color */
  font-size: 1.25rem;
}
```
</glyphix>

::: warning
Отображаемый размер `switch` не контролируется такими свойствами, как `width` и `height`, а всегда определяется через `font-size`. Поэтому не задавайте размеры вроде `width` вручную во избежание некорректного отображения.
:::

### CSS-псевдоклассы

#### `active`

Псевдокласс `active` используется для определения стиля `switch` в активном (включенном) состоянии. Как показано в примере ниже, он обычно настраивается вместе с правилами обычного стиля:

<glyphix id="components-switch-colors" height="36" title="siwtch 滑块颜色设置">

``` html
<div>
  color switch: <switch/>
</div>
```

``` css
/* Стиль switch в выключенном состоянии */
switch {
  color: #415a77;
  background-color: #bde0fe;
}

/* Стиль switch в включенном состоянии */
switch:active {
  color: #fefae0;
  background-color: #ffafcc;
}
```
</glyphix>

В этом примере цвета при переключении `switch` управляются с помощью CSS-свойств `color` и `background-color`. Компонент `switch` реагирует только на настройку этих двух CSS-свойств даже в состоянии, активированном псевдоклассом `active`.

::: tip
Пожалуйста, определяйте свойства `color` и `background-color` как для обычного состояния, так и для состояния `active`, иначе при переключении `switch` не будет соответствующего изменения цвета.
:::

# image

Компонент изображения используется для отображения элементов изображений, по умолчанию выравнивается по центру. Компонент `image` по умолчанию является строчным элементом.

## Свойства

### `src` <decl type="string" get set />

Устанавливает [URI](/framework/application/resource.md) изображения. Для локальных ресурсов изображения внутри пакета приложения поддерживаются как относительные, так и абсолютные пути. Компонент `image` поддерживает распространенные форматы изображений PNG и JPEG.

::: tip
Компонент `image` поддерживает только локальные ресурсы изображений, в отличие от элемента `img` в Web, который может напрямую отображать сетевые ресурсы изображений. Подробнее см. в разделе [Отображение сетевых изображений](#显示网络图片) в Glyphix.
:::

### `noCache` <decl type="boolean" get set />

Определяет, нужно ли кэшировать изображение. По умолчанию кэширование используется для оптимизации скорости загрузки. При включении свойства `noCache` компонент `image` не будет использовать кэш, и в этом случае при изменении свойства [`src`](#src) изображение всегда будет перезагружаться из файла.

Кэширование изображений — это технология, позволяющая оптимизировать скорость загрузки и уменьшить потребление памяти. Когда в системе уже загружено изображение с тем же URI, компонент `image` с включенным кэшем будет использовать этот ресурс напрямую. Однако файлы изображений с фиксированным именем, загружаемые из сети, содержимое которых может меняться (например, аватар пользователя `internal://cache/avatar.png`), обычно требуют включения свойства `noCache` для обеспечения корректного поведения.

Даже при включенном свойстве `noCache` компонент `image` по-прежнему не отслеживает обновление содержимого файла изображения, поэтому в таких случаях необходимо вручную изменить свойство [`src`](#src). Учитывая, что реактивный фреймворк фильтрует одинаковые операции присваивания, вы должны использовать следующий прием:
``` html
<!-- Предположим, это изображение, отображение которого нужно обновить; свойство no-cache является обязательным. -->
<image :src="avatarImage" no-cache />
```

``` js
const avatarImage = 'internal://cache/avatar.png' // Предположим, это изображение, загруженное из сети

export default {
  data: {
    avatarImage: avatarImage
  },
  // Вызовите этот метод после завершения загрузки аватара для обновления интерфейса
  onAvatarDownloaded() {
    this.avatarImage = null // Сначала необходимо присвоить новое значение
    this.avatarImage = avatarImage // Повторно присвоить правильный URI
  }
}
```
В приведенном выше примере реактивное свойство `this.avatarImage` сначала изменяется на `null`, а затем переназначается. Таким образом, значение меняется, что позволяет обойти механизм оптимизации реактивного фреймворка и выполнить обновление изображения.

::: warning
Вы должны использовать этот прием для обновления ресурсов с фиксированным URI, иначе отображаемое содержимое может не измениться. Для перестраховки, если путь к ресурсу, полученному из сети, может повторяться, вам также следует использовать этот прием для обеспечения обновления интерфейса.

Кроме того, необходимо дождаться завершения загрузки изображения или записи файла перед обновлением свойства `src` компонента `image`, иначе интерфейс также не сможет обновиться должным образом.
:::

### `async` <decl type="boolean" get set />

Использует асинхронный способ загрузки ресурсов изображений. Этот режим гарантирует, что загрузка изображения не будет блокировать UI-поток, повышая плавность интерфейса. Однако по сравнению с режимом синхронной загрузки по умолчанию, изображения при асинхронной загрузке не отображают фактическое содержимое, поэтому этот режим подходит не для всех интерфейсов.

Режим асинхронной загрузки подходит для изображений, загружаемых из сети. В отличие от ресурсов изображений, которые автоматически оптимизируются при сборке приложения, сетевые изображения обычно представляют собой универсальные форматы с медленным декодированием, такие как PNG или JPEG. Синхронное декодирование сетевых изображений может сильно тормозить работу, кроме того, в подобных сценариях обычно не требуется немедленное отображение картинки.

Свойство `async` может использоваться вместе со свойством [`noCache`](#nocache), так как последнее также в основном применяется для сетевых изображений:
``` html
<image :src="avatarImage" no-cache async />
```

## Наследуемые свойства

Эти свойства наследуются от [общих свойств](/framework/generic/properties.md) базовых компонентов, однако компонент `image` обрабатывает их особым образом.

### `opacity` <decl type="number" set />

Устанавливает прозрачность изображения. Диапазон значений составляет $[0, 1]$, где $0$ означает полную прозрачность, а $1$ — полную непрозрачность. Значение по умолчанию — $1$.

### `transform` <decl type="string" set />

Устанавливает эффект трансформации изображения, что эквивалентно свойству [`transform`](/framework/generic/styles.md#transform) в CSS.

## Описание CSS

### Неподдерживаемые общие свойства

По сравнению с другими базовыми компонентами, `image` является особенным: он не поддерживает такие общие свойства, как `background-color`, `border` и т. д. Это сильно отличается от стандартов Web. В частности, не поддерживаются следующие CSS-свойства:

- [`background-color`](/framework/generic/styles.md#background-color), [`background-image`](/framework/generic/styles.md#background-image)
- [`border`](/framework/generic/styles.md#border), [`border-top`](/framework/generic/styles.md#border-top), [`border-right`](/framework/generic/styles.md#border-right), [`border-bottom`](/framework/generic/styles.md#border-bottom), [`border-left`](/framework/generic/styles.md#border-left)

Это означает, что вы не можете добавить цвет фона или изображение к компоненту `image`, установив CSS-свойства, а также не можете задать для него стиль границы. Тем не менее, компонент `image` поддерживает свойство [`border-radius`](/framework/generic/styles.md#border-radius).

### Специальные свойства

Компонент `image` поддерживает другие CSS-свойства, применимые к неконтейнерным компонентам, но несколько свойств используются для достижения специальных эффектов.

#### `transform`

Устанавливает трансформацию изображения. Когда это CSS-свойство применяется к `image`, оно работает аналогично [`transform`](/framework/generic/styles.md#transform) для других элементов, но для корректного отображения не требуется устанавливать свойство [`transparent`](/framework/generic/styles.md#transparent).

#### `opacity`

Устанавливает прозрачность изображения, эффект аналогичен свойству [`opacity`](#opacity).

#### `border-radius`

Устанавливает радиус скругления углов изображения. Вы можете использовать это свойство для добавления скругленных углов к изображению, способ использования совпадает с общим [`border-radius`](/framework/generic/styles.md#border-radius). Компонент `image` всегда применяет скругление к четырем углам изображения независимо от того, совпадают ли соотношение сторон изображения и соотношение сторон самого компонента `image`.

#### `object-fit`

Значение свойства `object-fit` для компонента `image` по умолчанию равно `none`, что отличается от стандартов Web (где по умолчанию используется `fill`). По умолчанию изображения не масштабируются автоматически, а отображаются по центру в своем исходном размере; если размер превышает контейнер, они обрезаются. Такой дизайн обусловлен особенностями устройств на базе MCU:
- **Производительность превыше всего**: масштабирование изображений обычно требует дополнительных вычислений, а на некоторых устройствах интерполяционное масштабирование и вовсе реализуется программным путем, что существенно снижает частоту кадров.
- **Однородность качества изображения**: на некоторых устройствах даже пропорциональное уменьшение может привести к заметному размытию или зубчатым краям. Отказ от масштабирования по умолчанию гарантирует, что попиксельный рендеринг останется без искажений.
- **Ограниченная память**: масштабирование по умолчанию может замаскировать проблемы с использованием ресурсов, приведя к непреднамеренной загрузке слишком больших изображений и, как следствие, к пустой трате драгоценного места на хранилище и в оперативной памяти.

Рекомендуется на этапе проектирования предоставлять ресурсы изображений, соответствующие области отображения, и по возможности позволять изображению правильно отображаться в состоянии по умолчанию; настраивать отображение с помощью явного задания `object-fit` (например, `contain`) следует только тогда, когда это действительно необходимо.

## Советы по использованию

### Отображение сетевых изображений

#### Сценарии с аватарами

В этом разделе демонстрируется метод загрузки изображений из сети, который в основном используется в таких случаях, как аватары пользователей, когда у изображения есть фиксированное место хранения локально, но его содержимое может изменяться. Из-за стратегии кэширования среды выполнения Glyphix вам потребуется использовать прием из этого примера, чтобы обеспечить обновление отображаемого содержимого.

``` html
<template>
  <image :src="avatar" no-cache />
</template>
```

``` js
import request from '@system.request'

export default {
  data: {
    avatar: null
  },
  onInit() {
    this.downloadAvatar()
  },
  async downloadAvatar() {
    const saveFile = 'internal://files/avatar.png'
    await request.download({
      url: 'https://example.com/url/to/avatar.png',
      filename: saveFile,
    }).complete
    // Подробнее об этом приеме см. в описании свойства noCache
    this.avatar = null
    this.avatar = saveFile
  }
}
```

# barcode

组件 `barcode` 用于显示 [Code 128](https://en.wikipedia.org/wiki/Code_128) 条形码。`barcode` 组件可以显示任意 ASCII 字符串，适合用于显示商品条码、支付码等信息。

在流式布局中，`barcode` 组件默认为块级元素（`block`），会单独占据一行显示。

## 属性

### `value` <decl type="string" get set />

设置条形码要显示的内容。支持任意 ASCII 字符串。

## CSS 说明

要想让条形码容易被扫描，应正确设置 `barcode` 组件的 CSS 属性，这包括：
- `color`：条形码的条颜色，一般设置为黑色（`black` 或者 `#000`）；
- `background-color`：条形码的背景色通常要是白色（`white` 或者 `#fff`）；
- `padding` / `margin`：足够的内外边距可以避免条形码和其他元素混淆，增加扫描识别率；
- `width` / `height`：条形码的尺寸必须足够大以方便拍摄。

默认情况下条形码组件的每一条码会占据 $2\rm px$ 宽度和 $32\rm px$ 高度，这在手表等小屏幕设备上可能过小，建议开发者根据需要手动设置条形码组件的 `width` / `height` 属性并在设备上进行测试。

下面的例子展示了条形码组件的使用方法，请注意 CSS 中为 `barcode` 组件设置了各种边距，这都是为了保证条形码和其他界面元素有足够的间隔以免干扰扫描。

<glyphix id="barcode-1" :height="150" :width="350">

``` html
<div>
  <barcode :value="text"/>
  <p>{{ text }}</p>
</div>
```

``` js
export default {
  data: {
    text: '9787111407010'
  }
}
```

``` css
div {
  background-color: black;
  padding: 8px;
}

barcode {
  margin: 8px;
  padding: 8px;
  color: black; /* 将条形码前景色设置为黑色 */
  background-color: white; /* 将条形码背景色设置为白色 */
  border-radius: 16px;
  height: 80px;
}

p {
  color: white;
  font-size: 0.75rem;
  text-align: center;
}
```

</glyphix>

::: tip
应总是显式设置**高对比度**的条形码组件的码点颜色（`color`）和背景（`background-color`）样式，以免设备的默认样式主题和继承的样式属性偏差导致识别性下降。

同时，请设置足够大的内边距（`padding`），确保容易扫描识别。
:::

# slider

Ползунок (slider), по умолчанию является блочным элементом.

## Свойства

### `value` <decl type="number" get set listen />

Текущее значение, значение по умолчанию: $10$.

При установке свойства `value` изменяется текущее значение компонента. Вы можете отслеживать изменения текущего значения с помощью директивы `on`, которая будет срабатывать при каждом изменении значения.

### `min` <decl type="number" set />

Минимальное значение, значение по умолчанию: $0$.

### `max` <decl type="number" set />

Максимальное значение, значение по умолчанию: $100$.

### `vertical` <decl type="boolean" set />

Если значение свойства `vertical` равно `true`, компонент `slider` будет отображаться вертикально, в противном случае — горизонтально. Значение по умолчанию: `false`.

## Спецификация CSS

Разработчики могут настраивать внешний вид компонента `slider` с помощью CSS.

### Расчет размеров

Ширина и высота `slider` по умолчанию равны размеру шрифта элемента, который задается свойством [`font-size`](/framework/generic/styles.md#font-size) (или наследуется). Вы можете задать собственные размеры `progress` с помощью свойств [`width`](/framework/generic/styles.md#width) и [`height`](/framework/generic/styles.md#height).

### CSS-свойства

Следующие CSS-свойства могут быть весьма полезны:
- [`background-color`](/framework/generic/styles.md#background-color) управляет фоновым цветом `slider`;
- [`color`](/framework/generic/styles.md#color) управляет цветом полосы прогресса `slider`;
- [`border-radius`](/framework/generic/styles.md#border-radius) позволяет сделать углы `slider` скругленными, например, значение `50%` создаст полукруглые края.

Другие CSS-свойства также могут пригодиться, например, вы можете использовать свойство [`border`](/framework/generic/styles.md#border) для настройки стиля рамки.

### CSS Псевдоэлементы

#### `value`

Этот псевдоэлемент позволяет отдельно задавать стиль полосы прогресса `slider` без учета фоновой части. Например, можно задать разные радиусы скругления для фона полосы прокрутки и для самой полосы прогресса, чтобы внешняя рамка имела закругленные концы, а полоса прогресса — прямые.

``` css
slider {
  border-radius: 50%; /* Скругление углов фона полосы прокрутки */
}

slider::value {
  border-radius: 0; /* У полосы прогресса нет скругления углов */
}
```

#### `thumb` <experimental/>

Псевдоэлемент `thumb` используется для определения стиля ползунка `slider`. По умолчанию `slider` не содержит ручки (ползунка); чтобы она отображалась, необходимо указать ширину и высоту элемента `thumb`:
``` css
slider::thumb {
  width: 150%;
  height: 150%;
  border-radius: 50%;
}
```
Значения `width` и `height` в процентах рассчитываются относительно размеров самого элемента. Ширина и высота ползунка горизонтального `slider` рассчитываются на основе CSS-свойства `height` элемента, в то время как для вертикального `slider` размеры ручки рассчитываются на основе CSS-свойства `width`. Например, если CSS элемента выглядит так:
``` css
slider {
  width: 200px;
  height: 24px;
}
```
Тогда ширина и высота ползунка для указанного выше `slider::thumb` составят $24\rm{px} \times 150\% = 36\rm{px}$. В свою очередь, процентный радиус скругления углов ручки рассчитывается исходя из ее собственных размеров; в данном примере расчетное значение радиуса скругления псевдоэлемента `thumb` со значением `50%` составит $36\rm{px} \times 50\% = 18\rm{px}$.

Псевдоэлемент `thumb` поддерживает CSS-свойство `border`, однако граница не будет выходить за пределы размеров самого псевдоэлемента `thumb`.

# textarea

`textarea` <experimental/><version-badge since="0.9" /> — это компонент многострочного текстового ввода, который по умолчанию отображается как блочный элемент. В отличие от аналогичных GUI-элементов на мобильных устройствах или ПК, `textarea` в настоящее время не реагирует на устройства ввода, такие как клавиатура, и не вызывает интерфейс метода ввода (клавиатуру), поэтому редактировать его содержимое необходимо вручную. `textarea` поддерживает управление курсором с помощью сенсорных жестов (например, нажатие и прокрутка) и предоставляет методы для перемещения курсора вверх, вниз, влево и вправо.

`textarea` подходит в качестве базового компонента для ввода многострочного текста, позволяя самостоятельно реализовать программную клавиатуру и управление курсором в соответствии с вашими требованиями. Подробности см. в [примере](#基本示例).

::: important Совместимость
`textarea` — это экспериментальный расширенный компонент, который в настоящее время доступен только в Glyphix версии 0.9 и выше, причем поддерживается только на некоторых устройствах.
:::

## Свойства

### `text` <decl type="string" get set listen />

Свойство `text` представляет собой строку, содержащую текущий редактируемый текст в `textarea`. Чтение или прослушивание этого значения позволяет получить введенный текст, также это свойство можно устанавливать.

Обычно `text` двунаправленно связывается с определенным реактивным свойством, но текст также можно задать через внутреннее содержимое элемента, например:

```html
<textarea ::text="inputText" />
```

или

```html
<textarea @text="onTextChanged">{{ inputText }}</textarea>
```

:::tip
Свойство `text` компонента `textarea` аналогично по функционалу свойству [`value`](text-field.md#value) компонента [`text-field`](text-field.md).
:::

### `placeholder` <decl type="string" set get />

Когда содержимое `textarea` пусто, с помощью свойства `placeholder` можно показать пользователю короткую подсказку, например «Введите текст» и т. п.

`placeholder` отображается автоматически, когда вводимый текст пуст, поэтому обычно требуется лишь фиксированное содержимое, например:

```html
<textarea ::text="inputText" placeholder="type here" />
```

### `insert` <decl type="(text: string): void" method />

Вставляет текст с содержимым `text` в позицию курсора, при этом курсор автоматически перемещается сразу за вставленным текстом. Вызов этой функции вызывает событие прослушивания `text`.

### `backspace` <decl type="(): void" method />

Удаляет символ в позиции курсора, при этом курсор автоматически смещается назад. Вызов этой функции вызывает событие прослушивания `text`.

### `moveCaret` <decl type="(direction: 'up' | 'down' | 'left' | 'right'): void" method />

Перемещает курсор на одну позицию в указанном направлении. Параметр `direction` может принимать значения `'up'`, `'down'`, `'left'`, `'right'`, которые соответствуют направлениям вверх, вниз, влево и вправо.

# button

Компонент кнопки, по умолчанию является строчным элементом. При касании компонента генерируются соответствующие события.

## Свойства

### `checkable`  <decl type="boolean" set />

Если установлено значение `true`, это означает, что одно касание вызывает изменение состояния только один раз, а именно: переход из состояния нажатия в отпущенное или из отпущенного в нажатое. При этом значение прослушивателя состояния нажатия `press` равно `true`, а для отпущенного состояния — `false`.

### `toggleable` <decl type="boolean" set />

Если установлено значение `true`, это означает, что значение прослушивателя `press` может изменяться: при нажатии оно равно `true`, а при отпускании — `false`.

### `press` <decl type="boolean" get set listen />

При установке свойства `press` можно изменить состояние компонента. Состояние компонента также можно отслеживать с помощью директивы `on`. По умолчанию после завершения одного касания параметр обратного вызова равен `ture`. Вы можете использовать свойства `checkable` и `toggleable` для получения различных значений прослушивателя и состояний.

## Ограничения функциональности

### Сбой события `click`

Когда компонент `button` не используется, для прослушивания событий клика любых нативных компонентов обычно применяется свойство [`click`](/framework/generic/properties.md#click). Однако этот подход обычно не применим к `button`. Например, следующий код:
```html
<button on:click="onOuterClick">
  <p on:click="onInnerClick">inner</p>
  outer button
</button>
```

```js
export default {
  onOuterClick() {
    console.log('outer click');
  },
  onInnerClick(event) {
    // 阻止事件冒泡，以免外层按钮响应点击事件
    event.stopPropagation();
    console.log('inner click');
  }
}
```

``` html
  <p on:click="onInnerClick">inner</p>
  outer button
</button>
```

``` css
  display: flex;
  align-items: center;
```

Вы можете ожидать, что при нажатии на текст `"inner"` сработает метод `onInnerClick` и предотвратит выполнение `onOuterClick`. Но вы обнаружите, что это не так (лучше открыть консоль браузера для просмотра логов): метод `onInnerClick` вообще не вызывается, а на клик реагирует только внешний компонент `button`, то есть:
- При нажатии на текст `inner` лог `inner click` не появляется, выводится только лог `outer click`;
- Срабатывает интерактивный эффект нажатия `button` (снижение прозрачности).

Это происходит так же, как при клике на внешний текст `outer text`. Причина такого поведения заключается в том, что компонент `button` имеет приоритет в обработке всего жизненного цикла жеста нажатия (от нажатия до отпускания пальца), в то время как событие `click` срабатывает в момент отпускания. Это означает, что независимо от того, предотвращает ли обработчик события `click` внутреннего элемента всплытие события, такое поведение не изменится.

#### Решение

Для решения этой проблемы следует прослушивать событие `press` внешнего элемента `button` и событие `touchstart` внутреннего элемента:

```html
<button on:press="onOuterClick">
  <p on:touchstart="onInnerClick">inner</p>
```

# progress-arc

Компонент `progress-arc` используется для отображения кругового индикатора выполнения (прогресс-бара) и по умолчанию является блочным элементом.

## Свойства

### `max` <decl type="number" set />

Максимальное значение прогресса. Значение свойства [`value`](#value) не может превышать его.

### `min` <decl type="number" get setet />

Минимальное значение прогресса. Значение свойства [`value`](#value) не может быть меньше него.

### `value` <decl type="number" get set listen />

Установка значения прогресса. Отображаемая доля выполнения зависит от соотношения значения свойства `value` в диапазоне от `min` до `max`, при этом коэффициент отображения ограничивается в пределах от $0\% \text{ до } 100\%$. Значение `value` является целым числом; если задано число с плавающей точкой, будет взята только его целая часть.

### `busy` <decl type="boolean" get set />

Устанавливает, находится ли компонент `progress-arc` в состоянии загрузки (занят). В этом состоянии отображается анимация загрузки вместо значения свойства `value`. В следующем примере показано, как использовать круговой индикатор выполнения для имитации анимации загрузки:

<glyphix id="components-progress-arc-busy" height="100" width="300" title="Имитация анимации загрузки">

``` html
<progress-arc busy :startAngle="0" :stopAngle="360" />
```

</glyphix>

В этом примере начальный и конечный углы индикатора выполнения отличаются на $360^\circ$. В таком случае свойство `busy` позволяет отобразить типичный эффект анимации загрузки.

::: tip
Если индикатор выполнения имеет форму кольца, всегда будет отображаться фиксированный эффект анимации загрузки, независимо от начального и конечного углов.
:::

### `startAngle` <decl type="number" get set />

Начальный угол дугового индикатора выполнения, значение по умолчанию — $135$. Для получения дополнительной информации обратитесь к разделу [Конфигурация углов](#конфигурация-углов).

### `stopAngle` <decl type="number" get set />

Конечный угол дугового индикатора выполнения, значение по умолчанию — $405$. Для получения дополнительной информации обратитесь к разделу [Конфигурация углов](#конфигурация-углов).

## Инструкции по использованию

### Конфигурация углов

В отличие от линейного компонента [`progress`](progress.md), для корректного отображения дугового или кольцевого индикатора выполнения необходимо правильно настроить свойства `startAngle` и `stopAngle`. Оба эти свойства используют градусы в качестве единицы измерения. В системе координат экрана угол $0^\circ$ указывает в горизонтальном направлении вправо (положение часовой стрелки на `3` часа) и увеличивается по часовой стрелке, уменьшаясь против нее.

Отображение `progress-arc` представляет собой линейную интерполяцию диапазона углов на основе пропорции `value` в диапазоне $[\texttt{min}, \texttt{max}]$. В частности, пользователи увидят, что выделенный угол выполнения начинается с `startAngle` и заканчивается на `valueAngle`:

$$
\begin{aligned}
  k &= \frac{\texttt{value} - \texttt{min}}{\texttt{max}-\texttt{min}}\\
  \texttt{valueAngle} &= (1-k)\texttt{startAngle} + k\cdot\texttt{stopAngle}
\end{aligned}
$$

Поэтому, чтобы отобразить полный круг индикатора выполнения, необходимо, чтобы начальный и конечный углы отличались на $360^\circ$, даже если визуально эти углы совпадают. Кроме того, начальный угол может быть больше конечного, что приведет к инвертированию направления прогресса.

В следующем примере показаны реальные эффекты различных конфигураций углов. Обратите внимание, что второй пример демонстрирует прием обратного отображения прогресса.

## Спецификация CSS

### Расчет размеров

Отображаемый размер `progress-arc` определяется его свойствами `width` и `height`. Компонент `progress-arc` заполняет более короткую ось, а центром дугового индикатора является центр элемента. По умолчанию размер `progress-arc` может быть близок к размеру одного символа, что может привести к очень странному визуальному эффекту. Поэтому обычно требуется явно указывать ширину и высоту в CSS или использовать другие разумные стратегии компоновки.

::: tip
Лучше всего задать для компонента `progress-arc` разумную ширину и высоту, иначе он может стать неразличимым. Как минимум, следует задать CSS-свойство `width`, и стратегия компоновки компонента автоматически применит соотношение сторон $1:1$.
:::

### Свойства CSS

Внешний вид компонента `progress-arc` можно настраивать с помощью CSS.

#### `stroke-width`

Это свойство задает ширину контура дуги компонента `progress-arc`. Тип значения — [длина](/framework/render/style-and-layout.md#长度), проценты не поддерживаются.

::: tip
Если вы хотите, чтобы ширина отрисовки компонента `progress-arc` была пропорциональна размеру шрифта, рекомендуется использовать единицы длины [`rem`](/framework/application/font-config.md#rem-字号单位), например `0.15rem`.
:::

#### `color`

Устанавливает цвет выделенной полосы прогресса `progress-arc`. По умолчанию используется основной цвет темы системы.

#### `background-color`

Устанавливает цвет фоновой полосы прогресса `progress-arc`. По умолчанию цвет настраивается в соответствии с системной темой.

## Свойства

### `checked` <decl type="boolean" get set listen />

Это свойство указывает, выбран ли данный флажок. Установка свойства `checked` позволяет переключать состояние флажка: когда значение равно `true`, он отображается как выбранный. Также можно управлять отдельным флажком с помощью двустороннего связывания:
``` html
<checkbox model:checked="yes" />
```

В предыдущем примере этой статьи показано использование такого связывания. Обратите внимание, что следует привязываться не к свойству [`value`](#value), а к `checked`.

Событие срабатывает только тогда, когда пользователь нажимает на флажок, что приводит к изменению свойства `checked`.

::: warning
Не устанавливайте свойство `checked` в [группе флажков](#group), чтобы избежать путаницы.
:::

### `value` <decl type="any" get set />

Значение JavaScript, определяющее значение флажка, обычно это строка или число. Это значение не отображается визуально, но может использоваться в [операциях с группами](#group).

### `group` <decl type="any[]" get set listen />

Если у вас есть несколько связанных компонентов `checkbox`, вы можете объединить свойства `group` и `value`; флажки в одной группе образуют массив выбранных значений. Пожалуйста, обратите внимание на следующий пример:

<glyphix id="checkbox-group" :height="65" title="Группа флажков" >

``` html
<div>

  <div>
    <checkbox id="red" value="red" model:group="selected" />
    <label target="red">red</label>
    <checkbox id="blue" value="blue" model:group="selected" />
    <label target="blue">blue</label>
    <checkbox id="yellow" value="yellow" model:group="selected" />
    <label target="yellow">yellow</label>
  </div>
</div>
```

``` js
export default {
  data: {
    selected: ['yellow']
  }
}
```

``` css
label {
  margin-right: 0.5rem;
}
```

</glyphix>

Используя `model:group` или `::group` для двустороннего связывания свойства `group` с реактивным массивом (`selected` в примере), можно добиться следующего:
- После того как пользователь взаимодействует с каким-либо флажком в группе, значение реактивного массива обновляется;
- Изменения элементов реактивного массива отражаются на внешнем виде `checkbox`.

Как показано в примере выше: в начальном состоянии выбор флажков в группе определяется значением свойства `group`. В частности, для такого флажка:
``` html
<checkbox value="red" model:group="selected" />
```
Поскольку свойство `value` задает значение `"red"`, когда значение реактивного свойства `selected` содержит `"red"` (например, `["red"]`), этот флажок будет выбран. Повторный клик пользователя по этому флажку приведет к тому, что он станет невыбранным, а элемент `"red"` будет удален из массива `selected`.

::: tip
Если вы не хотите группировать флажки, вы можете использовать свойство [`checked`](#checked) для управления каждым по отдельности. Но не используйте `checked` и `group` одновременно, Glyphix не рассчитан на такой сценарий.
:::

### `indeterminate` <decl type="boolean" get set />

Свойство `indeterminate` указывает, что флажок находится в **неопределенном** состоянии. Когда это свойство имеет значение `true`, посередине флажка отображается горизонтальная линия, похожая на знак минус, обозначающая неопределенность его состояния.

Неопределенное состояние может использоваться, когда у элемента есть несколько подэлементов: если выбраны все дочерние элементы, выбирается и родительский; если не выбран ни один, родительский также не выбирается. Если выбрана лишь часть дочерних элементов, родительский элемент переходит в неопределенное состояние.

В следующем примере демонстрируется такое использование. Здесь показан список ингредиентов для зачарования стола: когда вы выбираете только часть рецептов, флажок «Enchantment table» переходит в частично выбранное состояние. Как вы можете видеть, этот пример позволяет использовать родительский флажок для выбора или отмены выбора всех дочерних элементов.

<glyphix id="checkbox-indeterminate" :height="140" title="Трехсостояниевой флажок" >

``` html
<div>
  <div>
    <!--
      Когда selected.length == 3, entirety выбирается, в противном случае:
      - Если selected.length == 0, то не выбран;
      - В остальных случаях выбрана лишь часть рецептов, поэтому состояние indeterminate. 
      -->
    <checkbox id="entirety"
              :indeterminate="selected.length && selected.length < 3"
              :checked="selected.length == 3"
              on:checked="selectEntirety" />
    <label target="entirety">
      &nbsp;Enchantment table:
    </label>
  </div>
  <div class="group">
    <div for="x in parts">
      •
      <checkbox :id="x" :value="x" model:group="selected" />
      <label :target="x">&nbsp;{{x}}</label>
    </div>
  </div>
</div>
```

``` js
export default {
  data: {
    selected: ['Diamonds'],
  },
  parts: ['Book', 'Diamonds', 'Obsidian'],
  // Вызывается при клике на флажок entirety для установки состояния выбора всех рецептов
  selectEntirety(status) {
    // Используйте [...this.parts] для копирования списка, чтобы избежать изменения исходного массива
    this.selected = status ? [...this.parts] : []
  },
}
```

``` css

  margin-left: 0.4rem;
}
```

</glyphix>

При установке свойства `checked` (обратите внимание: именно при установке, а не при сбросе) свойство `indeterminate` автоматически очищается. Даже если у флажка установлены оба этих свойства, он будет отображаться как выбранный, а не в неопределенном состоянии.
:::

# qrcode

Компонент `qrcode` используется для отображения [QR-кодов](https://en.wikipedia.org/wiki/QR_code). Этот компонент может отображать любые текстовые данные и отлично подходит для показа URL-адресов, платежных кодов, ссылок для авторизации по QR-коду и другой информации.

В потоковой разметке (flow layout) компонент `qrcode` по умолчанию является блочным элементом (`block`) и занимает отдельную строку.

## Свойства

### `value` <decl type="string" get set />

Устанавливает текстовые данные, которые будут отображаться в виде QR-кода. Компонент `qrcode` автоматически выбирает подходящую версию в зависимости от длины данных. В настоящее время максимальная поддерживаемая версия — $12$.

## Стили CSS

Чтобы QR-код легко сканировался, необходимо правильно настроить CSS-свойства компонента `qrcode`, включая:
- `color`: цвет точек (модулей) QR-кода, обычно устанавливается черным (`black` или `#000`);
- `background-color`: цвет фона QR-кода, обычно должен быть белым (`white` или `#fff`);
- `padding` / `margin`: достаточные внутренние и внешние отступы предотвращают слияние QR-кода с другими элементами и повышают процент успешного распознавания при сканировании;
- `width` / `height`: размеры QR-кода должны быть достаточно большими для удобства съемки.

По умолчанию каждый модуль (точка) компонента QR-кода занимает область $4\rm{px}\times 4\rm{px}$, что на часах может оказаться минимально допустимым для распознавания размером. Однако стратегии верстки, такие как flex, могут уменьшить размер QR-кода, поэтому разработчикам рекомендуется вручную настраивать свойства `width` / `height` компонента QR-кода в соответствии с потребностями и тестировать его на устройстве.

В следующем примере показано использование компонента QR-кода. Обратите внимание, что в CSS для компонента `qrcode` заданы различные отступы — все это сделано для того, чтобы обеспечить достаточный зазор между QR-кодом и другими элементами интерфейса во избежание помех при сканировании.

``` html
  <p>{{ text }}</p>
```

# mapview

Картографический компонент, используемый для загрузки и отображения карт на основе тайлов (Tile). `mapview` поддерживает панорамирование жестами, переключение уровней масштабирования, отображение текущего местоположения и прорисовку навигационных маршрутов. Это ключевой компонент для создания картографических приложений.

По умолчанию `mapview` является блочным элементом.

::: tip
`mapview` — это компонент расширения среды выполнения (runtime). Перед использованием убедитесь, что целевая платформа интегрировала модуль `mapview`.
:::

## Свойства

### `baseUri` <decl type="string" get set />

URI **базового пути** к ресурсам тайловой карты. Файлы тайлов будут храниться в этом каталоге в виде фиксированной иерархической структуры. `mapview` автоматически рассчитывает путь к нужному файлу тайла на основе текущего уровня масштабирования и координат в следующем формате:

```
{baseUri}/{zoomLevel}/{tileX}/{tileY}/normal.png     (стандартная карта)
{baseUri}/{zoomLevel}/{tileX}/{tileY}/satellite.png  (спутниковая карта)
```

Типичное использование заключается в кэшировании тайлов карты в локальном хранилище устройства с последующим указанием `baseUri` на соответствующий каталог:

```html
<mapview baseUri="internal://files/tiles/map_provider" />
```

### `tileType` <decl type="number" get set />

Тип слоя тайловой карты, возможные значения:

| Значение | Описание |
| :-: | :-- |
| `0` | Стандартная карта (по умолчанию), загружает файлы тайлов `normal.png` |
| `1` | Спутниковая карта, загружает файлы тайлов `satellite.png` |

### `loadPlace` <decl type="string" get set />

URI **изображения-заглушки**, отображаемого во время загрузки тайла. Если соответствующий файл тайла еще не кэширован локально, `mapview` отобразит это изображение в позиции тайла до тех пор, пока тайл не будет загружен, после чего вызывается обновление [`reload()`](#reload).

```html
<mapview loadPlace="/assets/imgs/loading.png" />
```

### `zoomLevel` <decl type="number" get set />

Уровень масштабирования карты, диапазон значений составляет $[3, 23]$, значение по умолчанию — $17$. Чем выше уровень, тем подробнее карта; чем ниже уровень, тем больше видимая область.

::: info
Это свойство соответствует стандарту уровней масштабирования (Zoom Level) для тайлов карт и совпадает с определениями уровней в таких популярных тайловых сервисах, как Bing Maps и Google Maps.
:::

### `arrowIcon` <decl type="string" get set />

URI изображения значка текущего местоположения. Этот значок отображается на экране в точке с географическими координатами, заданными свойствами [`navCoordinate`](#navcoordinate) или методом [`setLocation()`](#setlocation). Значок выравнивается по центру относительно координатной точки.

```html
<mapview arrowIcon="/assets/imgs/location.png" />
```

### `navCoordinate` <decl type="{ x: number, y: number }" get set />

Координаты текущего местоположения в формате `{ x: latitude, y: longitude }`, где `x` — широта (latitude), а `y` — долгота (longitude). Установка этого свойства обновляет только положение значка и не приводит к автоматическому смещению центра карты в эту координату. Если вам нужно одновременно с этим центрировать карту на текущем месте, используйте метод [`setLocation()`](#setlocation) с параметром `force: true`.

::: tip
Для сценариев, требующих отслеживания текущего местоположения в реальном времени, рекомендуется использовать метод [`setLocation()`](#setlocation) вместо прямого присваивания значений этому свойству, чтобы управлять автоматическим возвратом в центр с помощью параметра `force`.
:::

### `arrowLineWidth` <decl type="number" get set />

Ширина линии навигационного маршрута в пикселях, значение по умолчанию — `12`.

### `arrowLineBackgroundColor` <decl type="color" get set />

**Цвет фона** навигационного маршрута (цвет уже пройденного участка). Принимает значения цветов CSS, по умолчанию `#898b90`.

### `arrowLineForgeColor` <decl type="color" get set />

**Цвет переднего плана** навигационного маршрута (цвет оставшейся части маршрута). Принимает значения цветов CSS, по умолчанию `#4b73ec`.

### `smallMem` <decl type="boolean" get set />

Включать ли режим работы на устройствах с ограниченным объемом памяти (Low Memory), по умолчанию `false`.

При включении `mapview` объединяет и масштабирует четыре тайла размером 256×256 в одно изображение 512×512 для рендеринга. Это снижает количество одновременно кэшируемых в памяти тайлов для адаптации под устройства с ограниченной оперативной памятью.

::: warning
Режим экономии памяти ухудшает детализацию карты, поэтому его следует включать только при явной нехватке памяти на устройстве.
:::

### `missTiles` <decl type="Array<{ z: number, x: number, y: number }>" get listen />

Свойство только для чтения, срабатывает, когда карта обнаруживает отсутствие локальных файлов тайлов. Параметр обратного вызова представляет собой массив, каждый элемент которого описывает один недостающий тайл:

| Поле | Тип | Описание |
| :-- | :-- | :-- |
| `z` | `number` | Уровень масштабирования (Zoom Level) |
| `x` | `number` | Координата X тайла (номер столбца) |
| `y` | `number` | Координата Y тайла (номер строки) |

Получив это событие, приложение обычно должно скачать соответствующие файлы тайлов с сервера и после завершения загрузки вызвать [`reload()`](#reload) для обновления карты:

```js
export default {
  missTileHandler(tiles) {
    // tiles: [{ z: 17, x: 105234, y: 49832 }, ...]
    downloadTiles(tiles).then(() => {
      this.$element('mapview').reload()
    })
  }
}
```

```html
<mapview id="mapview" on:missTiles="missTileHandler" />
```

### `directionInfo` <decl type="{ event: string, stepIndex?: number, distance?: number }" get listen />

Свойство событий карты только для чтения, срабатывает при выполнении следующих действий с картой:

| Значение `event` | Момент срабатывания | Дополнительные поля |
| :-- | :-- | :-- |
| `"move"` | Срабатывает при панорамировании карты пользователем с помощью жестов | Нет |
| `"calc"` | Срабатывает при пересчете местоположения и отклонения от маршрута во время навигации | `stepIndex` (индекс текущего участка маршрута), `distance` (расстояние отклонения текущего положения от маршрута в метрах) |

```js
export default {
  onDirectionInfo(info) {
    if (info.event === 'move') {
      // Пользователь вручную перетащил карту, можно приостановить автоматическое центрирование
    } else if (info.event === 'calc') {
      console.log(`Текущий шаг: ${info.stepIndex}, расстояние отклонения: ${info.distance} м`)
    }
  }
}
```

## Методы

### `reload()`

Перезагружает все тайлы. Этот метод необходимо вызывать для обновления отображения карты после записи новых файлов тайлов в локальное хранилище.

```js
this.$element('mapview').reload()
```

### `locate()`

Перемещает центр карты в текущее местоположение (координаты, заданные в [`navCoordinate`](#navcoordinate)). Используется для функции «вернуться к текущему местоположению».

```js
this.$element('mapview').locate()
```

### `setLocation(location)`

Устанавливает координаты текущего местоположения и опционально перемещает центр карты в эту точку.

| Поле параметра | Тип | Описание |
| :-- | :-- | :-- |
| `latitude` | `number` | Широта |
| `longitude` | `number` | Долгота |
| `force` | `boolean` | Если `true`, немедленно центрирует карту на этих координатах (эквивалентно вызову [`locate()`](#locate)); если `false`, обновляет только положение значка |

```js
// Обновляем только положение значка, не перемещая карту
this.$element('mapview').setLocation({
  latitude: 39.9042,
  longitude: 116.4074,
  force: false,
})

// Обновляем положение значка и центрируем карту на этих координатах
this.$element('mapview'].setLocation({
  latitude: 39.9042,
  longitude: 116.4074,
  force: true,
})
```

### `startNav(linePoints)`

Устанавливает навигационный маршрут и запускает навигацию. После вызова карта автоматически позиционируется на начале маршрута и прорисовывает его целиком.

`linePoints` — массив точек маршрута, где каждый элемент представляет собой двумерный массив в формате `[долгота, широта]`:

```js
const route = [
  [116.397428, 39.909736],  // [долгота, широта]
  [116.404730, 39.913370],
  [116.410072, 39.918933],
]
this.$element('mapview').startNav(route)
```

::: warning
Внимание к порядку параметров: первым значением для каждой координатной точки является **долгота** (longitude), а вторым — **широта** (latitude), что противоположно общепринятому соглашению «широта на первом месте».
:::

### `insetNavPoint(linePoints)`

Добавляет точки маршрута к существующему навигационному маршруту. Формат аналогичен [`startNav()`](#startnav). Применяется в сценариях поэтапного получения данных маршрута. После добавления необходимо вызвать [`reload()`](#reload) для обновления отображения.

```js
this.$element('mapview').insetNavPoint(newPoints)
this.$element('mapview').reload()
```

# collapsible-header

Компонент `collapsible-header` используется для добавления сворачиваемой панели заголовка в прокручиваемый список. Такой эффект применяется на устройствах типа «умные часы» для экономии экранного пространства и улучшения пользовательского опыта.

::: warning
<experimental /> Это экспериментальный компонент, не используйте методы, не описанные в данной документации.
:::

## Свойства

Данный компонент поддерживает [общие свойства](/framework/generic/properties.md) и не имеет собственных специализированных свойств.

## Использование

Компонент `collapsible-header` должен содержать ровно два дочерних элемента, в противном случае возможно непредсказуемое поведение. Пример использования:

```html
<collapsible-header>
  <p>Это сворачиваемый заголовок</p>
  <scroll> ... </scroll>
</collapsible-header>
```

Здесь первый дочерний элемент является сворачиваемым заголовком, а второй элемент обязательно должен быть прокручиваемым контейнером, например [`scroll`](/components/scroll.md). Ниже приведен конкретный пример:

<glyphix id="components-collapsible-header-1" height="360" width="360" title="Сворачиваемая панель заголовка">

```html
<collapsible-header>
  <p class="title-bar" on:click="clickTitle">TITLE BAR</p>
  <scroll scroll-snap="center" deformation="fisheye">
    <p for="x in 20" class="item">item {{ x + 1 }}</p>
  </scroll>
</collapsible-header>
```

```js
import prompt from "@system.prompt";

export default {
  clickTitle() {
    prompt.showToast({ message: "title clicked" });
  }
}
```

```css
.title-bar {
  margin: 56px auto auto;
  transparent: true;
  font-size: 1.5rem;
}

.item {
  height: 33.3%;
  background-color: #ddd;
  border-radius: 20%;
  margin: 8px;
  transparent: true;
  padding: 12px;
  text-align: center;
}
```

</glyphix>

### Описание принципа работы

Компонент `collapsible-header` принимает два дочерних компонента: первый — это сворачиваемая панель заголовка, а второй обязательно должен быть компонентом прокрутки, аналогичным `scroll`. `collapsible-header` объединяет эти два компонента и управляет визуальным отображением сворачиваемого заголовка при прокрутке списка.

Для управления положением панели заголовка можно использовать методы, подобные потоковому макету (flow layout), например:

```css
/* Отступ сверху 48px, центрирование по горизонтали, подходит для круглых экранов. */
margin: 48px auto auto;
/* Отступы слева и сверху 12px, подходит для квадратных экранов. */
margin: 12px auto auto 12px;
```

Применив вышеуказанные стили к элементу заголовка в соответствии с вашими реальными потребностями, можно добиться определенного эффекта выравнивания. В качестве заголовка также можно использовать сложный компонент, содержащий дочерние элементы, например, компонент, включающий кнопку «Назад» и текст заголовка страницы. Однако обратите внимание, что при клике на панель заголовка событие клика может одновременно передаваться как в прокручиваемый список, так и в заголовок. Если возникает конфликт, его можно решить путем предотвращения всплытия событий (event bubbling).

### Меры предосторожности

Необходимо предоставить `collapsible-header` ровно два дочерних элемента в соответствии с указанными выше требованиями и не путать их порядок. Кроме того, поскольку сворачиваемая панель заголовка и нижележащий список прокрутки отображаются накладываясь друг на друга, это может привести к тому, что первый элемент списка будет перекрываться с заголовком. При необходимости разработчикам следует предусмотреть какой-либо способ заполнителя (плейсхолдера), чтобы избежать наложения. Кроме того, центрированный [режим привязки](/components/scroll.md#scrollsnap) (`scroll-snap="center"`) для компонента `scroll` также помогает избежать перекрытия.

# label

Компонент `label` используется для отображения текста или информации о метках и по умолчанию является строчным элементом (inline). `label` может использоваться в сочетании со следующими компонентами формы для отображения информации о метках:
- [input](input)
- [radio](radio)
- [switch](switch)
- [checkbox](checkbox)

Когда `label` связан с поддерживаемым компонентом формы, нажатие на компонент `label` также инициирует обновление значения компонента формы.

## Свойства

### `text` <decl type="string" set get />

Текстовое содержимое метки, поддерживает синтаксис атрибутов или синтаксис текстовых дочерних элементов:
``` html

<label>label text</label>
```

### `target` <decl type="string" set get />

Идентификатор (ID) целевого компонента. Например:
```html
<radio id="red" /><label target="red">red</label>
```
Нажатие на компонент `label` в примере также приведет к обновлению компонента `radio` с ID `red`, однако нажатие на компонент `label` не вызовет события касания (например, `click`) целевого компонента.

Из соображений производительности поддерживаются только целевые компоненты, находящиеся на том же уровне, что и компонент `label` (то есть имеющие общего родительского компонента).

::: warning
В настоящее время изменение целевого компонента не поддерживается.
:::

# radio

Радиокнопка (модификатор `radio`), по умолчанию является строчным элементом и часто используется в **группе радиокнопок**, которая содержит набор элементов для выбора одного варианта из серии связанных опций. Одновременно в группе может быть выбрана только одна радиокнопка. Обычно радиокнопки отображаются в виде небольших кружков, которые заполняются при выборе.

<glyphix id="radio-1" :height="65" title="单选按钮">

``` html
    <label target="blue">blue</label>
    <radio id="yellow" value="yellow" model:group="color" />
    <label target="yellow">yellow</label>
  </div>
</div>
```

``` js
export default {
  data: {
    color: 'blue'
  }
}
```

``` css
label {
  margin-right: 0.5rem;
}
```

</glyphix>

Радиокнопки похожи на [`checkbox`](checkbox.md), но элемент `radio` позволяет выбрать только одно значение из группы, в то время как `checkbox` позволяет выбирать несколько значений.
:::

## Свойства

### `checked` <decl type="boolean" get set listen />

Это свойство указывает, выбрана ли данная радиокнопка. Установка свойства `checked` позволяет переключать состояние выбора радиокнопки: если значение равно `true`, она отображается как выбранная.

Когда пользователь нажимает на радиокнопку, и ее состояние выбора изменяется, генерируется событие `checked`.

::: tip
Управление свойством `checked` не является рекомендуемым способом использования `radio`. Пожалуйста, используйте подход с [группой радиокнопок](#group).

### `value` <decl type="any" get set />

Значение JavaScript, идентифицирующее радиокнопку, обычно это строка или число. Это значение не отображается визуально, но оно используется в [группе радиокнопок](#group).

### `group` <decl type="any" get set listen />

# stack

`stack` 是堆叠布局组件。在堆叠布局中，每个子组件的尺寸和位置与 `stack` 组件相同，并且按照先后顺序依次堆叠显示。下面的例子展示了两个在 `stack` 组件内重叠显示的文本元素。

<glyphix id="components-stack-layout" height="100" width="200" title="堆叠布局">

``` html
<stack>
  <p class="text1">Text 1</p>
  <p class="text2">Text 2</p>
</stack>
```

``` css
* {
  text-align: center;
}

.text1 {
  font-size: 64px;
  color: #fff;
}

.text2 {
  font-size: 48px;
  color: #f008;
}

stack {
  background-color: gray;
}
```

</glyphix>

::: tip
`stack` 组件总是使用堆叠显示的布局策略，无法通过 `display` 等 CSS 属性将其更改为其他布局（如 flex 布局或流式布局）。
:::

## 布局行为

`stack` 组件具有固定的堆叠布局策略。其尺寸由以下规则决定：
1. `stack` 的尺寸首先由 [`width`](../framework/generic/styles.md#width) 或 [`height`](../framework/generic/styles.md#width) 等尺寸 CSS 属性指定；
2. 父级元素的布局可能会直接决定 `stack` 的布局，例如 flex 布局中的 `align-items: stretch`、`flex: 1` 等属性；
3. 否则，`stack` 组件的尺寸由子元素的最大宽度和最大高度决定。

一旦确定了 `stack` 的尺寸，其所有子元素都将具有相同的边框盒尺寸（即子元素加上 `border` 和 `margin` 后的尺寸）。这有时会带来困扰，例如通过 `stack` 将一张图片作为背景时，如果上层元素的尺寸过大，可能会导致这张图片无法铺满。

# scroll

Контейнер списка с возможностью прокрутки, поддерживающий любые дочерние компоненты. Направление прокрутки списка определяется конкретным способом компоновки: при использовании потоковой компоновки (flow layout) или flex-компоновки в направлении `column` элементы располагаются по вертикали, и список может прокручиваться по вертикали; при использовании flex-компоновки в направлении `row` элементы располагаются по горизонтали, и список может прокручиваться по горизонтали. Компонент `scroll` не поддерживает двунаправленную прокрутку (т.е. одновременную прокрутку по горизонтали и вертикали).

По умолчанию компонент `scroll` является блочным элементом, использующим потоковую компоновку.

Прокрутка в компоненте `scroll` может осуществляться с помощью жестов. Вертикальный компонент `scroll` также поддерживает прокрутку с помощью энкодера (вращающегося безеля часов, либо колесика мыши на симуляторе).

::: tip
Некоторые интерактивные примеры в этой документации поддерживают управление с помощью колесика мыши (в правой части заголовка имеется значок мыши): вы можете навести указатель мыши на пример и использовать колесико для прокрутки списка.
:::

## Свойства

### `scroll` <decl type="{ scrollX: number, scrollY: number, scrollState: number }" get listen />

Значение свойства `scroll` представляет собой объект, содержащий следующие поля: `scrollX`, `scrollY` и `scrollState`. Свойства `scrollX` и `scrollY` обозначают позицию прокрутки по горизонтали и вертикали соответственно (в пикселях); свойство `scrollState` указывает состояние прокрутки и принимает значение $0$, $1$ или $2$, значения которых приведены в таблице ниже. Изменение свойства `scroll` можно отслеживать с помощью директивы `on`. Любое изменение позиции контента, вызванное действиями пользователя или API, вызывает срабатывание слушателя.

| Значение `scrollState` | Описание эффекта                                                                                   |
| :--------------------: | -------------------------------------------------------------------------------------------------- |
|          $0$           | Прокрутка остановлена                                                                              |
|          $1$           | Выполняется прокрутка жестом пользователя                                                          |
|          $2$           | Пользователь отпустил палец, прокрутка вызвана методами вроде [`scrollTo`](#scrollto) или инерцией  |

::: info
Область, в которой находятся дочерние элементы `scroll`, называется «областью контента» (content), а фактически отображаемая часть компонента списка называется «областью просмотра» (view). Элементы располагаются в области контента, их размеры могут превышать размеры области просмотра, а прокрутка позволяет изменять отображаемую позицию контента.
:::

Диапазон позиции прокрутки обычно находится в пределах области контента: `scrollX` для горизонтального списка лежит в диапазоне $[0, \texttt{contentWidth}]$, а `scrollY` для вертикального списка — в диапазоне $[0, \texttt{contentHeight}]$. Однако, когда список прокручивается выше начала контента, `scrollX` или `scrollY` становится меньше $0$; аналогично, при прокрутке ниже конца контента значение `scrollX` или `scrollY` превышает `contentWidth` или `contentHeight`.

::: warning
Событие `scroll` срабатывает на каждом кадре во время прокрутки. Прослушивание этого события в коде JavaScript может привести к заметному падению частоты кадров (лагам), поэтому его по возможности следует избегать.
:::

### `scrollTop` <decl type="number" set get listen />

Позиция прокрутки по вертикали, то есть расстояние от верхней границы контента компонента `scroll` до верхней границы видимой области (viewport) в пикселях. Это свойство может использоваться как для установки позиции прокрутки, так и для отслеживания изменений позиции прокрутки.

В отличие от свойства [`scroll`](#scroll), прослушивание самого свойства `scrollTop` не позволяет отличить прокрутку жестом пользователя от прокрутки, вызванной вызовом API или инерцией.

### `scrollLeft` <decl type="number" set get listen />

Позиция прокрутки по горизонтали, то есть расстояние от левой границы контента компонента `scroll` до левой границы видимой области в пикселях. Это свойство может использоваться как для установки позиции прокрутки, так и для отслеживания изменений позиции прокрутки.

В отличие от свойства [`scroll`](#scroll), прослушивание самого свойства `scrollLeft` не позволяет отличить прокрутку жестом пользователя от прокрутки, вызванной вызовом API или инерцией.

### `scrollWidth` <decl type="number" get listen />

Ширина области контента компонента `scroll`. Ширина вертикального `scroll` равна ширине области просмотра, а ширина горизонтального `scroll` равна сумме ширин всех элементов. Позволяет отслеживать изменения ширины контента.

### `scrollHeight` <decl type="number" get listen />

Высота области контента компонента `scroll`. Высота вертикального `scroll` равна высоте области просмотра, а высота горизонтального `scroll` равна сумме высот всех элементов. Позволяет отслеживать изменения высоты контента.

### `damping` <decl type="number" set />

Задает коэффициент затухания (демпфирования) анимации прокрутки списка. Допустимый диапазон значений — $[0.1, 50]$ (недопустимые значения автоматически ограничиваются верхней или нижней границей), значение по умолчанию — $1.5$. Больший коэффициент затухания приводит к более быстрой остановке анимации, а коэффициент по умолчанию обеспечивает инерционный эффект на большую дистанцию и с большей длительностью.

<glyphix id="components-scroll-damping" height="360" width="360" title="Эффект демпфирования" wheel>

``` html
<div>
  <span>damping: {{damping}}</span>
  <button on:click="increase">+</button>
  <button on:click="decrease">-</button>
  <scroll :damping="damping">
    <p for="x in 50" class="item">
      Item {{ x + 1 }}
    </p>
  </scroll>
</div>
```

``` js
  decrease() {
    this.damping -= 1
    if (this.damping < 1)
      this.damping = 19.5
  }
}
```

### `snapshot` <decl type="boolean" get set />

При включении свойства `snapshot` дочерние компоненты в списке переходят в режим снимков (snapshot). Примеры использования можно посмотреть в описании свойства [`quiescent`](/framework/generic/properties.md#quiescent) для базовых компонентов.

Включение снимков может повысить частоту кадров (FPS) в сложных интерфейсах. Например, если элементы списка содержат много текста и непрозрачный фон, режим снимков позволяет кэшировать множество операций отрисовки и объединять их в небольшое количество снимков. Фреймворк Glyphix кэширует эти снимки при повторяющейся отрисовке для дальнейшего повышения производительности.

Однако свойство `snapshot` не гарантирует создание снимков для дочерних компонентов; оно может быть проигнорировано при недостатке системной памяти или если использование снимков не требуется.

### `deformation` <decl type="string | function" set />

Задает эффект деформации списка, с помощью которого можно реализовать такие внешние виды, как «рыбий глаз» (fisheye). Встроенный эффект можно указать по имени (строкой) либо определить с помощью функции JavaScript.

| :------------: | :------------------------------------: |
|    `'none'`    | Без эффекта деформации (значение по умолчанию) |
|  `'fisheye'`   | Встроенный эффект «рыбий глаз»         |
|    function    | Эффект деформации, заданный функцией JS |

Эффект деформации должен быть константным и не должен изменяться.

При установке для списка эффекта деформации «рыбий глаз» рекомендуется установить свойство [`scrollSnap`](#scrollsnap) в значение `'center'` для достижения наиболее корректного результата.

### `scrollSnap` <decl type="'none' | 'start' | 'center' | 'edge'" get set />

Задает способы выравнивания и привязки (snap) элементов списка. Например, позволяет центрировать элементы или привязывать их к границам.

|  Значение  | Описание                                                                                                                                              |
| :--------: | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
|  `'none'`  | Элементы не имеют привязки и выравнивания; дочерние элементы могут останавливаться в любой позиции в соответствии с инерцией прокрутки.              |
| `'start'`  | При остановке прокрутки начальная позиция элемента выравнивается по начальной позиции области просмотра. В настоящее время этот режим не поддерживается. |
| `'center'` | При остановке прокрутки центральная позиция элемента выравнивается по центру области просмотра.                                                       |
|  `'edge'`  | При остановке прокрутки начальная или конечная позиция элемента привязывается к ближайшей границе области просмотра. Привязка не происходит, если прокрутка не пересекает границу элемента. |

Свойство `scrollSnap` не изменяет размеры элементов, но механизмы компоновки можно использовать для создания списков из элементов одинакового размера.

::: warning
Это свойство следует задавать при инициализации компонента и не изменять в дальнейшем, иначе могут возникнуть ошибки взаимодействия.
:::

### `index` <decl type="number" get set listen />

Индекс текущего отображаемого дочернего компонента. При установке свойства `index` компонент плавно прокручивается к указанному дочернему элементу. Изменение позиции можно отслеживать с помощью директивы `on`, а изменение индекса дочернего элемента — через свойство `index`.

Значение `index` автоматически ограничивается для гарантии указания на существующий элемент. При использовании `index` все элементы компонента `scroll` должны быть статическими (т. е. свойство CSS [`position`](/framework/generic/styles.md#position) должно иметь значение по умолчанию `static`), в противном случае возникнет ошибка.

### `finalChanged` <decl type="bool" get set />

Задает, должно ли событие изменения свойства [`index`](#index) срабатывать только после остановки прокрутки. По умолчанию (когда `finalChanged` равен `false`), событие прослушивания срабатывает при любом изменении свойства `index` компонента `scroll`, вызванном жестом прокрутки или другими причинами. Однако это может легко привести к пропуску кадров анимации или слишком частым, ненужным срабатываниям событий. При установке `finalChanged` событие изменения `index` срабатывает только тогда, когда прокрутка полностью остановилась.

::: tip
При реализации таких эффектов, как индикаторы точек путем прослушивания свойства `index`, рекомендуется устанавливать `finalChanged` в значение `true`, так как это позволяет избежать потери кадров из-за обновлений рендеринга, вызванных срабатыванием событий во время прокрутки.
:::

Следующий пример демонстрирует работу свойства `finalChanged`. Вы можете попробовать переключить флажок «final-changed», а затем прокрутить список, чтобы понаблюдать за частотой и моментом изменения `index`.

``` html
  </p>

    <p for="x in 50">
      Item {{ x + 1 }}
    </p>
```

### `bounces` <decl type="'none' | 'start' | 'end' | 'edge'" get set />

Определяет, срабатывает ли отскок (bounce) при прокрутке `scroll` за границы с помощью жестов. Начальное значение этого свойства — `edge`, что означает разрешение отскока как на начальной, так и на конечной границе.

| Значение  | Описание                                                      |
| :-------: | ------------------------------------------------------------- |
| `'none'`  | Отключить все отскоки от границ.                              |
| `'start'` | Разрешить отскок только при перетаскивании за начало контента. |
|  `'end'`  | Разрешить отскок только при перетаскивании за конец контента.  |
| `'edge'`  | Разрешить отскок при перетаскивании как за начало, так и за конец контента. |

В примере ниже показано действие каждого значения `bounces`. Вы можете попробовать прокрутить каждый элемент влево или вправо за пределы границ и понаблюдать за соответствующим поведением.

<glyphix id="components-scroll-bounces" height="360" width="400" title="Анимация отскока при перетаскивании">

``` html
<scroll class="column-box">
  <scroll for="item in items" class="row-box"
          :bounces="item" scroll-snap="edge">
    <p class="item-body">bounces: {{item}}</p>
    <p class="slide-button">×</p>
  </scroll>
</scroll>
```

```js
export default {
  data: {
    items: ['none', 'start', 'end', 'edge']
  }
}
```

```css
.column-box {
  display: flex;
  flex-direction: column;
}

.row-box {
  display: flex;
  flex-direction: row;
}

  border-radius: 12px;
  text-align: center;
  margin: 8px;
  padding: 16px;
}

.item-body {
  background-color: #f0f0f0;
  width: 100%;
}

.slide-button {
  width: 30%;
  color: #ffffff;
  background-color: #f04040;
}
```

</glyphix>


::: note
В настоящее время свойство `bounces` влияет только на отскок при жестовых операциях, игнорируя быстрые инерциальные отскоки анимации. В примере выше используется прием для предотвращения непредвиденного поведения:
- `.row-box` использует стратегию привязки к краям (`scroll-snap="edge"`), чтобы избежать жестовой анимации с отскоком.
- Каждый элемент `.row-box` занимает не более `100%` ширины, гарантируя, что стратегия привязки к краям не вызовет внутренний отскок от границ.

Этот прием можно использовать для интерфейсов вроде меню удаления с помощью бокового свайпа.
:::

Свойство `bounces` также выполняет функцию, аналогичную [`weakGesture`](#weakgesture). В частности, при пересечении запрещенной для отскока границы автоматически разрешается всплытие (bubbling) событий жестов прокрутки. Поэтому нет необходимости одновременно задавать свойства `bounces` и `weakGesture`.

::: tip
Поведение всплытия жестов прокрутки для `bounces` и `weakGesture` является «противоположным»: например, стратегия отскока в режиме `end` позволяет пользователю прокручивать за конец списка с отскоком, и эта же стратегия разрешает всплытие жеста прокрутки на начальной границе. Это соответствует эффекту свойства `weakGesture` со значением `'start'`.
:::

### `weakGesture` <decl type="'none' | 'start' | 'end' | 'edge'" get set />

Определяет, в каких случаях компонент `scroll` передает жесты прокрутки дальше по цепочке всплытия. По умолчанию `scroll` перехватывает обрабатываемые им жесты, запрещая их всплытие, поэтому родительские элементы не могут получить жесты, вызывающие прокрутку `scroll`. `weakGesture` позволяет включить всплытие событий жестов при перетаскивании до границ контента, благодаря чему родительские элементы получают возможность перехватывать эти жесты.

| Значение  | Описание                                                                        |
| :-------: | ------------------------------------------------------------------------------- |
| `'none'`  | Не передавать обрабатываемые события жестов дальше по цепочке всплытия.         |
| `'start'` | Передавать события жестов дальше по цепочке после перетаскивания к началу контента. |
|  `'end'`  | Передавать события жестов дальше по цепочке после перетаскивания к концу контента.  |
| `'edge'`  | Передавать события жестов дальше по цепочке после перетаскивания к началу или концу контента. |

Если базовый элемент страницы представляет собой горизонтальный компонент `scroll`, но вы хотите, чтобы жест свайпа вправо возвращал страницу назад, вы можете настроить его следующим образом:
``` html
<scroll weak-gesture="start"> ... </scroll>
```
Когда пользователь прокрутит содержимое до начала компонента `scroll` и продолжит свайп вправо, страница закроется.

::: warning
Это свойство следует задавать при инициализации компонента и не изменять в дальнейшем, иначе могут возникнуть ошибки взаимодействия.
:::

### `scrollbar` <decl type="boolean" get set />

Указывает, должен ли компонент `scroll` отображать полосу прокрутки (по умолчанию не отображается). Поддерживается только для вертикально ориентированных компонентов `scroll`. Свойство `scrollbar` должно быть константой и не может изменяться реактивными свойствами, например:
``` html
<scroll scrollbar>
  ...
</scroll>
```
создаст компонент `scroll` с полосой прокрутки. Внешний вид полосы прокрутки можно посмотреть в примере метода [`setIndex`](#setindex).

Стиль полосы прокрутки определяется системой: например, на круглом экране она может отображаться в виде дуги, а на прямоугольном — в виде прямой полосы.

### `scrolled` <decl type="boolean" listen />

Позволяет отслеживать с помощью свойства `scrolled`, находится ли список в состоянии прокрутки. Значение `true` означает, что список прокручивается в данный момент, а `false` — что прокрутка остановлена.

Событие `scrolled` вызывается как при операциях прокрутки, вызванных касаниями пользователя, так и при программной прокрутке через свойство `scroll`. Когда список останавливается после прокрутки, параметром события `scrolled` передается значение `false`.

### `setIndex`
<decl method><pre>

  index: number,
  behavior?: 'instant' | 'smooth'

</pre></decl>

Перемещает область просмотра к дочернему компоненту, указанному по индексу. Если это перемещение выходит за границы области просмотра, позиция остановится на первом или последнем компоненте. Параметры объекта `options`:
- `index`: индекс целевого дочернего компонента для перемещения, где $0$ обозначает первый дочерний компонент.
- `behavior`: при значении `'smooth'` используется плавная анимация перехода, при `'instant'` (значение по умолчанию) — мгновенное перемещение к позиции указанного дочернего компонента.

При вызове `setIndex()` все элементы компонента `scroll` должны быть статическими, в противном случае возникнет ошибка.

### `scrollTo`
<decl method><pre>
(options: {
  left?: number,
  top?: number,
  behavior?: 'instant' | 'smooth'
}): void
</pre></decl>

Прокручивает содержимое в указанную позицию. Параметры объекта `options`:
- `left`: задает позицию прокрутки содержимого по оси y (игнорируется, если параметр не указан или если компонент scroll имеет вертикальную компоновку).
- `top`: задает позицию прокрутки содержимого по оси x (игнорируется, если параметр не указан или если компонент scroll имеет горизонтальную компоновку).
- `behavior`: задает эффект перехода при прокрутке: `'instant'` (по умолчанию) означает мгновенный переход к целевой позиции без эффекта перехода, а `'smooth'` выполняет плавную прокрутку с эффектом перехода.

Метод `scrollTo` игнорирует эффекты привязки (snap) элементов.

### `scrollBy`
<decl method><pre>
(options: {
  left?: number,
  top?: number,
  behavior?: 'instant' | 'smooth'
}): void
</pre></decl>

Прокручивает содержимое на заданное расстояние. В отличие от [`scrollTo()`](#scrollto), метод `scrollBy()` выполняет прокрутку относительно текущей позиции контента. Параметры объекта `options`:
- `left`: задает расстояние прокрутки содержимого по оси y (игнорируется, если параметр не указан или если компонент scroll имеет вертикальную компоновку).
- `top`: задает расстояние прокрутки содержимого по оси x (игнорируется, если параметр не указан или если компонент scroll имеет горизонтальную компоновку).
- `behavior`: задает эффект перехода при прокрутке: `'instant'` (по умолчанию) означает мгновенный переход к целевой позиции без перехода, а `'smooth'` выполняет плавную прокрутку с эффектом перехода.

Метод `scrollBy` игнорирует эффекты привязки (snap) элементов.

### `padding` и `overflow` <version-badge since="0.9" />

По умолчанию (`overflow: clip`) внутренние отступы (padding) компонента `scroll` напрямую обрезают видимую область. После прокрутки содержимого область отступов всегда остается невидимой. Установка `overflow: visible` позволяет области отступов оставаться видимой даже при прокрутке содержимого.

<glyphix id="components-scroll-padding-overflow-visible" height="360" width="740" title="Внутренние отступы при overflow: visible">

``` html

    <p for="20">overflow: clip</p>
  </scroll>
  <!-- Элемент-заглушка, так как flex-компоновка пока не поддерживает gap -->
  <div style="width: 20px"></div>
  <scroll style="overflow: visible;" :index="2">
    <p for="20">overflow: visible</p>
  </scroll>
</div>
```

``` css
div {
  display: flex;
}

scroll {
  padding: 20px;
  background-color: #f0f0f0;
  flex: 1;
}

p {
  background-color: #bdbdbd;
  text-align: center;
  padding: 20px;
  margin: 4px;
  border-radius: 16px;
}
```

</glyphix>

Даже при установке `overflow: visible` компонент `scroll` обрезает содержимое по границе `padding-box`, не позволяя ему выходить за пределы этого диапазона (в отличие от обычных элементов вроде `div`). Это обусловлено тем, что поведение прокрутки и механизм компоновки `scroll` требуют, чтобы контент прокручивался в строго определенной области, а не расширялся во внешнее пространство без ограничений.

В обычных контейнерах, таких как `div`, при аналогичном значении `overflow: visible` содержимое может выходить за пределы всего `div` (например, за красную рамку `border`):

<glyphix id="components-scroll-overflow-div" height="360" width="360" title="overflow: visible для div">


``` css
  background-color: #f0f0f0;

  text-align: center;
  padding: 8px;
  margin: 4px;

```

</glyphix>

#### Рекомендуемые настройки для сценариев i18n

В сценариях интернационализации (i18n) текст внутри `scroll` может нуждаться в переполнении во избежание обрезания. Для таких случаев рекомендуется устанавливать `overflow: visible`, что позволяет [выходящему за границы тексту](/framework/application/i18n.md#文本溢出) выходить за пределы области контента `scroll` при прокрутке, максимально задействуя пространство для отображения текста.

#### Связь со спецификацией HTML/CSS

Поведение компонента `scroll` при установке `overflow: visible` аналогично поведению `div { overflow-y: scroll; }` в спецификации HTML/CSS, где внутренние отступы (padding) позволяют контенту оставаться видимым во время прокрутки. Например, следующий CSS:

```css
div {
  padding: 20px;
  overflow-y: scroll;
}
```

дает следующий эффект: область padding не обрезает контент при прокрутке:

<div style="padding: 20px; background-color: var(--vp-c-grey-bg); overflow-y: scroll; height: 100px; width: 200px; border: 2px dotted red; font-family: sans-serif;">
  Michaelmas term lately over, and the Lord Chancellor sitting in Lincoln's Inn Hall.
  Implacable November weather. As much mud in the streets as if the waters had but
  newly retired from the face of the earth.
</div>

Элемент `div` в HTML не имеет прямого аналога поведения `scroll` с настройкой `overflow: clip`.

# text-field

Компонент для ввода однострочного текста, по умолчанию является строчным элементом (inline). В отличие от аналогичных GUI-элементов на телефонах или ПК, `text-field` в настоящее время не реагирует на устройства ввода, такие как клавиатура, и не вызывает интерфейс метода ввода (клавиатуру), поэтому вы должны редактировать его содержимое вручную. `text-field` поддерживает управление курсором с помощью сенсорных жестов (например, нажатие и прокрутка).

`text-field` подходит в качестве базового компонента для ввода однострочного текста, позволяя реализовать собственную программную клавиатуру в соответствии с вашими требованиями (например, цифровую клавиатуру для ввода пароля или даже голосовой ввод). Подробности см. в [примере](#基本示例).

## Свойства (Attributes)

### `value` <decl type="string" set get listen />

Свойство `value` представляет собой строку, которая является текущим редактируемым содержимым `text-field`. Чтение или прослушивание этого значения позволяет получить введенный текст, а также установить это свойство.

Обычно `value` двунаправленно связывается с определенным реактивным свойством, например:

```html
<text-field ::value="inputText" />
```

### `placeholder` <decl type="string" set get />

Когда содержимое `text-field` пусто, с помощью `placeholder` можно предоставить пользователю краткую подсказку, например «Введите текст» и т. д.

`placeholder` отображается автоматически, когда вводимый текст пуст, поэтому обычно требуется лишь фиксированное содержимое, например:

```html
<text-field ::value="inputText" placeholder="type here" />
```

### `password` <decl type="boolean" set get />

Когда это свойство установлено, `text-area` переходит в «режим пароля», то есть каждый символ заменяется на «•» ([Bullet, U+2022](http://www.fileformat.info/info/unicode/char/2022/index.htm)). Вы можете в любой момент включить или выключить свойство `password`, чтобы переключать состояние отображения/скрытия пароля.

В новых версиях <version-badge since="0.9" /> в режиме пароля вводится задержка перед скрытием символов: пользователь может увидеть только что введенный символ в течение короткого времени, после чего он заменяется на «•». В старых версиях введенные символы скрывались немедленно.

### `insert` <decl type="(text: string): void" method />

Вставляет текст с содержимым `text` в позицию курсора, при этом курсор автоматически перемещается после вставленного текста. Вызов этой функции инициирует событие прослушивания `value`.

### `backspace` <decl type="(): void" method />

Удаляет символ в позиции курсора, при этом курсор автоматически смещается вперед. Вызов этой функции инициирует событие прослушивания `value`.

## Инструкция по использованию

### Базовый пример

В следующем примере показано базовое использование `text-field`. Вы можете нажимать кнопки клавиатуры для ввода цифр. Нажмите кнопку «×» для удаления содержимого в позиции курсора, а нажатие «A/*» переключает между режимом пароля и обычным режимом ввода текста. В режиме пароля введенное содержимое скрывается с помощью `•`.

### Валидация и форматирование содержимого

Вы можете реализовать валидацию и форматирование вводимого содержимого, связав свойство [`value`](#value) компонента `text-field` двунаправленной связью с вычисляемым свойством (computed property). В следующем примере показан этот подход: он позволяет вводить не более 9 цифр (ввод букв и т. д. запрещен) и добавляет разделитель «`,`» каждые три цифры.

<glyphix id="components-text-field-validator" title="Валидатор содержимого" width="410" height="200">

```html
<div class="flex-column">
  <div class="flex-row align-baseline">
    <text-field id="text-field"
                ::value="inputText"
                :password="password"
                placeholder="type here" />
    <button checkable ::press="password">A/*</button>
    <button on:click="textField.backspace()">×</button>
  </div>
  <div class="flex-row" for="rows in keyboard">
    <button class="flex-1" for="key in rows"
            on:click="textField.insert(key)">
      {{key}}
    </button>
  </div>
</div>
```

```js
export default {
  data: {
    password: false,
    rawText: "",
  },
  computed: {
    inputText: {
      get() { return this.rawText },
      set(text) {
        if (text.length < 12 && /^[\d,]*$/.test(text)) {
          this.rawText = text.replace(/[^\d]/g, '')
                             .replace(/\B(?=(\d{3})+(?!\d))/g, ",")
        }
      },
    },
  },
  keyboard: [
    ["1", "2", "3", "4", "5"],
    ["6", "7", "8", "9", "0"],
    ["A", "B", "C", "D", "E"],
  ],
  textField: null,
  onReady() {
    this.textField = this.$element("text-field")
  },
}
```

```css
}

  border-bottom: 2px solid #666;
}

  margin: 8px;
  padding: auto 12px;
}

button:active {
  opacity: 0.5;
}

.flex-1 {
  flex: 1;
}
```
</glyphix>

Валидация и форматирование содержимого реализуются с помощью двунаправленного связывания и вычисляемых свойств. Для узла компонента `text-field`:
```html
<text-field id="text-field"
            ::value="inputText"
            :password="password"
            placeholder="type here" />
```
свойство `value` двунаправленно связано с `inputText`, который на самом деле является вычисляемым свойством. Его метод `set()` проверяет, соответствует ли вводимое содержимое стандарту (не более 11 символов, разрешены только цифры и запятые), затем с помощью регулярного выражения фильтрует цифры и форматирует их, добавляя запятую каждые три цифры:
```js
function set(text) {
  if (text.length < 12 && /^[\d,]*$/.test(text)) {
    this.rawText = text.replace(/[^\d]/g, '')
                       .replace(/\B(?=(\d{3})+(?!\d))/g, ",")
  }
}
```
Если вводимое содержимое не соответствует требованиям, метод `set()` игнорирует введенное значение, а механизм двунаправленного связывания гарантирует, что содержимое `text-field` останется согласованным со значением свойства `inputText` (получаемым через метод `get()`). Поэтому вы заметите, что ввод буквенных клавиш невозможен.

# progress

Компонент `progress` используется для отображения полосы прогресса (прогресс-бара) и по умолчанию является блочным элементом.

## Свойства

### `max` <decl type="number" set />

Максимальное значение прогресса. Свойство [`value`](#value) не может быть больше него.

### `min` <decl type="number" set />

Минимальное значение прогресса. Свойство [`value`](#value) не может быть меньше него.

### `value` <decl type="number" set get listen />

Установка текущего значения прогресса. Отображаемое соотношение прогресса зависит от позиции значения свойства `value` в диапазоне от `min` до `max`, при этом соотношение отображения ограничивается в пределах от $0\% \sim 100\%$. Значение `value` является целым числом; если задано число с плавающей точкой, будет взята только его целая часть.

### `vertical` <decl type="boolean" set />

Если значение свойства `vertical` равно `true`, компонент `progress` будет отображаться вертикально, в противном случае — горизонтально. Значение по умолчанию — `false`.

## Спецификация CSS

Разработчики могут настраивать внешний вид компонента `progress` с помощью CSS.

### Расчет размеров

Ширина и высота `progress` по умолчанию равны размеру шрифта элемента. Размер шрифта задается свойством [`font-size`](/framework/generic/styles.md#font-size) (или может наследоваться). Размеры `progress` можно настроить самостоятельно с помощью свойств [`width`](/framework/generic/styles.md#width) и [`height`](/framework/generic/styles.md#height).

### CSS-свойства

Следующие CSS-свойства могут быть весьма полезны:
- [`background-color`](/framework/generic/styles.md#background-color) управляет фоновым цветом `progress`;
- [`color`](/framework/generic/styles.md#color) управляет цветом полосы прогресса `progress`;
- [`border-radius`](/framework/generic/styles.md#border-radius) позволяет сделать границы `progress` скругленными, например, значение `50%` создаст полукруглые края.

Другие CSS-свойства также могут быть полезны, например, можно использовать свойство [`border`](/framework/generic/styles.md#border) для задания стиля границы.

### Псевдоэлементы CSS

#### `value`

Этот псевдоэлемент позволяет отдельно задавать стиль для самой полосы прогресса `progress`, исключая фоновую часть. Например, можно задать разные радиусы скругления для фона полосы прокрутки и для части прогресса, чтобы внешний контур имел закругленные концы, а сама полоса прогресса — прямые.

``` css
progress {
  border-radius: 50%; /* Скругление углов фона полосы прокрутки */
}

progress::value {
  border-radius: 0; /* Без скругления углов для индикатора прогресса */
}
```

### Пример CSS

В следующем примере показаны некоторые способы настройки внешнего вида полосы прогресса с помощью CSS.

<glyphix id="components-progress-styles" height="140" width="480" title="Стили полосы прогресса">

``` html
<div>
  <!-- Стиль по умолчанию -->
  <progress :value="40" />
  <!-- Стиль полосы прогресса с прямыми концами -->
  <progress class="flat" :value="50" />
  <progress class="more-style" :value="60" />
</div>
```

``` css
div > * {
  margin: 8px;
}

.flat::value {
  /* Установка радиуса скругления псевдоэлемента value в 0 создает прямые концы полосы прогресса */
  border-radius: 0;
}

.more-style {
  /* Пользовательский радиус скругления */
  border-radius: 30%;
  /* Цвет фона полосы прогресса */
  background-color: #b3c5d7;
  /* Цвет переднего плана полосы прогресса */
  color: #b5179e;
  /* С помощью padding можно настроить отступы переднего плана полосы прогресса */
  padding: 6px;
  height: 1.25rem;
}
```

</glyphix>

# a

Компонент якоря, по умолчанию является строчным элементом, используется для перехода на указанную страницу.

## Свойства

### `href` <decl type="string" get set />

Указывает [имя страницы](/framework/application/manifest.md#pages) или строку URI, на которую необходимо выполнить переход.

``` html
<a href="page1">Перейти на страницу page1</a>
``` 

В отличие от тега `<a>` в веб-разработке, компонент `a` поддерживает только переходы между страницами и не поддерживает гиперссылки.

Свойство `href` также поддерживает строку [URI](/framework/application/resource.md#uri) в формате `PageName?key=value`, то есть URI, состоящий из имени страницы (в качестве поля path) и поля query. Поле query этого URI будет преобразовываться в параметры перехода на страницу. Например, при нажатии на этот элемент `<a>`:

``` html
<a href="page1?text=test-text&message=hello">Перейти на страницу page1</a>
```

Это эквивалентно вызову следующего метода [`router.push()`](/api/system-router.md#push):

``` js
router.push({
  uri: 'page1',
  params: {text: 'test-text', message: 'hello'}
})
```

::: tip
Обратите внимание, что значение поля query в URI всегда интерпретируется как строка, поэтому `100` в `page1?size=100` будет распознано как строка `'100'`, а не число `100`. Если вам нужно передать параметры определенного типа, используйте API [`router`](/api/system-router.md).
:::

# swiper

Контейнер представлений карточек (карусель/свайпер), поддерживающий любые дочерние компоненты. Направление прокрутки представления карточек определяется конкретным способом компоновки: список с компоновкой `flex-column` является вертикальным, а список с компоновкой `flex-row` — горизонтальным.

## Свойства

### `scroll` <decl type="{ scrollX: number, scrollY: number, scrollState: number }" get listen />

Значение свойства `scroll` представляет собой объект, содержащий следующие поля: `scrollX`, `scrollY` и `scrollState`. Свойства `scrollX` и `scrollY` обозначают положение прокрутки по горизонтали и вертикали соответственно в пикселях; свойство `scrollState` обозначает состояние прокрутки и может принимать значения $0$, $1$ или $2$, значение которых описано в таблице ниже. С помощью директивы `on` можно отслеживать изменения свойства `scroll`. Любое изменение позиции контента, вызванное действиями пользователя или вызовами API, вызовет срабатывание прослушивания.

| Значение `scrollState` | Описание эффекта                                                                                    |
| :--------------------: | --------------------------------------------------------------------------------------------------- |
|          $0$           | Прокрутка остановлена                                                                               |
|          $1$           | Выполняется прокрутка с помощью жеста пользователя                                                  |
|          $2$           | Пользователь отпустил палец; прокрутка вызвана методами вроде [`scrollTo`](#scrollto) либо инерцией |

### `scrollTop` <decl type="number" get listen />

Положение прокрутки по вертикали, то есть расстояние от верхней границы контента компонента `swiper` до верхней границы области просмотра (вьюпорта) в пикселях. С помощью этого свойства можно отслеживать изменения положения прокрутки. В отличие от свойства [`scroll`](#scroll), само по себе прослушивание свойства `scrollTop` не позволяет различить, была ли прокрутка вызвана жестом пользователя, вызовом API или инерцией.

### `scrollLeft` <decl type="number" get listen />

Положение прокрутки по горизонтали, то есть расстояние от левой границы контента компонента `swiper` до левой границы области просмотра в пикселях. С помощью этого свойства можно отслеживать изменения положения прокрутки. В отличие от свойства [`scroll`](#scroll), само по себе прослушивание свойства `scrollLeft` не позволяет различить, была ли прокрутка вызвана жестом пользователя, вызовом API или инерцией.

### `scrollWidth` <decl type="number" get listen />

Ширина области контента компонента `swiper`. Ширина `swiper` с вертикальной компоновкой равна ширине вьюпорта, в то время как ширина `swiper` с горизонтальной компоновкой равна сумме ширин всех элементов. С помощью этого свойства можно отслеживать изменения ширины контента.

### `scrollHeight` <decl type="number" get listen />

Высота области контента компонента `swiper`. Высота `swiper` с вертикальной компоновкой равна высоте вьюпорта, в то время как высота `swiper` с горизонтальной компоновкой равна сумме высот всех элементов. С помощью этого свойства можно отслеживать изменения высоты контента.

### `snapshot` <decl type="boolean" get set />

Когда свойство `snapshot` включено, дочерние компоненты `swiper` переводятся в режим снимка (snapshot). Обратите внимание на свойство [`snapshot`](scroll.md#snapshot) компонента `scroll`.

### `deformation` <decl type="string" set />

Устанавливает эффект деформации дочерних элементов, с помощью которого можно реализовать такие внешние виды, как «рыбий глаз» (fisheye). Встроенный эффект деформации можно указать по имени (строке) либо определить его с помощью функции JavaScript.

| Значение | Описание эффекта |
| :---: | :--- |
| `'none'` | Эффект деформации отсутствует (значение по умолчанию). |
| `'fade'` | Эффект затухания и масштабирования при переключении. Этот эффект подчеркивает «фокус» на элементах внутри текущей области просмотра и заставляет элементы вне ее казаться отодвинутыми на второй план. Подробности см. в примере в этом разделе. |
| `'fisheye'` | Встроенный эффект «рыбий глаз». Данное свойство используется для компонента [`scroll`](scroll.md), а не `swiper`. |
| function | Определение эффекта деформации с помощью функции JavaScript. |

Эффект деформации должен быть константным и не должен изменяться.

Если содержимое дочерних элементов `swiper` часто меняется, при использовании эффекта деформации рекомендуется добавить к элементам свойство [`quiescent`](/framework/generic/properties.md#quiescent), чтобы избежать обновления при переключении и повысить производительность. Вы можете обратиться к следующему примеру:

<glyphix id="components-swiper-deformation" height="360" width="360" title="Эффект деформации элементов">

```html
<swiper deformation="fade" indicator>
  <div for="x in 5" :quiescent="x != 0">
    <progress-arc busy :start-angle="0" :stop-angle="360" />
    <p>pane {{ x + 1 }}</p>
  </div>
</swiper>
```

``` css
div {
  background-color: #eee;
  text-align: center;
  margin: 10px;
  border-radius: 24px;
  display: flex;
  flex-direction: column;
  justify-content: center;
}

progress-arc {
  width: 30%;
  height: 30%;
  margin-bottom: 5%;
}
```

</glyphix>

У первого дочернего элемента в примере не включено свойство `quiescent`, поэтому он будет непрерывно обновляться в процессе переключения, в то время как остальные элементы прекратят обновление.

### `vertical` <decl type="boolean" set />

В следующем примере продемонстрирован интерактивный эффект `swiper` с вертикальной компоновкой (обратите внимание, что прокрутка должна быть вертикальной, горизонтальное свайпание не вызовет отклика).

``` html
<swiper vertical deformation="fade" indicator>
  <p for="x in 5">
    pane {{ x + 1 }}
    {{ x == 0 ? '(swipe up)' : x == 4 ? '(swipe down)' : '' }}
  </p>
</swiper>
```

``` css
p {
  background-color: #eee;
  text-align: center;
  margin: 10px;
  border-radius: 24px;
```

### `indicator` <decl type="boolean" get set />

Устанавливает, отображает ли компонент `swiper` точечный индикатор. Позиция отображения точечного индикатора определяется свойством `vertical`: при вертикальной компоновке индикатор отображается по центру справа, а при горизонтальной — по центру снизу. Конкретный эффект см. в примерах свойств [`deformation`](#deformation) и [`vertical`](#vertical).

Обратите внимание на раздел [CSS-свойства точечного индикатора](#css-свойства-точечного-индикатора), чтобы узнать, как настроить стиль отображения точечного индикатора.

### `pageLength`  <decl type="number" set />

Устанавливает размер или долю дочерней страницы. Если задано в процентах, устанавливает размер дочернего компонента в направлении прокрутки (относительно самого компонента); если задано другим числом, устанавливает размер дочернего компонента в направлении прокрутки в пикселях.

### `index`  <decl type="number" get set listen />

Индекс отображаемого в данный момент дочернего компонента. При установке свойства `index` компонент с помощью анимации прокрутится к указанному дочернему компоненту. Изменение положения можно отслеживать с помощью директивы `on`, а при изменении индекса дочернего компонента об этом можно узнать через свойство `index`.

### `finalChanged` <decl type="bool" get set />

Устанавливает, должно ли событие изменения [`index`](#index) срабатывать только при остановке прокрутки. По умолчанию (когда `finalChanged` имеет значение `false`), событие прослушивания срабатывает каждый раз, когда жест прокрутки или другая причина изменяет свойство `index` компонента `swiper`. Однако это может легко привести к пропуску кадров (лагам) анимации или к слишком частым и ненужным срабатываниям событий. Когда установлен параметр `finalChanged`, событие изменения `index` будет срабатывать только тогда, когда прокрутка полностью остановилась.

::: tip
При реализации таких эффектов, как точечный индикатор, путем прослушивания свойства `index`, рекомендуется установить `finalChanged` в значение `true`. Это позволяет избежать пропуска кадров в процессе прокрутки, вызванного запуском рендеринга и обновлений по событиям.
:::

### `weakGesture` <decl type="'none' | 'start' | 'end' | 'edge'" get set />

Устанавливает, в каких ситуациях компонент `swiper` будет передавать (всплывать) жесты прокрутки наверх (bubble). По умолчанию `swiper` предотвращает всплытие жестов, на которые он реагирует, поэтому его родительские элементы не могут получить жесты, заставляющие `swiper` прокручиваться. Свойство `weakGesture` позволяет включить всплытие событий жестов при перетаскивании до границ контента, что позволяет родительским элементам перехватывать эти жесты.

| Значение  | Описание                                                                        |
| :-------: | ------------------------------------------------------------------------------- |
| `'none'`  | Не передавать (не всплывать) события жестов, на которые был отклик.             |
| `'start'` | Передавать события жестов после перетаскивания к начальной позиции контента.    |
|  `'end'`  | Передавать события жестов после перетаскивания к конечной позиции контента.     |
| `'edge'`  | Передавать события жестов после перетаскивания к начальной или конечной позиции.|

Если корневым элементом страницы является горизонтальный компонент `swiper`, но вы хотите, чтобы жест свайпа вправо позволял вернуться назад со страницы, вы можете настроить его следующим образом:
``` html
<swiper weak-gesture="start"> ... </swiper>
```
Когда пользователь прокрутит до начала компонента `swiper` и продолжит свайпать вправо, он сможет выйти со страницы.

### `bounces` <decl type="'none' | 'start' | 'end' | 'edge'" get set />

Устанавливает, срабатывает ли эффект отскока (bounces) при прокрутке `swiper` за границы с помощью жеста. Начальным значением этого свойства является `edge`, что означает разрешение отскока как на начальной, так и на конечной позициях. Свойство `bounces` компонента `swiper` похоже на свойство [`bounces`](scroll.md#bounces) компонента [`scroll`](scroll.md), подробнее см. в соответствующей документации.

### `scrolled` <decl type="boolean" listen />

С помощью свойства `scrolled` можно отслеживать, находится ли компонент `swiper` в состоянии прокрутки. Значение `true` срабатывающего события означает, что идет прокрутка, в противном случае это означает, что прокрутка остановлена.

Событие `scrolled` вызывается как операциями прокрутки, созданными касаниями пользователя, так и прокруткой через свойство `scroll`. При остановке из состояния прокрутки значение параметра события `scrolled` равно `false`.

### `setIndex`
<decl method><pre>
(options: {
  index: number,
  behavior?: 'instant' | 'smooth'
}): void
</pre></decl>

Перемещает область просмотра к дочернему компоненту, указанному по индексу. Если это перемещение выходит за пределы области просмотра, положение вьюпорта остановится на первом или последнем компоненте. Назначение свойств объекта параметра `options`:
- `index`: индекс целевого дочернего компонента для перемещения, где $0$ обозначает первый дочерний компонент.
- `behavior`: если установлено значение `'smooth'`, используется анимационный переход; если `'instant'` (значение по умолчанию), происходит мгновенное перемещение к позиции указанного дочернего компонента.

### `scrollTo` <decl type="(position: number): void" method />

Прокручивает контент в указанную позицию. Направление прокрутки совпадает с направлением компоновки компонента scroll.

Метод `scrollTo` игнорирует эффект прилипания (snap) элементов.

# pullable

Компонент `pullable` используется для добавления функции инкрементальной загрузки или взаимодействия с обновлением, которые срабатывают при потягивании вниз в верхней части или потягивании вверх в нижней части прокручиваемого списка. По умолчанию компонент `pullable` является блочным элементом.

::: warning
<experimental /> Это экспериментальный компонент. Функциональность `pullable` нестабильна, а анимация может выглядеть недостаточно естественно.
:::

`pullable` должен быть первым или последним дочерним компонентом [`scroll`](scroll.md). Когда он является первым дочерним элементом, продолжение потягивания вниз в начале содержимого `scroll` вызывает событие `pulling`; наоборот, когда `pullable` является последним дочерним элементом `scroll`, потягивание вверх внизу вызывает событие `pulling`.

Компонент `pullable` по умолчанию находится в скрытом состоянии и отображается только при потягивании вверх/вниз. В следующем примере продемонстрировано использование компонента `pullable`.

<glyphix id="components-pullable-1" height="360" width="360" title="Загрузка дополнительных данных при потягивании вверх/вниз">

```html
<scroll scrollbar>
  <pullable :hold="pulldown" on:pulling="onPulldown">
    <progress-arc busy start-angle="0" stop-angle="360" />
    <p>{{pulldown || 'keep pull down...'}}</p>
  </pullable>
  <p for="item in items">item ({{item}})</p>
  <pullable :hold="pullup" on:pulling="onPullup">
    <progress-arc busy start-angle="0" stop-angle="360" />
    <p>{{pullup || 'keep pull up...'}}</p>
  </pullable>
</scroll>
```

```js
export default {
  data: {
    pulldown: null,
    pullup: null,
    items: []
  },
  first: 0,
  last: 0,
  onInit() {
    this.update(0, 10)
  },
  update(first, last) {
    for (let i = this.first; i > first; --i)
      this.items.unshift(i)
    for (let i = this.last; i < last; ++i)
      this.items.push(i)
    this.first = first
    this.last = last
  },
  onPulldown(event) {
    this.pulldown = event ? 'please release' : 'updating...'
    if (!event) {
      setTimeout(() => {
        this.update(this.first - 5, this.last)
        this.pulldown = null
      }, 1000)
    }
  },
  onPullup(event) {
    this.pullup = event ? 'please release' : 'updating...'
    if (!event) {
      setTimeout(() => {
        this.update(this.first, this.last + 5)
        this.pullup = null
      }, 1000)
    }
  }
}
```

## Свойства

### `hold` <decl type="bool" get set />

По умолчанию `pullable` виден только при потягивании вниз вверху или вверх внизу, но когда свойство `hold` имеет значение `true`, компонент `pullable` остается видимым. Это свойство обычно устанавливается, когда событие [`pulling`](#pulling) приводит к обновлению содержимого, и сбрасывается после завершения обновления содержимого.

### `pulling` <decl type="bool" get listen />

Событие `pulling` срабатывает, когда `pullable` вытягивается полностью. Значения события означают следующее:
- `true`: событие срабатывает при достижении порога полного вытягивания `pullable` при потягивании вниз/вверх;
- `false`: событие срабатывает, когда пользователь отпускает палец после достижения вышеуказанного условия полного вытягивания.

В следующем примере показан момент срабатывания значений события `pulling`. Вы можете попытаться плавно потянуть список вниз с самого верха и обратить внимание на всплывающее сообщение toast при срабатывании события `pulling`.

<glyphix id="components-pullable-pulling" height="360" width="360" title="Событие pulling">

```html
<scroll scrollbar>
  <pullable :hold="refresh" on:pulling="onPulling">
    <p>pulling...</p>
  </pullable>
  <p for="item in 10">item {{item}}</p>
</scroll>
```

```js
import prompt from '@system.prompt'

export default {

      message: `pulling: ${event ? 'trigged' : 'release'}`
    })
    if (!event) {
      this.refresh = true
      setTimeout(() => this.refresh = false, 1000)
    }
  }
}
```

## Инструкции по использованию

### Расположение компонента

Компонент `pullable` должен быть первым или последним дочерним элементом вертикального `scroll`. Он автоматически определяет режим работы в зависимости от своего расположения: если он является первым дочерним элементом, он определяет операцию потягивания пользователя вниз от верхней части списка, и наоборот.

Для списка, которому требуется только обновление при потягивании вниз, достаточно следующего использования:
```html
<scroll>
  <pullable :hold="refresh" on:pulling="onPulling">
    <p>pulling...</p>
  </pullable>
  <div for="item in items">
    ...
  </div>
</scroll>
```

В коде JavaScript вы можете прослушивать событие `pulling` и управлять свойством `refresh`:
``` js
export default {
  data: {
    refresh: false
  },
  onPulling(hold) {
    if (!hold) { // hold равен false, когда пользователь отпускает палец
      this.refresh = true // Означает, что идет обновление
      // В этом примере таймер используется для симуляции операции загрузки, а загрузка останавливается через 1 с
      setTimeout(() => this.refresh = false, 1000)
    }
  }
}
```

Конкретный эффект см. в примере в документации по событию [`pulling`](#pulling).

### Управление подсказками

Внутри компонента `pullable` можно размещать различные компоненты для отображения подсказок. Как показано в предыдущих примерах в этой статье, вы можете комбинировать анимацию загрузки и текст подсказки. Кроме того, значение события `pulling` можно использовать для управления содержимым подсказки. Обычно рекомендуется следующий подход к обработке состояния:
1. Установите реактивное свойство (например, `refresh`) для каждого компонента `pullable` со значением по умолчанию `null`. Свойство `refresh` также используется для управления свойством [`hold`](#hold) компонента `pullable`.
2. В начальном состоянии (то есть когда `refresh` имеет ложное значение) подсказка `pullable` должна призывать пользователя «продолжать тянуть для обновления».
3. Когда пользователь тянет вниз, срабатывает событие `pulling`. В зависимости от его значения выполните шаг 4 или 5.
4. Когда `pulling` равен `true`, пользователю следует подсказать: «Отпустите, чтобы начать обновление».
5. Когда `pulling` равен `false`, это означает, что пользователь отпустил палец. В это время вы должны установить `refresh` в значение `true` и начать обновление содержимого. Также следует сообщить пользователю: «Идет обновление».
6. После завершения обновления содержимого снова установите `refresh` в значение `false`, чтобы вернуться в исходное состояние.

Вы также можете обратиться к первому примеру в этом документе, который реализует функцию продолжения загрузки как при потягивании вниз вверху списка, так и при потягивании вверх внизу. В этом примере используется прием использования всего одного реактивного свойства для управления всеми состояниями `pullable`.

Этот прием устанавливает начальное значение реактивного свойства `refresh` равным `null` (что аналогично `false`) и использует следующий шаблон кода:
``` html
<pullable :hold="refresh" on:pulling="onPulling">
  <p>{{refresh || 'Продолжайте тянуть вниз'}}</p>
</pullable>
```
Когда свойство `refresh` не задано, подсказка по умолчанию «Продолжайте тянуть вниз» отображается сразу же после вытягивания `pullable`. Затем функцию обратного вызова события `onPulling` следует написать следующим образом:
``` js
export default {
  async onPulling(event) {
    this.refresh = event ? 'Пожалуйста, отпустите' : 'Обновление...'
    if (!event) { // Запуск операции обновления при отпускании
        await runRefreshJobs()
        this.refresh = null // Сброс состояния после завершения обновления
    }
  }
}
```

### Ограничения

В настоящее время компонент `pullable` имеет ряд ограничений. Помимо обязательного использования внутри вертикального компонента `scroll`, вам также необходимо убедиться, что количество элементов списка превышает размеры видимой области `scroll`, иначе могут возникнуть проблемы. Кроме того, интерактивный эффект `pullable` может оказаться несколько резким.
