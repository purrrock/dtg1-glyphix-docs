# Тестирование фреймворка

## Импорт модуля

``` js
import test from '@system.test'
```

## Введение

Модуль `system.test` представляет собой фреймворк для сквозного (end-to-end) тестирования, который позволяет программно симулировать действия пользователя и проверять, соответствует ли поведение интерфейса ожиданиям.

Пример простого кода для симуляции действий пользователя:
``` js
await test.getByClass('play-button').click()
await test.getByClass('more-button').click()
await test.getByClass('download-button').click()
await test.getByClass('close-button').click()
await test.getByClass('menu-button').click()
await test.getHasText('下载列表').click()
await test.getByTag('Scroll').scroll(0, -200, 0.3)
await test.getHasText(/[a-z]/).click()
```
Этот код автоматически дождется рендеринга элементов в интерфейсе, с помощью жеста прокрутки переместит перекрытые элементы в видимую область, а затем выполнит над ними такие жесты, как клик или прокрутка.

## API

### Вспомогательные функции

Эти функции предоставляют вспомогательные возможности в тесте, такие как задержка (пауза) и т. д.

#### `wait` <decl method type="(duration: number): Promise<void>" />

Асинхронная задержка на указанное время, используемая для ожидания определенных операций в тесте или симуляции пауз пользователя.

### Локаторы

Локаторы ищут элементы (нативные компоненты) с верхнего уровня страниц приложения, например, по тегу или ID элемента. Подробнее о локаторах см. в разделе [Объект `Locator`](#locator-объект).

#### `getByTag` <decl method type="(tag: string): Locator" />

Поиск элемента по `tag`. В настоящее время поддерживается только стиль именования UpperCamelCase, например `'P'`, `'Swiper'` и т. д.

#### `getByClass` <decl method type="(class: string): Locator" />

Поиск элемента по атрибуту `class`.

#### `getById` <decl method type="(id: string): Locator" />

Поиск элемента по атрибуту `id`.

#### `getHasText` <decl method type="(text: RegExp | string): <Locator>" />

Поиск элементов по соответствию атрибута `text` элемента параметру `text`. Параметр `text` является регулярным выражением, например:
- `/hello/` проверяет, содержит ли значение атрибута `text` элемента подстроку `'hello'`;
- `/^hello/` проверяет, начинается ли значение атрибута `text` элемента с `'hello'`;
- `/^hello$/` проверяет, равно ли значение атрибута `text` элемента значению `'hello'`.

Правила сопоставления параметра `text` такие же, как у [`RegExp.test()`](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/RegExp/test).

### Объект `Locator`

Объект `Locator` возвращается методами API локаторов и может использоваться для дальнейших операций. Все операции локатора пытаются автоматически дождаться появления элемента и переместить его в видимую область.

#### `click` <decl method type="(): Promise<void>" />

Когда элемент существует и прокручен в видимую область, симулирует жест клика в позиции элемента.

#### `scroll` <decl method type="(dx: number, dy: number, duration?: number): Promise<void>" />

Когда элемент существует и прокручен в видимую область, симулирует жест прокрутки в позиции элемента. `dx` и `dy` — это смещения прокрутки $(x, y)$ в пикселях; необязательный параметр `duration` задает продолжительность жеста в секундах, значение по умолчанию составляет $0.5 \rm s$.

Этот метод будет ожидать, пока атрибут `scrolled` элемента не станет равным `false`, прежде чем разрешить (resolve) возвращаемый объект Promise. Таким образом, для таких компонентов, как `scroll` и `swiper`, метод `scroll()` запустит следующий шаг только после того, как инерционная анимация этих компонентов полностью остановится.

#### `wait` <decl method type="(): Promise<void>" />

Ожидает появления элемента и его прокрутки в видимую область, но не симулирует никаких жестов или других действий.

# Операции с путями

Данный модуль предоставляет интерфейсы для работы с путями, включая объединение, разделение, нормализацию и другие функции.

## Импорт модуля

``` js
import path from '@system.path'
```

## Определение интерфейсов

#### `path.basename` <decl type="(path: string, suffix?: string): string" method />

Возвращает имя файла для указанного пути `path`. С помощью параметра `suffix` можно также удалить определенный суффикс имени файла. Например:
``` js
path.basename('/foo/bar/baz.txt') // 'baz.txt'
path.basename('/foo/bar/baz.txt', '.txt') // 'baz'
```

#### `path.dirname` <decl type="(path:string): string" method />

Возвращает часть пути, соответствующую директории (в отличие от `basename()`, эта функция отбрасывает имя файла). Например:
``` js
path.dirname('/foo/bar/baz') // '/foo/bar'
```

#### `path.extname` <decl type="(path: string): string" method />

Получает расширение файла из пути `path`. Например:
``` js
path.extname('table.json') // '.json'
path.extname('/images/icon.png') // '.png'
```

#### `path.isAbsolute` <decl type="(path: string): boolean" method />

Определяет, является ли путь `path` абсолютным. Например:
``` js
path.isAbsolute('/foo/bar'); // true
path.isAbsolute('/baz/..');  // true
path.isAbsolute('qux/');     // false
path.isAbsolute('.');        // false
```

#### `path.join` <decl type="(...paths: string[]): string" method />

Соединяет несколько путей вместе и нормализует результат. Например:
``` js
path.join('/foo', 'bar', 'baz/asdf', 'quux', '..') // '/foo/bar/baz/asdf'
```

#### `path.normalize` <decl type="(path: string): string" method />

Приводит путь `path` к наиболее простому виду: разрешает директории `..` и `.` и удаляет лишние разделители пути `/`.

``` js
path.normalize('/foo///bar/.././/baz') // '/foo/baz'
```

#### `path.relative` <decl type="(from: string, to: string): string" method />

Вычисляет относительный путь от `from` до `to`.

``` js
path.relative('/data/orandea/test/aaa', '/data/orandea/impl/bbb') // '../../impl/bbb'
```

# Планировщик задач (定时任务)

## Импорт модуля

``` js
import schedule from "@system.schedule"
// Или
const schedule = require("@system.schedule")
```

Разработчикам необходимо объявить разрешение на доступ к `watch.permission.SCHEDULE` в файле [`manifest.json`](/framework/application/manifest.md#permissions).

## API

### `scheduleJob`
<decl method><pre>
(options: {
  type: number,
  timeout: number,
  triggerMethod: String,
  interval?: number,
  params?: Object,
}): number
</pre></decl>

Установка таймера для задачи. Назначение полей в параметре `options`:
- `type`:	
  - 1: Аппаратное время. Изменение системного времени может привести к вызову `triggerMethod`;
  - 2: Реальное истечение времени. Время учитывается даже в спящем режиме;
- `timeout`:
  - Если `type` равен 1, это метка времени (timestamp) для первого выполнения, то есть количество миллисекунд с 1970/01/01 00:00:00 GMT до текущего момента;
  - Если `type` равен 2, это интервал от текущего момента до первого выполнения в миллисекундах;
- `triggerMethod`: Имя метода, определенного в `app.js`, который вызывается фоновым сервисом при достижении времени срабатывания;
- `interval`: Интервал периодического выполнения в миллисекундах. Если не передано, задача не повторяется;
- `params`: Параметры задачи;

::: tip
Хотя точность `timeout` и `interval` составляет миллисекунды, срабатывание задач происходит с точностью до секунды. Интервал до первого выполнения и период повторения не могут быть меньше 60 секунд, в противном случае интерфейс выбросит исключение.
:::

Возвращаемое значение — это ID задачи, который используется для ее отмены. Возвращаемое значение `-1` означает сбой при создании.

``` js
let id = schedule.scheduleJob({
  type: 1,
  timeout: new Date('2025-03-14T23:00:00').getTime(),  // Метка времени для первого выполнения
  interval: 60000,     // Интервал периодического выполнения не менее 60 секунд
  triggerMethod: 'scheduleFunc',
  params: {
    food: 'apple',
  },
})

// app.js
export default {
  scheduleFunc(params) {
    console.log('scheduleFunc', params)
  },
}
```

### `cancel` <decl type="(id: number): void" method/>

Отмена запланированной задачи.

``` js
schedule.cancel(id)
```

# Переход между приложениями

## Импорт модуля

``` js
import launch from '@system.launch'
```

## Определение интерфейсов

### `launch` <decl type="(app: string): Promise<bool>" method/>

Запускает указанное приложение и переводит его на передний план. `app` — это строка с идентификатором уже установленного приложения. Возвращаемый Promise указывает, успешно ли загружено приложение.

### `inactive` <decl type="(app?: string): Promise<void>" method/>

Переводит приложение в фоновый режим. `app` — это идентификатор запущенного приложения. Если параметр не указан, в фоновый режим переводится текущее приложение. Перевести в фоновый режим можно только приложение, находящееся на переднем плане.

### `exit` <decl type="(app?: string): Promise<void>" method />

Завершает работу приложения. Параметр `app` — это идентификатор запущенного приложения. Если параметр не указан, завершается работа текущего приложения.

### `getRunning` <decl type="(): string[]" method />

Получает список имен пакетов запущенных приложений, включая те, которые находятся в фоновом режиме.

# Вплывающие окна

## Импорт модуля

``` js
import prompt from '@system.prompt'
```

## Определение интерфейсов

#### `showToast`
<decl method><pre>
(options: {
  message: string,
  duration?: number,
  important?: boolean
}): void
</pre></decl>

Отображает всплывающее окно типа toast. Toast — это текстовое всплывающее окно, располагающееся поверх интерфейса. В интерфейсе одновременно отображается только один экземпляр toast; при наличии нескольких сообщений они будут выстраиваться в очередь и отображаться по очереди.

Описание полей параметра `options`:
- `message`: текст, который необходимо отобразить.
- `duration`: длительность отображения toast в мс. По истечении этого времени toast автоматически скрывается.
- `important`: является ли toast важным, по умолчанию `false`. Если установлено значение `true`, разрешается отображение этого toast, когда приложение находится в фоновом режиме.

Стиль отображения toast (шрифт, цвет и т.д.) определяется прошивкой и не может быть изменен в приложении. Длительность отображения toast также ограничена и составляет от $200$ до $5000$ миллисекунд.

#### `showPopup` <decl type="(options: { uri: string, params?: Object }): Promise<any>" method />

Отображает плавающее окно страницы. Описание полей параметра `options`:
- `uri`: имя целевой страницы, которое должно быть зарегистрировано в секции `router` файла `manifest.json`.
- `params`: данные, которые необходимо передать при переходе. Свойства параметра `params` заменят значения свойств `data` целевой страницы.

Плавающая страница — это системное всплывающее окно (похожее на toast или диалоговое окно), но плавающая страница представляет собой полнофункциональную страницу с максимальными возможностями кастомизации. В отличие от обычных страниц, плавающая страница отображается в системном стеке плавающих страниц, а не в собственном стеке страниц приложения, поэтому такие API механизма [маршрутизации страниц](api/system-router), как `router.back()`, не могут управлять плавающей страницей. Чтобы закрыть плавающую страницу, вы можете использовать метод [`router.close()`](system-router.md#close).

Уровень отображения всплывающего окна выше, чем у приложения, поэтому плавающая страница будет отображаться поверх страниц всех приложений. Все приложения используют один и тот же стек плавающих страниц, и плавающие страницы определяют свой уровень отображения в соответствии с порядком их появления, то есть страница, появившаяся раньше, располагается наверху. Уровень отображения плавающей страницы совпадает с диалоговым окном и ниже, чем у toast.

Аналогично `router.push()`, метод `showPopup()` также возвращает объект Promise, который разрешается после выхода из плавающей страницы и возвращает пользовательский результат. Подробности см. в описании [`router.push()`](system-router.md#push) и [`router.close()`](system-router.md#close).

# Обмен данными

Модуль обмена данными `system.exchange` используется для хранения общих данных между приложениями. Эти данные не сохраняются персистентно и будут утеряны при выключении питания устройства. Данные, хранящиеся в `system.exchange`, доступны во всех приложениях, поэтому этот модуль можно использовать для хранения некоторой конфигурационной информации приложений, но он не подходит для хранения конфиденциальных данных.

`system.exchange` хранит данные в виде пар ключ-значение, где ключ должен быть строкой, а значение представляет собой значение JSON (или значение JavaScript, сериализуемое в JSON).

## Импорт модуля

``` js
import exchange from '@system.exchange'
```

## API

### `get` <decl type="(key: string): any" method />

Получает значение, соответствующее ключу `key` в хранилище. Возвращает `undefined`, если пара ключ-значение не существует.

### `set` <decl type="(key: string, value: any): void" method />

Этот метод принимает в качестве параметров имя ключа `key` и значение `value`, а затем добавляет эту пару ключ-значение в хранилище. Если ключ уже существует, его соответствующее значение обновляется.

### `delete` <decl type="(key: string): boolean" method />

Удаляет пару ключ-значение, соответствующую ключу `key` в хранилище. Возвращает `true`, если пара ключ-значение существовала и была успешно удалена.

### `watch` <decl type="(key: string, callback: (value: any) => void): number" method />

Отслеживает изменения значения данных с именем ключа `key` в хранилище и вызывает функцию обратного вызова `callback` при изменении значения. Параметр `value` функции обратного вызова представляет собой новое значение данных. Метод `watch()` возвращает `wtacher ID` (идентификатор наблюдателя), который можно использовать в методе [`unwatch()`](#unwatch) для отмены прослушивания.

::: tip
Когда прослушивание больше не требуется, следует использовать метод [`unwatch()`](#unwatch) для его отмены, иначе это может привести к утечке памяти.
:::

### `unwatch` <decl type="(watcherID: number): void" method />

Отменяет определенное прослушивание ключа в хранилище. Параметр `watcherID` — это `wtacher ID`, возвращаемый методом [`watch()`](#watch) при создании прослушивания.

# Взаимодействие устройств (设备互联)

## Импорт модуля

``` ts
import interconnect from '@system.interconnect'
```

## Определение интерфейсов

### `instance` <decl type="(options: {package: string, fingerprint: string}): Connect" method/>

Создает экземпляр [`Connect`](#connect-интерфейс).

```js
const connect = interconnect.instance({
  package: "com.xxxx.xxx",
  fingerprint: "xxxxx"
})
```

- package: Имя пакета мобильного приложения.
- fingerprint: Информация об отпечатке, которая должна совпадать с информацией об отпечатке, переданной при создании соединения мобильным приложением.

## Интерфейс `Connect`

### `onopen` <decl type="?: () => void" set />

Используется для указания回调 (обратного вызова) при открытии соединения.

```js
connect.onopen = () => {
  console.info("onopen")
}
```

### `onclose` <decl type="?: () => void" set />

Используется для указания回调 при закрытии соединения.

```js
connect.onclose = () => {
  console.info("onclose")
}
```

### `onerror` <decl type="?: () => void" set />

Используется для указания回调 при сбое соединения.

```js
connect.onerror = (data: any) => {
  console.info("onerror", data)
}
```

### `onmessage` <decl type="?: () => " set />

Используется для указания回调 при получении данных от мобильного приложения.

```js
connect.onmessage = (msg => {
  if (msg.isFileType) {
    this.msg = "recv a file " + msg.fileUri
  } else {
    this.msg = "recv a text message " + msg.data
  }
})
```

### `send` <decl type="(options: {data: any}): Promise<any>" method />

Отправка данных в мобильное приложение.

```js
connect.send({
  data: {
    name: "zhangsan"
  }
})
```

# Информация об устройстве

## Импорт модуля

``` js
import device from '@system.device'
```

Разработчикам необходимо заявить о доступе приложения к权限 `watch.permission.DEVICE_INFO` в файле [`manifest.json`](/framework/application/manifest.md#permissions).

## Определение интерфейсов

### `getInfo`
<decl method><pre>
(): Promise<{
  brand: string,
  manufacturer: string,
  model: string,
  product: string,
  osType: string,
  osVersionName: string,
  platformVersionName: string,
  platformVersionCode: number,
  language: string,
  region: string,
  deviceName: string
}>
</pre></decl>

Получение базовой информации об устройстве. Значения полей возвращаемого объекта:
- `brand`: бренд устройства.
- `manufacturer`: производитель устройства.
- `model`: модель устройства.
- `product`: кодовое имя устройства.
- `osType`: название операционной системы.
- `osVersionName`: название версии операционной системы.
- `platformVersionName`: название версии платформы выполнения.
- `platformVersionCode`: номер версии платформы выполнения.
- `language`: системный язык.
- `region`: системный регион.
- `deviceName`: имя устройства.

### `getId`
<decl method><pre>
(types: ('device' | 'mac' | 'user' | 'advertising')[])
: Promise<{
  device?: string,
  mac?: string,
  user?: string,
  advertising?: string
}>
</pre></decl>

Пакетное получение идентификационной информации об устройстве. Параметр `types` задает категорию запрашиваемой информации и представляет собой объект Array, состоящий из элементов `'device'`, `'mac'`, `'user'` или `'advertising'`. В зависимости от значений `types`, поля возвращаемого объекта имеют следующие значения:
- `type`: .
- `device`: уникальный идентификатор устройства, присутствует только в том случае, если `types` содержит элемент `'device'`.
- `mac`: MAC-адрес устройства, присутствует только в том случае, если `types` содержит элемент `'mac'`.

Отмена подписки на изменение местоположения.

```ts
type Location = {
```

# Компас

Модуль `@system.compass` предоставляет доступ к датчику компаса устройства, позволяя получать информацию о направлении движения устройства относительно магнитного северного полюса Земли.

## Импорт модуля

``` js
import compass from '@system.compass'
```

## Определение интерфейсов

### `subscribe` <decl type="(callback: (data: Value) => void): number" method/>

Подписка на изменение данных компаса. Функция обратного вызова будет вызываться автоматически при изменении ориентации устройства. Функция обратного вызова `callback` принимает данные компаса типа [`Value`](#value).

Возвращает идентификатор подписки (`subscribeId`), который используется для отписки.

### `unsubscribe` <decl type="(subscribeId: number): void" method/>

Отмена подписки на данные компаса. Параметр `subscribeId` — это идентификатор подписки, возвращаемый методом [`subscribe()`](#subscribe).

Этот метод следует вызывать при уничтожении страницы или компонента для отмены подписки `subscribe()`:
``` js
const subscribeId = compass.subscribe((data) => {
  console.log(`Направление: ${data.direction} радиан`)
  console.log(`Точность: ${data.accuracy}`)
})

// Отмена подписки
compass.unsubscribe(subscribeId)
```


### `calibration` <decl type="(): Promise<void>" method/>

Запуск процесса калибровки компаса. Когда точность компаса низкая, это помогает пользователю выполнить необходимые действия и вызывает этот метод для калибровки компаса.

Функция возвращает объект Promise без результата, который разрешается после завершения калибровки системой.

### `getValue` <decl type="(): Promise<Value>" method/>

Получение текущих данных компаса. Возвращает асинхронный результат в виде объекта Promise, содержащего информацию о направлении и точности компаса (тип [`Value`](#value)).

Пример:
``` js
// Использование Promise
compass.getValue().then((data) => {
  console.log(`Направление: ${data.direction} радиан`)
  console.log(`Уровень точности: ${data.accuracy}`)
})

// Использование async/await
async function getCompassData() {
  const data = await compass.getValue()
  console.log(`Направление: ${data.direction} радиан`)
  console.log(`Уровень точности: ${data.accuracy}`)
}
```

::: note
Из-за особенностей реализации данный метод не поддерживает вызовы в стиле callback (например, `{ success: (data) => {...} }`), пожалуйста, используйте Promise или async/await.
:::

## Определения типов

### `Value`

Сигнатура типа данных компаса `Value` выглядит следующим образом:
``` ts
type Value = {
  direction: number  // Направление компаса (в радианах)
  accuracy: number   // Уровень точности компаса
}
```
Описание свойств:
- `direction`: угол в радианах между осью Y устройства и магнитным северным полюсом Земли, диапазон значений $[0,2\pi]$, где:
  - `0`: строго на север
  - `Math.PI / 2` (около 1.57): строго на восток
  - `Math.PI` (около 3.14): строго на юг
  - `3 * Math.PI / 2` (около 4.71): строго на запад
- `accuracy`: уровень точности данных компаса
  - `3`: высокая точность
  - `2`: средняя точность
  - `1`: низкая точность
  - `0`: ненадежно (причина неизвестна)
  - `-1`: ненадежно (потеряна связь с датчиком)

Пример:
``` js
// Определение направления
const data = await compass.getValue()
const degrees = data.direction * 180 / Math.PI // Преобразование в градусы

console.log(`Направление: ${degrees}°`)
if (degrees >= 337.5 || degrees < 22.5) {
  console.log('На север')
} else if (degrees >= 22.5 && degrees < 67.5) {
  console.log('На северо-восток')
} else if (degrees >= 67.5 && degrees < 112.5) {
  console.log('На восток')
}
// ... определение других направлений

// Проверка точности
if (data.accuracy >= 2) {
  console.log('Точность компаса хорошая')
} else if (data.accuracy === 1) {
  console.log('Точность компаса низкая, рекомендуется калибровка')
  compass.calibration()
} else {
  console.log('Данные компаса ненадежны')
}
```

# Маршрутизация страниц (Page Routing)

## Импорт модуля

``` js
import router from '@system.router'
```

## Определение интерфейсов

### `push` <decl type="(options: {uri: string, params?: Object}): Promise<any>" method />

Переход на указанную страницу внутри приложения. Описание свойств объекта `options`:
- `uri`：название целевой страницы, которое должно быть настроено в файле `manifest.json`;
- `params`：данные, передаваемые при переходе. Свойства объекта `params` заменят значения свойств `data` целевой страницы.

Метод `push()` возвращает объект Promise, который разрешается (fulfilled) после закрытия целевой страницы и возвращает пользовательский результат. Например:
```js
const result = await router.push({ uri: 'PageName' })
console.log("the page 'PageName' was closed with the result:", result)
```
Здесь `result` — это значение, возвращенное страницей с помощью метода [`close()`](#close), которое вы можете получить описанным выше способом.

::: warning
Время возврата со страницы обычно зависит от действий пользователя, поэтому `await router.push()` может ожидать довольно долго. Если вам не нужно получать возвращаемое со страницы значение, использовать `await` для ожидания возврата не рекомендуется.
:::

Когда страница находится в режиме запуска `singleTask`, переход на уже открытую страницу аналогичен вызову [`back('<page-name>')`](#back), см. [`launchMode`](/framework/application/manifest.md#launchmode) <version-badge since="0.8" />.

### `replace` <decl type="(options: {uri: string, params?: Object}): Promise<boolean>" method />

Переход на указанную страницу внутри приложения с одновременным закрытием текущей страницы. Описание свойств объекта `options`:
- `uri`：название целевой страницы, которое должно быть настроено в файле `manifest.json`;
- `params`：данные, передаваемые при переходе. Свойства объекта `params` заменят значения свойств `data` целевой страницы.

Как и [`push()`](#push) и [`back()`](#back), вызов `replace()` всегда запускает стандартную анимацию перехода между страницами. Даже если вызвать `replace()` **немедленно** в коде, как только текущая страница перейдет в фазу рендеринга, пользователь все равно сможет на короткое время увидеть один кадр текущей страницы перед переходом на целевую страницу. Поэтому `replace()` больше подходит для сценариев, где «текущая страница сама по себе является частью пользовательского сценария», но не подходит в качестве средства для «тихого перенаправления» или «полного сокрытия страницы входа».

Если текущая страница была открыта с помощью метода [`push()`](#push), то поскольку метод `replace()` заменяет текущую страницу, это приведет к разрешению (fulfillment) объекта Promise, возвращенного методом [`push()`](#push).

::: tip
Не используйте метод [`push()`](#push) для перехода на новую страницу с последующим немедленным вызовом [`close()`](#close) для текущей страницы с целью ее замены — это прервет интерактивную анимацию и может вызвать мерцание экрана. Всегда используйте метод `replace()` для замены страниц, чтобы обеспечить плавный переход.

Кроме того, если требуется, чтобы какая-либо страница входа (например, страница `router.entry`, настроенная в `manifest.json`, или страница проверки конфиденциальности, используемая только для дистрибуции) **полностью не отображалась** в определенных сценариях, не вызывайте внутри этой страницы `replace()` в попытке «немедленно уйти». Подобные требования должны реализовываться путем [замены страницы по умолчанию](#замена-страницы-по-умолчанию) на раннем этапе запуска приложения (например, в `onCreate()` / `onRoute()`) с помощью прямого вызова `push()` для перехода на настоящий первый экран.
:::

Метод `replace()` часто используется для [перехода с экрана-заставки](#переход-с-экрана-заставки) и в аналогичных сценариях.

Когда страница находится в режиме запуска `singleTask`, переход на уже открытую страницу аналогичен вызову [`back('<page-name>')`](#back), см. [`launchMode`](/framework/application/manifest.md#launchmode) <version-badge since="0.8" />.

### `back` <decl type="(name?: string): Promise<boolean>" method />

Возврат на страницу с именем `name`. Если параметр `name` пустой или не передается, `router.back()` возвращает на страницу уровнем выше.

Вызов метода `back()` приводит к разрешению Promise, возвращенного методом [`push()`](#push) соответствующей страницы.

### `close` <decl type="(page: Component, result?: any): Promise<void>" method />

Закрытие указанной страницы. `page` — это объект view-model страницы. Например:
``` js
router.close(this.$page)
```

Метод `router.close()` может закрыть любую страницу внутри приложения. Если целевая страница находится на вершине стека страниц, то `router.close()` эквивалентен `router.back()`. `router.close()` также может корректно закрывать плавающие (悬浮) страницы.

Необязательный параметр `result` используется для указания возвращаемого значения страницы, которое возвращается при разрешении Promise, выданного методом [`router.push()`](#push) или [`prompt.showPopup()`](system-prompt.md#showpopup), открывшим эту страницу. Учитывая разнообразие способов выхода со страницы (например, свайп пользователя, метод `router.back()` и т.д.), вы можете явно вызвать метод `close()` в жизненном цикле [`onDestroy()`](/framework/component/life-cycle.md#ondestroy) компонента страницы, чтобы гарантировать передачу возвращаемого значения:
```js
import router from '@system.router'

export default {
  // Это объект компонента ...
  onDestroy() {
    router.close(this.$page, this.pageResult)
  },
  // Предположим, какой-то метод устанавливает возвращаемое значение страницы
  someMethod() {
    this.pageResult = { message: 'some page result' }
  },
}
```

::: tip
Если перед возвратом из `onDestroy()` метода к странице многократно вызывался метод `router.close()` **с передачей параметра `result`**, то в качестве возвращаемого значения страницы будет засчитан только последний вызов. Именно поэтому рекомендуется возвращать значения через метод `close()` именно в жизненном цикле `onDestroy()`.
:::

### `clear` <decl type="(): Promise<void>" method />

Очищает все фоновые страницы, оставляя только самую верхнюю. Вызов метода `clear()` не воспроизводит анимацию перехода между страницами. Возвращаемый этим методом Promise разрешается после выхода со всех фоновых страниц.

### `getPages` <decl type="(): Component[]" method />

Получает компоненты всех страниц, находящихся в текущем стеке страниц приложения.

### `getLength` <decl type="(): number" method />

Получает количество страниц в текущем стеке страниц приложения.

### `getPagesName` <decl type="(): String[]" method />

Получает названия всех страниц в текущем стеке страниц приложения.

### `getPage` <decl type="(index: number): Component | undefined" method />

Получает компонент страницы, указанный по индексу `index` в текущем приложении. `index` — это индекс страницы (то есть ее позиция в стеке страниц). Если искомая страница не существует, возвращается `undefined`.

### `getIndex` <decl type="(component: Component): number | undefined" />

Получает индекс страницы в текущем приложении, указанной с помощью компонента страницы `component`. Если искомая страница не существует, возвращается `undefined`.

### `queryPage` <decl type="(name: string): Component[]" />

Получает список всех страниц с именем `name` в стеке страниц. Порядок элементов в списке совпадает с порядком в стеке страниц.

### `queryIndex` <decl type="(name: string): number[]" />

Получает список индексов всех страниц с именем `name` в стеке страниц. Порядок индексов совпадает с порядком в стеке страниц.

## Заметки по разработке

### Повторное открытие страницы (дублирование)

Ошибочное использование метода `router.push()` может привести к повторному открытию (пушу) одной и той же страницы. Рассмотрим следующий элемент:
``` html
<p on:click="onClick">Click Me!</p>
```
Если метод обратного вызова события `onClick()` компонента просто открывает новую страницу, проблем не возникает:
``` js
export default{
  onClick() {
    router.push({ uri: 'CoverPage' })
  }
}
```
Поскольку во время воспроизведения анимации перехода (если она есть) страница не реагирует на жесты, метод `router.push()` не будет вызван повторно. Однако, если `onClick()` вызывает `router.push()` после некоторой асинхронной операции, может возникнуть проблема, например:
``` js
export default{
  async onClick() {
    // Здесь таймер на одну секунду имитирует асинхронную операцию. Реальные асинхронные операции,
    // такие как чтение/запись файлов или проверка сетевого статуса, вызовут ту же проблему
    await new Promise((resolve, reject) => {
      setTimeout(resolve, 1000)
    })
    // Вызов router.push() после асинхронной операции
    router.push({ uri: 'CoverPage' })
  }
}
```
Если пользователь несколько раз нажмет кнопку «Click Me!» во время выполнения асинхронной операции (в примере — таймера), страница откроется повторно несколько раз. Вы можете протестировать это на следующей демо-версии:

<glyphix id="api-router-push-repeat-1" height="100" inline>

``` html
<div class="window">
  <p class="button" on:click="onClick">Click Me!</p>
</div>
```

``` css
.window {
  display: flex;
  justify-content: center;
  align-items: center;
  background-color: #e5e5e5;
  border-radius: 12px;
}

.button {
  border: 2px solid gray;
  border-radius: 20%;
  padding: 8px;
}
```

``` js
import router from '@system.router'

export default {
```

Сначала быстро нажмите кнопку «Click Me!» несколько раз в течение одной секунды. Это приведет к многократному открытию страницы Cover Page, и вы сможете увидеть количество повторных открытий по счетчику на этой странице.

Затем нажмите на Cover Page или сделайте свайп вправо, чтобы вернуться на предыдущую страницу. Вы заметите, что независимо от того, насколько быстро и непрерывно вы нажимали, страницы возвращаются по одной и без дублирования действий, так как во время анимации перехода жесты не обрабатываются.

#### Избегайте асинхронных операций

Если вам нужно выполнить переход со страницы внутри обработчика жестов (например, клика), следует избегать асинхронных операций. Это не только легко приводит к дублированию страниц, но и увеличивает задержку отклика на жест. Следует особенно учитывать, что задержка некоторых асинхронных операций неконтролируема (например, проверка онлайн-статуса в условиях слабого сигнала сети может занять много времени).

Поэтому в сценариях, где переход на страницу инициируется кликом, лучше перенести возможные сетевые запросы на новую страницу, отображая состояние загрузки с помощью анимации.

#### Способы предотвращения

Если перед переходом по клику обязательно требуется выполнить асинхронную операцию, обязательно используйте специальный флаг, чтобы избежать повторного перехода. Взяв за основу предыдущий callback `onClick()`:
``` js
export default {
  async onClick() {
    // Добавляем флаг isClicked для пропуска повторных операций (не обязательно делать реактивным свойством)
    if (this.isClicked)
      return
    // Устанавливаем флаг перед началом логики обработки жеста
    this.isClicked = true
    await new Promise((resolve, reject) => {
      setTimeout(resolve, 1000)
    })
    router.push({ uri: 'CoverPage' })
    // Сбрасываем isClicked после завершения логики обработки жеста
    this.isClicked = false
  }
}
```
При использовании такого подхода непрекращающиеся нажатия на кнопку «Click Me!» не приведут к повторному открытию Cover Page:

### Замена страницы по умолчанию

Разработчики могут не хотеть, чтобы при запуске приложения открывалась страница [`router.entry`](/framework/application/manifest.md#entry), указанная в `manifest.json`. Типичным сценарием является запуск приложения через deeplink, когда требуется перейти на определенную страницу в зависимости от параметров запроса, а не на страницу entry.

Помимо deeplink, при «холодном» запуске приложению часто требуется выбирать первый экран в зависимости от локального состояния (например, в зависимости от статуса авторизации решать, открывать страницу входа или главный экран, либо в зависимости от сохраненного флага согласия с политикой конфиденциальности открывать страницу конфиденциальности или главный экран). Если напрямую настроить одну из этих страниц в качестве `router.entry`, а затем внутри этой страницы выполнить переход с помощью [`router.replace()`](#replace), то в некоторых случаях на короткое время будет отображаться ненужная страница, что выглядит как «мигание» экрана.

Для этого достаточно вызвать [`router.push()`](#push) на этапе запуска приложения до вызова жизненного цикла [`onShow()`](/framework/component/life-cycle.md#onshow-1), чтобы открыть именно ту страницу, которую вы действительно хотите показать. Обычно проверку локального состояния и переход на главный экран можно выполнять в жизненном цикле [`onCreate()`](/framework/component/life-cycle.md#oncreate) или [`onRoute()`](/framework/component/life-cycle.md#onroute) приложения. Например, в `onCreate()` файла `app.ux`/`app.js` можно синхронно прочитать статус соглашения о конфиденциальности и сразу перейти на страницу конфиденциальности или главный экран:
```js
// app.js
import router from '@system.router'
import storage from '@system.storage'

export default {
  onCreate() {
    const agreed = storage.get('privacyAgreed')
    if (agreed) // Пользователь согласился с политикой конфиденциальности, сразу переходим на главный экран
      router.push({ uri: 'MainPage' })
    else // Пользователь еще не согласился, на первом экране показываем страницу конфиденциальности
      router.push({ uri: 'PrivacyPage' })
  }
}
```
Как только разработчик вручную выполняет переход на страницу на раннем этапе запуска приложения, **фактическим первым экраном**, отображаемым пользователю при этом запуске, становится целевая страница, открытая через `router.push()`. А параметр `router.entry` в `manifest.json` используется исключительно как внутренний вход и не будет мелькать на экране.

### Переход с экрана-заставки

Многие приложения при первом входе отображают экран-заставку с логотипом, а затем переходят к основному функционалу. Типичная структура маршрутизации в этом случае: `router.entry` указывает на страницу логотипа, которая при инициализации переходит на главный экран с помощью [`router.replace()`](#replace). Таким образом, после запуска приложения пользователь сначала видит короткую заставку, затем наблюдает анимацию перехода с заставки на главный экран, после чего страница заставки удаляется из стека страниц.
``` js
// Предположим, это скрипт index.ux страницы логотипа
export default {
  onInit() {
    // Переход через некоторое время после показа экрана-заставки с логотипом
    setTimeout(() => {
      router.replace({ uri: 'MainPage' })
    }, 1000)
  },
}
```
При такой структуре сама страница логотипа является частью дизайна продукта, поэтому кратковременное отображение логотипа с последующим переходом на главный экран является ожидаемым поведением. Стоит отметить, что `replace()` гарантирует лишь плавность анимации перехода с логотипа на главный экран, но первый кадр страницы логотипа все равно появится на экране, и его невозможно «тихо» пропустить.

Если в приложении не предусмотрен отдельный логотип или экран-заставка, но при этом все равно используется подход «страница входа + переход через `replace()`» (например, страница соглашения о конфиденциальности настроена как `router.entry`, откуда через `replace()` происходит переключение на `MainPage`), то при холодном запуске пользователь увидит «мигание» этой страницы входа перед тем, как анимация переключит его на `MainPage`.

::: tip
Это явление обусловлено самой механикой маршрутизации. Если вы не хотите, чтобы пользователь наблюдал «переключение страниц», вам следует в первую очередь воспользоваться рекомендациями из раздела [Замена страницы по умолчанию](#замена-страницы-по-умолчанию) и выбрать конечный первый экран напрямую через `router.push()` на этапе запуска приложения, вместо того чтобы заменять саму себя через `replace()` внутри страницы входа.
:::

## Определение интерфейсов

### `getInfo` <decl type="(): Manifest" method/>

Получает информацию о контексте текущего приложения, возвращает объект [`Manifest`](./system-package.md#manifest-对象), содержащий базовую информацию о приложении, такую как имя пакета, номер версии и т.д.

### `terminate` <decl type="(): void" method version="0.8"/>

Завершает работу текущего приложения. После вызова этого метода приложение будет закрыто, и для продолжения работы пользователю потребуется перезапустить его.

::: note Риск совместимости
Этот API поддерживается не на всех платформах. В качестве временной альтернативы можно использовать метод [`launch.exit()`](./system-launch.md#exit).
:::

### `loadLibrary` <decl type="(name: string): object | undefined" method/>

Загружает по имени загрузчик библиотек (Library Loader), зарегистрированный нативной реализацией, и возвращает соответствующий объект библиотеки. Если библиотека с указанным именем не зарегистрирована, возвращается `undefined`.

В типичных случаях рекомендуется привязывать объект библиотеки к объекту APP:
```js
// app.js
import app from '@system.app'

export default {
  customLib: app.loadLibrary('custom-library'),
  onCreate() {
    if (!this.customLib) {
      // Обработка сбоя загрузки библиотеки, например, возврат к реализации на скрипте
      this.customLib = someStubImplementation();
    } else {
      // Нормальное использование объекта библиотеки
      this.customLib.someFunction()
    }
  }
}
```
Таким образом, компоненты могут напрямую использовать `this.$app.customLib` для доступа к объекту библиотеки.

Метод `loadLibrary()` подходит для подключения нестандартных системных функций. Приложение может проверить, является ли возвращаемое значение `undefined`, чтобы определить, поддерживает ли текущая платформа данную библиотеку, и тем самым обеспечить fallback (заглушку) на скрипт в универсальной среде симулятора, не полагаясь на специальную обработку путей к конкретным модулям в симуляторе.

Если приложение должно одновременно поддерживать стандартные API QuickApp и кастомные системные функции, оно может принять решение о возврате к резервному варианту на основе результата `loadLibrary()`.

### `keepForeground` <decl type="options: { enable: boolean }): void" method/>

Устанавливает, должно ли приложение оставаться на переднем плане. Если свойство `enable` в параметре `options` имеет значение `true`, приложение попытается остаться на переднем плане.

Для использования этого метода необходимо заявить разрешение приложения для `watch.permission.FOREGROUND_SERVICE` в файле [`manifest.json`](/framework/application/manifest.md#permissions).

Этот метод является лишь подсказкой для системного поведения, а не строгим требованием. Приложение может быть переведено в фоновый режим из-за действий пользователя или других стратегий с более высоким приоритетом. Когда приложение удерживается на переднем плане с помощью этого метода, устройство все же может переходить в режим пониженного энергопотребления:

- Если включен режим AOD (Always on Display), частота обновления пользовательского интерфейса (UI) снижается.
- В противном случае экран через некоторое время выключится, но приложение продолжит работать на переднем плане.

Когда устройство переходит в режим пониженного энергопотребления (включая выключение экрана), приложение на переднем плане по-прежнему планируется и выполняется с более низкой частотой, а не полностью переходит в спящий режим. Поэтому его можно использовать для навигационных или фитнес-приложений.

# Операции с файловой системой

Данный модуль предоставляет API для работы с файловой системой в стиле Promise. По сравнению со стилем обратных вызовов (callback), стиль Promise позволяет избежать «ада колбэков» (callback hell) и снизить сложность кода.

::: warning
Поскольку файловые API на основе колбэков крайне подвержены проблемам с таймингами, конкурентностью и обработкой ошибок, настоятельно рекомендуется использовать [Promise/`await` API](./README.md#асинхронные-интерфейсы-quick-app). Подробные рекомендации см. в разделе [Частные ловушки и рекомендации](#частные-ловушки-и-рекомендации).

Все API в `@system.file` являются [асинхронными операциями с файлами](#асинхронные-операции-с-файлами), что принципиально отличается от синхронного ввода-вывода (IO). Обязательно усвойте основные концепции асинхронного программирования и ознакомьтесь с использованием Promise и `async/await`.
:::

## Частные ловушки и рекомендации

Следующие примеры основаны на типичных проблемах подходов с использованием «колбэков», показывают, почему они легко выходят из строя или трудно поддерживаются при работе с файловым ввода-выводом, и предлагают эквивалентное переписывание через Promise/`await`.

### Асинхронные операции с файлами

Все API в модуле `@system.file` являются **асинхронными операциями**. Это означает, что при вызове функции работы с файлом функция **возвращает управление немедленно**, не дожидаясь завершения фактической операции ввода-вывода. Операции чтения и записи файлов выполняются в фоновом режиме, и после их завершения результат возвращается через Promise.

::: danger Обязательно к прочтению для новичков
Если вы не знакомы с асинхронным программированием, обязательно внимательно изучите этот раздел. **Игнорирование возвращаемого значения асинхронной операции** или **отказ дожидаться завершения Promise** приведет к серьезным программным ошибкам. Эти ошибки могут не проявиться в симуляторе, но на реальном устройстве вызовут потерю данных или сбои программы.
:::

#### Что такое асинхронная операция?

В синхронном программировании код выполняется последовательно, и каждая строка кода выполняется только после завершения предыдущей:

```js
// Пример синхронного кода (псевдокод, file API не предоставляет синхронную версию): блокирующее ожидание чтения файла
const text = file.readTextSync({ uri: 'internal://files/data.txt' });
console.log(text); // Обязательно выведет содержимое файла
console.log('Чтение завершено');
```

Но в асинхронном программировании операции ввода-вывода не блокируют выполнение кода. Когда вы вызываете асинхронную функцию, она немедленно возвращает объект Promise, в то время как реальная операция с файлом происходит в фоновом режиме:

```js
// Неправильно: игнорирование Promise, ожидание завершения отсутствует (вызов возвращает управление немедленно)
file.readText({ uri: 'internal://files/data.txt' });
console.log('Эта строка выполнится немедленно, к этому моменту файл может ещё не дочитаться!');

// Правильно: использование await для ожидания завершения операции
const text = await file.readText({ uri: 'internal://files/data.txt' });
console.log(text); // К этому моменту файл прочитан, его можно безопасно использовать
console.log('Чтение завершено');
```

#### Почему обязательно нужно использовать await?

Отказ от использования `await` для ожидания завершения асинхронных операций приводит к следующим серьезным проблемам.

Использование данных до того, как они готовы:
```js
// Неправильный пример: игнорирование возвращаемого значения
function loadConfig() {
  let config = null;
  file.readText({ uri: 'internal://files/config.json' })
    .then(text => config = JSON.parse(text)); // Этот callback выполнится в какой-то момент в будущем
  // Здесь config по-прежнему null, так как чтение файла ещё не завершено!
  console.log(config.theme); // Ошибка: попытка обратиться к null.theme приведет к падению
  return config; // Возвращает null
}

// Правильный пример: ожидание готовности данных
async function loadConfig() {
  const text = await file.readText({ uri: 'internal://files/config.json' });
  const config = JSON.parse(text);
  console.log(config.theme); // Правильно: файл прочитан, безопасный доступ
  return config; // Возвращает реальный объект конфигурации
}
```

Нарушение порядка операций:
```js
// Неправильный пример: отсутствие ожидания завершения записи
async function saveAndLoad() {
  // Запись новых данных, но без ожидания завершения
  file.writeText({ uri: 'internal://files/score.txt', text: '100' });
  
  // Немедленное чтение: к этому моменту запись может ещё не завершиться, и прочитаются старые данные!
  const score = await file.readText({ uri: 'internal://files/score.txt' });
  console.log(score); // Может вывести старое значение, а не '100'
}

// Правильный пример: чтение после завершения записи
async function saveAndLoad() {
  // Используем await для ожидания окончания записи
  await file.writeText({ uri: 'internal://files/score.txt', text: '100' });
  
  // Теперь читаем, гарантированно получая только что записанные данные
  const score = await file.readText({ uri: 'internal://files/score.txt' });
  console.log(score); // Выведет '100'
}
```

Состояние гонки и повреждение данных:

```js
// Неправильный пример: многократная параллельная запись в один и тот же файл
async function appendLog(message) {
  const log = await file.readText({ uri: 'internal://files/log.txt' });
  // Не используем await для ожидания записи, продолжаем выполнение
  file.writeText({ uri: 'internal://files/log.txt', text: log + message + '\n' });
}

// Параллельные вызовы: без await для appendLog
appendLog('Событие А'); // Чтение -> Запись А
appendLog('Событие Б'); // Чтение -> Запись Б
// Результат: оба чтения могут прочитать одинаковое старое содержимое, и последняя запись перезапишет предыдущую, в результате 'Событие А' будет потеряно

// Правильный пример: ожидание завершения каждой записи
async function appendLog(message) {
  const log = await file.readText({ uri: 'internal://files/log.txt' });
  await file.writeText({ uri: 'internal://files/log.txt', text: log + message + '\n' });
}

// Последовательные вызовы
await appendLog('Событие А'); // Полный цикл: чтение -> запись -> завершение
await appendLog('Событие Б'); // Полный цикл: чтение -> запись -> завершение
// Результат: оба события записаны корректно
```

#### Ловушка симулятора

::: warning Симулятор не выявляет все проблемы с асинхронностью
В среде разработки (симуляторе), из-за высокой скорости ввода-вывода на компьютере, файловые операции выполняются практически мгновенно. Поэтому даже если код некорректно использует `await`, в симуляторе он может казаться «работающим нормально».
:::

Файловый ввод-вывод на реальных встраиваемых устройствах имеет следующие ограничения:
- Медленная скорость чтения и записи Flash-памяти;
- Слабая способность файловой системы к кэшированию, чтение и запись файлов обычно напрямую обращаются к накопителю;
- Ограниченные системные ресурсы, операции ввода-вывода ставятся в очередь с задержкой.

Код без использования `await` на реальном устройстве **практически неизбежно приведет к ошибкам**! Не пренебрегайте стандартами асинхронного программирования только потому, что код прошёл тестирование в симуляторе.

#### Правила правильного использования async/await

1. Любая функция, вызывающая файловые API, должна быть объявлена как `async`:
   ```js
   async function saveData(data) {
     await file.writeText({ uri: 'internal://files/data.txt', text: data });
   }
   ```
2. Перед всеми файловыми операциями добавляйте ключевое слово `await`:
   ```js
   const content = await file.readText({ uri: 'internal://files/data.txt' });
   ```
3. Используйте `try/catch` для обработки возможных ошибок:
   ```js
   try {
     await file.writeText({ uri: 'internal://files/data.txt', text: 'hello' });
   } catch (err) {
     console.error('Ошибка записи:', err);
   }
   ```
4. Операции, требующие последовательного выполнения, должны вызываться через `await` по очереди:
   ```js
   // Правильно: сначала запись, затем чтение для проверки
   await file.writeText({ uri: 'internal://files/data.txt', text: 'test' });
   const verify = await file.readText({ uri: 'internal://files/data.txt' });
   console.log(verify === 'test' ? 'Проверка успешна' : 'Проверка не удалась');
   ```
5. Независимые операции могут выполняться параллельно, но нужно дожидаться завершения всех:
   ```js
   // Правильно: параллельное чтение нескольких файлов с ожиданием завершения всех
   const [file1, file2, file3] = await Promise.all([
     file.readText({ uri: 'internal://files/a.txt' }),
     file.readText({ uri: 'internal://files/b.txt' }),
     file.readText({ uri: 'internal://files/c.txt' })
   ]);
   ```

#### Полный пример: Управление пользовательской конфигурацией

```js
import file from '@system.file'

const CONFIG_URI = 'internal://files/user-config.json';

// Корректное асинхронное управление конфигурацией
class ConfigManager {
  async load() {
    try {
      const text = await file.readText({ uri: CONFIG_URI });
      return JSON.parse(text);
    } catch (err) {
      // Файл не существует или неверный формат, возвращаем конфигурацию по умолчанию
      console.warn('Не удалось загрузить конфигурацию, используются значения по умолчанию:', err.message);
      return { theme: 'dark', language: 'zh-CN' };
    }
  }

  async save(config) {
    try {
      const text = JSON.stringify(config, null, 2);
      await file.writeText({ uri: CONFIG_URI, text });
      console.log('Конфигурация сохранена');
    } catch (err) {
      console.error('Не удалось сохранить конфигурацию:', err.message);
      throw err; // Пробрасываем ошибку дальше, чтобы вызывающий код знал о сбое
    }
  }

  async update(changes) {
    // Полный цикл: чтение -> изменение -> сохранение
    const config = await this.load();
    Object.assign(config, changes);
    await this.save(config);
    return config;
  }
}

// Пример использования
async function main() {
  const manager = new ConfigManager();
  // Загрузка конфигурации
  const config = await manager.load();
  console.log('Текущая тема:', config.theme);
  // Обновление конфигурации
  await manager.update({ theme: 'light' });
  console.log('Тема обновлена');
}

// Обратите внимание: main сама по себе асинхронная, её нужно вызывать правильно
main().catch(err => {
  console.error('Ошибка выполнения программы:', err);
});
```

#### Итог

- Все API `@system.file` асинхронны, для ожидания их завершения обязательно требуется `await`.
- Отказ от использования `await` приводит к серьезным проблемам: неготовность данных, нарушение порядка операций, потеря ошибок, повреждение данных.
- Успешное прохождение тестов в симуляторе не означает корректность кода; на реальном устройстве операции ввода-вывода медленнее, и проблемы проявятся.
- Связка `async/await` + `try/catch` — это правильный и наиболее лаконичный подход.
- Никогда не игнорируйте возвращаемое значение Promise.

### Ловушки обратных вызовов (Callbacks)

#### Иллюзия порядка колбэков и перезапись в результате гонки

Этот сценарий включает последовательность операций чтения-модификации-записи для группы файлов. Пример проблемного кода, использующего колбэки для триггера логики:
```js
// Ожидается увеличение файла счетчика на +1, но два параллельных вызова могут перезаписать друг друга
function increment(uri, done) {
  file.readText({
    uri,
    success(text) {
      const n = Number(text || '0') + 1;
      console.log(`read ${text}, write ${n}`);
      // Вложенная операция записи файла внутри callback-функции успешного readText()
      file.writeText({
        uri,
        text: String(n),
        success() { done && done(); },
        fail(msg, code) { done && done(new Error(`${msg}:${code}`)); }
      });
    },
    fail(msg, code) { done && done(new Error(`${msg}:${code}`)); }
  });
}

// Сначала создаем файл counter, затем параллельно инициируем два инкремента (+1)
file.writeText({
  uri: 'internal://files/counter',
  text: '0',
  success() {
    // Параллельный запуск двух increment без какой-либо синхронизации
    increment('internal://files/counter');
    increment('internal://files/counter');
  }
})
```
После запуска этого скрипта вы можете увидеть только две строки логов `read 0, write 1`, и итоговое содержимое файла `counter` будет равно `1` вместо ожидаемого `2`. Механизм сбоя: оба чтения прочитали одно и то же старое значение, последующая запись перезаписала предыдущую, из-за чего значение увеличилось только на 1.

::: note
Приведенный выше скрипт выглядит крайне сложным и подвержен ошибкам при передаче функции обратного вызова `done`, что легко может привести к неверной реализации. На самом деле, после переписывания с использованием `async/await` код станет очень лаконичным и понятным.
:::

Сложный трюк заключается в использовании механизмов мьютексов и сериализации, которые позволяют полностью сохранить исходную семантику параллельного вызова `increment` и гарантировать атомарность всей операции чтения файла + инкремента счетчика:
```js
// Взаимное исключение по ключу на основе цепочки Promise
const lock = new Map();

/**
 * Сериализованное выполнение асинхронных задач для одного и того же ключа. Это утилитарная функция.
 * @param {string} key
 * @param {() => Promise<any>} fn
 * @returns {Promise<any>} Возвращает результат выполнения fn
 */
function withLock(key, fn) {
  // Получаем «хвост» предыдущей операции для этого ключа (или выполненный Promise, если его нет)
  const prev = lock.get(key) || Promise.resolve();
  // Даже если prev завершился ошибкой, мы должны продолжить очередь, поэтому сначала вызываем .catch(() => {})
  const p = prev.catch(() => {}).then(async () => {
    try {
      return await fn(); // Сама задача выполняется только тогда, когда до нее доходит очередь
    } finally {
      // Если мы все еще текущий хвост, значит, новых задач не поступало, можно очистить ресурс
      if (lock.get(key) === p) lock.delete(key);
    }
  });
  lock.set(key, p); // Прикрепляем новый хвост
  return p;
}

// Теперь фактический ввод-вывод внутри increment сериализуется через withLock:
async function increment(uri) {
  await withLock(uri, async () => {
    const n = Number(await file.readText({ uri })) || 0;
    console.log(`read ${n}, write ${n + 1}`);
    await file.writeText({ uri, text: `${n + 1}` });
  });
}

file.writeText({
  uri: 'internal://files/counter',
  text: '0'
}).then(() => {
  // Параллельный запуск двух increment, также без какой-либо синхронизации
  increment('internal://files/counter');
  increment('internal://files/counter');
});
```
После запуска этого скрипта содержимое файла `counter` гарантированно будет равно `2`, а порядок логов — `read 0, write 1` → `read 1, write 2`.

Тем не менее, такой код выглядит громоздким. Самый простой способ — напрямую вызвать `await increment()` (принцип «заражения» `await`):
```js
async function increment(uri) {
  const n = Number(await file.readText({ uri })) || 0;
  console.log(`read ${n}, write ${n + 1}`);
  await file.writeText({ uri, text: `${n + 1}` });
}

file.writeText({
  uri: 'internal://files/counter',
  text: '0'
}).then(async () => {
  // Используем await для ожидания increment, обеспечивая порядок
  await increment('internal://files/counter');
  await increment('internal://files/counter');
})
```

#### Уровни вложенности колбэков и утечки ресурсов

Следующий пример демонстрирует утечки ресурсов и логические ошибки, вызванные многоуровневой вложенностью и избыточными ветвлениями в коде на колбэках:

```js
function exportReport(uri, cb) {
  startBusyIndicator();
  file.readText({
    uri,
    success(t) {
      transformCb(t, (err2, out) => {
        if (err2) {
          stopBusyIndicator();
          return cb && cb(err2);
        }
        file.writeText({
          uri: `${uri}.bak`,
          text: out,
          complete() {
            // В некоторых ветках забыли вызвать stopBusyIndicator() или cb()
          }
        });
        // Это тоже ошибка, так как writeText() асинхронна и может еще не завершиться
        stopBusyIndicator();
        cb && cb(null);
      });
    },
    fail(msg, code) {
      stopBusyIndicator();
      cb && cb(new Error(`${msg}:${code}`));
    }
  });
}
```

Из-за слишком глубокой вложенности колбэков вызовы `stopBusyIndicator()` и `cb()` легко пропустить или использовать неправильно:
- Пропуск логики очистки приводит к тому, что индикатор занятости («busy indicator») никогда не останавливается, либо вызывающий код никогда не получает колбэк;
- Слишком ранний вызов логики очистки приводит к тому, что вызывающий код ошибочно считает запись завершенной.

Рекомендуемый подход (структурированная очистка):

```js
async function exportReport(uri) {
  startBusyIndicator();
  try {
    const t = await file.readText({ uri });
    const out = await transform(t);
    await file.writeText({ uri: `${uri}.bak`, text: out });
  } finally {
    stopBusyIndicator(); // Всегда вызывается после завершения файлового ввода-вывода (или исключения)
  }
}
```

#### Смешивание await и колбэков приводит к потере ожидаемого поведения await

Никакая функция обработки колбэков не возвращает объект Promise, что делает использование `await` неэффективным:

```js
// Из-за передачи параметра полного выполнения (complete callback), вызов переключается в стиль колбэков и не возвращает Promise
await file.writeText({
  uri: 'internal://files/a.txt',
  text: 'x',
  complete() {}, // Не передавайте поля параметров success/fail/complete
});
// Строка выше не будет реально дожидаться завершения записи, и последующий код может выполниться преждевременно
```

Рекомендуемый подход:

```js
// При использовании await не передавайте success/fail/complete
await file.writeText({ uri: 'internal://files/a.txt', text: 'x' });
```

### Лучшие практики

#### Четкий порядок и обработка ошибок

```js
import file from '@system.file'

export async function updateConfig(uri, patch) {
  try {
    const text = await file.readText({ uri });
    const json = JSON.parse(text || '{}');
    Object.assign(json, patch);
    await file.writeText({ uri, text: JSON.stringify(json, null, 2) });
  } catch (err) {
    // Централизованная обработка/логирование ошибок, не «глушите» их
    console.error('updateConfig failed:', uri, err);
    throw err;
  }
}
```

Главное здесь — обеспечить четкую последовательность с помощью `await`; использовать `try/catch`, чтобы гарантировать перехват и пробрасывание ошибок наверх. Если ошибки вовсе не обрабатывать, рантайм запишет исключение в лог и прервет всю цепочку вызовов.

#### Избежание TOCTTOU (состояния гонки между проверкой и использованием)

Не выполняйте последовательно `access()` -> `write*()`, полагаясь на то, что состояние между ними не изменится. Пример такого кода:

```js
file.access({
  uri: 'internal://files/a.txt',
  success(exists) {
    if (exists) {
      file.writeText({ uri: 'internal://files/a.txt', text: 'x' });
    } else {
      // Если файл не существует, сначала создаем директорию mkdir, затем пишем файл
      file.mkdir({
        uri: '/data',
        recursive: true,
        complete() {
          file.writeText({ uri: 'internal://files/a.txt', text: 'x' });
        }
      });
    }
  }
});
```

Рекомендуемый подход — сразу попытаться выполнить запись, рантайм автоматически создаст родительскую директорию:
```js
async function safeWriteText(uri, text) {
  try {
    await file.writeText({ uri, text });
  } catch (e) {
    // Здесь следует обработать ошибку, при этом ручной вызов mkdir перед записью не требуется
  }
}
```

#### Частичная запись и аварийное прерывание

На MCU-устройствах сбой системы обычно приводит к немедленной перезагрузке, и приложение не продолжает выполнение в «полуразрушенном» состоянии. Даже если приложение было завершено, уже зафиксированные операции записи в файл не прерываются (хотя могут и вовсе не выполниться), поэтому обычно не стоит беспокоиться о проблеме «наполовину записанного файла»:
```js
// Прямая перезапись, при отключении питания или сбое системы может остаться наполовину записанный файл
file.writeText({ uri: '/data/config.json', text: bigJson });
```

Для критически важных обновлений конфигурационных файлов можно использовать паттерн «временный файл + переименование в той же директории (rename)» для повышения стабильности:
```js
async function atomicWriteText(uri, text) {
  const tmp = `${uri}.tmp`;
  await file.writeText({ uri: tmp, text });
  await file.rename({ oldUri: tmp, newUri: uri });
}
```

# Запрос данных fetch

## Импорт модуля

``` js
import fetch from '@system.fetch'
```

## API

### `fetch`
<decl method><pre>
(options: {
  url: string,
  method?: 'GET' | 'POST' | 'PUT',
  header?: {[key: string]: string},
  params?: {[key: string]: string | number},
  data?: string | ArrayBuffer | {[key: string]: any},
  responseType?: 'text' | 'json' | 'arraybuffer',
  timeout?: number
}): Promise<{
  code: number,
  headers: {[key: string]: string},
  data: string | ArrayBuffer | any,
}>
</pre></decl>

Инициирует асинхронный сетевой запрос данных. Назначение полей в параметре `options`:
- `url`: URL-адрес веб-сайта, к которому нужно обратиться.
- `method`: поддерживаются `'GET'`, `'POST'` и `'PUT'`, по умолчанию — `'GET'`.
- `header`: объект, содержащий информацию о заголовках HTTP-запроса, где ключи и значения являются строками. Типичными полями заголовков HTTP могут быть `Authorization`, `Content-Type` и т. д.
- `params`: параметры запроса, все свойства которых будут добавлены к URL-адресу запроса.
- `data`: содержимое тела (body) HTTP POST-запроса.
- `responseType`: тип данных ответа в HTTP-запросе, по умолчанию — `'text'`, может принимать следующие значения:
  - `'text'`: ответ возвращает текстовые данные, то есть свойство `data` возвращаемых данных имеет тип `string`.
  - `'json'`: ответ возвращает данные JSON, при этом свойство `data` преобразует эти данные JSON в соответствующее значение JavaScript.
  - `arraybuffer`: ответ возвращает бинарные данные, то есть возвращаемые данные хранятся в виде объекта `ArrayBuffer`.
- `timeout`: время ожидания ответа на запрос в миллисекундах, значение по умолчанию — $6000 \rm ms$.

#### Параметр `data`

`data` — это тело (body) запроса, используемое только в POST-запросах. Обычно оно относится к одному из трех типов: строка, объект `ArrayBuffer` или объект JSON. Когда `data` является строкой или объектом `ArrayBuffer`, телом запроса будут соответственно текстовые или бинарные данные. Когда тело представляет собой объект JSON, оно сериализуется в текстовый формат. Формат сериализации определяется полем `Content-Type` метода запроса (параметр `method`):
- Когда `Content-Type` равен `application/json`, объект параметра `data` сериализуется в строку JSON и используется в качестве тела запроса;
- В остальных случаях объект параметра `data` сериализуется в формат `application/x-www-form-urlencoded`.

::: warning
Многие HTTP API используют тела POST-запросов в формате JSON. Обратите внимание, что необходимо правильно установить заголовок `Content-Type` в значение `application/json`. Подробности см. в этом [примере](#post-запрос-json-body).
:::

#### Возвращаемое значение

Возвращает объект `Promise`, свойства значения которого после завершения запроса следующие:
- [`code`](#code-код-ответа) — код ответа сервера, успешный код ответа обычно равен `200`.
- `header` — заголовок ответа сервера.
- `data` — возвращаемое значение запроса данных, конкретное содержимое определяется параметром `options.responseType`.

В случае сбоя запроса возвращаемый объект `Promise` будет отклонен (rejected).

## Инструкция по применению

### Код ответа `code`

Значения кодов ответа, возвращаемых сервером:
- `200`: запрос выполнен успешно;
- `1002`: ошибка проверки параметров;
- `1005`: введены неполные параметры;
- `5000`: ошибка запроса, ошибка ответа;
- `5001`: ошибка чтения буфера данных;
- `5002`: ошибка запроса, ошибка ответа;
- Другое: другие коды ответа HTTP/HTTPS, такие как `404` и т. д.

Когда код ответа, возвращаемый [`fetch`](#fetch), равен `200`, это означает, что сетевой запрос прошел успешно; другие значения указывают на ошибку запроса.

# Загрузка и выгрузка request

## Импорт модуля

``` js
import request from '@system.request'
```

## API

### `download`
<decl method><pre>
(options: {
  url: string,
  header?: {[key: string]: string},
  filename?: string,
  callback: (progress: number) => void
}): DownloadTask
</pre></decl>

Загрузка файла по протоколу HTTP/HTTPS. Назначение полей параметра `options`:
- `url`: URL-адрес веб-сайта для доступа;
- `header`: объект, содержащий информацию о заголовках HTTP-запроса, где ключи и значения являются строками. Типичными полями заголовков HTTP могут быть `Authorization`, `Content-Type` и т.д.;
- `filename`: URI для сохранения загружаемого файла, например: `internal://files/download.txt`;
- `callback`: функция обратного вызова для отслеживания прогресса загрузки. Эта функция вызывается многократно во время загрузки, где `progress` — значение прогресса загрузки в диапазоне от $[0, 100]$.

Метод `download()` возвращает объект [`DownloadTask`](#downloadtask), который можно использовать для ожидания завершения загрузки или управления задачей загрузки.

::: warning
Пожалуйста, не используйте достижение прогресса загрузки $100\%$ в функции `callback` в качестве триггера для действий после завершения загрузки. Подробности см. в разделе [Ожидание завершения загрузки](#ожидание-завершения-загрузки).

Текущая реализация не выполняет автоматический анализ свойства `filename` на основе `url`, поэтому обязательно укажите `filename`.
:::

## Типы

### `DownloadTask`

`DownloadTask` — это возвращаемый тип метода `download`, его сигнатура:

``` ts
interface DownloadTask {
  complete: Promise<void>,
  cancel(): void
}
```

Свойство `complete` представляет собой объект `Promise`, который можно использовать для ожидания завершения загрузки. Метод `cancel()` используется для отмены выполняющейся задачи загрузки. Если загрузка уже завершена, метод `cancel()` не производит никакого эффекта.

#### Ожидание завершения загрузки

Используйте `DownloadTask.complete` для ожидания завершения загрузки. Когда этот `Promise` переходит в состояние выполнения (fulfilled), гарантируется, что файл полностью записан, поэтому можно безопасно переходить к следующему шагу. В отличие от этого, достижение прогресса загрузки $100\%$ в `callback` не означает, что запись файла завершена; это подходит только для таких целей, как отображение индикатора выполнения в пользовательском интерфейсе.

При реальном использовании, учитывая возможность сбоя загрузки, рекомендуется использовать конструкцию `try...catch` для обработки ошибок загрузки. В следующем примере показано ее использование.

## Пример

Это простой пример загрузки файла из сети:

``` js
request.download({
  url: "http://www.rt-thread.com/service/rt-thread.txt",
  filename: "internal://tmp/rt-thread.txt",
})
```

Вы можете дождаться завершения загрузки с помощью свойства `complete`, возвращаемого методом `download()`:
``` js
try {
  await request.download({
    url: "http://www.rt-thread.com/service/rt-thread.txt",
    filename: "internal://tmp/rt-thread.txt"
  }).complete // отклонение complete означает сбой загрузки
  console.log('download finished.')
} catch (e) {
  console.error('download failed:', e)
}
```

Блок `try...catch` здесь используется для перехвата исключения при сбое загрузки. Это исключение на самом деле является ошибкой, выбрасываемой при отклонении (rejected) `DownloadTask.complete`, поэтому вы должны использовать `await` для ожидания свойства `complete`, иначе исключение не удастся перехватить.

# Управление пакетами

Этот модуль предоставляет функции для установки и удаления пакетов ресурсов.

## Импорт модуля

``` js
import pkg from '@system.package'
```

Поскольку `package` является ключевым словом в JavaScript и не может использоваться в качестве имени переменной, мы можем экспортировать модуль `"@system.package"` в переменную `pkg`.

## Определение интерфейсов

### `install` <decl function type="(options: { src: string }): Promise<void>" />

Установка приложения или пакета циферблата из файловой системы. Свойство `src` параметра `options` представляет собой URI файла устанавливаемого пакета ресурсов.

Если пакет ресурсов является пакетом приложения, то после его установки с помощью `pkg.install({ src: 'package-uri' })` его можно запустить с помощью [`launch()`](system-launch.md#launch-launch-app), а для доступа к содержимому пакета можно использовать URI-протокол [`app`](/framework/application/resource.md#app).

`src` — это URI файла устанавливаемого пакета ресурсов. Устанавливаемый пакет должен быть валидным пакетом приложения или циферблата, то есть содержать файл [`manifest.json`](/framework/application/manifest.md). Имя установленного пакета определяется полем [`manifest.package`](/framework/application/manifest.md#package).

После установки для доступа к ресурсам внутри пакета можно использовать протокол [`prc`](/framework/application/resource.md#prc), а для пакетов приложений также можно использовать протокол `app`.

Если устанавливаемый пакет уже существует, будет выполнена операция обновления. Если обновляемое приложение запущенно, оно будет сначала закрыто, после чего его можно будет снова запустить вызовом [`launch()`](system-launch.md#launch-launch-app).

Установленный пакет может быть удален с помощью API [`remove()`](#remove).

### `remove`<decl type="(options: { package: string }): Promise<void>" function />

Удаление пакета ресурсов, установленного с помощью [`install()`](#install). Свойство `package` параметра `options` является именем удаляемого пакета ресурсов, то есть полем [`manifest.package`](/framework/application/manifest.md#package).

Перед удалением пакета ресурсов следует закрыть связанные ресурсы, например, уничтожить соответствующие компоненты и закрыть связанные страницы. Функция `remove()` автоматически закроет приложение, соответствующее пакету ресурсов (если это пакет приложения).

::: warning
Вы должны использовать `remove()`, а не напрямую API файловой системы для удаления пакета ресурсов, так как последнее не очищает кэш ресурсов и не позволяет корректно удалить информацию об установке.
:::

### `getInfo` <decl type="(query?: string | Query): Manifest | undefined" method/>

Получение информации manifest пакета приложения. Необязательный параметр `query` может быть строкой с именем пакета или более сложным объектом `Query`:
``` ts
type Query = {
  package: string,                 // Имя запрашиваемого пакета
  options?: ('dial' | 'widgets')[] // Необязательные поля для запроса
}
```
Если пакет, указанный в поле `package`, существует, `getInfo()` возвращает информацию `Manifest` пакета, в противном случае возвращается `undefined`. Если параметр `query` не указан, `getInfo()` возвращает информацию manifest текущего приложения.

#### Объект `Manifest`

Возвращаемый объект `Manifest` в основном является подмножеством [`manifest.json`](/framework/application/manifest.md):
``` ts
type Query = {
  type: 'app' | 'dial', // Тип пакета: приложение или циферблат
  name: string,         // Имя пакета
  versionName: string,  // Название версии
  versionCode: number,  // Код версии
  icon?: string,        // Путь к изображению приложения, это поле существует только для пакетов приложений
  dial?: {              // Необязательное поле: информация о циферблате, присутствует только в пакетах циферблатов
    component: string,  // Путь к компоненту циферблата
    preview: string     // Путь к изображению предварительного просмотра циферблата
  },
  widgets?: {           // Необязательное поле: информация о виджетах и мини-приложениях
    name: string,       // Имя виджета/мини-приложения
    component: string,  // Путь к виджету/мини-приложению
    preview: string     // Путь к изображению предварительного просмотра виджета/мини-приложения
  }[]
}
```
Поля `dial` и `widgets` объекта `Manifest` являются необязательными, их наличие определяется содержимым `Query.options`. Например:
``` js
pkg.getInfo({
  package: 'com.example.app',
  options: ['dial', 'widgets']
})
```
приведет к тому, что результирующий `Manifest` будет содержать поля `dial` и `widgets` (однако пакет приложения всегда не содержит поле `dial`).

Когда параметр `query` является строкой, это эквивалентно пустому значению опции `options`, то есть
``` ts
pkg.getInfo('com.example.app')
pkg.getInfo({ package: 'com.example.app' })
```
дают одинаковый результат. В этом случае возвращаемый объект `Manifest` не содержит необязательных полей.

Если параметр `query` не указан, с помощью `getInfo()` можно получить информацию о текущем приложении:
``` js
let manifest = pkg.getInfo()
console.log(manifest)
```

Получение списка всех установленных имен пакетов приложений или циферблатов.

### `countOf` <decl function type="(type?: 'app' | 'dial'): string[]" />

Получение количества установленных приложений или циферблатов.

- Объект `AudioPlayer` (далее именуемый `audiokit.Player`) и объект `AudioPlayer`, созданный в модуле `system.media` (далее именуемый `media.Player`), являются разными объектами JS, но они управляют одним и тем же проигрывателем. При этом объект `audiokit.Player` имеет больше функций по сравнению с объектом `media.Player`, таких как методы `next()`, `previous()` и др. Операции вроде `play()`, выполняемые пользователем через объект `audiokit.Player`, также будут передаваться в прослушиватели объекта `media.Player`.

### `src` <decl type="string" set get />

Установка или чтение URL воспроизводимого аудио. Поддерживаются [пути к локальным ресурсам](/framework/application/resource.md#uri-和路径) и пути к сетевым ресурсам с использованием протоколов http и https (например, `https://www.rt-thread.com/service/test/001.mp3`). Ниже приведен простой пример установки src и запуска воспроизведения:

```ts
import audiokit from '@system.audiokit'
// Запрос аудиопроигрывателя, находящегося в активном состоянии в системе
let player = audiokit.getActivePlayer()
if (player != null) {
  // Сначала останавливаем воспроизведение текущего аудио
  player.stop()
  // Устанавливаем URL воспроизводимого аудио
  player.src = 'https://www.rt-thread.com/service/test/001.mp3'
  // Запускаем воспроизведение аудио
  player.play()
}
```

### `name` <decl type="string" set get />

Имя объекта проигрывателя. Если оно не задано, по умолчанию используется имя приложения, создавшего проигрыватель. Стоит отметить, что имя объекта проигрывателя не является глобально уникальным, и имя нельзя использовать для идентификации объекта проигрывателя.

### `icon` <decl type="string" set get />

URL иконки объекта проигрывателя. Поддерживаются [пути к локальным ресурсам](/framework/application/resource.md#uri-和路径).

### `mode` <decl type="string" set get />

Режим воспроизведения. Функция, соответствующая этому свойству, должна быть реализована приложением-проигрывателем; объект проигрывателя не обрабатывает ее по умолчанию, а лишь предоставляет это свойство.

- `sequential`: последовательное воспроизведение  
- `random`: случайное воспроизведение  
- `singleloop`: повтор одной композиции  
- `listloop`: повтор списка

Чтение текущего состояния воспроизведения:

- `play`: состояние воспроизведения  
- `pause`: состояние паузы  
- `stop`: состояние остановки 
- `ended`: состояние окончания воспроизведения  
- `error`: состояние ошибки воспроизведения

### `position` <decl type="number" set get />

Объект атрибутов песни.

::: details Сигнатура типа
```ts
type songAttribute = {
  title: string; // Название песни
  artist: string; // Имя исполнителя (может быть сольный артист или группа)
  album: string; // Название альбома, которому принадлежит песня
  year: string; // Год выпуска песни
  genre: string; // Жанр песни, например, поп, рок, классика и т.д.
  track: string; // Номер текущей песни в альбоме, например: "1/12" означает 1-я песня из 12
  coverArt: string; // URL изображения обложки песни
  lyrics: string; // URL текста песни
```

Объект songAttribute, как и объект AudioPlayer, является объектом Proxy, то есть его нельзя сериализовать и десериализовать с помощью JSON, а также ссылаться на него в реактивном фреймворке. Ниже приведен простой пример использования:

```ts
// Установка названия песни
this.player.songAttribute.title = "Неизвестно"
```

### `play` <decl type="(): void" method />

Запуск воспроизведения аудио, указанного в свойстве src.

- Если свойство src не было установлено до вызова этого метода, воспроизведение завершится ошибкой и вызовет событие onerror;
- Этот метод является синхронным интерфейсом. После его выполнения необходимо дождаться события onplay или onerror, чтобы определить успешность или неудачу воспроизведения. До срабатывания события любые другие выполняемые операции будут игнорироваться;  

Ниже приведен простой пример вызова интерфейса `play()`:

```ts
import audiokit from '@system.audiokit'
// Запрос аудиопроигрывателя, находящегося в активном состоянии в системе
let player = audiokit.getActivePlayer()
if (player != null) {
  // Сначала останавливаем воспроизведение текущего аудио
  player.stop()
  // Устанавливаем URL воспроизводимого аудио
  player.src = 'https://www.rt-thread.com/service/test/001.mp3'
  // Установка события onplay
  player.onplay = () => { console.dir("Начало воспроизведения") }
  // Установка события onerror
  player.onerror = () => { console.dir("Ошибка воспроизведения") }
  // Запуск воспроизведения аудио
  player.play()
}
```

Пауза воспроизведения текущего аудио.

- Этот метод является синхронным интерфейсом. После его выполнения необходимо дождаться события onpause или onerror, чтобы определить успешность или неудачу паузы. До срабатывания события любые другие выполняемые операции будут игнорироваться;  

### `stop` <decl type="(): void" method />

Остановка воспроизведения аудио. Воспроизведение можно возобновить с помощью `play`.

- Этот метод является синхронным интерфейсом. После его выполнения необходимо дождаться события onstop или onerror, чтобы определить успешность или неудачу остановки. До срабатывания события любые другие выполняемые операции будут игнорироваться;  

### `release` <decl type="(): void" method />

Освобождение аудиоресурсов.

- Выполнение этого интерфейса остановит воспроизведение текущего аудио. Необходимо дождаться события onstop или onerror, чтобы определить успешность или неудачу остановки. До срабатывания события любые другие выполняемые операции будут игнорироваться;   

### `next` <decl type="(): void" method />

Уведомление приложения-проигрывателя о воспроизведении следующего трека. После выполнения этого интерфейса будет сгенерировано событие onnext, уведомляющее приложение-проигрыватель, которое прослушивает это событие, и приложение выполнит логику переключения песен.

### `previous` <decl type="(): void" method />

Уведомление приложения-проигрывателя о воспроизведении предыдущего трека. После выполнения этого интерфейса будет сгенерировано событие onprevious, уведомляющее приложение-проигрыватель, которое прослушивает это событие, и приложение выполнит логику переключения песен.

### `requestFocus` <decl type="({acquireType: string, volumeType: string}): void" method />

Запрос фокуса аудио. После выполнения этого интерфейса базовой системе будет отправлено уведомление о запросе или освобождении фокуса аудио, и базовая система будет управлять логикой переключения и прерывания различных типов аудио.

Параметр `acquireType` указывает тип запроса:
- `gain`: запросить фокус аудио
- `loss`: освободить фокус аудио

Параметр `volumeType` указывает тип аудио:
- `system`: системные подсказки
- `media`: медиа-музыка
- `tts`: голосовое вещание

Следующий пример демонстрирует метод запроса фокуса аудио с помощью функции `requestFocus`:
``` ts
import audiokit from '@system.audiokit'
// Запрос аудиопроигрывателя, находящегося в активном состоянии в системе
let player = audiokit.getActivePlayer()
if (player != null) {
  // Получение фокуса аудио для медиа-музыки
  player.requestFocus({ volumeType: 'media', acquireType: 'gain' });
}
```

Освобождение фокуса аудио. После выполнения этого интерфейса базовая система будет уведомлена об освобождении фокуса аудио, и базовая система будет управлять логикой переключения и прерывания различных типов аудио.

Событие обратного вызова при возникновении ошибки во время выполнения таких интерфейсов, как `play`, `pause`, `stop`, `position`. При возникновении ошибки соответствующие события вроде `onplay` вызываться не будут.

### `ontimeupdate` <decl type="?: () => void" set />

Событие обратного вызова, которое срабатывает при обновлении свойства `position`. Это событие срабатывает только тогда, когда приложение находится на переднем плане, и прекращает генерироваться, когда приложение уходит в фоновый режим.

### `oninterrupt` <decl type="?: (action: {interruptHint: number}) => void" set />

Функция обратного вызова при возникновении события прерывания аудио. Уведомление о временном или полном прерывании, когда текущее аудио вытесняется аудио того же или другого типа.

Параметр `interruptHint` объекта `action` указывает тип прерывания:
- `1`: короткое прерывание (может восстановиться автоматически, например: прерывание музыки)
- `2`: полное прерывание (не может восстановиться автоматически, например: прерывание NetEase Cloud приложением Ximalaya)

Следующий пример демонстрирует метод регистрации обратного вызова `oninterrupt`, который вызывается при возникновении события:
``` js
player.oninterrupt = (action) => {
  console.log(action.interruptHint)
}
```

### `onprevious` <decl type="?: () => void" set />

Событие обратного вызова при изменении объекта атрибутов песни.

### `onposition` <decl type="?: () => void" set />

Событие обратного вызова при успешном установлении временной позиции воспроизведения текущего аудио с помощью `position`.

### `onrequestfocus` <decl type="?: () => void" set />

### `onreleasefocus` <decl type="?: () => void" set />

### `createAudioRecord` <decl type="(): AudioRecorder" method />

Создает объект [`AudioRecorder`](#audiorecorder-объект).

Разработчикам необходимо заявить о доступе приложения к разрешению `watch.permission.RECORD` в файле [`manifest.json`](/framework/application/manifest.md#permissions).

### `setVolume` <decl type="(volume: number): void" method />

Устанавливает системную громкость мультимедиа. Параметр `volume` представляет собой значение громкости в диапазоне $[0.0, 1.0]$. Это свойство используется для управления системной громкостью мультимедиа, и его конкретные функции зависят от реализации платформы. ### `getVolume` <decl type="(): number" method />

Получает системную громкость мультимедиа. Результатом является значение громкости в диапазоне $[0.0, 1.0]$. Это свойство используется для получения системной громкости мультимедиа, и его конкретные функции зависят от реализации платформы. Для получения громкости предпочтительнее использовать свойство `volume` объекта `AudioPlayer`.

### `src` <decl type="string" set get />

Устанавливает или читает URL аудио для воспроизведения. Поддерживаются [пути к локальным ресурсам](/framework/application/resource.md#uri-和路径) и пути к сетевым ресурсам с использованием протоколов http и https (например: `https://www.rt-thread.com/service/test/001.mp3`). Ниже приведен простой пример установки src и запуска воспроизведения:

```ts
import media from '@system.media'
// Создание аудиопроигрывателя
let player = media.createAudioPlayer()
// Установка URL воспроизводимого аудио
player.src = 'https://www.rt-thread.com/service/test/001.mp3'
// Запуск воспроизведения аудио
player.play()
```

### `name` <decl type="string" set get />

Имя объекта проигрывателя. Если не задано, по умолчанию используется имя приложения, создавшего проигрыватель. Стоит отметить, что имя объекта проигрывателя не является глобально уникальным, и его нельзя использовать для идентификации объекта проигрывателя.

### `icon` <decl type="string" set get />

URL иконки объекта проигрывателя. Поддерживает [пути к локальным ресурсам](/framework/application/resource.md#uri-和路径).

### `mode` <decl type="string" set get />

Режим воспроизведения. Функция, соответствующая этому свойству, должна быть реализована приложением-проигрывателем. Объект проигрывателя по умолчанию не обрабатывает её, а лишь предоставляет это свойство.

- `sequential`: последовательное воспроизведение  
- `random`: случайное воспроизведение  
- `singleloop`: повтор одного трека  
- `listloop`: повтор списка  

### `status` <decl type="string" get />

Чтение текущего состояния проигрывателя

- `play`: состояние воспроизведения  
- `pause`: состояние паузы  
- `stop`: состояние остановки 
- `ended`: состояние окончания воспроизведения  
- `error`: состояние ошибки воспроизведения  

### `duration` <decl type="number" get />

Общая продолжительность аудио в секундах.

### `position` <decl type="number" set get />

Текущая временная позиция воспроизведения аудио в секундах.

### `openSystemNotification` <decl type="bool" set get />

Включено ли системное уведомление, по умолчанию выключено. После включения этот объект проигрывателя может быть обнаружен [диспетчером аудиопроигрывателей](/framework/application/system-audioPlayerManager.md#音频播放器管理器).

### `songAttribute` <decl type="songAttribute" set get />

Объект атрибутов песни

::: details Сигнатура типа
```ts
type songAttribute = {
  title: string; // Название песни
  artist: string; // Имя исполнителя (соло или группа)
  album: string; // Название альбома, которому принадлежит песня
  year: string; // Год выпуска песни
  genre: string; // Жанр песни, например: поп, рок, классика и т. д.
  track: string; // Номер текущей песни в альбоме, например: "1/12" означает 1-я из 12
  coverArt: string; // URL обложки песни
  lyrics: string; // URL текста песни
  comments: string; // Дополнительная информация, например примечания об авторских правах
}
```
:::

Объект songAttribute, как и объект AudioPlayer, является объектом Proxy, то есть его нельзя сериализовать и десериализовать с помощью JSON, а также нельзя ссылаться на него в реактивном фреймворке. Ниже приведен простой пример использования:

```ts
// Установка названия песни
this.player.songAttribute.title = "Неизвестно"
// Установка исполнителя песни
this.player.songAttribute.artist = "Неизвестно"
// Просмотр названия песни
console.dir(this.player.songAttribute.title)
```

### `volume` <decl type="number" set get />

Громкость текущего проигрывателя, диапазон: [0.0, 1.0]

### `nextAvailable` <decl type="bool" set get />

Установка или проверка возможности переключения на следующий трек

### `prevAvailable` <decl type="bool" set get />

Установка или проверка возможности переключения на предыдущий трек

### `play` <decl type="(): void" method />

Начать воспроизведение аудио, указанного в свойстве src.

- Если свойство src не было установлено до вызова этого метода, воспроизведение завершится ошибкой, что приведет к срабатыванию события onerror;
- Этот метод является синхронным интерфейсом. После его выполнения необходимо дождаться события onplay или onerror, чтобы определить успешность или неудачу воспроизведения. До срабатывания события любые другие выполняемые операции будут проигнорированы;  

Ниже приведен простой пример вызова интерфейса play():

```ts
import media from '@system.media'
// Создание аудиопроигрывателя
let player = media.createAudioPlayer()
// Установка URL воспроизводимого аудио
player.src = 'https://www.rt-thread.com/service/test/001.mp3'
// Установка события onplay
player.onplay = () => { console.dir("Начало воспроизведения") }
// Установка события onerror
player.onerror = () => { console.dir("Ошибка воспроизведения") }
// Запуск воспроизведения аудио
player.play()
```

### `pause` <decl type="(): void" method />

Приостановить воспроизведение текущего аудио  

- Этот метод является синхронным интерфейсом. После его выполнения необходимо дождаться события onpause или onerror, чтобы определить успешность или неудачу паузы. До срабатывания события любые другие выполняемые операции будут проигнорированы;  

### `stop` <decl type="(): void" method />

Остановить воспроизведение аудио. Вы можете возобновить воспроизведение с помощью play.  

- Этот метод является синхронным интерфейсом. После его выполнения необходимо дождаться события onstop или onerror, чтобы определить успешность или неудачу остановки. До срабатывания события любые другие выполняемые операции будут проигнорированы;  

### `release` <decl type="(): void" method />

Освободить аудиоресурсы  

- Выполнение этого интерфейса остановит воспроизведение текущего аудио. Необходимо дождаться события onstop или onerror, чтобы определить успешность или неудачу остановки. До срабатывания события любые другие выполняемые операции будут проигнорированы;   

### `next` <decl type="(): void" method />

Уведомить приложение-проигрыватель о необходимости воспроизвести следующий трек. После выполнения этого интерфейса будет сгенерировано событие onnext, уведомляющее приложение-проигрыватель, подписанное на это событие, которое выполнит логику переключения песен.

### `previous` <decl type="(): void" method />

Уведомить приложение-проигрыватель о необходимости воспроизвести предыдущий трек. После выполнения этого интерфейса будет сгенерировано событие onprevious, уведомляющее приложение-проигрыватель, подписанное на это событие, которое выполнит логику переключения песен.

### `requestFocus` <decl type="({acquireType: string，volumeType: string}): void" method />

Запросить фокус аудио. После выполнения этого интерфейса система будет уведомлена о запросе или освобождении фокуса аудио, и на низком уровне будет осуществляться управление логикой переключения и прерывания для различных типов аудио.

Параметр `acquireType` указывает тип запроса:
- `gain`: запросить фокус аудио
- `loss`: освободить фокус аудио

Параметр `volumeType` указывает тип аудио:
- `system`: системные подсказки
- `media`: медиамузыка
- `tts`: голосовое вещание

Следующий пример демонстрирует способ запроса фокуса аудио с помощью функции `requestFocus`:
``` ts
import media from '@system.media'
// Создание аудиопроигрывателя
let player = media.createAudioPlayer()
// Получение фокуса аудио для типа медиамузыки
player.requestFocus({ volumeType: 'media', acquireType: 'gain' });
```

### `releaseFocus` <decl type="(): void" method />

Освободить фокус аудио. После выполнения этого интерфейса система будет уведомлена об освобождении фокуса аудио, и на низком уровне будет осуществляться управление логикой переключения и прерывания для различных типов аудио.

### `onplay` <decl type="?: () => void" set />

Колбэк-событие после успешного запуска воспроизведения (`play`) аудио.

### `onpause` <decl type="?: () => void" set />

Колбэк-событие после успешной паузы (`pause`) аудио.

### `onstop` <decl type="?: () => void" set />

Колбэк-событие после успешной остановки (`stop`) аудио.

### `onended` <decl type="?: () => void" set />

Колбэк-событие по окончании воспроизведения аудио.

### `onerror` <decl type="?: () => void" set />

Колбэк-событие при возникновении ошибки во время выполнения таких интерфейсов, как `play`, `pause`, `stop`, `position`. При возникновении ошибки соответствующие события вроде onplay не будут вызваны.

### `ontimeupdate` <decl type="?: () => void" set />

Колбэк-событие, которое срабатывает при обновлении свойства position. Это событие срабатывает только тогда, когда приложение находится на переднем плане, и прекращает генерироваться, когда приложение уходит в фоновый режим.

### `oninterrupt` <decl type="?: (action: {interruptHint: number}) => void" set />

Функция обратного вызова при возникновении события прерывания аудио. Уведомление о временном или полном прерывании текущего аудио, когда его перехватывает аудио того же или другого типа.

Параметр `interruptHint` параметра `action` указывает тип события прерывания:
- `1`: короткое прерывание (может восстановиться автоматически, например: музыка прервана звонком)
- `2`: полное прерывание (не может восстановиться автоматически, например: NetEase Music прервано Himalaya)

Следующий пример демонстрирует способ регистрации колбэк-функции `oninterrupt`, которая будет вызываться при возникновении события:
``` js
player.oninterrupt = (action) => {
  console.log(action.interruptHint)
}
```

### `onnext` <decl type="?: () => void" set />

Колбэк-событие при необходимости воспроизвести следующий трек.

### `onprevious` <decl type="?: () => void" set />

Колбэк-событие при необходимости воспроизвести предыдущий трек.

### `onrequestplay` <decl type="?: () => void" set />

Триггер колбэк-события, когда нижний уровень должен запустить воспроизведение, чтобы уведомить JS-приложение, которое затем выполняет логику запуска воспроизведения.

### `onrequestpause` <decl type="?: () => void" set />

Триггер колбэк-события, когда нижний уровень должен приостановить воспроизведение, чтобы уведомить JS-приложение, которое затем выполняет логику приостановки воспроизведения.

### `onrequeststop` <decl type="?: () => void" set />

Триггер колбэк-события, когда нижний уровень должен остановить воспроизведение, чтобы уведомить JS-приложение, которое затем выполняет логику остановки воспроизведения.

### `onsongattribute` <decl type="?: () => void" set />

Колбэк-событие при изменении объекта атрибутов песни.

### `onposition` <decl type="?: () => void" set />

Колбэк-событие при успешном выполнении установки временной позиции воспроизведения текущего аудио с помощью `position`.

### `onrequestfocus` <decl type="?: () => void" set />

Колбэк-событие при успешном запросе фокуса аудио.

### `onreleasefocus` <decl type="?: () => void" set />

Колбэк-событие при успешном освобождении фокуса аудио.

### `onmodechanged` <decl type="?: () => void" set />

Колбэк-событие при изменении режима воспроизведения.

### `onvolumechange` <decl type="?: () => void" set />

## Объект `AudioRecorder`

::: details Сигнатура типа
``` ts
interface AudioRecorder {
    start({
      uri: string, 
      sample?: 8000 | 16000 | 44100 | 48000,
      layout?: 8 | 16 | 32,
      channel?: 1 | 2,
      bitrate?: 16 | 32 | 64,
      codec?: "pcm" | "mp3" | "opus" | "silk",
      format?: "ogg",
    }): Promise<void>,
    read({callback: (ArrayBuffer) => void}): void,
    stop(): void,
    release(): void,
    onstart?: () => void,
    onstop?: () => void,
    onrelease?: () => void,
    onavailable?: (ArrayBuffer) => void,
    onerror?: ({error: string})=> void
```

:::

### `start`
<decl method><pre>
(options: {
  uri: string,
  sample?: 8000 | 16000 | 44100 | 48000,
  layout?: 8 | 16 | 32,
  channel?: 1 | 2,
  bitrate?: 16 | 32 | 64,
  codec?: "pcm" | "mp3" | "opus" | "silk",
  format?: "ogg",
}): Promise&lt;void>
</pre></decl>

Начать запись аудио. Назначение полей параметра `options`:
- `uri`: URI файла записи для сохранения, поддерживается только протокол `internal`, директория будет создана автоматически;
- `sample`: частота дискретизации аудио в $\rm Hz$, по умолчанию $8000$;
- `layout`: разрядность аудиоданных, по умолчанию $16$;
- `channel`: количество аудиоканалов, по умолчанию $1$;
- `bitrate`: битрейт аудио в $\rm kbps$, по умолчанию $16$. Чем выше битрейт, тем лучше качество звука, но тем больше размер файла.
- `codec`: формат кодирования аудио (строковый тип). Если не указан, подходящий кодек подбирается автоматически на основе параметра `format`;
- `format`: формат контейнера аудио (строковый тип). Если не указан, подходящий контейнер подбирается автоматически на основе суффикса параметра `uri`;

  Поддерживаемые соотношения часто используемых форматов записи, кодеков и контейнеров приведены ниже («пусто» в таблице означает, что соответствующий параметр можно не заполнять):

  | Часто используемые форматы записи | codec (кодек) | format (контейнер) |
  | --------------------------------- | ------------- | ------------------ |
  | pcm                               | пусто         | пусто              |
  | mp3                               | mp3           | пусто              |
  | opus                              | opus          | пусто              |
  | opus-ogg                          | opus          | ogg                |
  | silk                              | silk          | пусто              |

Ниже приведен пример кода для запуска записи:

``` js
let recorder = media.createAudioRecord()
recorder.start({
  uri: "internal://tmp/media_test.mp3",
  sample: 16000,
  layout: 16,
  channel: 1,
  bitrate: 16
})
```

::: info
Дополнительные инструкции по протоколу URI `internal` см. в документации [Доступ к ресурсам](/framework/application/resource.md).
:::

По окончании записи вызовите метод [stop()](#stop-1) для ее завершения.

<decl method><pre>
(options: {
  callback: (buffer: ArrayBuffer) => void,

</pre></decl>

Чтение записанных аудиоданных (каждый раз считываются все доступные данные с момента окончания предыдущего чтения до текущего момента).

### `stop` <decl type="(): void" method />

Остановить запись аудио. После вызова этого интерфейса другие модули могут прочитать аудиофайл, записанный методом [`start()`](#start) (определяется параметром `uri`).

### `release` <decl type="(): void" method />

Освободить ресурсы записи аудио.

### `onstart` <decl type="?: () => void" set />

Колбэк-событие после старта (`start`) записи.

### `onstop` <decl type="?: () => void" set />

Колбэк-событие после остановки (`stop`) записи.

### `onrelease` <decl type="?: () => void" set />

Колбэк-событие после освобождения (`release`) ресурсов записи.

### `onavailable` <decl type="?: (data: ArrayBuffer) => void" set />

## Примеры

### Запись звука

Следующий код демонстрирует самый простой пример записи 3 секунд аудио:
``` js
import media from "@system.media"

async function record() {
  // Создание объекта записи
  let record = media.createAudioRecord()
  console.log('start record')
  // Указан только параметр uri, остальные параметры используют значения по умолчанию
  await record.start({
    uri: 'internal://tmp/test.mp3'
  })
  setTimeout(() => {
    console.log('stop record')
    record.stop() // Остановить запись через 3 секунды
  }, 3000)
}

record()
```

При вызове функции `record()` создается объект записи, запускается процесс записи, который останавливается через 3 секунды. Запись будет сохранена в файл `internal://tmp/test.mp3` и закодирована в формате MP3.

В этом примере для метода [`AudioPlayer.start()`](#start) передан только параметр `uri`, в то время как `sample`, `layout`, `channel` и `bitrate` используют конфигурацию по умолчанию.

## Импорт модуля

## API

### `aes`
<decl method><pre>
(options: {
  action: string,
  text: string,
  key: string,
  transformation?: string,
  iv?: string,
  ivOffset?: number,
  ivLen?: number
  }): Promise&lt;{ text: string }>
</pre></decl>

Шифрование и дешифрование `aes`. Назначение полей параметра `options`:
- `action`：тип операции, два возможных значения: `'encrypt'` — шифрование, `'decrypt'` — дешифрование;
- `text`：текстовое содержимое для шифрования или дешифрования. Текст для шифрования должен быть обычным текстом, а текст для дешифрования должен представлять собой бинарное значение, закодированное в формате `base64`;
- `key`：ключ, используемый для шифрования или дешифрования, представляет собой строку, сгенерированную после кодирования в `base64`. До дешифрования в формате `base64` длина ключа должна быть кратна $16$ байтам;
- `transformation`：режим шифрования (`'ECB'`, `'CBC'`, `'CFB'`, `'CTR'`, `'OFB'`) и параметры дополнения алгоритма `AES`. По умолчанию используется `'AES/CBC/PKCS5Padding'`. Доступные варианты дополнения для AES:
  - `'PKCS5Padding'`
  - `'PKCS7Padding'`
  - `'NoPadding'`
  - `'OneAndZerosPadding'`
  - `'ZerosAndLenPadding'`
  - `'ZerosPadding'` 
- `iv`：инициализирующий вектор для шифрования и дешифрования AES, строка в кодировке Base64, по умолчанию равен значению поля `key`;
- `ivOffset`：смещение инициализирующего вектора для шифрования и дешифрования AES, по умолчанию равно $0$;
- `ivLen`：длина инициализирующего вектора шифрования и дешифрования AES в байтах, по умолчанию равна $16$;

# API

Glyphix предоставляет полный набор исполняемых JavaScript API, включая такие API, аналогичные браузерному окружению, как [`setInterval`](timer.md) и [`console`](console.md), а также различные интерфейсы системных возможностей, необходимых для реализации работы приложения в целом.

Однако, в отличие от браузерного окружения, Glyphix не предоставляет DOM-интерфейсы, поэтому здесь нет объектов `window`, `document` и т.д., а также невозможно выполнять какие-либо манипуляции с DOM.

## Асинхронные интерфейсы QuickApp

Glyphix поддерживает стандарт QuickApp (быстрых приложений) для умных часов, но мы в основном используем асинхронные интерфейсы в стиле Promise, а не в стиле функций обратного вызова (callback). Например, режим callback для интерфейса `file.readText()` в QuickApp для часов используется следующим образом:
``` js
import file from '@system.file'

file.readText({
  uri: 'internal://files/test.txt',
  success(data) {
    console.log(data)
  },
  fail(data, code) {
    console.log(`read text failed: ${code}`)
  }
})
```
Однако в Glyphix обычно используется стиль Promise:
``` js
import file from '@system.file'

// Предположим, внутри какой-то асинхронной функции
try {
  const content = await file.readText({ uri: 'internal://files/test.txt' })
  console.log(content)
} catch (e) {
  console.error('read text failed:', e)
}
```
Поскольку API в стиле Promise больше соответствует привычкам использования после стандарта ES6, в этой документации сохраняются сигнатуры типов только для версии Promise.

### Promise против интерфейсов с callback

Если не указано иное, все интерфейсы с типом возвращаемого значения `Promise<...>` поддерживают как стиль функций обратного вызова (для старых версий стандарта QuickApp), так и оба стиля асинхронных интерфейсов Promise. Асинхронные интерфейсы в стиле callback обычно имеют следующие типы:
``` ts
type CallbackAPI = (options: {
  success: (data: any) => void,
  fail: (data: any, code: number) => void,
  complete: () => void,
  // Другие параметры...
}) => void
```
А асинхронные интерфейсы в стиле Promise имеют следующий тип:
``` ts
type PromiseAPI = (options: any) => Promise<any>
```

Когда в параметре `options` присутствуют любые свойства `success`, `fail` или `complete`, API автоматически использует стиль функции обратного вызова (без возвращаемого значения), в противном случае используется стиль возврата Promise.

::: warning
При использовании стиля функции обратного вызова асинхронный API не возвращает никаких значений, поэтому использование синтаксиса `await` невозможно. Поэтому убедитесь, что при использовании синтаксиса Promise/`await` вы не передаете никаких функций обратного вызова `success`, `fail` или `complete`.
:::

### Пример API

В качестве примера рассмотрим модуль [`system.file`](system-file.md): все функции одновременно поддерживают режимы асинхронного вызова как в стиле Promise, так и в стиле callback. В следующем фрагменте кода приведено сравнение двух вариантов использования API.

::: code-tabs#js

@tab async/await

``` js
import file from '@system.file'

// async/await на самом деле является синтаксическим сахаром для Promise
async function readFile() {
  let text = await file.readText({ uri: '/app.js' })
  console.log(text)
}

readFile()
```

@tab Promise

``` js
import file from '@system.file'

file.readText({ uri: '/app.js' })
  .then(console.log) // Подсказка: тип console.log() совпадает с Promise.then(), использование стрелочной функции не требуется
  .fail((error) => console.log(`${error.message}: ${error.code}`))
```

@tab callback

``` js
import file from '@system.file'

file.readText({
  uri: '/app.js',
  success(data) {
    console.log(data)
  },
  fail(msg, code) {
    console.log(`${msg}: ${code}`)
  },
  complete() {
    console.log("complete")
  }
})
```

:::

В этой документации будут приведены типы API исключительно в стиле Promise, а в примерах асинхронных операций будет использоваться только синтаксис await/async.

::: tip
Разработчикам не рекомендуется дополнительно обертывать API Glyphix, особенно вручную адаптировать их стиль обратного вызова под шаблон Promise. Такой подход требует написания лишнего кода и снижает производительность.
:::

## Интерфейсы подписки

API подписок регистрируют функцию обратного вызова для определенного модуля вместо того, чтобы напрямую возвращать результат. В отличие от обычных асинхронных интерфейсов, функции обратного вызова интерфейсов подписки могут выполняться многократно. Все интерфейсы подписки поддерживают регистрацию нескольких функций обратного вызова и возвращают идентификатор подписки (subscription ID), который можно использовать для отмены подписки с помощью соответствующего интерфейса.

Glyphix в настоящее время не поддерживает функцию обратного вызова `fail` для подписок в стиле QuickApp, но при сбое подписки может напрямую генерировать исключение.

# Хранение данных

Модуль хранения данных `system.storage` позволяет приложениям сохранять собственные данные, которые персистентно хранятся в объекте хранения приложения. При удалении приложения данные, хранящиеся в `system.storage`, удаляются.

`system.storage` хранит данные в формате «ключ-значение», где ключ должен быть строкой, а значение — значением JSON (или значением JavaScript, которое может быть сериализовано в JSON).

## Импорт модуля

``` js
import storage from '@system.storage'
```

## API

### `get` <decl type="(key: string): any" method />

Получает значение, соответствующее ключу `key` в хранилище. Если пара «ключ-значение» не существует, возвращает `undefined`.

### `set` <decl type="(key: string, value: any): void" method />

Этот метод принимает в качестве параметров ключ `key` и значение `value` и добавляет эту пару в хранилище. Если ключ уже существует, его соответствующее значение обновляется.

### `delete` <decl type="(key: string): boolean" method />

Удаляет пару «ключ-значение», соответствующую ключу `key` в хранилище. Возвращает `true`, если пара существовала и была успешно удалена.

### `clear` <decl type="(): void" method />

Очищает все сохраненные данные в приложении.

# Глобальный объект

## Глобальные функции

### `encodeURIComponent` <decl type="(str: string): string" function />

Глобальная функция `encodeURIComponent()` используется для кодирования компонента URI `str`. Она экранирует определенные специальные символы в соответствующие шестнадцатеричные escape-последовательности с символом процента (`%`) в кодировке UTF-8, что гарантирует правильную интерпретацию компонента при использовании его в качестве части URL, особенно в параметрах строки запроса, путях или фрагментах. 

Буквы, цифры и `- _ . ! ~ * ' ( )` не кодируются. Остальные символы кодируются в escape-последовательности с процентом (например, пробел кодируется как `%20`).

Поведение `encodeURIComponent()` идентично [одноименной функции](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/encodeURIComponent) в веб.

Пример:
```js
console.log(encodeURIComponent("https://example.com/page?id=100"));
// output: https%3A%2F%2Fexample.com%2Fpage%3Fid%3D100
```

### `decodeURIComponent` <decl type="(str: string): string" function />

Глобальная функция `decodeURIComponent()` используется для декодирования компонента URI `str`, закодированного с помощью `encodeURIComponent()`. Она преобразует escape-последовательности с процентом (`%`) обратно в их исходные символы, восстанавливая первоначальный компонент URI. Например, она преобразует `%20` обратно в пробел.

Поведение `decodeURIComponent()` идентично [одноименной функции](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/decodeURIComponent) в веб.

Пример:
```js
console.log(decodeURIComponent("https%3A%2F%2Fexample.com%2Fpage%3Fid%3D100"));
// output: https://example.com/page?id=100
```

### `URI` <decl type="(uri: string | Uri): Uri" function />

Эта функция принимает строку и преобразует ее в объект `Uri` для дальнейшей обработки. Параметр `uri` — это строка URI, которую необходимо распарсить.

Возвращаемое значение представляет собой объект, содержащий следующие поля:
- `scheme: string`: схема, извлеченная из параметра;
- `authority: string`: авторитетная часть (authority), извлеченная из параметра;
- `path: string`: путь (path), извлеченный из параметра;
- `query: string`: строка запроса (query), извлеченная из параметра;
- `origin: string`: исходная строка URI из параметра;
- `toString: () => string`: этот метод позволяет закодировать объект обратно в строку URI.

Например:
``` js
console.log(URI("https://app-name/icon.png"))
// {
//   scheme: 'https',
//   authority: 'app-name',
//   path: '/icon.png',
//   query: '',
//   origin: 'https://app-name/icon.png',
//   toString: <function>
// }
```

Функция `URI` также принимает в качестве аргумента объект. В этом случае функция `URI` добавляет к объекту-параметру метод `toString`, с помощью которого объект URI можно закодировать в строку:
``` js
let uri = {
  scheme: 'https',
  authority: 'app-name',
  path: '/icon.png',
  query: ''
}
console.log(URI(uri).toString()) // 'https://app-name/icon.png'
```

### `subscribeAccelerometer`
<decl method><pre>
(options: { 
  interval?: 'game' | 'ui' | 'normal', 
  callback: (data: AccelerometerValue) => void,
}): number
</pre></decl>

Прослушивание изменений данных акселерометра. Назначение полей параметра `options`:
- `interval`：частота опроса, по умолчанию `'normal'`, возможные значения:
  - `'game'`：режим игры, частота 20 мс/опрос;
  - `'ui'`：режим пользовательского интерфейса (UI), частота 60 мс/опрос;
  - `'normal'`：обычный режим, частота 200 мс/опрос.
- `callback`：обратный вызов (callback) при обновлении данных акселерометра. Сигнатура типа данных акселерометра `AccelerometerValue`:
  ``` ts
  type AccelerometerValue = {
    x: number   // ускорение по оси x
    y: number   // ускорение по оси y
    z: number   // ускорение по оси z
  }
  ```

Пример:
```js
const id = sensor.subscribeAccelerometer({
  interval: 'normal',
  callback(ret) {
    console.log(`gyroscope data, x = ${ret.x}, y = ${ret.y}, z = ${ret.z}`)
  }
})

// Отмена подписки
sensor.unsubscribeAccelerometer(id)
```

Отмена прослушивания данных акселерометра. Параметр `id` — это идентификатор подписки, возвращаемый методом [`subscribeAccelerometer`](#subscribeaccelerometer).

### `subscribeCompass`
<decl method><pre>
(options: { 
  callback: (data: CompassValue) => void,
}): number
</pre></decl>

Прослушивание изменений данных компаса. Возвращает идентификатор подписки, который используется для ее отмены. Назначение полей параметра `options`:
- `callback`：обратный вызов при изменении данных компаса.

Сигнатура `CompassValue`:
``` ts
  type CompassValue = {
    direction: number   // угол между осью y и магнитным северным полюсом (в радианах)
    accuracy: number    // точность
  }
```
- `direction`：угол в радианах между осью Y устройства и магнитным северным полюсом Земли, диапазон значений $(-\pi,\pi]$, где:
  - `0`：строго на север
  - $\pi$` / 2` (около 1.57)：строго на восток
  - $\pi$ (около 3.14)：строго на юг
  - -$\pi$` / 2` (около -1.57)：строго на запад
- `accuracy`：уровень точности данных компаса
  - `3`：высокая точность
  - `2`：средняя точность
  - `1`：низкая точность
  - `0`：недоступно (причина неизвестна)
  - `-1`：недоступно (датчик потерял связь)

Пример:
```js
const id = sensor.subscribeCompass({
  callback(ret) {
    console.log(`direction=${ret.direction}, accuracy=${ret.accuracy}`)
  }
})

// Отмена подписки
sensor.unsubscribeCompass(id)
```

### `getBLEScanResults`
<decl method><pre>
(): Promise&lt;Array&lt;ScanResult&gt;&gt;
</pre></decl>

Запрос результатов сканирования с использованием асинхронного callback-вызова Promise. Этот интерфейс асинхронно возвращает массив объектов [`ScanResult`](#scanresult) (то есть Array&lt;[`ScanResult`](#scanresult)&gt;).

::: warning
Поскольку нижележащий адаптер Bluetooth является синглтоном, могут возникать ситуации, когда несколько приложений одновременно работают с устройствами Bluetooth. Возможен такой сценарий: Приложение А запускает сканирование на некоторое время, после чего Приложение Б снова запускает сканирование — в этом случае результаты сканирования, прослушиваемые Приложением Б, могут быть неполными. Чтобы справиться с этой ситуацией, рекомендуется всем приложениям сразу после запуска сканирования запрашивать текущие результаты сканирования.
:::

Ниже приведен пример запроса результатов сканирования после его запуска:
```ts
import ble from '@system.bluetooth.ble'
export default {
    data: {
        scanList: [],
    },
    async scanStart() {
        // Запуск сканирования
        await ble.startBLEScan().then(async (result) => {
            console.dir('startBLEScan success')
            // Запрос результатов сканирования
            await ble.getBLEScanResults().then((results) => {
                this.scanList = results
            });
        }).catch((error) => {
            console.dir('startBLEScan error:' + JSON.stringify(error))
        })
    },
}
```

# Таймер

Этот модуль предоставляет функции таймера для отложенного или периодического выполнения кода. API таймера можно использовать напрямую без необходимости импорта.

## Определение интерфейсов

### `setTimeout` <decl type="(callback: () => void, duration: number): number" />

Устанавливает таймер, который выполняет функцию обратного вызова (callback) по истечении указанной задержки. Описание параметров:
- `callback` — функция обратного вызова, которая будет выполнена по истечении времени задержки;
- `duration` — время задержки в миллисекундах.

Возвращает ID таймера, который можно использовать для его отмены с помощью метода [`clearTimeout()`](#cleartimeout).

Пример:
``` js
// Выполнить callback через 1 секунду
const timerId = setTimeout(() => {
  console.log('Прошла 1 секунда')
}, 1000)
```

### `setInterval` <decl type="(callback: () => void, duration: number): number" />

Устанавливает таймер, который повторяет выполнение функции обратного вызова с заданным интервалом. Описание параметров:
- `callback` — функция обратного вызова, выполняемая при каждом срабатывании таймера;
- `duration` — интервал выполнения в миллисекундах.

Возвращает ID таймера, который можно использовать для его отмены с помощью метода [`clearInterval()`](#clearinterval).

Пример:
``` js
// Выполнять callback каждые 500 миллисекунд
const timerId = setInterval(() => {
  console.log('Прошло еще 500 миллисекунд')
}, 500)
```

### `clearTimeout` <decl type="(timerId: number): void" />

Отменяет таймер, установленный методом [`setTimeout()`](#settimeout). Параметр `timerId` — это ID отменяемого таймера.

::: warning
В отличие от веб-окружения, в данной реализации пул ID таймеров **может переиспользоваться**. Поэтому **не** вызывайте `clearTimeout()` повторно для одного и того же действующего ID таймера, иначе вы можете случайно остановить другой работающий таймер.

Рекомендуется устанавливать ID таймера в значение `null` после очистки во избежание повторных вызовов. `clearTimeout()` безопасно принимает недействительные ID вроде `null` или `0`, такие вызовы не имеют побочных эффектов.
:::

Пример:
``` js
const timerId = setTimeout(() => {
  console.log('Это сообщение не будет выведено')
}, 1000)

// Отменяем таймер до его срабатывания
clearTimeout(timerId)
```

Рекомендуемый подход — сбрасывать ID таймера после очистки, чтобы избежать повторной очистки действующего ID:
``` js
export default {
  onInit() {
    this.timerId = setTimeout(() => {
      console.log('Таймер сработал')
      this.timerId = null // Сбрасываем ID после выполнения
    }, 1000)
  },
  onDestroy() {
    // Безопасная очистка, даже если timerId равен null
    clearTimeout(this.timerId)
  },
  someMethod() {
    // Очищаем таймер и сбрасываем ID
    clearTimeout(this.timerId)
    this.timerId = null
  },
}
```

### `clearInterval` <decl type="(timerId: number): void" />

Отменяет таймер, установленный методом [`setInterval()`](#setinterval). Параметр `timerId` — это ID отменяемого таймера.

::: warning
В отличие от веб-окружения, в данной реализации пул ID таймеров **может переиспользоваться**. Поэтому **не** вызывайте `clearInterval()` повторно для одного и того же действующего ID таймера, иначе вы можете случайно остановить другой работающий таймер.

Рекомендуется устанавливать ID таймера в значение `null` после очистки во избежание повторных вызовов. `clearInterval()` безопасно принимает недействительные ID вроде `null` или `0`, такие вызовы не имеют побочных эффектов.
:::

Пример:
``` js
let count = 0
const timerId = setInterval(() => {
  count++
  console.log(`Количество выполнений: ${count}`)
  if (count >= 5)
    clearInterval(timerId) // Остановить после 5 выполнений
}, 500)
```

::: tip
`clearInterval` и `clearTimeout` по сути являются двумя псевдонимами одной и той же функции, однако для поддержания чистоты кода рекомендуется использовать соответствующие методы.
:::

## Заметки разработчика

### Переиспользование ID таймеров

Существует важное отличие данной реализации от стандартного веб-окружения: **ID таймеров могут переиспользоваться**.

В веб-браузерах и Node.js каждый вызов `setTimeout()` или `setInterval()` возвращает уникальный монотонно возрастающий ID, и эти ID не переиспользуются. Поэтому в веб-окружении безопасно вызывать `clearTimeout()` или `clearInterval()` для уже очищенных или недействительных ID таймеров без каких-либо побочных эффектов.

Однако в текущей реализации ID таймеров берутся из ограниченного пула. Когда таймер очищается или завершает работу, его ID может быть переиспользован новым созданным таймером. Это означает, что если вы повторно очистите один и тот же ID (число, возвращенное `setTimeout()` или `setInterval()`), вы можете случайно остановить другой работающий таймер.

`clearTimeout()` и `clearInterval()` могут безопасно принимать значения, не являющиеся ID таймеров, такие как `null`, `0`, `undefined` и т.д. Такие вызовы не имеют побочных эффектов.

Поэтому **обязательно соблюдайте следующие лучшие практики**:
1. Очищайте каждый ID таймера ровно один раз;
2. После очистки устанавливайте ID таймера в `null`, `0` или `undefined`, чтобы избежать случайной повторной очистки.

Поскольку `clearTimeout()` и `clearInterval()` безопасно принимают значения вроде `null` или `0`, предварительная проверка на валидность перед вызовом не требуется.

В примерах из документации API выше показан рекомендуемый подход.

Исключение: вы можете очистить ID таймера из его собственного callback-метода для `setTimeout`:
``` js
let timer = setTimeout(() => {
  clearTimeout(timer) // Это не повлияет на другие таймеры и не вызовет предупреждение в логе
}, 1000)
```

### Проблемы с точностью таймеров

API таймеров **не гарантирует точные временные интервалы**, и фактическое время выполнения может отличаться. Это происходит по следующим причинам:
- Системное планирование и ограничения производительности могут приводить к неточному срабатыванию таймеров;
- Минимальный интервал таймера ограничен системой и в любой момент может зависеть от стратегий энергосбережения.

Поэтому **не используйте** API таймеров для высокоточного измерения времени. Если вам нужно измерить временные интервалы или реализовать секундомер, используйте объект `Date` для получения актуальной метки времени.

#### Неправильный пример: использование счетчика таймера для измерения времени

Следующий код пытается вычислить прошедшее время путем суммирования количества срабатываний таймера, что является неверным подходом:
``` js
export default {
  data: {
    elapsedTime: 0, // Вычисление прошедшего времени путем суммирования
  },
  onInit() {
    // Ошибка: предполагается, что таймер срабатывает ровно каждую секунду
    this.timerId = setInterval(() => {
      this.elapsedTime += 1000
    }, 1000)
  },
  onDestroy() {
    clearInterval(this.timerId)
  },
}
```

Проблема этого метода заключается в том, что даже если заданный интервал составляет $1000\rm ms$, фактический интервал срабатывания может составлять $1010\rm ms$ или даже больше. Накопленная погрешность со временем сделает отсчет времени все менее точным. После перехода устройства в режим пониженного энергопотребления таймеры могут работать с точностью до секунды или быть временно приостановлены.

#### Правильный пример: использование объекта Date для отсчета времени

Правильным подходом является запись начальной метки времени и вычисление разницы с текущим моментом при каждом обновлении:
``` js
export default {
  data: {
    elapsedTime: 0, // Прошедшее время (в миллисекундах)
  },
  onInit() {
    // Записываем начальную метку времени
    this.startTime = Date.now()
    // Используем таймер для регулярного обновления отображения
    this.timerId = setInterval(() => {
      // Получаем реально прошедшее время через разницу меток времени
      this.elapsedTime = Date.now() - this.startTime
    }, 100) // Можно установить меньший интервал обновления для более плавного отображения
  },
  onDestroy() {
    clearInterval(this.timerId)
  },
}
```

### Полный пример секундомера

Ниже приведен полный пример компонента-секундомера, который демонстрирует правильную реализацию функций запуска, паузы и сброса:

``` html
<div class="container">
  <text class="timer">{{ formatTime(elapsedTime) }}</text>
  <div class="buttons">
    <text class="button" on:click="start">Start</text>
    <text class="button" on:click="pause">Pause</text>
    <text class="button" on:click="reset">Reset</text>
  </div>
</div>
```

``` js
export default {
  data: {
    elapsedTime: 0,     // Прошедшее время (в миллисекундах)
    isRunning: false,   // Работает ли секундомер в данный момент
  },
  onInit() {
    this.startTime = 0       // Метка времени текущего запуск
    this.accumulatedTime = 0 // Накопленное время (для продолжения после паузы)
    this.timerId = null
  },
  onDestroy() {
    // Очищаем таймер
    clearInterval(this.timerId)
  },
  start() {
    if (this.isRunning)
      return // Уже запущен, избегаем повторного старта

    this.isRunning = true
    // Записываем метку времени текущего запуска
    this.startTime = Date.now()

    // Регулярно обновляем отображение
    this.timerId = setInterval(() => {
      // Накопленное время + (текущее время - время запуска)
      this.elapsedTime = this.accumulatedTime + (Date.now() - this.startTime)
    }, 20)
  },
  pause() {
    if (!this.isRunning)
      return // Уже на паузе, делать ничего не нужно

    this.isRunning = false
    // Останавливаем таймер
    clearInterval(this.timerId)
    this.timerId = null // Сбрасываем ID после очистки

    // Сохраняем накопленное время для последующего продолжения
    this.accumulatedTime = this.elapsedTime
  },
  reset() {
    // Останавливаем таймер
    this.isRunning = false
    clearInterval(this.timerId)
    this.timerId = null // Сбрасываем ID после очистки

    // Сбрасываем все состояния
    this.elapsedTime = 0
    this.accumulatedTime = 0
    this.startTime = 0
  },
  formatTime(ms) {
    // Преобразование миллисекунд в формат "минуты:секунды.миллисекунды"
    const totalSeconds = Math.floor(ms / 1000)
    const minutes = Math.floor(totalSeconds / 60)
    const seconds = totalSeconds % 60
    const milliseconds = Math.floor((ms % 1000) / 10)

    return `${String(minutes).padStart(2, '0')}:${String(seconds).padStart(2, '0')}.${String(milliseconds).padStart(2, '0')}`
  },
}
```

### Предотвращение утечек памяти

При использовании таймеров обязательно вовремя очищайте их, иначе это может привести к утечкам памяти или обращению к уже уничтоженным компонентам. Очищайте все таймеры в функции жизненного цикла [`onDestroy()`](/framework/component/life-cycle.md) компонента:
``` js
export default {
  onInit() {
    this.timerId = setTimeout(() => {
      // Выполнение каких-либо действий
      this.timerId = null // Сбрасываем ID после выполнения
    }, 5000)
  },
  onDestroy() {
    // Очищаем таймер во избежание утечки памяти
    clearTimeout(this.timerId)
  },
}
```

Это особенно важно для периодических таймеров, созданных с помощью `setInterval()`, так как они будут работать бесконечно, пока не будут явно отменены.
