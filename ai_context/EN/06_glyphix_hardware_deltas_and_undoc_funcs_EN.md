# Glyphix OS: Спецификация и профилирование Canvas API
**Статус:** Фактологически подтверждено на эмуляторе, на реальном устройстве требует дополнительной проверки

---

## 1. Системные особенности работы Canvas API
1. **Инициализация:** Выполняется через вызов метода `getContext('2d')` (или `getContext()`) у нативного элемента `<canvas>` в фазе жизненного цикла `onReady`.
2. **Механизм Opaque Pointer (C++ Proxy):** Объект контекста представляет собой прокси-обертку над нативным C++ графическим конвейером.
3. **Опасность проверок `if (ctx.method)`:** Попытка проверить наличие метода перед вызовом всегда возвращает `true` (функцию-обертку). Вызов нереализованного в C++ метода приводит к фатальному исключению `TypeError: not a function` и крашу JS-контекста. Вызывать можно **строго** подтвержденный список функций.

---

## 2. Итоговая матрица поддержки API

### 2.1. Поддерживаемые методы и свойства

| Категория | Поддерживаемые сущности | Применение|
| :--- | :--- | :--- |
| **Свойства стиля** | `fillStyle`, `strokeStyle`, `lineWidth` | Управление цветом трека, курсора, текста и толщиной линий |
| **Базовые фигуры** | `fillRect`, `strokeRect`, `rect`, `fill` | Очистка кадра (`fillRect`), отрисовка плашек и фонов |
| **Контуры (Path)** | `beginPath`, `moveTo`, `lineTo`, `stroke` | Отрисовка нитки маршрута (Polyline) и векторов курсора |
| **Кривые** | `arc`, `arcTo`, `bezierCurveTo`, `quadraticCurveTo` | Отрисовка маркеров POI (`arc`), скруглений и шкалы компаса |
| **Трансформации** | `save`, `restore`, `translate`, `rotate`, `scale` | Аппаратный поворот и сдвиг холста под азимут движения |
| **Текст** | `fillText` | Прямой рендер дистанции, скорости и подсказок на Canvas |

### 2.2. Отсутствующие методы

| Отсутствующий метод | Причина / Альтернатива (Fallback) |
| :--- | :--- |
| `clearRect` | **Критично.** Заменен заливкой фоновым цветом: `ctx.fillRect(0, 0, width, height)` |
| `ellipse` | Эмулируется через `arc()` |
| `transform` | Использовать комбинацию `translate()` и `rotate()` |
| `strokeText`, `measureText` | Использовать только `fillText()`. Выравнивание текста задавать фиксированными смещениями |
| `getImageData`, `putImageData` | Прямая работа с пиксельным буфером на JS недоступна |
| `clip` | Маскирование отсечением недоступно |
| `createLinearGradient` | Градиенты не поддерживаются. Использовать сплошной цвет (`fillStyle`) |

---

## 3. Архитектурные преимущества подтвержденного API

1. **Аппаратные трансформации (`rotate` / `translate` / `save` / `restore`):**
   Наличие этих методов позволяет полностью отказаться от ручной тригонометрии поворота векторов на JS (`Math.cos`/`Math.sin`). Достаточно сдвинуть систему координат в центр экрана через `translate(cx, cy)` и повернуть на угол азимута `rotate(heading)`.

2. **Отрисовка кривых (`arc` / `arcTo`):**
   Позволяет рендерить круглые маркеры текущего местоположения, промежуточные точки (Waypoints), а также элементы интерфейса (шкалу компаса, спидометр).

3. **Прямой рендер текста (`fillText`):**
   Убирает необходимость верстать оверлеи из Flexbox-тегов `<text>` поверх `<canvas>`, уменьшая количество узлов в дереве элементов и снижая расход оперативной памяти MCU.

---

## 4. Канонический паттерн очистки и отрисовки кадра

```javascript
renderFrame() {
  // 1. Очистка экрана (Замена отсутствующему clearRect)
  this.ctx.fillStyle = '#000000';
  this.ctx.fillRect(0, 0, 466, 466);

  // 2. Сохранение состояния матрицы трансформации
  this.ctx.save();

  // 3. Сдвиг центра координат и поворот холста под азимут (Heading)
  this.ctx.translate(233, 233);
  this.ctx.rotate(this.userHeading);

  // 4. Отрисовка объектов (курсор/трек) относительно нового центра
  // ...

  // 5. Восстановление исходного состояния матрицы
  this.ctx.restore();

  // 6. Вывод статичной телеметрии поверх кадра
  this.ctx.fillStyle = '#00ff00';
  this.ctx.fillText('150m', 200, 420);
}
```

# Техническая спецификация: Особенности и ограничения платформы DT NO.1 G1 (ATS3085S / Glyphix OS)

В ходе реверс-инжиниринга и полевых тестов были выявлены следующие критические ограничения среды исполнения (JS Sandbox) на реальном устройстве:

## 1. Графический конвейер и Layout Engine
* **Отсутствие Canvas API:** Компонент `<canvas>` и методы его контекста аппаратно вырезаны производителем (Opaque Pointer Trap: `TypeError: not a function`). Весь кастомный рендеринг должен осуществляться через DOM-дерево (множество мелких `<div>`).
* **Ограничения Flexbox и CSS:** * Парсер стилей игнорирует значение `relative` для свойства `position`. Корневые контейнеры должны строиться без него.
  * Абсолютное позиционирование дочерних узлов отсчитывается строго от левого верхнего угла экрана `(0, 0)`.
  * Свойство `transform: rotate()` **не поддерживается** на реальном железе (вызывает `WARN: unknown style property` и игнорируется). Вращение элементов должно рассчитываться математически через `left`/`top`.
  * Динамический биндинг CSS-классов не поддерживается.
* **Геометрия дисплея:** Экран физически круглый с разрешением $466 \times 466$ пикселей.
  * **Безопасные зоны (Safe Areas):** Текстовые элементы и UI-компоненты должны размещаться по оси Y в диапазоне `45px` (верх) — `360px..370px` (низ), чтобы не обрезаться безелем.

## 2. Файловая система (VFS) и Хранилище (KV)
* **Точки монтирования (RW доступ):** Приложение имеет полный доступ на чтение и запись к трем директориям:
  * `internal://mass/` — Общая память. Физически мапится на `/1:/data/mass/` на часах (доступна по USB с ПК).
  * `internal://files/` — Приватная память приложения.
  * `internal://cache/` — Приватный кэш приложения.
* **Расположение в эмуляторе ПК:** Виртуальная ФС эмулятора мапится в папку проекта: `.glyphix-work\image\default-watch-466x466\data\`.
* **Аномалии API `@system.file` (Отличия от стандарта QuickApp):** * Метод `file.readText()` на часах возвращает **строку напрямую** (без обертки `{ text: "..." }`).
  * Метод `file.list()` возвращает **плоский массив строк** с именами файлов (например, `["test.txt", "purrgo.gpx"]`), а не массив объектов `{ uri, length }`. Получить размер файла через `list()` на текущей прошивке невозможно.
* **Аномалии FlashDB (`@system.storage`):**
  * Метод `storage.delete(key)` принимает **строку напрямую**, а не объект `{ key: "..." }` как в стандарте. Передача объекта приводит к попытке удаления ключа-строки `"[object Object]"` и не очищает реальную память, вызывая утечки и сбои чтения.
  * При запросе несуществующего ключа, API иногда возвращает строку `"undefined"` вместо типа `undefined`. Обязательно использование явного кастинга и проверок `String(val) !== 'undefined'`.

## 3. Процессорное время и Watchdog
* **Агрессивный Watchdog:** Микроконтроллер не имеет полноценной многозадачности. Блокировка главного потока тяжелыми вычислениями (например, RegExp-парсинг XML/GPX строк размером 5-10 КБ в одном цикле) приводит к зависанию устройства.
* **Асинхронные паузы:** Любые пакетные вычисления должны быть принудительно обернуты в макрозадачи (например, `setTimeout(..., 50)`), чтобы отдать процессорное время ОС для обработки аппаратных прерываний.

## 4. Сенсоры и Троттлинг
* **Событийный шторм (Event Storm):** Аппаратный модуль компаса (`@system.compass`) генерирует прерывания с частотой до 50 Гц.
* **Лимиты реактивности:** Реактивный движок привязки данных Glyphix не способен пересчитывать десятки инлайн-стилей `left`/`top` на высокой частоте. Недопустимо помещать ID подписок сенсоров (`subscribeId`) в реактивный объект `data: {}`.
* **Throttling (Дросселирование):** Перерисовку DOM необходимо жестко лимитировать до 5-10 кадров в секунду (через флаги блокировки и `setTimeout` на 100-200 мс), иначе гарантирован перегрев, разряд батареи и зависание интерфейса.
* **Аномалия сигнатур C++:** * `compass.subscribe()` принимает **напрямую функцию**: `((data) => {})`. Передача объекта вызывает краш `InternalError: first args must is a function`. Направление (`direction`) приходит в **радианах**.

## 5. Геолокация (`@system.geolocation`) и Аппаратные лимиты GNSS
* **Отсутствие поддержки Promise:** На платформе ATS3085S метод `geolocation.getLocation()` **не возвращает Promise**. Обязательно использовать передачу объекта с коллбеками `success` и `fail`. Попытка вызова через `await getLocation()` вернет `undefined`.
* **Измененная структура Payload:** В коллбеке `success(data)` целевые координаты находятся не в корне ответа, а во вложенном объекте `data` (т.е. `data.data.latitude` / `data.data.longitude`).
* **Изоляция встроенного GNSS (Tethered-заглушка):** На серийной прошивке JS-модуль `@system.geolocation` аппаратно отрезан от встроенного чипа. 
  * Метод обращается строго к Bluetooth-мосту и требует активного подключения к приложению-компаньону на смартфоне.
  * Без активного BT-моста функция мгновенно отбрасывает вызов через коллбек `fail` с ошибкой `Code: 1002` ("Currently not connected to the mobile phone Bluetooth network").
  * Метод непрерывного опроса `geolocation.subscribe()` аналогично не функционирует автономно и "глухо" молчит (не вызывает коллбеки), если телефон не подключен.
  * **Прямой доступ к GNSS-чипу часов в автономном режиме возможен исключительно путем создания Native Applet на языке C++** через внутренний HAL-интерфейс ОС.Или же возможен патчинг прошивки для перенаправления запроса на геолокацию к встроенному GNSS-чипу часов.
